# Nous 实现策略

从用户需要的实际操作出发，沿 CLI、运行中宿主或 SDK 的相关入口找到共同应用操作、数据和状态的所有者。按任务追踪文件输入、持久化、取消和恢复，不把某个入口的临时转换当成业务合同。已有设计、代码和测试都结合当前要求判断。

区分无外部承诺的开发期内部结构与真实持久数据、用户文稿、精确来源和明确支持的边界。内部结构直接迁移并删除旧路径；需要保留的数据和调用方式在实际边界完成迁移。不要因旧测试或局部 diff 大小保留内部双轨。

同一事实出现多套身份、编码、验证、状态或调用链，或为同一职责反复增加分支、包装和测试组合时，回到原始功能与共同所有者重设方案。逐项判断相关抽象、分支与测试应保留、替换还是删除；按真实职责实施，不建立额外证明表。合并真正需要一起变化的规则，迁移全部生产者和消费者，再删除被替换的实现及专属支撑。对新增抽象应用删除判断：删掉它是让无用复杂性消失，还是把必要复杂性分散给调用者；只为实际职责保留抽象。

从完整业务行为与独立失败重新组织验证，保留重启恢复、并发、实际数据与外部边界等相关场景，不让旧内部接口决定新结构。真实 CLI、宿主和 SDK 的相关路径应消费同一应用能力。

本技能根据 [OpenAI Agents SDK implementation-strategy](https://github.com/openai/openai-agents-python/tree/main/.agents/skills/implementation-strategy) 的复杂性重置与所有权方法适配 Nous；原项目的 SDK 专用流程不适用于本仓库。许可证见 [LICENSE](LICENSE)。
