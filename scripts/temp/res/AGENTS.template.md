# Temporary data and test material

`temp/` holds local development tools, caches, temporary work, and test material. Git ignores it. Put a product example, a formal script, or a regression test that remains useful long-term into the versioned place the repository assigns to it.

Create the directories, inspect status, and clean up with the [temp management guide](<ROOT>/scripts/temp/README.md) and its scripts:

- Windows: `pwsh -File ./scripts/temp/run.ps1 init`, `status`, `clean`. An actual cleanup uses `clean -Apply`.
- Linux: `sh scripts/temp/run.sh init`, `status`, `clean`. An actual cleanup uses `clean --apply`.

Run the commands from the repository root. Before cleaning, stop tasks that are using the directories involved, and move material worth keeping into `test-materials/`. A cleanup keeps test material, tools, and virtual environments unless told otherwise. The management guide states the cleanup scope and the toolchain option.

## Directory use

- `work/<task>/`: one-off scripts, probes, experiment output, and disposable instances. Keep temporary work together by task. Do not scatter it at the `temp/` root.
- `build/` and `cache/`: rebuildable build output and dependency caches. `runtime/`: temporary files of tool runtimes.
- `reference-code/`: reference repositories and temporary source that can be fetched again.
- `tools/` and `venvs/`: tools, runtimes, and virtual environments downloaded locally. Audio and video work may use the FFmpeg and ffprobe already there.
- `test-materials/`: test inputs, instances, and results kept for later inspection. Material that needs to be kept long-term goes here, together with its manuscript, source, and license information.

## Test material

A file whose name starts with `0-` was supplied by the user. Prefer it for tests against real material, and do not modify it. An Agent does not use this prefix for content it generates or downloads.

`test-materials/` is grouped by use:

- `Text/`: text and Markdown sources. Project documents may also be used as test input.
- `Image/`: everyday scenes, text, illustration, pixel art, screenshots, and photographs. `Probes/` holds probe images generated by a program.
- `Audio/Speech/`: speech samples. `TTS/` holds short sentences, stories, document readings, and dialogue; the manuscript and metadata stay with the audio. `FormatChecks/` holds format-check samples.
- `Audio/Music/`: music with and without vocals. `sources.json` holds source, license, and reference information. `*-listen.wav` is suitable for listening.
- `PDF/` and `Video/`: PDF originals and video material.
- `Config/`, `Prompts/`, `Schemas/`, and `Collections/`: configuration, prompts, structured-output constraints, and collection manifests.
- `Results/`, `Exports/`, and `Diagnostics/`: results, exports, and diagnostic material kept on purpose. `Diagnostics/Fixtures/` contains material that is deliberately damaged or used for abnormal scenarios.
- `Instances/`: test instances worth keeping. Create them with Nous `init`. `Incoming/`: material gathered from scattered directories during cleanup and waiting to be classified.

A local file reference in JSON metadata is relative to that JSON file. A path in a dialogue-concatenation file is relative to the concatenation file. Keep these references when using the material.

Volcengine Ark TTS audio may be used as a standard audio sample, and new audio may be generated with the repository's [TTS tool](<ROOT>/integrations/volcengine-tts/synthesize.py). Images generated by ChatGPT ImageGen may be used as standard image samples. A Codex Agent may generate new material with the corresponding tool or skill.

High-value material includes:

- Real file content supplied by the user.
- Normal TTS audio and AI-generated images.

Exclude damaged files, test fixtures, and program probes that have no actual content.
