# 部署、更新、导出与清除

## 安装形态

当前交付支持 Windows 11、Ubuntu 24.04 LTS 和 macOS。两个产品可以同机或分机运行；主要代码使用 Node 24 LTS 与跨平台依赖，原生二进制从其维护方正式发行物取得。普通使用者通过产品 CLI 完成设置与服务操作。

提供 npm/压缩包形式的应用、包含标准 Node 运行时的可选发行包，以及容器 Compose 组合。开发环境使用 pnpm，AstrBot 插件跟随上游 Python 环境，通过 uv 或官方容器安装。后端普通 ESM，LanceDB/keyring 等原生依赖保留其平台分发文件。

服务器连接系统 PostgreSQL 或官方容器；个人本地安装采用 `embedded-postgres` 管理自己的 PostgreSQL 18 实例。该库负责初始化、启停及跨平台二进制，产品只保存实例配置并调用公开方法。pnpm 构建许可明确包含该依赖所需的安装脚本。数据库由安装级的一个服务拥有，Nous 与 Hept 分别使用自己的库，不各自启动同一个实例。

部署引导显示实际选择并生成连接配置。Node、数据库和原生工具的下载与安装由显式命令触发，正常启动只使用已配置资源。独立安装可由产品服务生命周期托管本地库；联合安装的数据库服务由系统服务管理，避免其中一个产品停止时关闭另一方仍在使用的数据库。

## 目录与数据库

安装目录只保存版本化程序。配置根保存 bootstrap 与秘密引用；数据根保存产品数据库连接所指资料、blobs、世界包、导出和任务成果；缓存与日志使用独立根。默认 DBOS 使用同一产品数据库中的官方 dbos schema，普通业务模块通过官方接口访问执行信息。

Nous 与 Hept 使用各自数据库和账户。默认可共享一个 PostgreSQL 实例，数据库权限隔离。LanceDB 索引位于 Nous 数据根的派生目录，删除后可重建。文件引用通过对象存储接口解析，业务记录不保存开发机绝对路径作为身份。

工作空间由 OpenClaw/沙箱拥有，明确区分主体任务和维护工作。媒体临时目录与正式保全目录分开，清理临时目录不会删除已经成为来源的原件。

## 启动、暂停与服务

服务启动完成 bootstrap、数据库与必要迁移、模块组成、DBOS 注册、资源检查和 HTTP 入口。产品状态可以是 running 而主体仍处于 stopped。`subjects.start/pause/stop` 影响主观生活运行，收件和管理继续按各自设置工作。

系统服务使用 systemd、launchd 和 shawl。CLI 调用现成服务命令安装、启动、停止、查看日志和更新环境，不实现常驻监督器。容器环境使用编排器的生命周期和重启设置。

联合启动顺序为数据库、Nous、Hept、执行器及指定通信渠道。Hept 独立模式省略 Nous。必要依赖不可用时只暂停对应操作，确定性世界状态和可用管理路径继续提供。

## 发布与更新

每个发布包包含一份依赖锁和对应数据库迁移。第三方源码改编以可构建依赖版本发行，应用更新原子替换程序目录。两个仓库的公开 Client 按正常包版本协作，源码开发可使用 workspace/link；产品发行不引用开发人员手工打出的陈旧 tarball。

`updates.prepare` 暂停新主观与后台模型工作，完成当前短事务和已派发模型步骤，保存形成成果与原生任务引用。等待自然节点的工作取消其旧定时，重启后按正式节点重新安排。仍在运行的原生 Task 保留 run 引用，升级后继续查询同一 run。

与新代码流程一致的 DBOS 工作继续使用官方应用版本机制。需要改变执行步骤顺序的发布先结束有限业务流程，保留其正式成果与尚待处理的业务状态，再由对应 owner 继续剩余动作。更新命令显示需要等待或显式结束的具体操作；不自行把任意旧检查点解释为新流程。

迁移使用 Kysely 和 DBOS 官方 schema 初始化。当前从空库建立首版迁移，不承接旧项目私有 RPC、表、配置或接口。未来正常升级只维护实际已发布的数据变化。

## 跨平台工作环境

路径使用标准库，进程调用使用 execa，避免 shell 字符串拼接。文件上传下载通过流，Unicode 文件名和路径在接口中保持原始名称及独立对象身份。需要执行脚本时按平台提供相应入口，通用工作由 Node 完成。

浏览器与工具隔离优先使用 OpenClaw 的成熟 sandbox/容器能力。Windows 原生 CLI、管理与世界运行完整支持；要求 Linux 工具环境的任务可配置容器或远端 worker。界面显示该工作空间的真实位置与能力，主体任务仍使用同一 Task 合同。

macOS 使用同样 API/CLI/Console 代码，服务和 keyring 适配交给现成系统工具。平台接线只覆盖目录、凭据、服务、原生包和任务环境；认知与生活代码不分叉。

## 主体导出与跨机迁移

`data.export` 导出当前产品的正式主体对象、历史修订、来源、资料、世界、交往、WorkContext、成果和必要权限。包内使用逻辑身份与相对文件路径，包含 formatVersion、产品版本、主体、截点、对象与 blob 清单以及有意省略项。安装级密钥、模型账户和机器绝对路径排除。

联合导出先对选定主体建立短暂静默窗口：暂停新的主观采用与该主体成长，完成已经接受的跨产品交接，取得共同截点，再从各自一致读取快照生成导出。其他主体继续运行。新收件可以保存在截点之后，明确归于本次导出以外的后续内容。

包携带外部引用的来源与可用状态。被授权省略的隐私材料列明省略原因；尚未取得的资料保留缺口。已完成原生成果作为普通材料导出，原生执行会话可由宿主公开导出能力附带。可移植主体包保存业务目标、进展和结果，不携带另一机器上的活动连接与进程句柄。

导入先预览主体、能力、世界、资料范围和所需连接。新实例为包内对象保留 UUID，按导入清单将其本地定位改为当前安装；原始来源安装保留在 provenance。包内相互引用一次解析，外部引用保持其来源。完成后重建派生索引。

迁移恢复保留 SubjectId，目标必须为空或明确选择替换。身份已经存在而需要保留两份生活时，使用分支操作生成新 SubjectId。默认导入后暂停外部发送，管理员重新绑定账号、凭据与工作空间后启用。

## 分支

`subjects.fork` 从选定知情/记录截点建立新主体，复制获准继承的认知、世界和历史资料，记录 branchedFrom。分支重新映射自身对象归属，保留原始来源与跨主体分享许可。

执行中的 Task、尚未发送的表达和通信账号不会作为两个同时活动的外部执行复制。分支取得相应目标、进展和成果，默认处于暂停状态，由新主体明确决定继续。认知历史可以分化，原主体保持独立。

## 安装备份与恢复

安装备份使用 PostgreSQL 官方 dump 或实例快照，加正式文件与原生可导出状态，再交给 restic 保存、加密和保留。备份启动前使用维护静默窗口取得一致的数据库与文件集合，完成后恢复运行。管理员选择存储目标、保留期和计划，计划由现有调度执行。

正常重启继续当前执行。恢复旧快照时，明确进入 restored 状态：所有快照中未终结的对外发送、发布、计费请求和原生任务先暂停核对，原生存在的 run 继续查询；实际效果无法确定的项目显示 unknown，由管理员明确结束或重新发起。恢复不会自动把过去的 pending 全部发出。

安装备份恢复与主体逻辑导入是两个公开操作。前者适合恢复同一安装的数据库和运行记录，后者用于跨平台搬运、分支和不同部署形态。二者都重新检查当前凭据与外部连接。

## 限制、遗忘与物理清除

`suppress` 调整普通召回，`retire` 结束当前认识，`policy.update` 调整读取和传播，`data.purge` 物理删除指定范围。用户界面分别解释实际影响。

purge 先在正式 owner 阻止继续读取和传播，确定受影响的原件、派生材料、认识、索引、工作上下文和执行引用；再取消相关未完成工作并调用各存储与原生宿主的公开删除能力。材料、认知与已发生的交往关系按用户授权范围清理，仍需保留的外部引用变成已清除占位信息。

DBOS 工作流以主体及输入来源带有可查询属性，清除时通过公共管理能力停止并删除包含相关敏感内容的工作流及检查点。一般运行工作流只服务一个主体，跨主体管理操作只保存对象引用。原生 transcript、摘要、工具结果文件与 debug 快照分别调用对应删除入口，换 Session 只负责未来执行隔离。

备份中的物理清除通过 restic forget/prune 或存储提供方的相应能力完成。当前安装维护一份紧凑的删除清单并同步到备份控制位置，恢复旧备份先应用最新清单；该清单位于恢复目标之外。暂时离线的备份、外部平台和提供方保留项在操作结果中列出实际状态，恢复访问后继续处理已有操作。

删除工作返回每个存储范围的 blocked、removed 或 pending 原因，页面展示实际进度和用户可执行动作。这个结果属于数据管理操作，不扩展为独立的证明服务。

## 初始产品交付

发行包包含可直接使用的示例世界、空白主体与记忆服务配置模板，提供三平台安装说明。普通安装者能够使用 CLI 或 Web 完成创建、配置、渠道接入、启动、观察、暂停、重启和导出。

主流程在 Windows 与 Ubuntu 实际运行；macOS 的服务、凭据及原生依赖在对应环境执行同一组入口检查。运行检查共用正式示例，不按平台复制一套业务测试。
