# 召回与 NousQL

## 查询入口与结果

`knowledge.query` 接受自然语言、NousQL 或类型化 Query。三种入口进入同一个查询计划，默认返回 12 项。精确读取使用 `knowledge.read`，关联扩展使用 `knowledge.expand`。纯自然语言请求直接工作，显式语法用于精确表达已知条件。

Query 包含 `intent, subjectId, kinds, entities, concepts, tags, time, knowledgeAt, recordedAsOf, refs, sources, preferences, exploration, expand, limit, workContextId?`。身份、用途、听众来自 CallContext。默认 kinds 是当前启用的 Memory、Episode、Journal、Schema、Concept；Self、Social、Motivation 在明确请求或上下文准备中加入。

结果返回 `items, resolvedQuery, nextCursor?, indexState`。每项带 `ref, title, excerpt, formation, stance, confidence?, time, sourceRefs, matchReasons, relatedRefs?`。排序分数仅供技术诊断，用户界面显示具体匹配理由与认识状态。模型阅读格式是“编号、正文、时间、短引用”；使用 `read [3]` 可在当前查询结果中继续读取，服务将编号解析为精确 Ref。

## NousQL 的正式语法

采用 Chevrotain 实现语法与定位错误，Query AST 仍是同一个公共类型。仅在文本以 `FIND` 开始时按 NousQL 解析；其他文本作为自然语言意图。关键字不区分大小写，字符串使用双引号，列表使用方括号。正式语法为：

```text
FIND "自然语言意图"
RETURN [Memory, Episode, Journal, Schema, Concept]
ENTITY ["person:对象ID", "group:对象ID"]
TAG ["考试", "旅行"]
TIME observed IN "world:校园" BETWEEN "2026-10-01T00:00:00Z" AND "2026-10-20T00:00:00Z"
KNOWLEDGE_AT "world:校园" "2026-10-12T08:00:00Z"
RECORDED_AS_OF "2026-10-20T01:00:00Z"
REF ["完整或可读对象引用"]
SOURCE ["来源引用"]
PREFER [recent, independent_sources, diverse]
EXPLORE 2
EXPAND [sources, relations]
LIMIT 12
```

除 FIND 外均可省略，每种指令最多一次。TIME 支持 occurred、observed、formed、valid、recorded；valid 使用区间相交，其余按时间点过滤。多个 ENTITY 默认“与任一个有关”；需要全部匹配时使用 `ENTITY ALL [...]`。TAG 同样支持 ALL。REF 表示限定起点或精确目标，SOURCE 表示来源范围。EXPLORE 的整数为最大关联跳数。LIMIT 为正整数，服务根据当前预算限制上界并在结果中返回实际限制。

正式引用支持 UUID、完整 Ref 字符串与主体内可读别名；别名和会话编号首先通过所属主体的引用服务解析。引用歧义返回候选身份，不猜测目标。解析器只生成 AST，SQL 条件由 Kysely 参数绑定建立。

例如：

```text
FIND "Alice 当时怎样理解那次争论"
RETURN [Memory, Episode]
ENTITY ["person:alice"]
KNOWLEDGE_AT "world:校园" "2026-10-12T08:00:00Z"
EXPAND [sources]
LIMIT 8
```

示例中的 `person:alice` 是当前主体已登记的可读别名。正式接口返回实际 UUID。`query.explain` 公开指称消解、时间解释、通道、截点和排序理由，供用户修正查询。

## 指称消解

优先使用当前 WorkContext、当前会话参与者、显式时间与已知对象，把“我们”“上次”“那家店”补成有来源的候选条件。纯查询无需固定追加一次模型调用：姓名、已返回引用和确定时间先由已有实体与时间解析完成；真正需要语义改写时，使用配置的轻量模型产生候选 Query，保留原问题。

未知日期保持范围或空缺。“上次讨论”先按参与者与话题检索近期经历，再把找到的经历作为第二次精确查询起点。全部步骤共享同一次查询预算。多种解释返回可比较结果；用户明确选择对象时再缩小范围。

## 可访问候选与历史修订

PostgreSQL 保存正式对象、全部修订、时间、来源与权限；LanceDB 保存可重建的文本、向量与筛选字段。当前查询索引使用当前可读修订，历史修订索引按启用的历史保留策略保存。

检索计划先建立主体、用途、听众、能力、时间截点等约束，再调用相应索引。取得候选后批量回读 PostgreSQL，选择在目标知情时刻已经形成的那一修订，检查当前访问限制，丢弃失效候选。分页继续补足被过滤的候选，直到达到数量或预算。

历史结果按 `formed` 与真正来源接触共同解释 knowledgeAt，recordedAsOf 另行约束现实记录截点。历史缺失的索引通过正式修订读取与一次有界重建处理；接口明确给出该范围的索引状态。已撤销访问的对象在回读处立即退出结果。

## 召回与内部重排序

词项和向量使用 LanceDB；词项索引明确配置 **ICU tokenizer**，覆盖连续中文、混合文字与名称。索引构建时将分词器、字段、向量模型和维度写入索引配置。普通安装无需另装中文模型；确有更好的任务效果时再改用现成 jieba 或其他受支持分词器。

一次查询按所需条件组合以下候选：

| 通道 | 实现与职责 |
|---|---|
| 精确引用、人物与时间 | PostgreSQL 索引读取，保留精确对象与修订 |
| 词项 | LanceDB FTS；名称、别名和正文分别设置字段权重 |
| 语义 | LanceDB ANN；文本及可用多模态表征 |
| 概念与关联 | 正式概念成员与有界关系遍历，使用 Graphology 的图操作 |
| 当前工作集 | 本次输入与 WorkContext 中明确保留的来源，直接参与上下文选择 |

默认词项与向量各取 80 项，结构化候选最多 80 项，关联扩展最多 60 个对象、2 跳。合并按对象及所选修订去重。使用 LanceDB 支持的 RRF 融合；跨结构化通道的同一种 RRF 由少量纯函数完成，不另建排序框架。

融合后按任务约束进行内部重排序：精确引用和明确实体优先，来源独立性、适用时间、内容匹配与真实使用反馈作为小幅调整。一个来源的多个摘要合并为同组，保留最有信息量的呈现。相似内容用已计算向量做有界多样性选择，避免整页是同一事实的不同表述。

独立 reranker 只在配置启用时处理候选前 40 项。调用使用正式模型资源和费用控制；模型不可用时保留本地排序结果并标明本次未用该模型。程序内排序始终完整存在。

## 联想、残差与语义吸积

常规联想从高相关候选及其概念出发，沿具有明确含义的关系逐跳展开。每跳按边权衰减，默认系数 0.6；记录路径、原始命中与独立来源组。已在当前结果中覆盖的概念降低继续探索优先级。路径用于解释，不写成新的事实来源。

残差探索是正式可选检索策略。把查询向量与已经返回内容向量进行正交分量分离，使用成熟矩阵库 `ml-matrix` 的 QR/SVD 运算；残差范数过小就结束。非零残差归一化后再次检索，默认最多一次额外轮次。所得候选仍回到原问题重排序，保留“弱线索发现”的理由。

语义吸积持续更新概念成员、相关边与可访问性。重复转述按来源根分组，使用反馈按实际采用和结果计入。概念与来源语义固定，召回策略在 retrieval 内通过同一 Query/Result 契约替换。VCP 的研究方向落实在这些算法位置；默认交付使用独立实现与可直接采用的通用算法库。

## 新内容与索引生命周期

当前输入直接进入上下文，精确读总是读取正式存储。认知修改的工作流在数据库提交后更新便宜的文本索引，再把操作报告为 `completed`；向量计算在后台完成。操作结果分别给出 `textReady` 与 `vectorReady`，需要立即查询的调用者可等待同一操作。

数据库与索引间的继续由原 DBOS 工作流承担。索引落后时，查询返回当前索引进度；单次模型输入需要的新资料继续通过当前工作集提供。这里不建立第二套“增量影子搜索库”。

向量模型更换创建新的 embedding space，分批构建后切换索引引用。查询在切换前继续使用原空间；同一次查询不混用维度或距离语义。旧索引在进行中的读结束后清理。索引重建、压缩与存储管理直接调用 LanceDB 能力。

多主体默认共享一组分区表与索引，通过 subjectId 过滤。达到真实容量瓶颈后按主体拆分索引目录；公开 Query 与身份保持一致。批量读、嵌入批处理、候选上限和缓存由资源设置控制。

## 可调初值与使用场景

候选数、图跳数、衰减、reranker 数量、可访问性半衰期都是配置初值。用户可查看一次查询的候选来源、最终排序因素和耗时，并关闭成本较高的探索。

施工使用一组实际材料覆盖：连续中文长句与专名、同义改写、多个相似来源、周一阅读周三理解的历史截点、明确引用展开、弱线索多跳和无权限材料。语法错误、时间选择与融合去重放在一个参数化规则文件中维护。
