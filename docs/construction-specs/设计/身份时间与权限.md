# 身份、时间与权限

## 主体身份与能力

任何一个产品都可以通过 `subjects.create` 创建 UUIDv7 SubjectId。请求包含显示名称、启用能力、可选种子来源和世界起点；创建返回正式主体引用。显示名称可以改变，身份保持连续。

`subjects.bind` 由管理员或授予绑定权限的服务调用，参数是本地主体、对端 installationId、对端主体身份和授权连接。绑定已有同一身份时返回当前绑定；将另一个已有主体合并进来属于单独的数据操作，本次绑定不执行合并。Hept 创建后首次接入 Nous 时，Nous 以同一 SubjectId 建立认知容器并采用选定种子。

安装支持的能力由实际加载的模块描述；主体供给保存 `enabled`、必要的设置和停用原因。可用状态从模块、设置和依赖读取。Memory-only 主体拥有完整材料、记忆、历史、检索、导出和清除能力。停用 Self 等领域后保留资料，停止该领域新增自动成长，并从普通上下文选择中移出。

恢复保留 SubjectId。分支产生新的 SubjectId，记录 `branchedFrom` 与分支截点，并按导出许可取得可共享历史。数据库中的 subjectId 一直表示资料归属，不作为访问凭证。

## 引用与内容身份

对象以 UUIDv7 定位。来源引用含产品、安装、对象、修订和区域；名称和平台 ID 作为查询线索。明确历史引用读取固定修订，省略 revision 的引用读取当前状态。

模型友好引用使用三组 CVCVC 词序，采用 `deoxxa/proquint` 的 Buffer 编解码，使用 Node crypto 产生 6 字节随机别名；沿用该库的 16 位分组编码。别名表在所属主体内设唯一约束，冲突时重新生成。短词序映射到完整对象身份，UUID 仍是机器定位值。一次查询可以另分配 `1,2,3` 等编号；编号只在返回的 resultSet 内使用。

Blob 的内容摘要用于字节去重和存储定位。访问检查落在 Material、Message、Artifact 等有归属的对象上。客户端提交摘要不会获得另一主体的内容。

## 五种时间

所有业务时间包含 `clockId`。内置真实时钟，世界可创建有明确映射的时钟。ISO 时间用于表达一个时间域中的坐标；时区用于解释日历和显示。PostgreSQL 使用 timestamptz 与 clockId 保存，TypeScript 使用 Temporal；Node 24 中使用 `@js-temporal/polyfill`。

| 时间 | 保存位置与意义 |
|---|---|
| occurred | 来源事件实际发生的时间或范围，如昨晚的平台消息 |
| observed | 某消费者实际取得该资料的时间，如主体今天阅读 |
| formed | 该认知修订在主体的认知中形成并采用的时间 |
| valid | 该认识描述的内容适用的时间范围 |
| recorded | 软件将该事实写入正式数据库的真实时间 |

工作流超时、提供方计费、磁盘保留期限和网络重试使用真实时间。主体睡眠、课程、生活兴趣与经历使用对应世界时间。未建立映射的两个时间域分别显示，查询要求调用方明确比较依据。

世界时钟保存真实锚点、世界锚点、速率、暂停状态及生效区间。变更速率时结束原映射区间并建立新锚点；已实现生活仍使用其原时钟关系。虚拟世界提前发生、后来才细化的事情，可以有早于 recorded 的 occurred；主体实际认识它的时间由 observed 和 formed 决定。

## 两种历史视图

`knowledgeAt` 读取主体在目标时刻已经形成的认识。候选修订的 formed 必须不晚于截点，所用外来材料必须在相应接触时刻已可供该消费者使用；再按 valid 判断对目标问题的适用性。初始设定按正式采用时间进入可知状态。

`recordedAsOf` 读取数据库在真实时间截点已经保存的版本。它可以与 knowledgeAt 同时使用，返回系统当时保存的、主体在另一时刻持有的认识。

周一读到材料，周三才理解：周二的知识视图可返回“曾读过该资料”和当时已有的认识；周三形成的结论从周三进入知识视图。后来纠正过去内容时，新修订可以说明其适用期从过去开始，formed 仍保留本次纠正的时间。

实现查询时先按 subject、权限和时间选定每个对象在截点对应的修订，再做全文、向量或结构召回。当前版本的索引不能替代历史修订选择；历史全文/向量行使用同样的 revisionId 和时间字段。

## 权限的三项职责

软件管理员管理安装、认证、密钥、能力和数据。主体行为管理员可以指示交往和生活策略。普通交往者通过会话与主体互动。维护助手在独立授权的管理会话中使用管理工具；主体交谈所使用的模型没有安装管理权限。

认证采用 Better Auth 的会话、API key 和管理能力。模块内的权限判断围绕产品实际操作：某主体的读取、写入、行为指示、外部发送、世界管理、导出、清除与安装管理。关系亲密、群管理员身份和模型自述不会改变软件授权。

服务委派包含 subjectId、purpose、允许操作、资料范围、截止时间以及外部目标范围。worker 和 world-author 使用独立身份。消费者身份由宿主绑定，MCP 参数和模型工具输入只传业务内容。 服务委派的 Actor.consumer 固定消费者种类、宿主与身份；HTTP 从凭据 metadata 构造调用上下文，不从模型参数取得执行身份。

## 来源、用途与受众

每份材料及认知保存可读范围、允许用途与可传播范围。私聊来源默认用于该主体理解及对应私聊；群聊、公开资料和管理员发布内容有各自的传播范围。管理员可以明确发布经过整理的内容，记录实际变更。

派生材料和认知引用其依赖来源。默认有效限制取依赖来源的共同允许范围，读取时计算当前策略。限制收紧后更新派生索引标记，并在权威读取和模型上下文中立即检查。概念扩展、排序解释、来源数量和短引用也经过相同可见性过滤。

主体内部审议可使用其获准读取的私密认识。renderer 只接收当前听众可披露的 `ExpressionIntent`、选定公开来源及语言习惯。Decision 的内部理由保存在私密操作结果中。ExpressionIntent 用明确的发言行为、主题、可引用内容、语气和已经采用的承诺组成；自由叙述部分同样属于对外内容，生成它时只使用本次可披露的信息。

读取角色素材时将安全管理与人物设定分开。种子中的“永远允许访问全部文件”等文本保留为创作原文，其权限效果由软件设置决定。

## 权限变化与正在执行的工作

每次新模型调用和实际外部发送前读取当前权限。已经准备但尚未发送的上下文，在来源被撤销时重新准备。正在使用敏感来源的长任务收到撤销通知后停止继续读取与发送，保留当前操作的实际状态。原生 Session 按隐私操作关闭或清除，后续任务在新范围中启动。

隐私修改的正常操作为 `policy.update`，清除为 `data.purge`。这些操作负责触发相应上下文、原生历史和索引处理，细节见[部署更新导出与清除](部署更新导出与清除.md)。

## 本地与远端部署

默认 HTTP 只监听回环地址，初始管理员通过本机 CLI 创建。开启远程访问时配置 TLS 反向代理、正式登录和服务凭据。CLI 使用系统凭据存储保存登录引用。导出的主体包携带资料权限与来源，不携带安装级密钥。

真实计算环境获得明确的工作目录、可访问域名、凭据和网络范围。OpenClaw 的 sandbox、浏览器 profile 和工具授权承担底层隔离。world-author 读取世界私有资料的权限，与主体在世界中的感知范围分别配置。
