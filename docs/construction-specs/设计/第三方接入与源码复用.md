# 第三方接入与源码复用

## 采用方式

通用能力优先直接依赖完整项目或库。需要少量语义扩展时，在其真正负责的位置改编源码并构建依赖；独立的工具函数或提示材料可以复制到所属集成中，保留来源与必要声明。项目自己的代码集中在认知、生活、行为及这些能力之间的语义交接。

第三方源码可以下载到开发机器的 reference-worktrees，供搜索、运行示例和直接改编。它们不进入产品自己的通用框架，也不计作我们重写的领域实现。被采用的改编只保留实际需要的差异，普通版本更新用包管理器和依赖锁完成。

Client 生成使用 [OpenAPI Generator typescript-fetch](https://openapi-generator.tech/docs/generators/typescript-fetch/) 7.26.0 的官方容器，输出普通 Fetch/TypeScript。生成器不依赖旧 TypeScript 编译器 API；仓库只保留 TypeScript 7 正式编译入口。

采用稳定版本并提交 lockfile。TS 后端普通 ESM 编译，DBOS 注册的工作流不经过通用打包器重写；Vite 只构建前端。TypeScript 7 的工具 API 变化通过选择兼容工具解决，仓库保留一套正式编译入口。格式与静态检查使用 Biome，规则保持简洁。

## AstrBot 渠道宿主

默认通信宿主采用 AstrBot，QQ 使用其 OneBot 适配器及 NapCat。AstrBot 负责平台连接、事件转换、媒体、账号及插件生命周期。`integrations/astrbot` 是一个独立插件，只将指定主体管理的渠道接入 Hept。

插件收到事件后先识别管理范围，再停止该范围的默认聊天处理；从 `message_obj` 与原始事件构建包含全部分段的 Message，使用正式 Hept Client/API 接收。收到临时文件时，在事件结束清理前完成流式保全。规则外的其他 AstrBot 使用可以继续独立运行，配置明确列出各个账号/会话的负责方。

入站接收完成只表示 Hept 已保存消息。主体是否察觉、阅读和回复由 Hept 决定。AstrBot 的人格、长期记忆和默认模型循环在该范围关闭。

出站通过已存在的客户端和转换逻辑发送。QQ群/私聊调用 `CQHttp.send_group_msg`、`send_private_msg`，转发调用现成 `call_action`。目前 AstrBot 发送封装丢弃部分结果，本次直接改编该发送 owner，使每次物理调用返回结果列表。公开接口为插件的 `sendExpression`，包含 part 与平台回执对应关系。消息转换与特殊媒体处理优先取自上游对应实现，不另写协议客户端。

插件使用现成 aiohttp 提供仅监听本地或受认证网络的控制端点，生命周期由 AstrBot 管理；Hept 对该端点发送授权的出站请求、账号查询和能力查询。请求体使用生成的 OpenAPI 类型或 Pydantic 模型，原始平台细节留在插件内。它不增加数据库、任务队列或后台重发系统。

Hept 服务先于指定渠道启用。Hept 暂停主体时继续收件；整个 Hept 停止时，插件暂停该范围，恢复后使用平台公开历史能力补读并显示缺失范围。数据库与 DBOS 保存已接收工作的继续。

## OpenClaw 专业执行与认知插件

OpenClaw v2026.10.5 作为默认原生基线。Hept 插件提交任务、取消与获取结果，Nous 插件实现逐调用认知。浏览器、计算机、沙箱、子代理、工具、原生历史与压缩全部使用原生实现。

逐调用合同及源码修改位置以[上下文、模型与原生执行](上下文模型与原生执行.md#openclaw-的执行边界)为准。新增扩展点是本次需要完成的上游适配工作，调用顺序与数据内容已经确定。OpenClaw 的事实来源包括插件类型、真实派发入口、原生保存路径和 transcript cursor；不得把诊断回调当作已提供的事务钩子。

改编代码放在受版本控制的 upstream source 分支或可构建源码依赖中，构建出的包作为正常依赖。上游提交保留这项通用能力；项目集成包只负责把公共合同接到 Nous。发布包包含构建结果与必要声明，开发与安装均不运行搜改 node_modules 的脚本。

选型与接线需要运行的有限场景为：有工具的普通任务、一次子代理、模型切换、上下文压缩、准备失败、结果已保存而接受中断。它们共用同一个真实任务，无需为每个内部钩子建立独立资格体系。

## MaiBot 的自然交往复用

MaiBot 的价值集中在自然语言、群聊参与、语言惯例与交往策略。当前完整运行时按会话组织自己的心流与人格状态，项目选择复用可独立的提示材料、消息整理和表达方法。

优先来源包括 `src/maisaka/attention_drift.py` 中的表达联想、回钩与短反应提示组织，以及回复与语言惯例相关的独立逻辑。将所选片段直接改编到表达职责中，参数映射到主体与关系配置，删除依赖另一套会话管理的部分。实际语义仍由统一 Situation、Self、Social 与 ExpressionIntent 提供。

源代码名称相同的“注意力”或“记忆”需要按实际行为接入。表达联想参数只影响措辞，生活注意选择由 Hept 的活动、责任和机会共同决定。

## 普通资源与可选系统

文档库、网站、搜索和数据库优先通过成熟 MCP server 或资源 SDK 接入。Nous 统一保存 ResourceRef、内容版本、选择区域和权限，现成连接器负责分页、协议和格式。

Docling 用于需要版面识别的复杂文件，作为可选资源处理服务启用。RAGFlow 可作为已有知识系统的外部资源，普通 Nous 安装不部署它。S3 及兼容对象存储由官方 SDK 接入，默认本地文件。桌面壳需要时使用 Tauri，当前 Web Console 与 CLI 完整工作。

VCP 的联想与残差思想保留在检索策略设计中；默认产品不纳入尚未解决使用范围的 VCP 源码依赖。选择成熟矩阵、图与搜索库完成相同研究目标。

## 源码采用的日常做法

需要复制或改编时，记录上游仓库、对应文件及所用版本，保留原有许可证和声明，修改后的文件归入实际责任模块。一般包依赖由 lockfile 与许可证工具汇总，少量源代码改编在该目录 README 中说明用途。

整个项目仅两个产品仓库。第三方镜像、包缓存与开发用源码工作树属于构建材料；它们不变成第三个业务核心，也不要求自建许可证审批、依赖评分或资格登记服务。

## 接入完成时的形态

产品内部只有一套 Message、ContextView、Decision、TaskRequest 与正式认知对象。外部协议在对应集成入口转换一次。改变平台、模型或执行器时，替换的是该边界及其真实消费者。第三方已经承担的重连、队列、查询执行、原生工具循环和备份机械随采用一起从自有代码中退出。
