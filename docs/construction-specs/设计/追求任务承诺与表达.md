# 追求、任务、承诺与表达

## 行为组织

Pursuit 表示主体决定持续投入的目标，保存目标描述、关联愿望、当前方案、资源范围、进展、复查时刻及 active/paused/completed/abandoned 状态。Activity 表示实际占用生活时间的活动，Task 表示委派给执行者的工作，Commitment 表示已经向特定听众承担的责任。

它们通过引用协作。一项追求可以包含多个活动和任务；完成一个任务可以推进追求；对他人的承诺可以由这些活动履行。每类状态由自己的业务操作改变，共同决定在 agency 的采用事务中组合。

## 专业任务与工作空间

`tasks.start` 接受 `goal, requester, subjectId, pursuitRef?, activityRef?, workContextId, inputRefs, allowedTools, workspaceRef, budget, returnTarget`。returnTarget 保存原请求会话、消息、相关活动和期望成果，后续对话切换不会改变它。

OpenClaw 是默认执行者。Task 保存原生 run/session 引用、工作范围、结果资料和当前业务状态；执行步骤与工具历史由原生系统保存。创建任务和启动原生 run 通过 DBOS 工作流串联，重复启动以 TaskId 为请求身份。启动结果未知时查询原生 run 或请求确认，已有 run 不重新创建。

工作空间由原生沙箱提供。每个主体或任务按授权选择目录、网络、工具、凭据和计算配额。浏览器会话、桌面、文件浏览和接管能力复用 OpenClaw 及现成容器/远程桌面工具。操作者通过 Hept 界面取得授权入口，真实机器路径不暴露给人格模型。

文件修改、发布与真实外部动作调用原生工具，但其允许范围由正式委派提供。重要发布、运行命令或访问私人目录可以要求管理员确认；普通已授权的任务读取直接执行。维护助手使用独立账号与工作空间。

## 进度、暂停和结果

任务状态为 queued、running、waiting、result_ready、completed、failed、cancelled。waiting 带明确原因，如需要凭据、需要选择或原生执行暂时不可用。result_ready 表示成果已生成，主体尚可选择何时查看；完成状态保留实际交付记录。

`tasks.inspect` 取得原生进度并结合当前成果返回，不复制完整运行状态机。暂停、继续和取消使用原生公开接口；原生只支持取消时，保存已获得的成果和 WorkContext，继续作为明确的新任务从保存位置开始。

任务交付物包含自然语言结论、具体成果引用、来源、实际尝试结果、未解决事项和建议阅读入口。原生执行日志保留在后台，用户可展开。整理工作优先使用 worker 的正常最终结果；只有成果格式确实缺失时再补一次有界整理。

成果就绪生成注意机会。主体查看选定结论或文件后产生实际接触，之后决定采用、继续、分享或结束。专业能力通过被理解的成果进入主体生活，学习过程在 Nous 中逐步形成。

## 承诺的完整状态

Commitment 保存 `audience, terms, dueRange?, linkedPursuit?, linkedActivities, linkedTasks, communicatedParts, fulfillmentBasis, status, changes`。terms 包含答应的内容、数量或范围、时间、条件和可评价结果。

采用决定先建立承诺意向 `prepared`，与允许表达的具体 terms 相连。相关发送部分被平台接受后转为 `active`。发送明确失败保留未传达意向；结果未知保留 `communication_unknown`，等待真实回执或操作者处理。

未结束承诺进入 Situation 与注意。实际成果或行为满足 terms 后，通过 `commitments.evaluate` 写入 `fulfilled` 及依据；明确未在时限内满足且观察充分时写入 `breached`。观察不足保持待确认并显示缺口。对方撤销要求或双方协商结束可变为 `released`。

改约创建 proposedChange，明确旧条款、新条款与需要听众接受的条件。新的对外表达及必要同意成立后，采用新修订，保留旧承诺、原话和修改依据。主体自己改变计划只改变 Activity/Pursuit，原对外责任仍进入其情境。

## 表达意图与自然语言

ExpressionIntent 保存听众、交流目的、当前姿态、可披露认知引用、允许表达的事实与范围、具体承诺条款及可选语言惯例。内部 Decision.internalReason 保留在主观资料中。表达模型取得对外意图、听众范围的认知和必要对话，生成自然正文及媒体选择。

输出包含 `parts` 和可选 `semanticChanges`。parts 是将要发送的完整内容块；semanticChanges 只用于本次确需新增的重要生活细节或承诺，指向具体 part。普通问候、解释、玩笑、疑惑和拒绝返回自然 parts 即可。

角色风格由 Self、Social、当前情境与所选表达模型共同决定。可引用 MaiBot 的局部提示材料与语言惯例组织方法；不要在界面或回复中解释“采用了真实样式”“自然化处理”等内部工作。表达默认不运行工具循环；确需取材料时由主体读操作补足后再生成。

## 普通表达与重要语义的分流

普通表达直接使用已经采用的意图生成并发送。重要语义在发送前按具体对象处理：世界细节调用 `world.realize` 或 `world.adoptDetail`，承诺调用 `commitments.prepare`，涉及旧说法的更正关联原表达。

已给定条款的承诺无需再做一次全量模型 review。输出改变时间、范围或责任时，返回受影响的具体差异，重新生成该部分或重新由主体决定。重要世界细节检查现有时间线、地点、参与者和已发生事件；无冲突的补充一次采用。

语义与叙事核对只在新增重要内容或实际冲突出现时调用。所有普通发言保存完整原文及关系，不逐句抽取 Claim。长期陈述、反复出现的矛盾和实际查询需要，可以由既有成长工作按需整理。

## 真实生活、认识与对外说法

Statement 保存重要表达的正文引用、听众、涉及时段、实际发送结果及后续解释关系。世界事实、Nous 中的主体认识和 Statement 分别保有身份，通过 refs 相连。

主体可以记错、误解、回避或有意隐瞒。Decision 允许明确的对外姿态与可披露范围；刻意隐瞒不改变真实生活，也不将该说法写成事实性 Memory。世界实现只采用正式世界细节，成长保存“对某人说过某句话”这一交往事实。

后来澄清通过新表达建立 corrects 或 explains 关系。编辑或撤回平台消息只改变交往记录的相应版本和平台状态。已经发生的真实动作继续保留。

## 物理发送与回执

`messages.sendExpression` 接受 ExpressionId、目标及已经通过必要采用的 parts。渠道 owner 使用宿主的现成消息转换、媒体处理与发送客户端。每个实际平台调用产生 DeliveryPart：`partId, expressionPartRefs, platformMessageId?, attemptedAt, status, error?, nativeReceiptRef?`。

默认 QQ 使用 AstrBot 的 OneBot 客户端。上游 `send` 方法目前丢弃部分返回值，因此本次在其实际 `_dispatch_send`、文件与转发发送处保留每次调用结果，并把结果聚合返回。可直接改编该独立发送实现，复用现成 CQHttp 客户端和消息转换，不重写 OneBot 通信栈。

若一部分媒体失败而另一部分文本成功，按各部分显示 accepted 和 not_sent；平台调用超时且结果未知时只标记该部分 unknown。已经 accepted 的部分不会被内部异常重新发送。再次发送失败部分是明确操作，保留与原表达的关系。

本地 Web 会话由 Hept 自己保存消息并返回消息身份。其他平台采用其成熟宿主的实际反馈能力；完整回执不足时返回真实粒度和 unknown 部分，运行能力说明注明该平台的反馈范围。

## 发送后的反馈

发送结果立即更新交往历史、相关承诺和待完成操作，再向主体提供可感知的结果。后续平台送达、已读、表情回应、回复和撤回各自追加事件。平台“接受”与他人实际阅读分开显示。

消息内容本身按已完成表达进入主体经历；发送失败、对方纠正和后续回应也可以进入经历。长期认知形成沿共享成长路径进行。普通发送成功不额外调用一个解释模型。

## 流式体验与顺序

Web UI 可以展示模型草稿，发送到外部平台的内容按完整表达部分组织。需要自然连续短句时，表达者给出有意义的多个部分，渠道在平台允许的速率下依次发送。预算和权限在开始发送前检查，重要条款的语义采用先于对应部分。

一项表达的顺序由它的发送工作流保存，主体前台在提交发送后可以继续生活。撤销只停止尚未发送部分。恢复旧备份后出现的待发送工作先暂停核对，正常进程重启继续同一 DBOS/原生操作。

## 用户可见操作

用户能查看一项追求的活动、任务、成果和承诺，暂停或结束投入，查看原生工作空间，接管浏览器，取消待发送部分，处理未知效果，以及阅读某句话的原文、听众和后来更正。

这些入口共享同一正式操作。原生执行细节由所属宿主显示，业务页面按主体实际目标连接资料和结果。
