# 上下文、模型与原生执行

## 一次实际调用的共同操作

`contexts.prepare` 接受受信消费者身份、主体、角色、工作上下文、当前情境、最新材料、听众、实际模型与输入预算，返回 `ContextView`。ContextView 包含自然语言区块、来源与选中修订引用、实际裁剪范围、有效权限与配置修订、预算使用量。完整机器字段留在宿主，模型只读所需正文与短引用。

消费者类型为 `subject / worker / author / maintenance`。主体审议和主体表达使用 subject，专业执行使用 worker，世界规划使用 author，维护助手使用 maintenance。身份由运行宿主注册并授权。人格与知识供给按能力组合选择，角色只获得本次需要的部分。

共同顺序是：当前输入与工具结果就绪，确定实际模型和工具表面，准备认知，完成最终预算，执行模型，保存成功输出，再接受本次实际接触。下一模型调用重新走准备操作。失败的准备留在工作状态；模型尚未执行的材料没有接触记录。

## WorkContext 与短期工作集

WorkContext 保存 `goal, openQuestions, progress, currentRefs, temporaryNotes, resumeCue, participantRefs, lifecycle`，可关联任务、追求、会话和多个执行者。它的修改通过 `contexts.updateWork` 完成，暂停与继续保留同一身份。当前聊天与长期研究可以各有一个上下文。

最新消息、正在看的网页片段和临时想法直接进入当前工作集。按来源保留版本与区域，按用途设置保留期限。默认普通临时材料在 24 个主体小时后退出活跃集合，仍被任务引用的材料随任务保留。明确的“想记住”作为主体的记忆意向进入成长；正式删除与访问变更通过管理操作完成。

上下文压缩使用原生执行器或 AI SDK 可用的现成消息裁剪能力。目标、未决问题、关键引用和恢复线索通过 WorkContext 独立保存。摘要保持来源关系，工具调用及结果 ID 保持匹配；隐藏或截短区域在宿主记录中可查。

## 内容组织与预算

准备过程依次取得：固定角色任务、当前主体身份及知识立场、当前事件与最近必要对话、相关 Self/Social/Motivation、检索结果、正在继续的任务资料。作者私密安排只进入 author，听众资料只按用途提供。

预算先扣除模型输出预留、工具 schema、调用方必须输入和图片音视频估计，再在剩余范围选择认知。初始分配为身份与行为立场 15%、当前情境及工作进展 35%、相关认知 35%、可继续读取的来源 15%；某类不足时释放给其他类。硬性必须内容超限时返回明确超限项，调用者缩短本次任务或选择合适模型。

相同来源的重复摘要合并，完整工具结果保存在材料或执行器，模型取得所选片段与读取入口。候选选择先按相关性和权限，再按信息密度裁剪。原件、区域、截短情况与短引用保持关联。

`contexts.prepare` 每次调用均执行轻量有效性检查；未变的内容和检索结果可按主体修订、查询、用途、听众及预算缓存。权限、模型、关键情境或相关认知变化会重新选择内容。旧身份、已限制的资料从新视图退出。

## AI SDK 与 DBOS 接线

Hept 主观模型、自然表达模型及 Nous 成长模型使用 AI SDK 7。`prepareStep` 调用持久的 `contexts.prepare` 步骤；实际模型使用官方 `@dbos-inc/vercel-ai` 的 `durableCalls`。只读工具用 `durableTools`，MCP 用 `durableMCPTools`。语义写入在完整结果之后调用相应业务事务。

在官方持久模型外设置一个薄的结果处理层：得到本次成功模型结果后，以固定 `invocationId + stepNumber` 调用 `encounters.accept` 和费用结算。该处理在工具继续及下一模型步骤前完成；恢复时重用官方已保存的模型结果，重复接受返回原记录。异步日志回调不承担这项提交。

每个模型步骤保存 ModelInvocation 的必要元信息：主体、角色、实际提供方与模型、开始时间、完成情况、用量、费用、提供方请求标识、输入引用和 DBOS 工作流引用。完整响应由 DBOS 检查点保存，重要成果再进入正式材料。

官方持久层默认可重试模型请求，本产品按错误阶段设置策略：连接建立前失败及明确拒绝的可重试请求有限重试；已发出而结果丢失的请求保留 unknown。内部 provider middleware 在首次派发前写入稳定调用身份，恢复遇到尚无结果的同一身份时查询提供方原请求；没有查询能力时停止该调用，向操作页提供“继续查询”或“重新调用”的明确动作。此元信息同时服务费用管理，执行步骤与响应检查点继续由 DBOS 管理。

模型接线的组合顺序为：外层结果接受、官方 durableCalls、内层提供方调用元信息、实际 provider。稳定调用身份由 workflowId 与逻辑模型步骤序号产生，重试次数不进入身份。内层元信息使用所属模块的短 Kysely 事务，不在 DBOS 模型 step 内嵌套另一套持久步骤。完成响应已在官方检查点时，恢复直接返回响应，再完成尚未提交的接触与费用。

主观审议、成长和带工具的内部角色默认使用 `generateText`；外层 middleware 等待官方 durableCalls 返回完整结果，再执行接触接受，最后把结果交回 SDK 继续工具循环。`onStepEnd` 等通知回调只用于观测，业务错误在正式等待的调用中传播。

自然表达默认没有工具。普通纯文本使用 `streamText`，结束后形成一个 text part；需要媒体选择、多个自然内容块或 semanticChanges 时，在同一次调用使用 AI SDK 的 `Output.object` 与 ExpressionDraft schema。UI 通过 SDK 的文本或 partialOutputStream 展示草稿，不自行解析残缺 JSON。工作流消费到完整结束，取得已保存并校验的最终结果后执行接触接受和表达采用；已完成内容使用官方持久流读取。需要工具的角色通过步骤进度显示工作状态，最终自然表达独立流式呈现。这两条明确路径免去自写流式模型检查点。

一个工作流的模型及工具步骤保持确定顺序，并行工作使用子工作流。模型输出失败保留已有输出与费用，结构修正只重做必要的小结果段。

## 主体接触与其他消费者

`encounters.accept` 参数为受信消费者、实际步骤身份、实际用过的 ContextView 引用、成功输出引用、发生与接触时间、输入区域。它一次完成接触保存、使用反馈和适用的经历流追加。

subject 的实际阅读、思考与表达形成主体经历；worker 和 author 的读取保存在各自工作范围。worker 成果成为待查看材料，主体真正查看后才进入其经历与成长。种子采用使用 initial_setting 来源。模型调用前的材料保全和候选准备没有成长副作用。

多步执行在第三步失败时，前两步已经接受的接触保留。第三步只有已确认实际完成的模型结果或原生被接受步骤才能产生接触。提供方计费但无法确认内容时，费用保留未知或已计费用，认知状态维持未确认。

## OpenClaw 的执行边界

OpenClaw 负责专业任务的工具循环、浏览器、隔离执行环境、子代理、原生历史、会话压缩与执行继续。Hept 只提交 TaskRequest，保存原生 run 引用，取得进度、结果和取消能力。Nous 为原生执行提供同一套上下文与接触操作。

本次选定 OpenClaw v2026.10.5 为接入基线。源码中现有循环准备依赖 `ownsCompaction`，部分调用复用旧视图，组装失败会继续原输入；循环路径还未应用新返回的 systemPromptAddition。现有接口需要在其责任位置直接补齐。

**本次施工新增一个原生逐调用扩展合同**。以下名称是本项目要求实现的目标接口：

| 目标扩展点 | 输入与结果 |
|---|---|
| `modelContext.prepare` | 宿主确定的 callId、runId、角色、实际模型、当前原生消息、工具、预算与信任范围；返回补充区块、来源视图及实际裁剪信息 |
| `modelContext.dispatch` | 宿主先保存 callId、已准备视图与原生恢复信息，再等待费用 owner 的派发登记；随后立即调用实际 provider |
| `modelContext.accept` | 同一 callId、实际使用的视图、已保存的成功输出及用量；等待 Nous 接受后继续当前循环 |

准备点位于原生历史读取与压缩之后、实际 provider 派发之前。它每次重新取得当前消息和模型，作用于第一轮、工具后续、模型切换、子代理及压缩后的调用。原生消息保有其所有权，认知以本次有效区块加入；同一 slot 的旧认知区块被替换。prepare 返回的系统区块与消息区块都由宿主实际应用。注册为必需的准备失败时，停止本次调用并保留原任务。

原生 prepare 结果持久保存后才调用 dispatch；崩溃恢复依据同一 callId 核实已保存响应或未知派发。联合运行的 OpenClaw worker 由 Hept 结算，Nous 认知 binding 使用 external billing；独立 Nous 使用自己的费用 owner。同一调用只由一边结算。

接受点位于成功响应已进入原生保存路径之后、进入下一模型调用之前。宿主以 callId 保留待完成的接受动作，恢复只补交接。失败步骤中的已完成调用也逐个交接。通知型 `llm_output` 与 `model_call_ended` 继续用于观测，不承担必须提交的接触。

修改集中在 OpenClaw 的插件合同、模型调用边界和对应宿主接线。现有定位入口包括 `src/plugins/hook-types.ts`、`src/plugins/hooks.ts`、`src/agents/embedded-agent-runner/run/attempt-setup.ts`、`attempt.model-diagnostic-lifecycle.ts` 及 `tool-result-context-guard.ts`。开发时沿实际调用派发点接入，删除原有重复的认知重写路径。修改以独立源码提交构建为产品依赖，并向上游提交；安装过程不修改 node_modules。

原生压缩继续使用内置算法和公开委派能力。Nous 无需承担压缩调度或私有 transcript 布局。插件默认不保存原生完整对话副本；来源读取使用公开 transcript delta 游标及已接受步骤提供的片段。

## 支持的原生执行形态

默认深度执行使用已完成上述接线的 embedded harness 及其子代理，所有实际模型调用经过同一合同。外部执行器若自行持有不可观察的模型循环，作为普通任务工具返回成果，能力清单注明其认知接入范围。需要将其升级为深度执行时，在该执行器的真实模型边界实现同一合同，避免在 Hept 侧猜测内部步骤。

Nous 的独立 OpenClaw 插件与 Hept 使用相同 ContextView、Encounter 和 WorkContext API。安装插件可为其他 Agent 直接提供身份、记忆及逐调用准备；Hept 并非此插件的必需依赖。

## 角色提示与模型分工

提示由角色静态说明、受信任务、动态情境、认知视图和输出合同组成；各部分只有一个生成者。模型名称与采样参数由资源配置决定。世界作者看规划与历史约束；审议者看局部生活、真实知识立场与关系；worker 看任务和授权资料；表达者看对外意图与听众可披露认知；成长者看有来源的实际经历；维护助手看运维权限范围。

普通对话可以在同一次审议中决定直接答复，由表达模型形成一次自然回复。无需工具和新重要事实时不追加语义审查模型。重要新世界细节、对外承诺或历史冲突进入相应采用操作。表达风格来自主体、关系、当前心境与上下文，提示不向用户讲述内部工作过程。

接线时使用一个连续任务覆盖首轮、读取工具、切换模型、子代理和压缩，再让一次准备失败发生在中途。观察实际调用输入、接触记录和已付费结果的继续即可；这些接线场景与日常功能示例共用。

角色任务的起始文本与字段组合见[角色任务示例](../示例/角色任务.md)。静态职责、动态情境、认知和输出合同分别组装，避免在多个模板中复制同一人格或行为规则。
