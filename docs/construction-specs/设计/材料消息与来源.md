# 材料、消息与来源

## 三项独立事实

材料表示已经取得的内容。Encounter 表示某个消费者在一次实际活动中接触了哪些内容。Knowledge 表示主体后来形成的认识。下载、解释、检索和认知形成分别使用自己的正式操作。

当前请求携带的材料可以立刻参与模型输入和搜索线索。只有实际发生的读取步骤产生接触；稳定认识由明确记忆意向或成长操作形成。

## 材料结构

| 对象 | 必要字段 |
|---|---|
| Material | `id, ownerSubjectId?, kind, mediaType, title?, bodyRef, source, occurred?, policy, createdAt` |
| MaterialVersion | `materialId, version, bodyRef, originVersion?, recordedAt`；原件改变产生新版本 |
| Blob | `id, digest, bytes, mediaType, storageRef`；内部保存实际路径 |
| Selector | 文本范围、页、图像区域、音视频时间范围、消息部分或嵌套转发节点 |
| Derivation | `id, inputs[{ref,selector}], method, parameters, modelResource?, outputRefs, status, recordedAt` |
| Encounter | `id, subjectId, consumer, activityRef?, contextRef?, invocationRef, observed, portions[], resultRef?, purpose` |
| SourceLink | 起点、终点、关系、区域与来源根；关系包含 extracted、summarized、observed、supports、contradicts、corrects |

原始文本用 UTF-8 保存；文本区域按 Unicode code point 的半开范围解释。图像区域采用左上原点的归一化坐标；视频和音频使用毫秒区间。区域可以组合，例如文档第 3 页中的图像。所有读操作返回实际取得的区域及缺失原因。

材料的 `source.inputs` 保存直接依赖的固定版本与区域；`source.roots` 保存最初来源。认知、接触与派生材料的读取即时解析依赖策略，限制收紧不等待索引刷新。Blob 通过正式材料持有者授权读取。

来源根表示最初的事件或资料。同一文章的截图、转写、摘要和多次模型解释共享来源根。认识形成时同时保存“引用了哪些表示”与“它们来自哪些根”。不同来源是否独立是明确关系，可由资料元信息和后续修订补充。

## 完整消息

Hept 的 `Message` 保存 `id, channelAccount, conversationRef, platformMessageId, direction, authorRef, sentAt, receivedAt, revision, parts, rawRef, policy`。平台消息 ID 在账号与会话范围内定位，API 使用产品 ObjectId。

`parts` 是有序的标记联合：text、mention、reply、image、sticker、audio、video、file、link、card、forward 和 unsupported。每部分有稳定 partId；媒体部分引用原件与派生表示。Forward 保存节点顺序、每个节点的作者和时间、原始节点引用以及嵌套 parts。Reply 保存引用身份和取得情况，原作者不会被当前转发者覆盖。

平台修改与撤回形成消息新修订和对应交往事件。此前接触固定引用此前实际看到的版本。卡片或未知协议片段保留 rawRef 和可读描述，后续解析器可以补充表示。平台只提供部分历史时返回覆盖范围和缺失段。

批量消息只在阅读视图中组织，源消息保持各自身份。去重依据来源 ID 与修订，不按正文相同去重。账号昵称、头像、群名片等资料由 communication.directory 保存带来源和有效时间的版本，社会理解在 Nous 中形成。

## 收件和易过期内容

AstrBot 插件在受管会话的消息处理入口读取完整 `message_obj` 和 `raw_message`，停止宿主默认聊天传播，提交 `messages.receive`。插件不把内容先合成模型 prompt。Hept 接收后持久保存原始 envelope、规范消息和接收时间，随后产生感知候选。

平台临时文件在插件处理结束前传到 Hept 的材料上传入口；短期 URL 由紧急媒体保全作业取得字节。接收默认保全易过期图片、音频、视频和文件，受最大单件、单日流量和磁盘预算约束。长期稳定网页可以保存 URL 与版本线索，按阅读需求抓取。保全失败、超限和已过期在相应 part 上明确显示。

收到媒体时保存原件，视觉理解、转写和文档抽取按需要启动。原件存在本身不触发主体成长。主体暂停、睡眠和不参与群聊时，产品接收和保全继续运行。

服务启动先准备 Hept 接收入口，再启动受管渠道。Hept 停机时暂停相应受管渠道；恢复时使用平台已有历史接口补取已知会话的遗漏范围。平台无法提供的范围作为缺口显示。正常收件不引入第二个自建离线队列。

## 媒体解释与复用

原件版本、选择区域、处理方法、模型/算法版本和有效参数共同决定一次派生请求。已经存在的相同成果直接读取。普通失败保留原件及已完成的派生部分；再次处理只执行尚缺的工作。

| 内容 | 采用实现 | 项目保留的语义 |
|---|---|---|
| 网页 | Mozilla Readability、Cheerio、现成 HTTP client | 原 URL、时间、页面版本与引用区域 |
| PDF | unpdf；扫描页按需交视觉/OCR provider | 页码、文本/图像区域与原件对应 |
| Office 文档 | officeparser 等成熟解析库 | 段落、表格、幻灯片、原件定位 |
| 图像与动图 | sharp、FFmpeg | 帧/区域选择、原顺序和时间 |
| 音频 | 配置的 ASR provider 与 FFmpeg | 原音频、转写区间、说话者和不确定片段 |
| 视频 | FFmpeg 取片段与关键帧，已有视觉模型 | 时间区间、画面和音轨关系 |
| 大型复杂文档 | 按需启用 Docling 服务 | 把成熟服务结果转成统一区域与来源 |

解析器输出首先是材料表示。信息损失通过 `coverage` 描述具体页面、时间段或内容部分；模型可以继续读取原始区域。调试信息记录处理器选择与费用，不保存另一份独立“最终标准文本”。

## 实际接触

`encounters.accept` 接收一个可信宿主已经执行完成的步骤：消费者身份、实际使用的来源区域、观察时间、输出引用和用途。唯一键为 host、invocation、step；同一资料在另一时刻再次看到会产生新的 Encounter。

消费者为主体自身时，接触加入其 ExperienceItem 与活跃 WorkContext，并按设置提出成长工作。worker 的接触保存于执行用途；world-author 的接触保存于创作用途；维护与索引工作保存运行用途。主体后来查看 worker 摘要或原件时，再记录那次实际阅读的区域。 Material.scope 保存受信消费者范围，与传播 Policy 分开。工作者与作者的原始输入、草稿和输出只在同一执行范围或数据管理员授权下读取。受信宿主通过 materials.publish 选择已保存成果及区域，生成主体范围的材料；直接来源仍指向所选私有修订。读取成果时解析完整来源传播限制，私有祖先的正文仍留在原执行范围。

成功的前几个模型步骤已经发生，即使后面的工具失败，也保留对应接触。尚未发出、预算拒绝或仅准备的输入保留在操作诊断中。流式调用在已接受的完整步骤或明确终止的可用部分上记录接触，部分结果注明完成程度。

## 原始资料与人物目录

Directory 保存实际平台事实：账号、平台主体 ID、当前与历史名称、头像、简介、群内身份，以及明确提供的个人资料。未知字段保持未知，同一人物可以有多条冲突资料。

跨平台绑定以明确线索、操作者确认或已有已确认关系为依据。新线索先成为候选关系；按名字相同合并会丢失真实人物身份。确认绑定只更新 Account→Person 对应及其历史；旧消息保留当时账号和显示资料。

Nous 使用 Person/Group/Account 引用组织社会认识，可以把实际接触过的资料保存为自身材料。它的独立查询无需实时调用 Hept 才能解释过去已知的某个人。

## 外部资料源

资源连接器的公开能力只有目录/搜索/读取与变更观察；优先通过成熟 MCP、官方 SDK 和已有连接器实现。连接保存资源身份、授权引用、版本线索和可读范围。读取结果经 `materials.capture` 进入来源体系，后台搜索命中仍是候选材料。

本轮提供本地目录、HTTP 文档与 MCP 三类正式入口。云盘、资料服务和数据库可以配置已有 MCP server 或对应官方 connector。资源连接器对外返回受授权的内容与来源，不泄露文件系统凭据或数据库连接。

## 本地字节存储

采用 npm 维护的 cacache 处理流式写入、按摘要读取和字节去重，正式 Material/Blob 关系仍在 PostgreSQL。私有 BlobStore 只提供 put、read、stat、remove，S3 模式使用官方 SDK。调用方取得 blob 引用与大小，不接触目录布局。

默认采用库的完整性摘要表示，业务侧把它作为存储键保存。存储维护按正式引用决定保留，普通启动不会对来源目录执行缓存逐出。清除先解除授权引用，最后一个需要保留的引用消失后调用 `rm.content` 删除字节，并清理相应索引项；仅删除 key 索引不视为字节清除。故障诊断使用库的读取与校验能力，备份包含正式内容目录和关系数据。
