# 世界、日历与生活实现

## 世界的正式内容

Hept 的 world 模块拥有 World、Clock、Place、Route、Character、Object、Device、CalendarRule、Occurrence 和 RealizedEvent。近期情节草案与已经实现的事件分别保存。主体认识通过实际感知进入 Nous。

World 保存背景、规则、时钟、地点与人物引用。Place 保存可到达位置、邻接路线、设备和公开环境；角色私密安排位于作者范围。Character 保存人物设定、所在位置、日程与已经发生的交往事实。基础人物能够维持连续身份、在场状态和交谈，复杂独立人格模拟保留为扩展。

RealizedEvent 保存发生区间、地点、参与者、具体事实、来源、实际形成时间、现实记录时间和修订关系。后续更正通过新修订说明错误及影响，过去版本继续可读。当前地点、活动和设备状态由最新已采用事件与活动记录确定。

## 世界包

世界包是 ZIP 或目录，以 `world.toml` 为入口，内容包括 `worldId, formatVersion, title, clock, defaultTimezone, entryPoint` 以及文件引用。采用 confbox、Zod 和成熟 ZIP 库读取。

```text
world.toml
background.md
places.json
characters.json
calendar.json
rules.md
initial-state.json
assets/
```

JSON 文件包含有类型的实体与引用，Markdown 保存自由背景与规则。首次创建时包内使用局部 key 相互引用，采用操作一次分配正式 UUID 并解析关系；worldId 可省略，更新已有世界时明确提供其 UUID。world.toml 声明哪些内容对主体公开、哪些仅供作者使用。真实地理、真实天气等连接以 ResourceRef 指定，密钥保存在安装设置。

`worlds.preview` 一次解析全部内容，返回可读概要、未解析引用、冲突日程和入口状态；`worlds.create` 采用一个完整初始化组。世界包不携带运行队列、机器路径和秘密。人格种子由独立的 seed 操作采用；世界可以向初始主体提供公开背景材料，但实际经历按形成来源处理。

格式演化使用导入时的显式版本处理。当前清仓重建只实现当前格式，正常升级时再随版本提供需要的格式转换。

## 时钟映射

Clock 保存 `mode, worldAnchor, realAnchor, rate, timezone, pausedAt?, offlinePolicy`。同步模式 rate 为 1；自定义模式可以加速、减速或暂停。世界时刻按最近一段锚点与现实经过时间计算，修改倍率时先结束旧段再建立新段，过去映射保持可查。

网络超时、DBOS 调度和计算预算使用现实时间。事件发生、生活持续与精力变化使用世界时间。需要调度世界节点时，由时钟转换成现实到期时刻；暂停的世界没有自动到期执行。

离线策略默认 freeze，重启从保存的世界时刻继续。catch_up 按离线期间的日程和已采用活动推进到目标时刻；确定性事实直接推进，需要细化的情节集中形成。错过的外部通信保留真实平台时间，恢复后按接收和感知顺序进入生活。离线期间不会虚构平台发送成功。

## 日历、规则与单次安排

CalendarRule 包含标题、所属人物或地点、当地开始时间、时区、时长、RRULE、适用日期、参与要求和遵循程度。使用 rrule-temporal 计算发生次数，Temporal 处理时区。Occurrence 保存具体实例及 exception、取消、移动、参与计划和实际参与结果。

编辑范围明确为本次、从本次起、整个规则。本次变化保存 exception；从本次起结束旧规则并建立新规则；整个规则更新未来尚未实现的实例。已经发生的日程和实际参与结果保留。夏令时重复或缺失的当地时间遵循 Temporal 的显式 disambiguation 设置，默认 compatible，并在日历编辑预览中显示对应 UTC。

日程的发生与主体参加分开。课程按学校规则开始，主体可以准时、迟到、缺席或提前结束。参与结果由活动实际开始和结束时刻形成；因缺席产生的老师反应或后续责任由世界规则与场景实现。

遵循程度采用 `free / expected / binding`，配合出席要求和后果说明。它进入情境和注意权重，主体可以考虑改变计划并承担后果。固定考试的时间限制由世界规则执行，管理员仍能正式编辑其设定。

## 从规律到当前场景

世界规划分三种工作：加载长期规律；在有必要时准备未来 7 个世界日的近期安排；在活动临近、主体主动观察或外界打断时实现当前片段。作者模型只生成需要的场景，不提前写出逐分钟生活。

`world.advanceTo` 在短事务中推进已经确定的时间状态与日程节点，并返回需要实现的有界片段。`world.realize` 根据该片段、人物、地点、已发生事实和作者规则取得具体内容，再由 world 模块采用。主体侧收到的是符合其局部视角的 Percept。

粗略记录可以是“08:00—08:20 在教室上课”。之后询问具体细节时，`world.realize` 在已知地点、参与者、结果和时间约束中补充。新细节保留实际形成与记录时间。若后来发现事实错误，使用 `world.correct` 更正，引用旧记录与解释。

## 外部事件进入进行中的生活

平台消息保存真实发送与接收时间。到达主体的通知前，world.advanceTo 把已经经过的生活协调到当前映射时刻，结束此前已完成的片段，保留正在继续的活动。新通知只呈现设备允许的提醒信息。

主体选择查看时，创建新的感知动作；此时取得消息正文、附件或转发中实际展开的区域，并给出主体世界接触时间。通信发送时间、服务接收时间与主体接触时间分别保留。之后的场景允许受到这次交往影响，已经实现的部分继续成立。

当模型处理耗时较长，世界时钟继续映射；真正采用决定前再次推进到当前时刻，检查活动是否已结束、地点是否变化或承诺时限是否过去。变化只影响相关动作，现成模型成果保留用于调整。

## 局部感知与动作

`world.observe` 根据主体位置、当前活动、感知通道与权限返回当前可见人物、物品、设备、通知和事件。`world.act` 接受具体对象与动作，如移动、参加、休息、拿起设备、阅读或交谈，返回采用后的事件与状态。

动作目录随对象类型提供，模型使用短引用选择。打开某个会话可以直接作为一个有意义的阅读动作；无需模拟每次点击。移动沿 Route 计算到达时间，必要时进入通勤活动。设备的授权与可用性由其实际 owner 查询。

世界作者私密计划与其他人物私聊不进入主体 Percept。作者可以创造意外和互动，其实际影响经 world.realize 采用后才进入当前世界。真实浏览器取得的网页与虚拟人物描述分别保存来源，主体可以在虚拟设备界面中查看真实成果。

## 活动、感知通道与中断

Activity 保存目标、所在位置、时间范围、关联日程或追求、所需设备、通道需求、可打断程度、恢复线索和状态。

| 通道 | 示例需求 |
|---|---|
| vision | 阅读、观察环境、查看视频 |
| hearing | 听课、音乐、语音交谈 |
| language | 复杂对话、写作、理解长文 |
| reasoning | 解题、规划、专业学习 |
| hands | 输入、操作物体或设备 |
| mobility | 行走、通勤、运动 |

每种需求为 none、light、focused。同通道两个 focused 默认冲突；focused 与 light 需要明确允许的短暂窗口。场景可以在活动定义中给出组合例外，例如散步与听音乐允许并行，驾驶与输入长文限制并行。规则由少量类型与表驱动函数表达。

中断等级为 open、glance、brief、closed，分别允许自由切换、看通知、短回复和只接纳明确的重要中断。恢复线索保存此前目标、进展、材料位置和待继续问题。主体切换活动时使用一次 `activities.interrupt`，恢复使用 `activities.resume`。

## 精力与心境

LifeState 保存 energy、fatigue、mood、focus 和最近更新的世界时刻。energy 与 fatigue 使用 0—1 范围，mood 使用少量可读维度与事件说明。变化按实际经过的活动时长计算，事件影响由已采用的结果加入。

初始活动速率可以使用每世界小时：睡眠 energy +0.10、fatigue −0.12；安静休息 +0.04、−0.05；学习 −0.06、+0.07；运动 −0.10、+0.08；轻松社交 −0.03、+0.02。值在范围内截断，世界包与主体设置可以调整。模型解释生活感受，程序负责连续数值推进。

疲劳影响注意候选、活动选择和可打断窗口。计算预算独立控制实际模型与工具开销。后台 worker 只占实际计算资源，主体在委派、查看和再思考时产生相应注意需求。

## 天气、旅行与基础人物

天气由地点与有效区间决定。真实天气默认通过 Open-Meteo 官方 HTTP API 资源取得，地点提供经纬度，按地点时区解释小时区间，保存查询时刻、适用区间、原始单位与来源。当前天气和未来天气预报分别标明，预测不会回写已发生的天气事实；虚构世界使用世界包季节规则和作者给出的有界天气段。资源暂时不可用时显示已有资料的有效时间，虚构值保留 fictional 来源。

真实天气按地点和请求范围缓存，默认每现实小时刷新，已覆盖区间直接复用；开启连接时选择适用的公开、订阅或自托管端点。时钟离开真实资料可用范围时使用明确设定的世界天气，保留 fictional 来源。

旅行变更当前地点与当地显示时区。日程继续按其所属地点的时区解释，远程会议保留原时区；同一个时刻可以显示两地时间。路线影响移动活动、设备和感知范围。

基础人物按自己的日程、位置和已发生交往响应。与主体交谈时只提供该人物合理可知的内容。作者保存必要私密安排，主体通过实际交流逐步了解。多主体共享世界和完整独立 NPC 认知是后续扩展，当前正式事件与参与者身份已能承接这些关系。

## 下一自然节点

agency 汇总 world 提供的发生边界与自身的行为责任，计算 `nextNode`：正在进行的活动结束、日程变化、自由窗口、既定观察时机、承诺到期或主体选择的再次考虑时间。单个主体只保存一个最近节点及其原因集合。

节点调度使用独立 DBOS 等待工作流，前台队列不在其中长睡眠。安排变化后更新节点修订并重排等待；旧到期工作读取当前节点后直接结束。到期时推进世界，再向 Reactor 提交实际变化。无需每分钟模型心跳，也无需第二个调度框架。
