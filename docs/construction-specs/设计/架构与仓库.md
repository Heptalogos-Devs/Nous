# 架构与仓库

## 目标与交付范围

Nous Wave 提供跨时间、可修订、有来源的认知；Heptalogos 使同一个主体生活、感知、选择、交往和行动。两者各自拥有可独立运行的产品、数据库、正式客户端、CLI 和管理界面。联合部署沿用同一个 SubjectId，通过完整业务操作协作。

本次从空数据和新目录结构开始实施。项目宪纲决定产品目标，本包决定当前实现；仓库 AGENTS、旧 Spec、Architecture-Vault 中的派生设计随本包调整。旧代码用于寻找有价值的算法和业务情境。被采用的实现进入新的责任模块，被替代的源码、命令、测试支架和文档一起删除。

当前交付涵盖宪纲中的独立记忆产品、全部认知领域、持续世界、生活与自主性、完整消息与工具执行、管理和工程能力。第四十九章中的实时视音频、三维/VR、深度独立 NPC、多人共同世界和更广泛自主行动保留明确扩展位置。普通语音/视频附件、持续的环境人物和功能完整的 Web 管理属于当前交付。

## 两个模块化服务

默认部署中，Nous 和 Hept 各运行一个 Node.js 服务。需要提高后台吞吐时，使用同一产品程序的 worker 启动模式连接自己的数据库和 DBOS 队列。模块内部使用普通函数调用；跨产品、跨独立宿主才使用网络接口。

| 产品系统 | 责任与正式状态 | 主要消费者 |
|---|---|---|
| Nous identity | 主体登记、能力供给、绑定和分支身份 | 所有认知操作 |
| Nous materials | 原件、区域、派生、真实接触、来源关系 | 认知形成与读取 |
| Nous knowledge | Memory、Episode、Journal、Schema、Concept、Self、Social、Motivation 的语义与修订 | 召回、成长、管理 |
| Nous retrieval | NousQL、候选召回、融合、排序、展开、派生索引 | runtime 与外部查询 |
| Nous cognition | 活跃工作上下文、模型上下文准备、共享成长和维护 | Hept、SDK、原生集成 |
| Nous resources | 外部资料源的授权读取、版本和材料引入 | 查询与学习 |
| Hept communication | 账号人物目录、收件、媒体保全、表达、发送结果 | agency、世界设备、管理 |
| Hept world | 世界包、时间、日历、地点人物、已实现生活和活动 | 感知、agency、可视化 |
| Hept agency | 注意、自发机会、主观决定、追求、承诺及采用行为 | 通信、世界、任务 |
| Hept work | 委派、计算环境、结果、取消和人工接管 | agency 与维护助手 |
| 两边 management | 设置、身份权限、产品控制、导出清除和用户任务入口 | CLI、Console、API |
| 两边 platform | 数据库、模型 SDK 接线、配置加载、遥测、文件与系统调用 | 所属产品内部 |

platform 只容纳实际共用的机械。生活规则留在 world/agency，认知规则留在 knowledge/cognition。模块公开的是操作和可读视图，SQL、工作流步骤、原生 Session 文件、索引路径与宿主私有对象留在模块内部。

## 第三方承担的运行能力

采用 Node 24 LTS、TypeScript 7、PostgreSQL 18、Kysely、DBOS 5.3、AI SDK 7 与 DBOS 官方 AI SDK 集成。LanceDB 承担派生全文与向量索引；全文默认使用 ICU 分词。具体版本与公共接口见[第三方接入与源码复用](第三方接入与源码复用.md)。

Hept 的主观审议和自然表达直接使用 AI SDK。OpenClaw 承担专业 worker、工具、浏览器、沙箱和子代理；Nous 提供独立 OpenClaw 认知集成。AstrBot 作为默认即时通信与插件宿主，QQ 使用其 OneBot 适配器连接 NapCat。受 Hept 管理的会话关闭宿主自动聊天、人格和记忆处理，消息交给 Hept 的单一主体前台。

选择 AstrBot 的依据是现成的完整消息对象、原始平台事件、停止事件传播和平台客户端入口。OpenClaw OneBot 插件当前会在普通聊天路径合并正文、图片并只传末条消息身份；保持它的聊天路径会增加本项目的补偿工作。默认通信由一个宿主负责，OpenClaw 保持专业执行职责。

MaiBot 的自然交谈、语言惯例和表达资料用于独立能力复用；采用适合的提示块、处理函数和研究结论。其按会话维护的完整人格运行时留在上游。本项目需要的一条跨会话主观前台由 agency 实现。

## 仓库结构

两个仓库均采用 pnpm workspace。目录按独立发布物分包，业务子系统在核心包内按功能分目录。

```text
Nous-Wave/
  apps/server/                 # HTTP、MCP、worker 启动入口
  apps/cli/                    # nous 命令
  packages/nous/src/           # identity/materials/knowledge/retrieval/cognition/resources/management/platform
  packages/contracts/          # 公共 Zod schema、纯公共值类型、OpenAPI
  packages/client/             # 从 OpenAPI 生成的 HTTP 客户端与少量易用函数
  packages/console/            # 独立认知控制台，可嵌入联合界面
  integrations/openclaw/       # 原生认知插件与必要的上游源码改编
  migrations/                  # Kysely 迁移
  examples/                    # 可直接运行的记忆型和完整认知示例
  docs/                        # 当前设计与使用说明

Heptalogos/
  apps/server/
  apps/cli/
  packages/hept/src/           # identity/communication/world/agency/work/management/platform
  packages/contracts/
  packages/client/
  packages/console/
  integrations/astrbot/        # 渠道语义插件，Python；协议和连接交给宿主
  integrations/openclaw/       # 专业执行能力接线
  migrations/
  worlds/                     # 随产品提供的完整世界包
  docs/
```

`createNous()` 和 `createHept()` 是可嵌入的应用组成入口，接受已选定的外部依赖及设置，返回公开业务操作和关闭方法。HTTP、CLI 离线命令和工作流使用同一业务实现。模块通过自己的 `index.ts` 导出；消费者从公开入口导入。只为实际需要替换的搜索算法、资源连接器、渠道和执行宿主定义接口。

公共基础值类型存放在 `@nous-wave/contracts/common`，内容限于主体身份、引用、时间、调用身份和错误。Hept 引用这个纯数据包时不会安装或启动 Nous。两个产品各自生成自己的 Client；Hept 通过 Nous Client 使用认知，Nous 不依赖 Hept 源码。

## 数据归属

PostgreSQL 保存正式业务状态与修订。默认将 DBOS systemDatabaseUrl 指向该产品自己的 PostgreSQL 数据库，由官方包管理 dbos schema；业务事务经官方 datasource 保存事务检查点。文件存储保存原件和用户成果；LanceDB、缩略图与搜索图是可重建表示。

一条消息的正式交往记录由 Hept 保存。OpenClaw 保存该任务的原生执行历史。Nous 保存实际接触的来源及形成的认知。跨产品用稳定来源引用连接，当前模型输入按需构成临时视图。为了独立导出或保留真正被引用的区域，接收方可保存自己的材料副本，并明确其来源与保留责任。

业务操作负责本地提交。一个领域规则变化时，修改该规则的所有者和真实消费者；避免让调用者查询内部行、拼 SQL、重建世界状态或解释队列状态。

## 独立与联合运行

Nous 的 memory-only 模式只启用材料、记忆、查询和必要运行能力；高级领域可以按主体供给。高阶模型或 OpenClaw 未启用时，显式写入、读取、历史和管理照常使用。

Hept 单独运行时使用管理员提供的角色素材、当前生活与近期交往，保持世界、日历、注意、表达和任务能力。长期认识交由配置的 Nous 提供；界面明确显示认知连接和已启用能力。绑定 Nous 时，角色素材通过种子采用操作进入相应认知领域。

联合模式由 Hept Console 提供入口，认知页面复用 Nous Console 组件，操作仍提交到 Nous。管理员身份联通通过已有认证能力完成，两个产品的数据库权限分别授予。

## 开发组织

后端由 TypeScript 编译成 ESM 后运行，DBOS 代码保留正常模块加载。Web 使用 Vite 打包，CLI 通过标准 package bin 发布。采用 Biome 负责格式和常规静态检查，避免为编译器 API 再保留第二套 TypeScript。

第一条完整链就带有设置、身份、来源时间、traceId、操作状态和费用记录；后台成长、复杂世界和更多渠道随后填入相同操作边界。执行顺序见[施工顺序](../施工顺序.md)。
