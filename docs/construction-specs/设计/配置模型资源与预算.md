# 配置、模型资源与预算

## 模块定义与统一入口

每个模块导出一个 Zod schema，以 `.meta()` 标注名称、说明、所属任务、作用范围、可见层级、生效方式、单位与界面提示。产品启动时静态组合定义。Zod 校验输入，JSON Schema 供 OpenAPI 和 RJSF 使用，模块仍拥有字段的业务含义。

Standard、Advanced、Developer 是渐进披露层级。普通使用按模型、生活、交往、资料与运行组织；复杂日历、角色模型和预算使用专门界面，简单选项交给表单组件。

`settings.describe` 返回定义，`settings.read` 返回覆盖值与有效值，`settings.update` 保存修改，`settings.reset` 删除本层覆盖，`settings.history` 和 `settings.restore` 处理历史。修改后返回有效值、每项来源、已保存修订、当前运行修订及生效方式。

## 启动文件与路径

启动文件采用 TOML，使用 confbox 解析，使用 env-paths 取得各平台标准目录。显式 `--config` 优先，其次 `NOUS_CONFIG` 或 `HEPT_CONFIG`，最后固定的用户配置目录。启动文件只包含数据库连接、目录、监听地址、实例身份及密钥引用。

环境变量仅覆盖明列的启动字段：数据库连接引用、监听地址、配置路径、数据根目录、日志级别和秘密输入。环境覆盖的字段在有效配置中显示来源，管理界面对其显示只读及对应变量名。运行设置不按任意双下划线规则自动映射整棵树。

实例二进制、安装配置、主体数据、缓存、日志和工作空间有独立路径。路径在 bootstrap 解析后形成 Paths 对象，其他模块通过资源接口取得文件能力，不自行拼接安装目录。

## 四层继承

顺序为产品默认、安装、主体、该主体的角色。保存各层的稀疏覆盖值，先合并覆盖，再由最终 schema 补默认值。

标量由后层覆盖；对象按字段递归；数组整体替换。字段缺失表示继承，null 只在 schema 允许时代表明确空值。恢复继承删除该层字段。模型列表、渠道范围和提示段落不会因为隐式拼接改变顺序。

配置项声明允许作用范围。数据库路径只在安装级，角色模型在角色级，注意参数在主体级。预算上限和权限采用各层授权范围的收紧关系，普通覆盖值不能扩大上层授权。

原生 OpenClaw/AstrBot 自己管理的模型、账号、渠道及插件设置通过正式配置接口读取和修改。产品保存关联引用，界面将这些任务整合呈现。主体自己的认识通过认知操作编辑，不塞进配置覆盖层。

## 保存、生效与历史

模块在短事务中保存覆盖值、修订与修改摘要，提交后通知有关消费者。单进程用直接事件通知，多进程通过 PostgreSQL LISTEN/NOTIFY 携带修订号；启动与重连重新读取当前修订。

生效方式为 hot、next_call、restart。hot 由所属模块立即应用并返回实际生效修订；next_call 供下一次完整调用准备使用；restart 同时显示当前运行值与已保存值。一次模型调用使用固定配置快照，调用中途不会拼入另一半参数。

修改日程时由 world 更新发生边界，再由 agency 重算最近自然节点，修改渠道范围时由 communication 调整对应路由，修改检索模型时由 retrieval 建立新空间。配置模块保存变化，不解释这些内部操作。

历史保存 actor、现实时间、修改前后差异和可选说明。回滚以新修改应用此前值。后续版本改名或删项时，在正常配置迁移中转换或报告；清仓重建只提供当前名称和格式。

## 模型资源

ModelResource 包含 `provider, modelId, capabilities, contextLimit, outputLimit, pricing, credentialRef, executionHost, providerOptions`。模型实际能力和价格由提供方元数据及人工设置共同形成，手工覆盖标明来源和更新时间。

RoleProfile 选择模型资源，并设置温度、推理程度、输出上限、工具范围、上下文份额和费用策略。角色包括 deliberation、expression、worker、author、growth、maintenance 与资源处理用途。角色可以共用模型，但其输入范围与权限各自成立。

采用 AI SDK 提供方包和模型 registry，兼容端点通过现成 OpenAI-compatible 提供方接入。新模型先注册资源并设置能力，正常业务不按模型名称写分支。豆包角色模型等特殊 API 仅在提供方边界适配，表达职责仍使用同一输出合同。

表达模型默认偏向自然语言，专业 worker 选择工具执行强的模型，后台形成使用适合结构化输出的模型。具体商业型号由使用者配置，示例使用逻辑资源名，避免把某一个在线型号固化为架构。

## 预算与费用

预算按安装、产品、主体、角色和后台用途限制时间窗口内的实际调用。联合安装采用总上限与两个产品固定分配的子额度，子额度总和受安装上限约束；两个产品各自结算并提供统一查询。调整分配在明确操作中完成，不建立额度借贷系统。

已知价格时，在 ModelInvocation 中保存本次最大输出及预计输入对应的预留额，短事务检查当前已消费与未结束预留。完成后以实际 token、缓存、媒体用量与工具费用结算，释放剩余预留。状态未知时保留该调用的预留，待查询或管理员处理。

价格未知的模型显示实际用量与费用未知。启用严格金额上限前需要明确价格或单次费用上限；普通使用者也可选择 token、调用次数和并发限制。模型供应商优惠、订阅或代理价格由资源配置给定，不在代码中猜测。

OpenClaw 的模型调用通过原生逐调用扩展报告同一 Invocation 身份和用量，避免在父任务和子调用重复计费。工具自身收费另列 source 与单位。原生无法提供的收费项显示未取得，预算可使用管理员设置的单次上限。

预算不足时，前台返回可理解的暂停原因，后台维护等待下个授权窗口。接收消息、保存附件、推进确定性世界和管理入口继续工作。自动更换模型仅按角色明确配置的候选列表进行，并在执行记录中标注实际选择；重要知识和行为规则不随提供方随意降级。

## 计算与存储资源

并发由 DBOS 队列、模型资源限制和原生执行器配额承担。默认主观前台每主体 1，后台模型安装级 2，媒体处理 2，嵌入按现成批处理上限分批。现实机器资源限制优先使用容器与系统服务配置。

本地嵌入或 reranker 可作为独立推理服务或成熟本地运行库。CPU/GPU、模型下载与常驻内存由该提供方管理；产品显示启用、占用和可用状态。普通启动只使用已经配置的资源，获取新模型与运行包由明确安装操作完成。

媒体保全按资源有效期、大小和总存储预算执行。默认文本与元数据保留，附件大小和临时素材保留期由用户设置；超限时保留消息与内容缺口，向管理页提示。实际理解、转写和索引另有计算预算。

## 密钥

SecretRef 指向系统 keyring、受保护文件或明确环境来源。桌面使用 @napi-rs/keyring；无桌面服务使用所属服务账户能访问的秘密文件或系统凭据功能。Windows 用户凭据与服务账户分开设置，Linux 文件采用受限权限，macOS 使用对应账户 Keychain。

密钥输入后只返回是否配置、来源和最近修改时间。配置导出保留引用，诊断与日志默认去除密钥值。修改秘密由所属连接模块重新取得凭据并应用，长任务的既有授权按任务生命周期处理。

## 用户可见配置

初次配置按实际任务渐进展开：创建主体；选择模型与费用；选择世界或仅交往；设置通信和工具；阅读摘要后启动。高级参数默认收起，当前真正缺少的项目直接显示在对应任务旁。

“只在被提及时参加群聊”只修改参与策略；“停止接收这个群”修改收件范围；“关闭主动联系”修改发送行为范围。界面明确区分这些行为，资料保全和历史保留按独立设置执行。

用户能在每项值旁查看继承来源、生效时机、当前运行值和恢复继承按钮。预设提供可读的目标，如安静生活、活跃交往、低预算研究；应用预设只是一次可展开的配置修改。
