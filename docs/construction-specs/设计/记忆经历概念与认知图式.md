# 记忆、经历、概念与认知图式

## 一套修订机械与明确的领域含义

知识子系统共用对象身份、不可变修订、来源边、权限与时间读取。Memory、Self、Social、Motivation、Journal 和 Schema 各自定义内容 schema、变更规则及读取视图。Episode 和 Concept 有独立的成员或关联结构，并沿用相同修订语义。

私有持久结构采用 `knowledge_objects`、`knowledge_revisions`、`source_links`、`object_relations`，加上实际需要查询的经历成员和概念表。对象行保存 kind、当前 revision、状态及归属；修订行保存类型化 JSON 内容、五种时间、形成身份与认识立场。每个 kind 使用独立 Zod schema 和必要的查询索引。公共读写接口使用领域名称，存储细节由 knowledge 模块封装。

明确记忆意向通过 `growth.run` 的 remember 用途接纳来源并形成认识；管理员直接提供内容时使用 `knowledge.create`。正式采用同时安排索引工作。`knowledge.revise` 在同一对象上保存新认识及变更原因。模型提出两个不同事项时创建两个对象；同一事项的纠正保留身份。`expectedRevision` 只约束实际被修改的对象。

## Memory

一项 Memory 包含 `content`、可选标题、认知角色、形成方式、认识立场、适用范围、相关实体/概念及来源。

认知角色可以是 experience、fact、reported、preference、procedure、interpretation 等。形成方式包含 observed、told、read、inferred、reflection、initial_setting。认识立场包含 accepted、uncertain、hypothesis、disputed，另有该判断的 confidence。偏好和自我解释按自身意义保存，来源真实性始终是独立字段。

追加支持、出现反证、纠正内容、收窄适用范围分别生成修订。旧修订继续供历史查询。系统保留支持与反驳来源并存的状态，成长模型可提出分拆或新的解释。

读接口返回所选修订、主要内容、形成方式、适用期、支持与反例摘要及可继续阅读的来源。模型呈现优先使用自然语言，例如：“她目前更喜欢提前约定时间；这一理解来自最近两次私聊，仍有一次临时赴约的反例〔短引用〕。”

## 实际经历流

主体 Encounter 形成 ExperienceItem，包含主体、观察时间、当时活动、地点、参与者、内容区域、感受或思考结果及其来源。ExperienceItem 引用实际接触，不复制完整原始消息。

最新 ExperienceItem 直接进入活跃上下文。将其整理为 Episode、日记或长期认识可以稍后执行。worker 读取和世界作者工作留在各自执行记录；主体查看结果后产生自己的 ExperienceItem。

## 多轨道 Episode

默认轨道为连续生活、人物交往和长期工作。连续生活按世界时钟组织；人物轨道可横跨多个场景；工作轨道聚合多次 Session 的同一 WorkContext。同一接触允许参加不同轨道。

`episodes.organize` 输入轨道、所选经历范围、当前已有边界与新的组织方案，返回新增或修订的 Episode。Episode 包含起止范围、标题、摘要、参与者、地点、活动、成员引用和可选父 Episode。父子关系保持无环；成员只引用当前主体有权使用的经历。

先使用便宜的边界信号：活动或主要地点改变、显式结束、长间隔、任务阶段改变。初始长间隔取 45 分钟世界时间，可由轨道设置改变。共享成长在自然结束节点对不清楚的边界作一次语义整理，返回边界和摘要。持续变化的草稿只保存当前聚合，不为每条消息单独调用分段模型。

已组织片段可以被合并、拆分或重新命名。引用固定 Episode 修订的日记继续说明当时的理解；当前阅读可以沿修订关系查看新组织。

## Journal 与自我叙事

`journals.write` 以明确的时间段、经历集合、写作视角和当时知识截点生成或保存日记。正文、作者、写作时刻、来源、情绪立场和修订分开保存。后来的重新理解建立新修订，并注明新的写作时刻。

日记可以由主体主动写、在日终生成，或由管理员按需请求。默认日终只在存在值得组织的新经历时提出一次工作。主体后续实际阅读日记产生新的接触，日记的引用源与原经历仍属于同一来源谱系。

Self 的叙事身份是有关自身变化的认识，引用经历、日记和 Self 修订。它随重要变化更新，供“最近处于怎样的阶段”一类情境读取。

## CognitiveSchema

Schema 保存模式描述、适用情境、支持经历、例外、尚待解释的问题和可选预测。一次观察形成的猜测可以先标为 hypothesis；多次独立经历支持后再调整认识立场。

修订操作可以增加例外、收窄范围、拆成两个模式或终止采用。Schema 的抽象文字与它的支持经历可分别读取。检索将模式作为候选，同时保留直接经历，帮助主体比较概括和具体情况。

## Concept 与关联

Concept 有稳定身份、当前名称、别名、语言、定义和修订。概念可以是词、规则、事件、程序或较长描述。对象与概念之间保存显式引用；提及某个人与以某个人为认识对象使用不同关系类型。

`concepts.merge` 选择保留身份并记录被合并身份的指向，原引用继续能够定位历史。`concepts.split` 创建新概念，依据具体引用与语境分配关系；无法判断的引用保持在原宽概念中。当前查询可以沿显式关系展开，历史查询按当时关系读取。

关联边包含 relation、weight、evidenceRefs、共同来源根和更新时间。明确支持、反证、人物关联和事件先后属于正式语义；共现强度与吸积中心属于可重建服务图。

## 语义吸积

默认吸积按已发生的共同经历、实际引用、行动采用和有意义的反馈更新边权。一个来源根在同一统计窗口中的重复摘要只贡献一次经历信号。context 展示记录使用信息，证据支持由相应来源关系维护。

每日或累计足够变化后，维护任务批量计算概念的活跃度、关联强度与候选合并/拆分建议。使用成熟矩阵或图算法库，数据量较小时直接由 PostgreSQL 取得有界邻接数据。只有会被查询使用的派生表示进入索引。

## 可访问性与遗忘

对象可访问性由显著性、最近有意义的使用和时间衰减参与排序。初始计算采用 `salience + log1p(sum(useWeight * exp(-ln(2) * elapsed / halfLife)))`；halfLife 默认 30 个主体日。展示、引用、行动采用使用不同权重，范围在高级设置中调整。它影响自然浮现顺序，精确引用和授权历史读取仍能定位对象。

管理状态为 active、suppressed、retired 和已清除墓碑。`suppressed` 从普通召回和人格呈现中移出，历史读取由权限决定；传播限制缩小受众；彻底清除删除内容并处理依赖表示。自然语言“忘了吧”进入主体决定，只有正式授权的数据管理操作执行清除。

## 使用反馈与来源变化

`cognition.feedback` 接收完成步骤中的 presented、cited、adopted、outcome 和 corrected 引用。按实际步骤批量记录，避免为每个候选命中写入认知事件。行动成功可以提高某项方法的可访问性；对内容真实程度的更新仍通过有来源的认知修订完成。

来源被纠正、收紧权限或删除时，materials 产生明确的变更引用。knowledge 查找直接依赖，标记需复核或限制读取，retrieval 更新相应行。依赖图遍历采用有界批处理，操作状态显示尚待处理的数量与具体原因。当前权威读取已应用限制，后台索引刷新不承担访问授权。
