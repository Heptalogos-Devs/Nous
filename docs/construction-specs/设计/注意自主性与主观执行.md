# 注意、自主性与主观执行

## 主体的唯一前台

Reactor 是 agency 模块中的完整业务操作。每个主体只有一条主观决定链，来自所有会话、世界和任务的机会共同进入它。DBOS 前台队列按 SubjectId 分区并发 1，任务工具、媒体、作者和成长在后台运行。

前台保存当前 Activity、焦点、最近决定、未处理通知和下一自然节点。会话保存交往内容，模型 Session 保存执行上下文；两者均不创建另一个独立主体。一次决定可以处理多个相关通知，也可以只查看其中一个。

## 机会来源

机会以 `originRef, kind, availableAt, expiresAt?, subjectId, notice, reasonRefs, state` 表示。originRef 指向真实消息、活动、日程、追求、承诺、任务结果或主体此前采用的再次考虑意向。它保留可操作来源，正文仍由所属模块读取。

| 来源 | 产生时机与后续动作 |
|---|---|
| 通信 | 新消息、编辑、撤回、提及、平台邀请；生成设备通知 |
| 世界 | 场景变化、人物互动、活动结束、日历到期；推进局部感知 |
| 工作 | 任务需要选择、可读结果完成或失败；等待主体查看 |
| 追求与关切 | 已采用的复查时间、可利用的空闲时段或新相关材料 |
| 承诺 | 截止临近、履行结果或协商反馈 |
| 自主生活 | 自由窗口开始、探索兴趣的时间、休息结束、主体自己选择的回看时间 |

`agency.collectOpportunities` 从各 owner 提供的 due/read 操作取得当前候选，合并同一来源的重复提醒。新消息与旧消息有独立身份，已看过却未回复的消息保留对应交往状态。

**无外部事件时也有自主生活。** 世界包默认在空闲时段提供一次“自由安排”机会；主体可选学习、娱乐、联系朋友、探索、继续休息或确定再次考虑时间。默认白天没有其他节点时，每 60 个世界分钟有一个自由安排节点；睡眠时等待既定醒来或明确允许的中断。模型调用还受现实预算与最小间隔控制。

## 察觉、扫视、阅读与参与

通知状态使用 `unnoticed / noticed / glanced / read / decided`，回复与发送状态由通信模块单独提供。每次变化说明实际感知了哪些区域。

察觉只包含设备可显示的来源、提及和未读提示；扫视可以取得明确的通知预览，保存预览区域；阅读取得选定消息、媒体解释或转发层级；参与表示主体选择加入交往。尚未展开的附件和任务报告不会因为系统已保存而进入主体经历。

机器可以按已经可见的通知元数据排序。高层语义如“朋友希望我解释一个专业问题”需要主体实际读取相应内容，或来自明确被呈现的预览。后台处理得出的私密全文摘要不进入通知描述。

消息接收与资源保全始终由 communication 执行。主体的休息、专注与沉默只影响感知和参与。

## 有界注意选择

先应用正式行为范围，例如允许接收的渠道、暂停参与的群组及禁止主动发送的对象。随后根据活动兼容性划分“现在可查看”“可短暂中断”“等待自然节点”。真正的紧急中断来自明确配置的渠道事件或已经采纳的责任。

候选初始分数使用归一化因子：直接提及 2.0、关系相关 1.2、兴趣相关 1.0、承诺或任务相关 1.5、明确紧迫性 1.5、新颖性 0.5、等待机会 0.3，减去中断代价 1.5 与陈旧失效程度 0.8。因子在 0—1 内，等待项封顶；权重位于 Advanced 设置。所用关系与兴趣只从 Nous 的当前可用认识取得，缓存随修订更新。

程序保留前 8 个可行动候选，并从其他来源保留至多 2 个不同类别候选，避免所有机会都来自一个高频群。日程与承诺的必要时点始终出现在情境中。默认一个聚合窗口为现实 1.5 秒，原消息独立保存，聚合只减少唤醒次数。

分数用于给主体选择的有限视野。审议可以继续、读取、参与、推迟、拒绝、忽略、委派、休息或主动安排其他行为。沉默保存其决定与可选回看时刻，系统不会因等待时间自动发送回复。

## 一次 Reactor 操作

`agency.react` 按以下顺序工作：

1. 推进世界到当前映射时刻，取得活动、设备、感知限制与未结束责任。
2. 读取当前候选、WorkContext 和相关认知，形成可读 Situation。
3. 调用主观模型。允许使用读取、查询、世界观察及查看任务结果工具；每个实际模型步骤均准备新的认知。
4. 得到 Decision 后再次确认当前时刻与相关对象修订。
5. 在 `agency.adoptDecision` 中一次采用相互关联的活动、追求、日程、承诺意向与委派，并保存本次处理的机会。
6. 启动外部工作或自然表达，安排下一个自然节点，结束本次前台。

Situation 包含当前时间与地点、在做的事、能看见的变化、需要考虑的候选、未完成目标和可用动作。原始标识留在结构对象中，模型视图使用简短引用。关键变化只使受影响动作重新判断，已有分析和材料保留。

## Decision 的结构

Decision 包含 `focus, actions, internalReason, resumeCue?, reconsiderAt?, expressionIntent?`。actions 使用具体联合类型：observe/read、continue、start/interrupt/resume activity、create/update pursuit、delegate task、schedule、rest、wait、dismiss。每项有对象引用、实际参数和预期目的。

模型通过 actions 提出选择，业务模块应用权限、可用设备、时间与对象规则。读取工具可以直接取材料；正式写操作集中在采用决定时完成。外部工作在事务结束后启动，结果经其 owner 返回。

internalReason 是内部决策资料。ExpressionIntent 另有用途、听众、可披露事实、允许新增的重要细节及语言姿态；renderer 只得到这份对外资料。没有表达意图的决定不会调用自然表达模型。

## 自发行为与长期连续性

愿望和关切提供可考虑的主题。主体选择投入后创建 Pursuit，安排活动与复查时间。一次新的兴趣可以只有探索意向，也可以成为持续学习。主动联系朋友须符合当前行为授权与关系情境，并给出实际由来。

主体等待 worker 时可以继续生活；结果完成后形成新机会。前台转向别的事情时保存恢复线索，后续自然节点取得原任务进展。当前焦点与后台计算占用分别显示。

无新材料且主体刚选择等待时，以其 reconsiderAt 为下一节点；没有指定时，使用世界自由窗口。现实预算耗尽则保留节点与候选，在预算恢复或管理员调整后继续。每天空闲自发审议默认最多 12 次，受安装总预算进一步约束，用户可以调整；确定性世界推进不消耗此模型调用限额。

## 打断与取消

新到通知先进入待处理范围。open 活动可立即参加下一次前台，glance 与 brief 分别允许扫视或短回应，closed 等待自然停顿。长模型步骤在可取消的边界接受中断信号；已开始付费调用的默认动作是完成当前步骤后重新选择焦点。

明确管理员停止与权限收紧可以立即取消对应运行。已经完成的输出、工具成果与实际接触保留，后续外部效果停止。挂起 Activity 保存目标、完成位置和预计恢复条件，恢复时先取得当前世界与新发生变化。

## 查看未回复的原因

`agency.explainAttention` 根据已有通知、活动、决定与发送结果返回可读原因，例如尚未察觉、只看了预览、选择稍后、活动不方便、预算暂停、正在等待资料或发送结果未知。回答来自正式状态，附相关事件与操作引用，不再调用模型编造理由。

用户可以调整参与策略、暂停会话、让主体再次考虑或取消待发内容。社会交往者提出的请求由主体判断；管理员通过正式行为策略接口调整范围，系统维护权限另行认证。

## 前台异常的继续

准备或模型失败由原 DBOS 工作流记录，保留已读材料与成功步骤。确定未调用模型的瞬时依赖错误有限重试；已存在原生 run 时读取该 run。唯一自然节点失效或依赖恢复后，由原节点工作流重新投递该主体的待处理机会。

前台失败不停止收件、世界时间、管理接口和其他主体。调试入口显示本次调用、当前等待原因及可继续位置。恢复职责限于这一操作及持久下一节点。
