# 可观测性与调试

## 从正式操作看系统

每个正式业务操作从首次进入产品时就建立 operationId 与 traceId。日志、模型调用、数据库事务、任务、消息结果和认知采用通过这些引用连接。用户从“这一条消息”“这一项任务”“今天没有回复”进入，开发者再展开技术调用。

业务模块保存有长期意义的结果与解释，执行框架保存运行进度，日志和 trace 保存诊断信息。一次已完成事务不会因为 telemetry exporter 暂时不可用而回滚。费用、外部效果和认知来源属于正式业务记录，按各自事务提交。

## 统一接线

Node 进程使用一个 OpenTelemetry SDK，Pino 输出结构日志；Fastify、数据库、HTTP Client 与模型使用现成 instrumentation 或对应库的官方 telemetry。注册应先于被观测模块加载。默认本机保留 JSON 日志，配置 OTLP 后向现成 Collector、Grafana/Tempo 或兼容服务发送。

每个产品的 platform/telemetry 只提供初始化、上下文传播和少量业务 span helper。DBOS 官方 telemetry 与应用使用相同 tracer provider；执行器已有 trace 通过原生引用或 span link 关联。进程内不安装多个独立自动采集实例。

HTTP 使用 W3C traceparent/tracestate，跨产品 Client 自动传播。DBOS 后台工作保存触发 trace 引用，新执行 span 与原请求建立 link，避免把长时间等待算成一个持续运行的请求。AstrBot 插件与 OpenClaw 接线同样携带 trace 和 operation 引用。

## 字段与事件

日志基础字段为 `time, level, service, instanceId, event, operationId?, traceId?, spanId?, subjectId?, actorKind?, resourceRef?, outcome?, durationMs?`。错误保存稳定业务 code、简洁消息和内部堆栈，外部接口只提供允许公开的部分。

常用 span 名称采用正式操作，如 `nous.contexts.prepare`、`nous.growth.apply`、`hept.agency.react`、`hept.messages.sendExpression`。属性说明检索通道、模型与提供方、候选数量、token、权限范围类别和实际等待原因；个人姓名、完整问题和消息正文默认不放入 attributes。

业务事件直接由所属模块写日志：收件接受、媒体缺失、实际阅读、决定采用、任务成果、发送结果、认知修订、配置生效、预算暂停、依赖恢复。没有新的全局事件账本；用户长期历史从 Message、Encounter、Decision、Task、Revision 等正式对象读取。

## 成本、延迟与状态

ModelInvocation 为费用的正式来源，关联实际提供方、角色、上下文引用、用量与 native request/run。计算多个层级时按 invocationId 去重。未知费用和估计费用分别显示，不把默认单价混成真实账单。

监控初始包含请求延迟与错误、前台排队时长、模型耗时/费用、索引滞后、未解决外部效果、媒体失败和后台工作量。系统指标采用低基数标签，如产品、操作、模型资源与结果；主体、个人和消息 ID 留在日志与业务查询中。

主体状态汇总当前活动、主观前台、后台任务、最近决定、下一节点与阻塞。依赖状态显示 PostgreSQL、Nous、渠道、模型、执行器和索引的实际可用性。状态页区分服务正在运行、主体已经启动和某项能力当前可用。

## 用户解释入口

`operations.inspect` 汇总 DBOS 公共状态、当前业务结果、等待原因和可继续动作。`operations.trace` 返回关联的 trace/日志/native-run 入口。`agency.explainAttention` 使用已有决定与通知说明近期未回复的原因。`knowledge.explain` 显示形成、修订与来源，`query.explain` 显示过滤和排序因素。

默认显示最近一层原因与对应动作，用户展开后查看调用链。多次依赖错误聚合成一个告警，恢复后关闭该告警。生产页面不向操作者展示内部字段证明、检查计数或完整原生协议。

## 调试快照

开发者可对一个主体、操作或有限时间窗口开启诊断模式。快照包含配置修订、输入引用、选中认知、裁剪情况、实际模型参数、输出引用、工具调用和采用结果。默认只存引用；需要捕获正文时显式授权、设置有限保留期，沿用材料的用途与受众限制。

敏感字段使用 Pino redaction 与统一秘密字段描述清理。导出诊断包默认包含日志片段、错误、依赖版本及结构信息，秘密、认证头、原始个人文件和未授权对话排除。管理员可以明确添加特定材料，包内标明来源与范围。

debug 模式不会把作者秘密传给主体，也不会把维护工具权限授予人格模型。调试页面可由管理员看到被允许的内部决策资料，普通交往者只看到自己的交往结果。

## 重现与重新运行

`operations.replayView` 按现成检查点及业务记录还原一次操作的输入、结果和采用顺序，用于解释与调试。它是只读视图。

需要比较新模型或新策略时，`operations.rerun` 创建明确的新操作，选择保存的输入快照与新的资源配置。默认禁止对外发送和发布，结果保存在实验工作空间；需要真实效果时由管理员明确开启该操作的对应权限。它复用正常模型与业务接口，不建立另一个模拟执行框架。

已完成模型输出可直接重新采用冲突组、重建索引或重新交付结果，无需再次付费调用。操作页把“复用成果”和“重新调用”分成两个具体动作。

## 诊断命令与故障定位

`nous doctor`、`hept doctor` 检查当前必要项：配置是否可解析、数据库能否连接、schema 是否可用、目录是否可写、已选模型/渠道/执行器是否可访问、所需能力是否存在。检查按当前启用范围运行，关闭的可选依赖不作为错误。

`doctor --operation <id>` 沿该操作的实际调用链读取失败位置、等待原因和有关配置；模型诊断默认使用提供方元数据或不收费的连通接口，付费试调用需显式请求。

普通代码调试使用 Node inspector、IDE source map、Pino 和原生工具日志。真实缺陷回到负责模块修正，重现材料留在一个紧凑场景中。遥测存储默认保留 7 天日志、短期 trace，业务历史按数据策略保存；保留期在设置中可调。
