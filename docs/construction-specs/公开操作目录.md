# 公开操作目录

## 公共接口约定

本文确定公开任务、主要输入和完成结果。字段的领域含义以对应设计为准，编码时由公共 Zod schema 生成 OpenAPI 与 Client。`S` 表示 `/v1/subjects/{subjectId}`；路径中的 S 是表格缩写，OpenAPI 使用完整路径。

外部写请求带一个客户端提交 ID，宿主事件使用来源身份；受信 actor、purpose、audience 由认证入口建立。较长的操作返回 OperationRef，读取与短修改直接返回对象。服务端不接受任意函数名执行或通用 SQL。

共同对象草稿保存语义内容、来源、时间和范围；ID、recorded、修订、actor 与执行状态由服务产生。所有列表使用相同 CursorPage，所有失败使用 Problem Details。`/v1/operations/{id}` 提供实际结果、当前等待和可继续动作，`/events` 提供 SSE。

## 主体、权限与运行

| 操作 | HTTP 路径 | 主要输入 → 完成结果 |
|---|---|---|
| subjects.create | POST /v1/subjects | 名称、可选外部 SubjectId、能力、种子/世界选择 → 主体 |
| subjects.list / read | GET /v1/subjects；GET S | 查询或主体 → 可读身份、供给、状态 |
| subjects.bind | POST S/bindings | 对端安装、同一主体身份、授权连接 → 绑定 |
| subjects.capabilities | PATCH S/capabilities | 启停能力与作用设置 → 当前供给及可用状态 |
| subjects.start / pause / stop | POST S/runtime/{action} | 运行操作及影响范围 → 实际主体运行状态 |
| policy.read / update | GET/PATCH S/policy | 读取/传播/行为范围、expectedRevision → 有效策略 |
| subjects.changes | GET S/changes?after=cursor | 已消费游标 → 变更引用与新游标 |
| subjects.fork | POST S/forks | 截点、共享范围、新名称 → 新主体与来源 |
| capabilities.read | GET /v1/capabilities | 无 → 当前安装实际支持的模块、宿主与接口能力 |

Nous 不提供 Hept 生活 start；其 runtime 操作控制认知自动形成与维护。Hept 的 start/pause 控制主体前台，服务生命周期通过安装管理完成。相同公共值并不使两个产品导出无意义的同名能力。

## 长操作与资料读取

操作页通过 DBOS 公共管理接口与正式业务记录拼成可读进展；SSE 消息只携带状态、引用和进度摘要。文件流由所属产品授权，支持标准范围读取和内容类型。跨进程传递文件引用或流，避免把大文件反复嵌入 JSON。

Public schema 保留有实际消费者的字段。新增正常业务信息时在 owner 的正式结构中增加并迁移当前消费者，删除受影响的重复转换。底层 SQL、队列私有状态、Session 路径和平台客户端对象留在各自模块内。
