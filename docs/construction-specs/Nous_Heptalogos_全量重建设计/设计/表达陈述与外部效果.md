# 自然表达、陈述与外部效果

## 表达由主体意图驱动

主观决定提供表达意图、听众、立场、所需内容与可以使用的认识，renderer 使用适合语言表现的模型生成自然文本或媒体表达。renderer 不承担任务规划、工具执行或管理操作。

Expression 保存完整输出、实际听众、所依赖决定和必要来源。正文保持模型生成的语言形态，不要求以 JSON 包装一句普通话。多条消息、图片说明、回复引用与语音使用标准 MessageContent 表示。

## 普通表达的短路径

普通表达执行：取得已采用意图和当前听众上下文 → renderer → 检查实际收件范围、允许媒体与内容结构 → expression.commit → 原生发送。普通问候、日常回答、玩笑和已知事实的转述无需独立 review 模型。

结构检查只处理能确定的收件人、引用、大小、媒体可用性和权限。它不强行把自然措辞变成机械模板，也不进行逐句客观真理认证。

Claims 在实际发送后由后台整理，从最终发送版本提取陈述、时间和引用，关联真实平台 messageId。整理延迟不阻塞消息，已发正文始终可从通信系统读取。再次回答“刚才说过什么”可以直接读取消息，无需等 Claim 索引完成。

## 需要同步采用的内容

表达会新建重要世界细节、明确长期承诺或处理与当前事实的重要冲突时，进入对应的语义操作。决定或 renderer 提供具体待采用内容，必要时由独立 narrative review 判断其与当前世界、认识和既有说法的关系。

review 只看该表达及其必要材料，输出采用、有限修改或具体冲突。一次需要修改的输出保留原文，由同一表达进行修改；没有新信息时不反复调用不同 review 模型。

`expressions.commit` 在一个 Heptalogos 事务中保存最终表达、采用的新世界细节、承诺及待发送意图。世界模块验证时间、已发生事实与角色范围；承诺模块保存义务与下一节点。外部发送在事务后执行。

表达已经被采用但最终没发出去时，承诺是否生效按内容用途决定：向他人的对外承诺在确认发送后成为已表达义务，内部决定承担的行动仍按 Decision 有效。字段分别记录 adoptedAt 与 sentAt；世界内采用的事实与对外表达状态保持各自含义。

## 世界事实、主体认识与听众版本

同一事件可以有世界实际情况、主体目前的理解、对某一听众的说法。Claim 保存 actualMessageRef、关于的事项/时间、表达立场、引用来源与认识/世界事实关系。每条 Claim 可以说明是断言、猜测、隐瞒、玩笑、引用或有意虚构。

Subject 可以误解或有意欺骗，这属于其行为和社会关系的研究范围。表达意图明确给出有意策略时，系统保留该决定和听众版本；不让 renderer 意外把未读后台结果当作自己的经历。

`claims.toAudience` 按实际听众读取已表达版本，`claims.explainStatement` 从消息返回当时的意图、认识与实际世界材料。来源后续被纠正时追加关联，不覆盖已经发出的句子。

普通消息也可能产生重要关系后果。后台 Claim 和成长可以据实际互动更新认识；需要立刻处理的真实安全或权限要求仍在行为边界执行。

## 一处实际发送

物理发送使用 OpenClaw 官方 durable outbound。Heptalogos 保存业务 Expression/DeliveryRequest，原生系统保存排队、连接、分部分发送与平台回执。项目不再维护第二个物理发送调度器。

服务端通过官方 Gateway `send` 提交已采用表达，公开 `idempotencyKey` 使用 expressionId 与逻辑消息序号组成。文本、媒体、语音、GIF 和回复目标使用正式 SendParamsSchema；编辑、撤回和表情反应使用 `message.action` 的独立动作身份。自有渠道插件只实现平台语义，原生队列和 `sendDurableMessageBatch` 由 OpenClaw 承担。

Expression 中保存有序的逻辑消息及每项交付结果。处理一项发送前，业务操作把它从 pending 改为 submitting；明确取得结果后记录实际回执。后续项按前项的结果继续。Gateway 或进程中断使结果未知时，该项停在 unknown，保留实际文本、听众与操作身份，等待原生回执、平台读回或管理员处理。已确定发出的部分保持原结果。

所查2026.10.5的公共 `send` 接口提供 idempotencyKey；普通外部调用的路由去重使用进程内缓存，跨进程的 producer intent 字段标为内部接口。因此重建采用公开 RPC，并将结果未知时的重新发送交给明确的业务决定。项目不传内部 deliveryIntentId，不读原生队列表，也不为此维护上游补丁。重新尝试只针对已经确认未发送的逻辑消息；原生已接纳工作继续由原生队列处理。

## 发送权限与回执

实际 send adapter 在调用平台之前核对当前账号、听众与许可。普通 chat hook 的失败跳过策略不承担权限。普通 worker 的模型工具也只能提出发送请求，必须经过 agency/expression 的采用入口。

回执按每个内容部分记录 notSent、accepted、failed 或 unknown；整个表达另有完整、部分、未知等汇总。平台返回的 messageId、实际时间与原始响应保存在渠道 owner。未知状态保持原请求身份，支持平台读回或管理员核实；不自动再次发送。

原生回声去重与发送队列维护优先使用 OpenClaw 官方能力。Heptalogos 从确定的回执记录实际 MessageFact，并以原 messageId 去重。查询和界面展示“已采用”“已提交平台”“部分已发”“状态未知”这些真实区别。

## 媒体、引用与修改

一次表达可以包含文本、表情包、图片、音频、视频和文件，按原次序发送。平台支持多个物理部分时，使用原生批处理与逐部分回执；不因一条大消息超过限制而创建另一套队列。

图片/GIF/视频的实际字节通过正式材料接口取得，不向模型提供受保护文件路径。回复引用绑定实际目标消息。编辑、撤回、表情反应、群管理等能力由渠道声明；其操作同样需要真实行为意图和平台结果。

平台没有相应原生能力时，动作目录不向主体开放该动作；存在的渠道能力应完整映射到统一通信接口。不会通过发送一条“假撤回”文本模拟平台操作。

## 重复流程的删除单位

删除原 renderer 注册、brief 二次绑定、候选 receipt、review gate、custody prepare、host begin、原生授权再回调等重复身份链。保留一个 Expression、一个真实原生发送引用、逐部分结果以及实际需要的 Claim/Commitment。

业务表达模块不读取原生 Session 内部状态；原生插件不读 Heptalogos 的私有表；通信模块只消费已采用表达及当前发送许可。这个边界同时支持 QQ、其他即时通信和 Web 主体私聊。
