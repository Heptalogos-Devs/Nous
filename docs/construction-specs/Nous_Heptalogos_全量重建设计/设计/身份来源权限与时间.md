# 身份、来源、权限与时间

## 稳定身份

`SubjectId` 标识独立主体。Nous 创建主体时分配 UUIDv7，Hept 绑定同一 ID。独立 Hept 安装可以先建立未绑定的产品配置，再通过正式创建或绑定操作取得主体。账号、模型、Session、安装和世界均使用各自身份。

`EntityRef` 是带发行者的稳定引用，形如 `issuer / kind / localId`。Hept Directory 拥有人、平台账号、群体和世界人物的事实身份；其他 Nous 使用者可以提供自己的发行者。Nous 为被接纳的外部引用建立本地寻址记录，PersonUnderstanding、SocialRelation 等认知引用它。身份发行者可以修正对应关系，旧接触仍保留当时的账号和作者快照。

同一个人物可对应多个平台账号；某个账号属于哪个人物是一项具有来源、确认状态与修订的对应。显示名称、群名片、备注和别名均可变化。真实人物、世界演员和独立 Subject 各有明确种类，同名不触发自动归并。

内部 ID 使用 `uuid` 库。模型可读地址使用标准 Proquint，把随机 48 位值表示为三组 CVCVC，类型前缀指明 memory、person、tag 等对象。优先使用已有 Proquint 实现；现有项目的短小编码器可作为语法场景参考。地址表依靠数据库唯一约束分配，并保留被清除地址的占用，避免重新指向另一个对象。

名称供发现，Proquint 供跨调用精确引用，`result:3` 供一次查询后的简短续接。引用解析由 Nous 统一提供。名称冲突返回实际候选；已有准确结果引用时直接读取，调用方不再额外查询一次内部 ID。

## 材料、接触与认知

`Material` 表示可读取的原件或派生内容。`Encounter` 表示某个主体在某个用途与时刻接纳了哪一部分材料。`CognitionRevision` 表示形成或修订的认识。

一张图片可以被多次接触，一次消息可只被看到预览，一个模型提案可以引用多份材料。分别保存这些关系。相同字节的去重只作用于存储，实际接触身份由接触事件决定。

来源至少区分：外部直接材料、工具结果、主体输出、初始化设定、世界已实现事实、世界作者草稿、第三方陈述、导入资料。接触性质区分主体经历、专业执行资料、世界创作资料与管理资料。模型身份与运行角色由受信执行入口填入，模型正文不能改变它们。

世界已实现事实可成为相应世界的经历；世界作者的隐藏安排留在世界作者的材料范围。工具任务的全部材料先属于该任务，主体查看其中结果时才建立自己的接触。初始化设定保存自己的采用来源，不补写没有发生的过去接触。

## 形成依据与认识判断

每个认知修订保存完整自然语言内容及以下关系：它来自哪些接触或既有认知；其中哪些材料支持、反对、纠正或仅提供背景；哪些判断来自推断。叙事内容允许有多条陈述，具体来源映射用正文选区或陈述局部键定位。

来源链在材料进入与认知形成时整理根来源。读取时复用这些关系，查询不重新遍历全库。直接证据被撤回时，依赖处理标记受影响认识需要重新查看，并创建必要的成长任务。主体的信念如何变化由实际修订保存。

一份资料的两次摘要仍共享来源根。重复使用影响可访问性；实际新佐证、反例和结果可以影响认识判断。关系或概念没有统一的“两份证据才成立”门槛。领域按当前材料说明采用、暂存假设或保留分歧。

## 来源访问与对外表达

访问控制使用三类信息：

- 调用者的服务身份、Subject 与已授予操作；
- 材料的来源范围、世界视角和隐私要求；
- 本次用途与实际听众。

受信运行配置生成 `AccessContext`，服务将它传给内部操作。模型工具只提交任务参数。跨服务凭据只存在于服务端，工具参数中没有可自填的管理员身份、角色、任意 source scope 或 unrestricted 标志。

主体内部审议可以使用自己已经知道且获准处理的私人认识；表达模型只取得适用于当前听众的材料和有意表达的意图。世界作者、专业执行者和维护助手各自使用限定视角。某次内部知道的事实不会因为换了输出渠道就变成可公开内容。

来源限制以少量 `DisclosurePolicy` 保存，派生认识继承其实际依据的限制组合。索引记录对应 policy bucket，召回先按当前可读 bucket、Subject 与视角筛选，再生成候选；领域最终读取检查当前删除与权限状态。这里的 bucket 是查询加速的派生值，权限规则仍由正式来源记录决定。

普通设置提供清楚的私聊、群聊、公开、指定接收者和仅内部用途。复杂派生使用组合策略，当前调用必须满足所有必要来源条件。新增一项公开陈述可以有独立的人工授权来源；不能只改一个缓存标签扩大其访问范围。

## 一套带域时间

所有语义时间使用 `TimePoint { domainId, tick }`；tick 是相对该域历元的整数微秒，传输为十进制字符串。时间区间明确区分 unknown、instant、interval，interval 的起点或终点可开放。区间统一左闭右开。

现实记录时间使用 PostgreSQL timestamptz。世界领域自己拥有 ClockMapping：现实锚点、世界锚点、速度分子/分母、暂停状态和生效时间。Temporal 负责日历日期、IANA 时区与夏令时，整数时间工具负责域内比较。世界更换速度只建立一条新的映射段；旧事件时间不改写。

Hept 拥有世界时钟，Nous 接收并保存相关时钟映射与接触快照。Nous 独立使用时，现实域默认可用，其他宿主可登记带发行者的时间域。认知服务无需在数据库事务中请求世界服务获取时间。

## 五种时间及两个历史视图

| 时间 | 所属事实 | 使用场景 |
|---|---|---|
| occurred | 原材料描述的事情何时发生 | 查询事件、经历顺序 |
| observed | 主体何时实际接纳材料 | 当时知情范围、经历组织 |
| valid | 某项认识适用的时间范围 | 任职、关系、习惯、期望条件 |
| formed | 某个模型/主体形成该认识的时间 | 反思与认知发展 |
| recorded | 系统实际写入的现实时间 | 恢复、数据库历史、晚到资料 |

`knowledgeAt` 限定主体当时已经知道的内容，`recordedAsOf` 限定数据库当时已有记录，`validAt/validDuring` 限定内容适用的时段。它们可共同使用。历史查询还使用当时的名称对应、概念意义和认知修订；当前删除与访问限制继续生效。

晚到的材料保存实际到达与实际接触，不挪动到过去。世界在某时段按规则持续发生、稍后才被详细实现时，保存世界发生时间、实现时间和各角色的知情时间。数据库重建历史不创造角色曾经读过的内容。

## 统一读取结果

接口返回完整业务 View，含对象引用、当前修订、正文或材料表示、来源摘要、适用时间和必要状态。详细原始数据与谱系在显式展开中读取。

自然语言 renderer 与管理页面使用同一领域 `describe` 操作。它负责表达该领域的当前内容；Core、Hept 和插件不再各写一份人格摘要。结构化完整 JSON 仍由 API 提供，普通模型上下文只出现内容、简短来源与有意义的限制。

设计依据：宪纲主体、来源、时间、模型角色、社会认识和管理权限诸节；现状中的身份与原生输入图。实现差异及外部接口来源见[依据目录](../依据/来源与版本.md)。
