# 完整重建与施工顺序

## 重建范围

本包授权的是从目标能力构建新系统。旧实现提供对象语义、真实故障、有效算法与使用场景，代码结构整体替换。两个仓库分别在明确的重建分支工作，生产默认分支通过完整产品变更合入。

旧代码、旧测试、旧协议和生成文档不搬进新架构继续维持。先建立目标目录与完整领域操作，将确有价值的算法或映射移入其新 owner；删除支撑旧路径的代码、配置、脚本和文档。Git 历史保存旧实现。

## 当前资料与个人资产

开始前读取实际工作树和已开放的分支。用户未提交内容、真实种子、账号登录、付费模型成果、数据库、素材与任务记录分别保存；重建不得以替换代码为由删除这些资产。

本次已核实远端 Nous master 为412b0620、开发分支aa93ede6，Hept master为21f00804、开发分支f855c686。执行时重新读取实际 HEAD 和工作树，把后来真实变化作为输入。旧 archived 分支只作历史参考。

资产优先通过旧系统的导出入口或既有离线归档保全。旧字段到新主体包的转换作为一次导入工具，完成指定归档转换后退出活动代码；业务服务不带旧表双写或兼容读取。导入的外部效果保持历史状态，发送默认暂停。

## 先打通共同运行与最短业务链

建立两个仓库的目标目录、Node/TypeScript、Fastify、Zod、Kysely、pg-boss 与正式 Client。Nous 首先完成 Subject、材料、实际接触和基本 Memory；Hept 完成 Directory、Communication、Activity 和官方 OpenClaw 接入。

这一施工单位必须实际贯通：创建同一 Subject → 收到一条消息 → 取得当前材料 → 原生模型接受输入 → 记录 Encounter → 形成和读出一条记忆 → 采用并发送一句自然表达 → 保存真实平台结果。

同时验证官方 context engine、发送关联与未知结果处理、中文全文和平台原生依赖。若选定依赖存在真实接口缺口，在这一单位直接解决提供者接线或上游替换；不以旁路补丁延后到全部领域建成后。

## 完成认知的整体结构

按材料与共同修订基础，完成多轨道 Episode、Journal、Schema、Tag、Association、Self、PersonUnderstanding、关系、语言惯例与 Motivation。一次共享反思输出完整跨域变更，接入统一召回、上下文与管理读取。

该单位包含多文件种子预览/采用、领域开关、人物资料实际输入与学习结果更新。已经完成的 read/mutate/history/lifecycle 操作全部进入官方 Client/CLI；不把入口工程留成最后集中补齐的大任务。

Memory 身份、实体纠正、未知/开放时间、反例、原生失败输入、重复反馈等已知风险在新的完整操作上验证。旧函数签名测试随旧结构移除。

## 完成世界、生活与主观前台

建设独立 ClockMapping、WorldProfile、Calendar、Actor、Object、RealizedEvent 和 Perception。接入实际活动、精神/体力、情绪、个体化注意与 Reactor。世界确定性推进不依赖 Nous 或模型在线。

完成一个学生或其他内容包的实际生活：入场、移动、课程/活动、休息、收到来信、选择读或延后、查看任务成果、继续生活。当前示例只提供内容，不使核心系统依赖“学生”身份。

同一单位包含 NPC 三个层次的数据与运行接入，至少常驻人物的连续互动实际可用；深度角色使用第二个明确 Subject 和共同世界接口，不伪装成第一主体的 worker。

## 完成任务、表达与长期成长

接通 Pursuit、TaskResult、浏览器/文件环境、人工接管、等待与恢复。完成普通表达短路径及重要世界事实/承诺的采用路径，逐部分回执和后台 Claim 均可读取。

开展一条真实长任务：主体提出问题，worker 搜索并形成媒体或文档结果；主体去做别的事；结果到达；之后选择读取与使用；已知信息进入后续回答和成长。取消、进程重启和延迟送达沿同一业务对象继续。

学习、反思、概念维护与 Dream 使用真实接触和授权低活跃机会。弱线索、拓扑与 VCP 使用统一候选接口，完成可选策略接入及一个能区分策略的真实问题；默认算法选择保持实际质量与成本判断。

## 完成独立产品与可移植性

两个 CLI 和 Console 的主要管理能力完整可用。联合界面能够创建主体、管理多文件种子、读写日历、读取任务、控制模型与费用，并查看当前原生执行。

完成 Windows/Ubuntu 无源码安装、服务启停、无头远程管理、主体迁移/分支、安装备份恢复与彻底清除。macOS 使用相同公开合同和原生平台适配，构建及实际设备检查独立列出真实结果。

补齐 Web Subject Chat 与可用的第二渠道，验证同一人物和主体跨平台连续性。语音入口使用实际 ASR/TTS provider 接入统一消息材料；三维/VR作为呈现扩展的接口和示例消费者保留，具体视觉资产由后续产品内容制作承担。

## 施工中的完成单位

每一份变更按完整能力组织：目标代码、正式入口、数据与文档、有关旧路径删除一同完成。需要跨仓库协作时先发布 Nous 当前契约/Client，再让 Hept 使用该产物；不依赖相邻未提交源码或手工打补丁的 tgz。

实现者保留普通内部编码判断权。重大语义变更在本包所属设计文档中更新决定，不能通过新增配置开关、兼容接口或恢复层隐藏分歧。尚未实现的功能在导航中直接显示其实际状态。

整个重建的终点是本文各完整能力都能从正常入口使用。某个 PR、测试套件或第一次回声仅关闭其实际完成的施工单位，剩余能力按本顺序继续。
