# 世界、日历与人物

## 世界的正式组成

World 子系统拥有世界设定、时间、场所、人物、物件、规律、日程、已实现事件与角色见闻。其内部按 `definition / clock / calendar / actors / realization / perception` 组织代码，外部通过 enter、advance、act、readCalendar 和 perceive 等完整操作使用。

| 对象 | 核心内容 |
|---|---|
| WorldDefinition | 场景背景、时间域、日历、地点、规律、创作范围和外部资料连接 |
| Place / WorldObject | 稳定身份、描述、位置、可感知属性和可执行动作 |
| Actor | 世界内身份、表现层次、设定、当前状态、已知信息与关联 EntityRef |
| ScheduleRule / Exception | 重复规律、权威来源、可调整范围、单次及未来例外 |
| PlannedEvent | 未来安排、参与者、地点、可见范围和细化程度 |
| RealizedEvent | 已走过的世界区间、实际参加者、行为、后果与原安排引用 |
| Perception | 某角色实际可见的一段内容、实际场景与时间 |

世界资料不是全部塞进一份不断覆盖的 JSON 文档。稳定设定、规则、例外、发生事件和当前状态分别存储，常用场景读取由世界模块一次组合返回。

## 世界时间由世界系统推进

Heptalogos 的 ClockMapping 保存现实锚点、世界锚点、速率与暂停状态。世界点采用正式 TimePoint，真实 timeout、费用与模型耗时仍使用机器时间。

`clock.configure` 是明确管理操作，rate 可以为零；正常世界行为不能擅自倒拨时间。暂停后保留锚点，恢复时从该点继续。更换速率记录映射版本；跨映射区间按各自版本计算。

Nous 接收事件随附的时间域与映射快照，用于组织接触、有效时间和历史查询；独立 Nous 默认现实时间，也可接受其他可信宿主的时间域。Heptalogos 的日历、状态读取和确定性推进在 Nous 暂停时继续可用。

日历采用世界的 civil calendar、时区和历元映射。首个内建是公历与 IANA 时区，使用 Temporal；其他历法作为 CalendarAdapter 内容能力接入，TimePoint 保持统一。

## 从长期设定到具体生活

世界内容按四个尺度组织：基础设定、长期轮廓、近期计划、已实现事件。远期保存主题与约束，临近时才补充具体场景。已经实现的内容形成当前世界历史，后续叙事只能在它允许的范围细化。

WorldPlanner 接收作者视角的有界场景、相关 NPC 状态和当前规律，输出未来计划或尚缺的已发生场景提案。Subject deliberation 只取得本人可见的 Perception。未来剧情、隐藏人物意图与作者草稿留在世界侧。

`world.advance(to)` 先完成到当前世界点为止的已采用动作，再展开到期规律和必要状态变化，写入已实现事件，并安排下个自然节点。确定性推进不调用模型。只有场景缺内容、NPC 重要互动或真实事件需要创作时，才安排 WorldPlanner。

读日历和历史不推进世界。世界事件的发生、计划的到期和主体感知分别保存；一门课按计划开课时可以真实发生，主体是否到场由自己的地点和活动决定。

## 日历与例外

使用 rrule 处理 RRULE、RDATE、EXDATE，Temporal 处理本地时间及夏令时。重复规则的原始本地 occurrence key 保持稳定，移动一次日程后依旧对应原 occurrence。规则有来源和生效区间；课堂、工作制度等固定规则与主体可调整的个人安排分别表达。

`calendar.change` 选择 this、future 或尚未实现范围；操作在一个事务中写规则版本/例外和新的下次节点。过去已经发生的事件保留原安排引用。节假日、考试周、调课、取消与补课作为同一规则/例外体系的内容，优先导入 iCalendar 或内容包。

`calendar.read` 支持任意有限区间、planned/lived/combined、时区、角色与活动过滤、分页。按请求区间展开，避免预先生成几年日程。FullCalendar Standard 展示日、周、月与列表，实际数据仍由世界模块读取。

同一区间中的计划冲突返回涉及的安排、可移动范围和当前选择。主体可以迟到、缺席、临时离开或拒绝参加；系统据实际地点与参与区间形成 attendance 和后果。教师或同事的回应属于世界人物互动，不通过把主体瞬移到地点解决。

## 动作、地点与后果

WorldAction 包含动作种类、目标、开始点、预计完成点与已实现范围。内建移动、参加、休息、睡眠、阅读和场景交互；每种动作由世界可供性与角色实际能力决定。

移动持续时间由路线与交通方式产生；参加活动取日程和当前场景；休息以选定时长或下个自然节点结束。网络模型调用所用秒数不直接变成世界里移动了同样的距离。

`world.act` 可以与 agency.adoptDecision 在同一事务采用。下次 advance 只实现正式时钟已走过的部分；取消或打断结束当前区间并保留已经发生的行为。地点、精神/体力积分和设备状态在该事务内同步更新。

物件通过 affordance 声明可做的动作，如打开设备、借用书本、查看公告。通用动作调度使用固定接口，具体内容放入世界包，避免为学生、工程师、艺术家各写一套世界系统。

## NPC 的三个层次

背景人物随具体事件生成，保留涉及当前生活的身份和言行。常驻人物具有稳定 Actor、简短经历与态度，可在重要互动时由模型更新。深度角色拥有独立的认知或执行实例，通过实际可见材料参与同一世界。

一个世界可以混合三种层次。升级人物时继承其稳定 Actor 与已发生的事件，建立新的计算配置；不重写既有关系历史。深度角色的 SubjectId 与主人公分别存在，共享的是世界事件。

NPC 只能读取自己的已知信息。人物之间存在误解、秘密、冲突、合作和和解，世界事实记录言行及结果，Nous Social 记录主体从中形成的认识。重要人物持续状态按事件更新，空闲时不定时对每个人调用模型。

## 现实材料与世界生活结合

真实搜索、视频、文件与通信在 TaskResult 或 Message 中保留来源。主体查看时可以在世界中表现为使用设备阅读，其 Perception 引用实际材料。世界内课堂或交往生成的内容保留 world_realized 来源。

初次入场建立当前地点、角色、可用设备、初始精力和世界时间。再次编辑 WorldProfile 只修改被选定的设定字段；已经发生的生活和当前精力通过正式操作变化，重新导入模板不会重置主体。

## 离线期间

世界配置选择暂停、确定性继续或有限补写。暂停保持时间锚点；确定性继续在重启后按规则和已采用动作推进到当前点；有限补写对有意义的缺失区间生成概述并标明来源。默认只补规则和实际已有结果，重要选择仍等待主体。

机器长时间关闭后可以读到离线世界概要及未处理事件。已发送消息、旧 Claim 和数据库记录时间原样保存。补写的世界事件采用原世界区间和新的 recordedAt，历史查询能够分别查看当时记录与后来补充。
