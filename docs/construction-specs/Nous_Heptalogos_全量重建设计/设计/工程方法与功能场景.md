# 工程方法与功能场景

## 正常开发方法

先读本次功能对应的目标文档和真实上游接口，再实现完整操作。内部模块以同一正式对象协作，SQL、路径、框架状态与解析器留在所属模块。重复出现同一业务判断时回到 owner 合并；独立变化原因保持独立。

schema 在外部输入边界校验一次，内部使用可信类型。数据库返回的领域数据由 repository 解析；同一对象经过几个纯函数时不再次全量校验。权限检查放在接纳意图和实际工具/发送边界，版本比较放在真正基于旧快照写入的位置。

直接使用语言、数据库和库已有的错误、事务、异步任务与取消机制。必要的业务错误保留具体含义；技术异常只在 API 边界翻译一次。不存在真实调用需求的 generic manager、policy registry 或 wrapper 不进入新系统。

## 验证围绕功能

开发检查分三类：编译/schema/静态依赖方向的机械检查；能覆盖真实操作的少量产品场景；脆弱算法或已知独立故障的集中用例。复用 Vitest、数据库及所选库的现成工具，不新建测试 DSL 或自定义资格框架。

一个场景中已经验证的同一字段与调用顺序，不再拆成十几个同义 mock 测试。第三方的排序、压缩、密码、队列重试等通用实现由其维护者测试，项目只验证实际接线及项目自己的语义。

测试数量和覆盖百分比不设完成目标。新增测试需要对应一个能独立失败的真实行为；旧接口消失时，其 fixtures、mock adapter 和支持脚本一并删除。失败定位后在受影响操作内修复，避免每个小修改重复运行全套。

## 重建必须贯通的场景

| 场景 | 直接操作与可观察结果 |
|---|---|
| 当前材料与长期认识 | 消息接收后立即可读；真正接受的模型回合产生接触；记忆形成后可通过语义和精确引用取回 |
| 多来源与认知纠正 | 相同材料多个接触分别保留；错误实体、开放时间、反例和来源撤回正确修订相关认识 |
| 多文件种子与分支 | 编辑两份文档和图片，预览并选择采用；导出并生成新 Subject，内部引用完整且不重发历史消息 |
| 世界生活与来信 | 世界推进、日历例外、实际移动、缺席/休息影响状态；来信可以延后处理，之后回到原活动 |
| 人物与语言成长 | 两平台资料对应同一人物；共同经历形成有范围的称呼，后续在适合的听众下使用 |
| 任务结果与追求 | 后台任务完成并保留成果；前台随后读取；期望条件根据实际资料评价，Pursuit继续或结束 |
| 表达与外部结果 | 普通表达短路径发送；重要承诺原子采用；部分接受和未知发送保留真实结果，重启不重复发送 |
| 隐私与清除 | 来源范围收紧后新上下文立即排除；清除触及索引、派生与原生历史；恢复后仍应用清除范围 |
| 独立安装与恢复 | Windows/Ubuntu无源码安装，界面关闭后继续运行；认知或渠道停机时管理可用；备份和重定位能恢复实际主体 |

这些场景可以用同一组虚构人物、世界和材料连续执行，减少大量分散 fixture。真实模型、真实渠道和纯确定性场景分别记录实际结果，未运行部分直接标记，不通过假模型替代语言质量判断。

## 需要保留的算法用例

Episode 分段保护成员与处理位置的同事务更新；时间过滤保护未知、开放区间和双截面；检索保护候选预算公平及固定融合；可选传播保护预算不串用；PCA保护权重一致；地址与语法保护稳定引用及作用域。每类集中在所属模块。

外部效果重点检查一次“平台已接收、后续反馈中断”的真实时序，因为它会造成重复发送风险。原生接触重点检查 prepare成功但回合失败、接受后交接重投两种时序。其余正常路径由完整场景覆盖。

## 文档和交付

每个能力的维护文档说明当前完整操作、状态和真实缺口。当前实现导航跟随代码更新，不保留已经失效的 Deferred 标签和旧执行计划。宪纲原文保留为目标来源，本包目标设计进入两个仓库各自的当前设计目录；两侧公共合同只保留一个编辑来源。

编码结果应清理生产代码、测试、脚本、generated glue 与当前文档的总体负担。减少测试名却新增大型验证框架不算简化；删除旧库又自己实现通用机制同样偏离目标。

交付前执行相关完整场景，核对仍未完成的功能，然后检查文档链接与新增措辞。AntiRLHF 的检查器用于发现重复防御表达，结合段落清理；原始宪纲和引用资料保持原样。检查只服务于当前交付，不额外变成长期的门禁工程。
