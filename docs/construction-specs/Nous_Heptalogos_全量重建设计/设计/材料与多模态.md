# 材料、实际接触与多模态

## 材料系统的完整职责

材料系统接纳文字、文件、网页、数据库结果、图片、音频、视频、消息片段、工具成果与世界事实。它负责保存原件、建立选区、调用解析器、关联派生来源、按消费者能力提供表示、记录实际接触与清理数据。

公开操作收敛为 `import`、`describe`、`read`、`derive`、`recordEncounter`、`remove`。上传、校验字节、原件登记、根选区建立和返回引用由 import 一次完成。大文件使用库支持的流式传输；客户端无需先创建空 Artifact，再上传，再回填元数据。

## 数据模型

| 对象 | 必需内容 | 生命周期 |
|---|---|---|
| Material | ID、Subject/资料空间、媒体类型、字节摘要、尺寸、原始文件名、存储引用、访问策略 | 原件不可变，可解除引用或清除 |
| Region | 原件/派生件引用、坐标类型与坐标、父选区 | 坐标稳定，可独立引用 |
| Representation | 输入引用、解析器/模型、输出 Material、描述或结构化类型 | 不可变派生成果 |
| Encounter | 主体、参与角色、接受事件身份、实际选区、接触深度、来源性质、五轴时间 | 不可覆盖的实际接触 |
| DerivationRequest | 所需表示、既有结果或正在执行的 job 引用 | 使用后只保留有价值成果 |

Region 支持文本范围、页与块、图片矩形、音频时段、视频时段与帧、JSON Pointer、消息树节点。坐标属于原件，分段方式变化产生新表示和选区，不改写旧引用。

原件由成熟内容寻址库 `cacache` 保存，本地磁盘为默认存储；S3 兼容存储用 AWS SDK 作为显式部署选项。业务数据库只持有存储引用、摘要和保留关系。摘要负责字节去重，业务身份使用独立 ID。

## 原件与认知内容的颗粒度

导入 PDF 或视频时，解析器可以分块以支持读取和检索。Memory、Journal 与 Self 的正文保持有意义的完整内容，不能因为 embedding 输入长度而固定切成数据库里的多个认知对象。

长认知生成一个或多个检索表示，各表示引用同一个认知修订；最终结果按认知修订合并。只返回一个选区时同时说明它属于哪份原文，后续 read 可继续展开。

## 解析和派生

文档解析使用 Docling 服务或 CLI，保留页、块、表格与图片关系。网页正文提取使用 Mozilla Readability 与 DOM 库，原网页快照同时保留。媒体探测、音视频转码、时间切片和帧提取使用 FFmpeg/ffprobe；图片缩放与缩略图使用 Sharp。语音识别与视觉理解经已配置模型供应商完成。

模型派生提供三种完整业务方式：自由描述、直接结构化、描述后结构化。选择来自该材料类型与用途的解析配置。两阶段操作保存已完成的第一阶段结果；第二阶段结构化错误只影响第二阶段。

结构化成果使用 Zod schema。每个字段可附其来源 Region；没有直接来源的推断注明形成关系。通用 JSON Schema 校验属于 SDK/库，领域检查负责这个结果能否表达实际任务。

同一输入、同一解析配置、同一模型/提示与输出结构可以复用原成果。复用键由 derive 操作内部计算，调用方只描述需要的结果。修改解析方式时生成新 Representation，旧成果继续解释历史使用。

## 图像、动图和视频

静态图片可直接进入有视觉能力的模型；同时保留可读描述，供无视觉能力消费者使用。GIF/WebP 动画读取帧时序与持续时间，按变化与任务选择关键帧，而不是只使用封面。视频保留音轨、片段、帧及时间关系，字幕和声音共同参与理解。

直接视频能力可用且成本合适时使用直接视频输入；否则由 FFmpeg 取有界片段、音频与关键帧。抽取范围和省略片段进入表示说明，模型需要更多内容时 read/derive 继续同一材料。图像识别不会静默替代原始消息中的文字、作者或顺序。

## 完整消息材料

消息是一棵有顺序的内容树。文本、@、引用、表情、贴纸、图片、语音、文件、链接卡片和合并转发各自保留节点。嵌套转发中的作者和时间属于该节点声明，实际收到该转发的人与时间属于外层接触。

Hept 通信系统先保存原始消息。Nous 在实际接触时接收选定的 MessageView 和材料引用；需要独立保管的媒体由 import 收到一次不可变副本。Hept 的协议缓存和 Nous 的主体材料有各自保留期，删除缓存不破坏已经形成的认识来源。

外部链接、短期下载地址和私密协议数据留在受信适配器。模型读到稳定材料引用或已经选定的内容，不获得任意原生文件路径、账号 token 或临时鉴权 URL。

## 当次可用与长期保存

ContextView 可以直接引用本次输入中的临时材料。材料还没形成 Memory 时，主体已经可以阅读、理解、讨论和使用它。

`recordEncounter` 在实际接受内容后创建 Encounter、经历流以及后续成长任务。上传、预览生成、预算计算、renderer 编排均不创建接触。只看到通知预览时，保存预览 Region 与接触深度；完整 read 被接受后再保存完整接触。

专业执行资料保存为 execution 类型，世界创作资料保存为 authoring 类型，主体实际查看这些结果时产生新的 subject-experience 接触。它们共用材料模型，不共用认知权限。

## 有意义的失败与继续

大文件导入失败保留可继续的上传/供应商状态，用户可以重试相同导入；没有被正式引用的临时字节按期清理。解析不可用时返回原件与未完成表示，文字部分继续可读。媒体超过本次模型预算时由调用方选择摘要、片段或推迟，记录实际选入的部分。

材料删除按引用关系处理：删除一个 Memory 不必删除其他认识仍依赖的原件；明确删除来源时停止它的继续使用并清理派生内容。完整规则见[部署、可移植性与清除](部署可移植性与清除.md)。
