# 部署、可移植性、清除与恢复

## 运行单元

Nous 服务包含领域逻辑、API、成长 worker 和嵌入式搜索连接。Heptalogos 服务包含产品领域、API、Reactor 与交付作业。OpenClaw、NapCat、数据库、解析工具和可选本地模型分别作为成熟运行依赖。

联合安装可以共用一个 PostgreSQL 实例中的 nous 与 heptalogos 两个数据库；OpenClaw 自己的数据存储由其原生安装负责。每个产品保持自己的数据库用户与私有表，跨产品只通过公开 API 协作。

默认生产运行采用 PostgreSQL 18 的受支持维护版本。连接已有数据库或安装平台维护的 PostgreSQL，是首选路径。私有便携安装收集正式二进制，调用 initdb、pg_ctl、pg_dump 等原生命令；生命周期由 OS 服务管理承担。当前 embedded-postgres 包可用于开发环境快速启动，发布包不能因为 wrapper 更新落后而绑定过期的数据库安全版本。

Node.js 24 LTS 随独立安装包或由系统提供。程序使用构建后的 ESM 与生产依赖，包含 LanceDB 等适用平台的原生包；不把原生依赖塞进自制单文件执行器。

## 目录与归属

| 逻辑目录 | 内容 | 生命周期 |
|---|---|---|
| program | 构建产物、锁定依赖、静态界面 | 产品更新替换 |
| config | bootstrap、产品导出设置、内容包配置 | 管理操作 |
| data | 正式数据库、主体资料、原生运行状态 | 备份/迁移/清除 |
| blobs | 原件、派生材料、长期成果 | 引用与保留政策 |
| workspace | 主体和任务工作目录、浏览器 profile | 活动与主体生命周期 |
| secrets | OS keyring 引用或受保护文件 | 凭据管理 |
| cache | 可重建索引、下载暂存和临时表示 | 可清理与重建 |
| logs | 技术日志、短期诊断与用量记录 | 保留策略 |
| exports / backups | 主体包和安装快照 | 操作者管理 |
| run | socket、pid 及临时连接信息 | 本次进程 |

路径由 env-paths 等成熟库按平台计算，安装设置可以明确指定数据根。内部模块拿到所属存储接口，不自行猜测全局路径。数据库中保存相对 artifact/workspace 标识，重定位时只修改根映射。

## 三个平台

Ubuntu 使用 systemd；Windows 使用 SCM/WinSW；macOS 使用 launchd。平台适配器只负责安装声明、启动、停止、状态及日志位置，复用对应工具的生命周期。普通业务状态不复制 OS 服务状态。

提供前台 `serve` 和安装后的后台服务两种入口。容器部署使用正式 Node/PostgreSQL 镜像及持久卷；无头服务器通过 HTTPS Console/CLI 管理。Windows 与 Ubuntu 的独立安装属于首批执行场景，macOS 构建与实际设备运行在同一产品合同中完成，不依赖平台专属领域逻辑。

产品启动、Subject 启用、Growth 启用和系统开机自启分别保存设置。正常模式完整运行；受限模式关闭受影响功能；维护模式暂停新主体行为并保留管理；恢复模式允许导入、数据修复和依赖重新配置。

## 停机与重新启动

停止顺序为停止接纳新的主动工作、等待当前短事务、请求原生调用和任务进入可继续状态、关闭连接。到达正常停止期限后交给 OS 结束进程，数据库与原生队列保留已提交内容。

重启读取实际 Activity、原生 run、发送回执与未完成作业。已完成成果直接复用；活动中的 run 继续观察；未知外部效果等待核实；确定性索引/清理任务由框架重试。项目不开发独立的多代进程 fencing 和恢复权威协议。

固定配置选一个活动服务实例；多台机器部署通过明确实例划分或接入同一服务。高可用集群不是当前交付的运行模式，不增加 leader election 和跨节点租约。

## 安装备份

默认提供短暂静默快照：暂停新业务采用和成长，排空短事务，确认各原生系统已经保存状态，再调用 PostgreSQL dump 与原生备份/停止后复制操作。相同静默窗口中保存两个产品的数据、blob 清单、配置和需要的原生历史。

备份文件交给 restic 负责加密、去重、远端存储和保留。安装 manifest 记录产品版本、数据库大版本、各部分位置与快照时间。密钥备份采用操作者明确选择的受保护方式，分享用主体包默认不包含这些内容。

备份结束恢复原运行设置。恢复到新安装时先恢复数据库和文件，再核实凭据/网络位置，重建可派生索引，最后显式启用主体与发送。快照中的已接受效果保留，恢复不把它们转换成新发送任务。

## 软件更新

产品更新使用发行包和包管理工具下载与安装。更新前保存安装快照；停止对应服务；替换 program；执行当前 schema migration；启动并读取核心管理状态。数据库跨大版本按 PostgreSQL 原生工具处理。

发布文件只记录实际依赖版本、入口与所需迁移。普通启动不重新扫描源码仓库、核对所有生成物或运行测试。更新失败时使用原安装快照恢复，副作用记录保留在实际原生执行与产品数据中。

开发阶段的彻底重建使用新 schema，旧系统只读导出重要主体资料及材料，通过正式导入操作进入新系统；旧表兼容、双写和旧RPC代理全部移除。已有个人资产的处理见[完整重建与施工顺序](完整重建与施工顺序.md)。

## 清除的完整操作

`cognition.remove` 区分 suppress、withdraw 和 purge。purge 接受具体对象/来源/主体范围，返回受影响认知、材料和执行历史的范围及清理进度。用户可以选择只删除某项认识，或删除来源并阻止其再次形成相同认识。

同一事务先改变当前可用状态、删除范围声明及相关依赖，并安排清理作业。所有读取、搜索最终正文和新模型上下文立即执行当前清除规则。后台清除搜索行、派生表示、blob 引用、缓存和相关原生历史。

共享原件有其他合法引用时保留字节，清除当前主体的接触及传播路径。跨产品来源删除由原 owner 产生语义删除通知，接收方在自己的事务中执行，不让通用 SQL 脚本扫描两个数据库。

原生历史清除使用官方接口重建受影响 Session；缺少安全局部删除接口时替换该 Session，并从保留的 WorkContext 重建。旧历史不再参与模型调用。备份中的清除范围按备份保留期限与清除清单处理；恢复后先应用清除清单再启用消费。

清理作业可以重复执行，同一对象引用检查与删除结果共用一个业务任务。失败显示具体未清理部位，重试不重新撤回已经完成的当前状态。

## 空间与资源管理

存储使用量按原始素材、派生、搜索索引、工作空间、日志和备份分别汇总。清理入口展示可重建内容与保留内容，普通“清缓存”只操作 cache 和无引用暂存。

大媒体处理使用流式接口，CPU 密集工具独立进程，后台并发按资源政策控制。磁盘不足时保留已经收到的状态和实际错误，延后新下载与生成；管理仍能读取空间并清理。
