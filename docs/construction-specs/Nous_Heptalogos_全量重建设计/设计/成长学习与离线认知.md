# 成长、学习与离线认知

## 成长工作的来源

成长围绕真实接触、自己的思考、实际行动结果、认知冲突与主体关注展开。消息已经收到、worker 正在工作或索引已更新，只提供各自的技术状态。成长任务读取的是实际 Encounter、采用的解释和可追踪的结果。

Growth 子系统统一组织模型参与的形成活动。它保存一份 `GrowthWork`：任务目的、来源范围、已取得模型成果、已采用变更和剩余问题。队列负责运行，领域负责写入；不再给每种领域各建一套模型执行框架。

## 工作种类与自然时机

| 工作 | 触发 | 主要输出 |
|---|---|---|
| 记忆形成 | 新经历、明确记住、当前任务需要 | 新 Memory 或修订提案 |
| 经历组织 | 活动/交往边界、晚到材料 | Episode 及组织关系 |
| 日记 | 一段生活结束、低活跃窗口 | Journal |
| 共享反思 | 新经历、结果、关系或人格问题 | 跨领域变更组 |
| 学习整理 | 阅读、练习、应用和反馈 | DomainKnowledge、Schema 与学习问题 |
| 概念维护 | 新主题、概念冲突、反复联系 | Tag、Association 和吸积调整 |
| 关联探索 | 主体兴趣或低活跃授权 | 新联系、暂定假设和整合认识 |
| 来源复核 | 来源被修订、撤回或清除 | 当前认识的保留、修订或撤回 |

时间窗口由宿主或独立 Nous 的维护配置提供。仅“到了夜间”不会强制启动全库重写。没有新来源和实际问题时任务结束。后台工作按当前费用与资源预算取得机会。

## 共享反思操作

`growth.reflect` 根据经历、人物、任务与直接依赖取得局部资料，包括已有相关 Memory、Self、Social 和 Motivation。输入是完整语义片段及 source keys，模型输出领域提案、形成原因和所用来源。

一次模型调用可以提出多领域结果。系统把临时 source keys 绑定为真实引用，再按依赖关系将变更分组。同组新对象间的引用在一次事务中解析并写入；跨领域规则由各 owner 检查。相同提案结果重放沿用稳定操作身份。

已经生成的提案先保存，再应用。模型结构错误保存原结果与具体位置；可以由同一次工作的有限修正请求重用原材料。默认只允许一次纠正结构的额外调用，后续需要新的资料或操作者处理。余额不足时保留现有成果和待处理工作。

领域修订发生冲突时，只重新理解受影响的变更组；独立组继续采用。源头材料已经消失时，提案保留为不可采用并显示缺失来源，避免从摘要反向生成不存在的原始经历。

## 学习的连续过程

学习活动具有所学主题、当前理解、实际资料、练习、结果和下一问题。Heptalogos Activity 组织阅读、搜索、练习和工具工作，Nous 组织理解的演化。

新资料首先进入当前工作上下文。主体可以提出疑问、尝试应用、发现与已有认识的冲突，再形成长期 Memory、Schema 或 DomainKnowledge。领域知识级别由实际经历支持，可以分别记录“见过”“能解释”“用过”“仍常出错”，不使用模型本身的普遍知识填满主体档案。

一次失败练习也能形成有价值经验。来源包含实际输入、采用方法、结果与主体评价；练习成功不自动升级全部领域能力。这个区分直接落在知识事项与来源范围中，不需要额外能力认证平台。

## 关联与 Dream

Dream 是低活跃时期对长期材料的有界重组与关联探索。输入由当前兴趣、未解决问题、重要经历和反复出现的概念确定，允许跨时间、人物与知识领域寻找联系。

一次探索保存 `Exploration`：问题、起点、可访问资料范围、最大候选数、费用/模型调用限额、当前假设与停止原因。候选由普通召回、图邻域或可选 VCP 生成；系统将显著的新联系提供给反思模型，形成 Association、Schema、整合 Memory 或暂定 Hypothesis。

Hypothesis 保存命题、形成材料、支持与反例、尚需观察的问题和当前采用态度。它可以帮助后续思考；是否开展真实验证行动由 Heptalogos 按行为权限决定。

默认一次探索从一个问题开始，最多两轮“寻找材料—修订假设”，达到资料或费用限额即保留结果。没有新材料或新判断时提前结束。该初值是资源政策，允许按实际任务调整；生产工作不自动生成无限候选树。

## 正常退化与资源调度

确定性经历组织与已保存成果的应用优先于新增付费反思。来源清除和权限变化立即作用于消费，后台模型工作可以延后。大批历史导入采用批量材料与索引处理，不为每条记录立即调用反思模型。

用户可暂停全部成长、只启用记忆形成，或选择 Self/Social/Motivation 的自动采用范围。配置关闭自动采用后，已有认知继续可读，新的提案可进入待处理列表。

失败处理使用 pg-boss 的标准重试与业务成果读取。确定性重试上限由任务类型设置，付费尝试只由模型执行策略增加。执行器不会因为框架重新投递同一任务而再次支付已经完成的调用。

## 可见结果

管理入口提供近期成长、实际来源、发生的变化、成本和未完成问题。开发者可以从某一人格或关系修订返回其 GrowthWork，再看到原材料与模型提案。

普通读者看到“最近形成了哪些认识、有哪些问题尚在理解”，诊断层才展开模型参数与队列状态。成长完成后只留下有继续价值的认识、来源和成果，临时选取、排序和准备数据按短期保留策略清理。
