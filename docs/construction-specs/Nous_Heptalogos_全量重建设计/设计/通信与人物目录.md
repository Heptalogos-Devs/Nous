# 通信、消息材料与人物目录

## 通信层的完整责任

通信系统保存各平台的实际消息、事件、附件、引用、历史覆盖和发送结果。它向主体提供通知与可读材料，向管理员提供连接、账号和资料管理。普通消息进入系统后先保全，是否立即阅读或回复由注意与主观过程决定。

渠道插件处理协议与平台差异，Communication 处理统一消息语义。OpenClaw 的原生 ingress/outbound 承担通用持久队列与发送机械，项目不再编写自己的 WebSocket 请求相关器、连接重试器和通用 send queue。

首个完整渠道使用 NapCatQQ 的外部进程和 node-napcat-ts 的连接/API 能力，并接入 OpenClaw 官方渠道接口。node-napcat-ts 的原始大整数与完整 envelope 暴露方式需要在接入中读取实际实现；完整无损接收统一选择 NapCat HTTP 事件入口，保留原始 body，再以 lossless-json 解析。SDK 主要承担主动接口调用，收到的数据需要原始字节时使用官方 HTTP 响应流。这样无损材料保存不依赖某个 SDK 的私有 WebSocket 字段。

其他成熟 OpenClaw 渠道优先直接使用其正式插件。现有开源 QQ 插件可以复用已完成的媒体或目标映射，接入前按本章的消息结构检查其实际支持；缺失的项目语义在一个渠道 mapper 中补全，上游协议功能优先贡献回原项目。

## 统一消息内容

Message 的身份由 channel、接收账号、会话类型、会话原生 ID、nativeMessageId 共同确定。所有原生标识符使用字符串，真实数值字段才解析为数字。

MessageContent 是有序 segment 数组：text、mention、reply、image、sticker、audio、video、file、card、share、location、forward 与 unknown。每段保留平台类型、原材料引用和必要可读表示。陌生 segment 保留原始内容及类型，不丢弃相邻文本。

Forward 保存树形节点、每节点作者声明、时间、内容次序、附件与继续读取信息。引用中的作者是转发者声称的作者，真实发送者另存。GIF 保留帧时间与实际文件，不能仅用一帧概括所有动作。

| 记录 | 所需内容 |
|---|---|
| Conversation | 平台端点、参与者、当前权限与资料快照 |
| Message | 稳定身份、作者、发送/接收时间、有序内容、生命周期 |
| PlatformEvent | 撤回、成员变化、反应等原始事件及目标 |
| Attachment | 材料引用、取得状态、格式和大小 |
| ReferenceExpansion | 引用/转发的实际展开内容、覆盖和继续位置 |
| HistoryCoverage | 原生游标、区间、完整/有限/缺口与来源 |
| ContactPosition | 当前主体/消费者实际读到的位置与细读范围 |

## 收件路径

HTTP/原生渠道接收原始事件，使用官方 ingress monitor 持久接纳。deliver 调用一次 `communication.accept`，事务中写消息、作者快照、会话次序和 Subject 唤醒任务，返回稳定 MessageRef。重复原生事件取得原记录。

原生 ingress 的 adopted 表示通信系统已经接收该事件。主体接触仍由执行适配器的实际接受回合建立。平台已接收、软件已保存、主体已看到通知、主体读过正文都具有各自的明确位置。

附件下载和引用展开按实际阅读需要取得，可以在后台预取小型元数据。下载使用成熟 HTTP client 与文件流，大小/域名/私网访问限制在渠道网络边界执行。过大内容返回可选择的预览与下载操作，不删除原始消息。

## 历史与重复接收

连接恢复时先恢复实时收件，再用平台官方历史接口补拉有限区间。历史消息进入相同 accept 操作。相同 native identity 的不同正文保留原记录和收到的后续版本/冲突事件，避免静默覆盖。

历史覆盖记录实际 provider 能提供的区间和继续游标。遇到时间缺口、权限变化或已删除内容时保留说明。重复页、同一游标或预算结束停止当前读取；不宣称任意空页都代表完整历史。

新会话的查询、附件、转发和管理列表使用同一分页方式。读取一个有限窗口不会把窗口之后的消息标为已读。

## 人物目录与资料变化

Directory 保存 Person、ExternalAccount、Group、GroupMembership、ProfileSnapshot 和 IdentityLink。Person 代表跨平台的人物，对应多个账号；WorldActor 是独立来源的实体类型。各平台姓名、昵称、头像、群名片、自述与时间保留完整来源。

自动导入新账号时先形成独立实体。跨平台归并通过明确操作者输入、可信平台身份或有来源的候选确认完成。相似名字/头像提供候选，不直接执行合并。错误绑定可以撤销并重新归属，过去消息仍保留当时作者快照及当前解释。

`directory.describePerson` 一次提供当前真实资料、账号链接和变化历史；需要主体理解时由 Nous Social 返回 PersonUnderstanding。某人隐私资料只向允许的管理者/Subject 情境展示，renderer 读取当前听众允许披露的资料。

## 读取与感知

`communication.read` 接收实际 conversation/message 引用、所需窗口、媒体层级及当前访问上下文，返回直接可用的 ReadView。选区可以是通知概要、文字窗口、完整转发或某个媒体片段。

主观过程的 readAndConsider 调用该操作，再将结果交给原生执行适配器。成功接纳后记为实际接触，并更新读取位置。查询界面、预加载和管理员查看不自动替主体写接触。

已撤回而主体尚未读过的消息显示撤回事件；主体已接触过的内容是否保留按材料保留与隐私规则处理。撤回后的状态变化可以参与后续理解，而不是覆盖原 Message 的内容历史。

## 对外动作与多入口

发送、编辑、撤回、反应、邀请和群管理通过渠道能力声明进入动作目录。已经被采用的表达和当前权限由[表达陈述与外部效果](表达陈述与外部效果.md)处理。QQ 文本使用原生 text segment，文本中的 CQ 字符不会被当成隐式指令。

Web Subject Chat 是同一通信系统的 first-party channel，采用真实管理员/用户身份。它向主体发出行为意图，系统配置操作使用管理 API。未来语音入口通过 ASR 产生带原音频来源的消息，TTS 使用已采用表达生成发送材料；两者沿相同接触和效果流程。

多个渠道服务于同一 Subject，可以分别配置观察、主动参与、回复和通知方式。新增渠道无需更改记忆、世界或 Reactor 的内部模型。
