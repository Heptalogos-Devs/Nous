# 上下文、原生执行与实际接触

## 当前可用内容与长期认知

一个模型调用需要当前输入、正在做的事、适用的长期认识和原生历史。`ContextView` 一次返回这些认知部分：必要身份、当前工作、相关人物与关系、动机、召回内容、当前材料以及继续信息。每个语义单元附真实来源引用、用途和披露范围。

当前材料可以在尚未形成 Memory 时参与推理。它们作为本次调用的 PerceptionInput 存在，引用已经取得的原件或临时表示。长期 Encounter 与成长提交依据实际接纳事件，不能在预算计算、上下文准备或调用失败之前提前成立。

`contexts.prepare` 是只读认知操作；`encounters.record` 是实际接触写入；原生执行适配器负责两者与真正运行的连接。Heptalogos 只调用 `execution.run`，不会在每个角色上重新拼装这些步骤。

## WorkContext 与 Session

WorkContext 保存 purpose、当前理解、未完成问题、结果引用、约束、下一步和相关认知锚点。它可以跨 Session 使用，可以暂停、恢复和结束。Session 只表示某个消费者的认知连续范围。

活动的目标、执行权限、运行状态和任务结果由 Heptalogos Activity 保存。WorkContext 记录其中值得提供给下一次思考的内容。暂停活动时，Activity 先保存自己的完整业务状态，并安排一次 WorkContext 更新；原操作重试沿用同一检查点身份。

原生历史由 OpenClaw 管理，WorkContext 无需再次保存整段对话。每次角色调用从当前 Activity、WorkContext 和适用认知构造输入；同一角色可复用自己的原生 Session，世界作者与主体视角使用不同 Session。

## 两种正式接入方式

独立 Nous 消费者通过 SDK 调用 `contexts.prepare`，执行自己的模型后提交实际接触与使用反馈。SDK 提供一次 `withCognition` 操作组合，接受宿主提供的真实运行结果。无模型消费者可以直接读取和记录手工采用的资料。

OpenClaw 消费者安装 Nous 的正式 context engine 插件。Heptalogos 复用这个插件，额外提供角色用途、实际情境和当前权限；不建立第二套 persona、memory 或 social 注入器。

选用 OpenClaw 2026.10.5 的公开接口。`registerContextEngine` 注册引擎，`assemble` 参与模型上下文构建，`commitTurn` 接收被原生系统接受的成功回合，`compact` 委派原生压缩。接口依据见[第三方复用与替换清单](第三方复用与替换清单.md)。

## 一个角色调用的正常路径

1. Heptalogos 从当前已采用活动生成 RoleRequest：角色、意图、实际材料、工具范围、听众、世界时间和预算。RoleRequest 的业务身份由调用方产生一次。
2. 执行适配器建立或取得对应原生 Session，使用当前角色的模型配置启动原生调用。每次 `assemble` 读取 Nous ContextView，当前未提交材料保留在本次模型输入。
3. Context engine 先给必需身份、当前输入和工具结果保留空间，再选取完整认知单元。总预算由本次实际模型窗口扣除输出、工具定义和原生历史后计算。
4. OpenClaw 执行模型及授权工具。中间工具结果归实际 run；需要下一次模型理解时重新组装适用上下文。角色切换不复制另一个角色的隐藏历史。
5. 原生系统接受终态回合后调用 `commitTurn`。以 `advancementKey` 为接触身份，原子保存该回合实际包含的输入/输出引用和交付义务。Nous 一次保存 Encounter、UseEvent 和经历流。
6. Heptalogos 使用正式 RoleResult 采用决定或保存 TaskResult。后续成长独立运行，当前回复不等待反思和索引完成。

这些步骤封装在执行适配器中。业务模块看到 RoleRequest 和 RoleResult，原生会话游标、入队字段与 handler 生命周期只在插件内部出现。

## 接受回合与失败尝试

插件声明 `currentTurnFence: before-current-turn-entry-v1` 和 `turnAdvancementIdempotency: atomic-idempotent-v1`，实现原生要求的原子 commitTurn。OpenClaw 的接受回合交接负责重试；Nous 以同一 advancementKey 去重。普通 `llm_input`、`agent_end` 和其他 observe hook 用于诊断，不能独立建立 durable 接触事实。

失败或取消的回合不因为曾经 prepare 而形成完整成功接触。已经实际发生的工具效果、已保存的成功中间结果和已发消息保留在其 owner；后续恢复可以读取这些成果，并形成相应实际接触。需要记录失败中途已读到的材料时，使用原生保留的具体已执行模型步骤，标为部分接触，不能用整份准备列表推断。

实际认知服务不可达时，原生接受回合的交接队列保留成果。新的认知依赖调用先处理已经接受的交接；普通管理、消息收件与确定性世界推进继续运行。重新连通后沿同一身份补交，无需建立 request、contact、presentation、source、ack 各自独立的恢复系统。

## 必需认知与原生降级

当前官方 context engine 在某些错误下会转到 legacy 路径。Heptalogos 的完整主体角色要求实际选择的引擎、用途和 ContextView 可用；在官方 `before_agent_run` gate 中检查当前调用绑定，缺少必需上下文时停止该调用。检查结果是本次运行条件，留在插件内部。

普通回复发送 hook 的异常策略会跳过失败 handler，所以它不承担权限边界。实际工具和发送通过[表达陈述与外部效果](表达陈述与外部效果.md)定义的正式操作及原生发送适配器授权。没有被采用的 RoleResult 不产生行为决定。

独立 Nous 的可选记忆消费者可以明确选择无认知降级运行，并收到实际降级信息。这个选择属于该消费者；Heptalogos 的主体运行不会隐式套用。

## 上下文选择与自然呈现

各领域先根据来源许可、当前时间和用途选取适用对象，再由 Context 子系统进行一次主预算选择。检索的 I/O 限制和最终模型 token 预算分别表达；避免上游按任意字节截断正文后，下游再次猜测内容。

Self/Social/Motivation 的自然描述由领域的 describe 输出。Context 只安排顺序，不重新总结一份人格。来源索引与技术元数据通过工具返回或诊断附件提供，正文保留必要的认识限定和实际情境。

固定身份与稳定规则在前，变化的当前任务和感知在后。内容变化时刷新相应语义单元。继续信息保存目标、决定和未完成工作，不重复堆放过去检查记录和代理自我解释。

## 压缩与隐私变化

原生历史只由一个压缩器维护。Nous 插件使用 `delegateCompactionToRuntime`，`ownsCompaction:false`；后台整理选择原生支持的维护方式，受影响前缀和当前尾部由原生 Session 机制管理。Nous 不再保留另一套压缩文本与重写历史协议。

隐私收紧、材料清除、主体切换或用途变化需要清理原生历史中受影响的内容。执行适配器使用官方 Session/context projection epoch 或明确的新 Session 替换旧上下文；无法安全保留时从 WorkContext 和当前授权材料重建。这个操作只影响对应消费者历史。

长任务的继续内容由 Activity/WorkContext 保存，压缩只是输入管理。模型 provider 自身的缓存通过稳定内容获得复用机会，实际 cached tokens 由 provider usage 计量。

## 子执行者与视角
