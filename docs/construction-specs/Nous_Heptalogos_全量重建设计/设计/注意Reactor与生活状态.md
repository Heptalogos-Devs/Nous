# 注意、Reactor 与生活状态

## 一条主观前台，多个后台工作

同一个主体在一个时刻只有一条主观决定链。世界推进、资料下载、工具任务、媒体解释和低优先级认知工作可以并行。前台读取结果、改变目的或决定表达；后台完成工作后把成果送回对应活动。

Reactor 是应用编排模块，使用 Attention、Life、World、Activity、Nous Context 和 OpenClaw Execution 的完整操作。它不直接访问这些系统的表，也不再扩展成拥有消息、人格、原生运行和世界状态的中央大对象。

pg-boss 使用按 Subject 的 stately 队列合并唤醒。Reaction 保存当前关注事项、当前已启动的原生 run、最近采用的决定和继续点。系统重启后先查询该 run 的真实状态，再决定继续读取成果或开始下一次选择。

## 有意义的机会

机会来自消息、世界变化、日程节点、任务成果、重要认知变化、关切及明确的自发意图。源对象在各自领域保持未处理状态；Attention 只记录考虑与消费位置，队列只负责唤醒。

一个候选包含来源引用、变更版本、轻量通知、相关人/活动、时间、紧急程度、可感知性和预计投入。通知可以是“开发群有新讨论”“朋友回复了你”“下载的视频可看了”。通知正文、完整材料与未公开后台内容分层读取。

被考虑、看见通知、阅读正文、采纳任务和作出回复各有实际含义。只有模型输入实际包含的内容进入接触记录。来源不能因为排过一次序就被标记为已经阅读。

## 个体化注意

Attention 先应用可访问性与当前物理条件，再根据情境排序。所需输入来自一份 `SituationProfile`：当前活动、精力与情绪、相关关系、愿望/关切、日程压力和对当前内容的兴趣。长期部分由 Nous 一次读取并可在相关认知变更时更新缓存。

默认将相关性、关切连接、关系重要性、时效和当前活动连续性归一化为 0..1；中断成本与预计认知投入同样归一化。初始分数采用：

`2 × 相关性 + 2 × 关切连接 + 关系重要性 + 时效 + 0.5 × 等待收益 − 1.5 × 中断成本 − 0.5 × 投入成本`。

系数是可修改的工程初值。重要安全约束、管理员明确暂停与无法访问的来源在分数之前执行。普通私聊、群聊和世界事件参与同一情境竞争，不再按固定类别永远盖过另一类。

每次选择先给各活跃来源保留候选位置，再按分数补足。等待收益饱和，已反复拒绝的同一内容降低重复打扰；新的版本或自然节点允许再考虑。没有必须处理的变化时保持当前活动，无需支付模型轮询。

最终主观模型可以选择继续、略过、等待或改变关注。候选评分决定如何控制有限输入，模型判断保留真实选择空间。行为结果提供后续偏好与中断成本修订的依据。

## 生活状态与精力

LifeState 记录体力、精神精力、情绪、当前地点、设备可用性和注意模式。真实计算并发与费用在模型资源系统，心理状态按世界生活更新。

体力与精神精力分别取 0..100。活动类型提供每世界小时的变化率；一个时间段只计主要活动和明确的附属负担，不能因多个 worker 并行重复扣减。睡眠、休息、运动、紧张交往和学习具有不同作用，数值来自世界包与主体设定。

初始示例：安静休息每小时精神 +8、体力 +4；睡眠 +12/+10；专注学习精神 −8、体力 −2。低于20时提高高投入行为的成本，低于5时触发明确的休息需要。数值按配置调整，恢复只来自已实现的时间段。

情绪保存 valence、arousal、描述、起因及时间。显著事件可以经主观评价产生有界变化，之后随生活时间缓慢回归个人基线。重大事件保留自己的叙事和记忆，数值更新不代替这些内容。情绪影响注意和表达，不直接变成某条认识的真值。

## 完整动作与较短的流转

前台动作以实际目的组织：

| 动作 | 完成范围 |
|---|---|
| consider | 查看候选和当前情境，选择是否投入 |
| readAndConsider | 打开实际目标、取得材料，并在同一交互中继续理解 |
| communicate | 按已采用意图生成自然表达，提交发送并保存继续点 |
| delegate | 建立有目标、材料、工具与结果要求的后台任务 |
| actInWorld | 采用一个移动、参与、休息或场景行为 |
| wait / pause / continue | 保存下一条件、保留或改变当前活动 |

打开页面等程序动作由系统完成；只有打开本身具有生活意义或改变可见范围时才进入主体选择。模型不需要调用“注册目标、预读状态、生成handle、确认读取、提交采用”等技术步骤。

一次 Decision 可同时表达兼容的意图，例如“把资料交给 worker 搜索，然后继续上课”，或“回复朋友并在发送完成后回到写作”。组合结构限定为明确字段与已知动作，避免新建通用工作流语言。

## 采用决定

主观模型返回目标、动作、理由、必要的表达意图、可选任务以及继续条件。原始自然理由保留在 Decision 中；结构化字段使用稳定业务引用，不让模型填写 SubjectId、数据库版本或管理权限。

`agency.adoptDecision` 在一个事务内读取当前 Reaction 和所需领域状态，检查实际目标及许可，写 Decision，调用 Life/World/Activity/Expression 的事务内方法。需要模型或网络的工作在提交后通过已有队列启动。

决定与当前状态冲突时，返回具体变化给原主观过程。已经完成的阅读材料和模型结果继续保存，只重新作出受影响的选择。普通结构解析失败允许原结果纠正一次，失败后保存问题并停止当前调用。

## 中断与恢复

来信可在安全节点打断当前思考。正在进行的外部效果不因新的候选出现而自动撤销。长 worker 在后台完成，前台可以先处理其他事项；新结果仍关联原目标。

Reaction 结束或让出前台时，Activity 保存目标、决定、已完成结果和下一条件，Nous WorkContext 接收对应认知继续信息。重启后先恢复这些业务状态，检查正在进行的原生运行和未知发送，不从旧 transcript 文本推断“应该再执行一次”。

stately 作业自动重试关闭以防重入。新作业若发现同一 Subject 的原生前台 run 仍活动，只订阅/读取该运行；终态后处理原成果。管理员取消使用原生取消 API，并保存实际取消结果。无需额外分布式 lease、takeover 或逐 token 检查点。

## 自然节点与冷却

调度仅安排最近一个实际节点：到期日程、动作结束、等待条件、合并消息窗口、任务结果或预算恢复。默认后台群消息合并窗口3秒；直接提及可在当前安全节点尽快考虑。重复通知冷却默认60秒，新的来源版本不受旧内容冷却约束。

这些初值集中在 `AttentionPolicy`，与世界时间策略及模型调用预算分别配置。选择结果显示影响当前决策的少数因素；不在每个事件上生成一份长篇解释报告。
