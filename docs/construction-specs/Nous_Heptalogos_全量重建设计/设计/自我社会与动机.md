# 自我、社会认识与动机

## 三个领域共同参与主体生活

Self、Social 和 Motivation 使用共同的认知对象、修订、来源与时间基础，各自维护内容语义和完整操作。三个领域可以分别启用；新增能力沿用同一 Subject，已有记忆和工作上下文继续存在。

共同操作为 `adopt`、`revise`、`addEvidence`、`read`、`list`、`history` 和生命周期操作。自动形成通过成长系统的跨域提案提交，人工修改从管理入口明确采用。不同入口调用相同的领域方法。

领域对外提供两种读取：完整管理读取，以及按当前用途组织的 `describe`。管理读取包含原文、来源和历史；describe 输出自然语言单元和必要引用。查询、上下文和界面复用 describe，避免在人格摘要、提示词和管理文档中分别维护三份解释。

## 自我事项与叙事

SelfFacet 表达可独立变化的一项自身认识：身份、角色、能力认识、局限、性格倾向、价值、偏好和领域知识。内容包含陈述、适用情境、采用态度、例外、认识状态与依据。

例如“我不喜欢在人多时发言”可以是倾向；“我愿意主动介绍熟悉的话题”是同一事项的条件或例外。领域操作保留这种变化，不把一次输出改成永久人格常量。

NarrativeThread 组织经历与自身理解，包含主题、解释和所引用的精确认知修订。新解释可以修订原叙事，也可以形成不同主题的叙事。来源中的 Episode、Memory 或旧 Self 正文保持各自历史。

领域知识使用 `DomainKnowledge`：主题、熟悉程度、接触过的资料、实际应用经历、已知不足及当前兴趣。知识描述通过经历和学习结果演化。worker 的广泛参数知识留在执行侧，只有主体实际读取和理解的成果参与自身知识更新。

Self 的必需身份单元与可选情境事项分开选择。上下文不足时省略完整的低相关事项，不能把限定语截掉后改变一个人的性格含义。管理员能查看某一人格变化对应的经历与采用原因，并撤回一次不合适的自动变化。

## 人物理解与事实资料

Heptalogos 的人物目录保存账号、平台资料和身份绑定事实。Nous 的 `PersonUnderstanding` 保存主体如何理解此人。它包含名字及称呼、关系背景、对方自述、观察到的习惯、兴趣、已知经历、当前问题，以及每项认识的来源、范围和不确定性。

年龄、地区、性别、职业等信息按单独 claim 保存，允许缺失、冲突和变化。平台展示的昵称、头像和群名片保留为带时间的外部资料；主体给人的评价进入 PersonUnderstanding。这样目录纠正账号归属时，相关认知可以重新解释，而无需覆盖过去的社交经历。

PersonUnderstanding 的稳定对象围绕 EntityRef 与事项键建立。资料页组合当前事实和主体认识，明确显示两类来源。一次查询“他最近在忙什么”可以直接取得适用内容，不要求先列出全部关系边再拼接画像。

## 关系与群体

SocialRelation 包含 from、to、关系类型、程度、情境、陈述和认识判断。熟悉、亲近、信任、合作、师生、群体成员与冲突分别采用合适的程度表示。关系程度与判断可信程度分开。

关系类型定义可随正式模块或内容包提供，选择 `none / ordinal / boundedScalar / typedState` 程度之一，并声明方向、对称性与必要情境。系统提供常用内建类型，安装扩展类型时使用同一校验。信任必须说明适用领域；“在数学上信任某人”和“愿意让他保管账号”分别成立。

GroupUnderstanding 保存主体对某一群体、社群或共同情境的认识，包含参与者、常见主题、气氛、互动惯例与适用范围。实际成员名册归目录，主观群体印象归 Social。虚拟人物与真实人物使用独立 issuer；同名人物通过明确链接建立关系。

关系修订围绕同一社会事项。更正错误实体归属使用专门的 `rebindSubjectMatter` 操作，记录纠正来源并更新相关索引；关系程度变化使用普通 revise。取消当前采用保留历史。

## 社会语言与自然表达

LanguageConvention 保存表达、变体、意义、指代、语用角色、来源和社会范围。可以表示绰号、梗、暗号、特定表情包、图像或语音片段的共同理解。媒介变体引用真实 MaterialRegion，文字表达作为检索入口之一。

理解入口 `social.interpretUtterance` 接收原话、实际参与者和情境，返回适用解释、原文以及仍有歧义的候选。表达入口 `social.expressionContext` 根据听众返回能使用的惯例和关系背景。两者共享对象，目的不同。

匹配由精确名称/变体、实体与范围过滤、语义候选共同完成；不再只做字符串包含。共同经历、外部人物解释和实际互动提供依据；主体重复使用自己编出的叫法只记录使用经历，不增加外部支持。

形成新的惯例时记录暂定认识，后续反例可以修订。对当前听众尚不熟悉的梗，renderer 可以不用、解释或改为普通措辞。系统传入背景和情境，避免把每条语言惯例改写成强制输出模板。

## 动机对象

Desire 表达愿望，Concern 表达持续关切，DesiredCondition 表达可以评价的期望状态。一个愿望可以暂时只有自然语言；它在形成具体目的后关联一个或多个期望条件。

对象内容包括稳定事项键、陈述、情境、时间、形成依据、长期重要程度、冲突/前置/细化关系。长期重要程度提供注意输入；当前要不要行动由 Heptalogos 决定。

例如“我想把那首歌学会”是 Desire；“朋友最近似乎情绪不好”是 Concern；“可以完整弹奏这首歌并通过自己的实际试听判断”是 DesiredCondition。它们可以因经历、反馈和新的偏好而改变。

## 期望条件与评价

条件由有限组合构成：事件见证、正式对象状态、数值测量、关系状态、语义判断，以及 ALL、ANY、NOT。组合器是小型类型结构；通用表达式解析与校验使用库，项目实现认知语义。

时间形式为 Achieve、Cease、Maintain、Avoid。评价接收精确条件修订、评价区间和实际资料，分别给出适用性、真假/未知、观察覆盖和结论状态。Maintain/Avoid 在尚未结束的窗口中返回截至当前的情况，窗口终止后再形成最终结论。

确定性 evaluator 从正式状态或真实 Measurement 读取。语义 evaluator 使用明确问题、限定材料和配置模型，保存判断与实际生产者。模型自己写“任务已完成”只是一条主体陈述；工具结果或实际试听等材料决定能评价的范围。

`motivation.evaluate` 是一个完整操作：收集适用资料，执行必要的语义判断，采用评价结果。公开参数不接受调用者任意写入 `truth=true` 或 `complete=true`。worker 完成任务后，Heptalogos 可以触发对相关条件的评价；评价结果沿跨产品通知进入对应 Pursuit。

## 与注意和成长连接

`motivation.describeSituation` 返回与人物、活动、当前时间和已知资料相关的愿望、关切、条件及其最近评价。它与 Self、Social 使用同一次情境请求，不让 Reactor 串行扫描三个领域的管理列表。

共享反思可以在同一轮提出人格变化、关系理解、语言惯例、愿望或记忆。提案声明实际依赖；相互依赖的一组在一个应用事务中提交，各领域负责内容验证。独立的提案可以分别采用，错误的目标引用返回原成果中的具体位置供修正。

人物资料、群体理解和知识更新是本次补齐的正式能力，随上下文和管理入口一起实现。禁止只新增表和 API 后把真实消费留在无期限的后续阶段。
