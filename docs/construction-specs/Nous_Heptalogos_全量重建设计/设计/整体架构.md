# 从持续主体重新组织两个产品

## 目标与结构

Nous Wave 保存主体的认识，Heptalogos 组织主体的生活与行动。两个产品共用稳定的 SubjectId，各自具有完整服务、数据、管理入口和发布包。Nous 可以独立作为认知服务使用；Heptalogos 在绑定 Nous 后获得长期认知，自己的管理、收件、世界时钟和已存生活仍由本地系统运行。

重建采用两个 TypeScript 模块化服务。Node.js 24 LTS 运行领域与应用逻辑；PostgreSQL 保存正式状态；Kysely 组织数据库操作；pg-boss 承担同库任务、延迟执行与重试。向量和全文检索交给 LanceDB 的原生库，文档与媒体处理交给既有解析工具，主体的模型、工具与子执行者交给 OpenClaw。

Rust 不再承担自有领域内核。原来的 Core—Kernel 私有 RPC、两套领域结构、重复协议转换和跨进程事务编排随旧实现删除。计算密集工作继续在成熟原生库、媒体工具及独立模型进程中执行。技术语言按维护责任选择，性能由实际耗时路径决定。

服务内部使用类型化函数调用。一个子系统拥有一组完整业务操作、私有数据访问和清楚的生命周期。子系统数量由功能决定；进程数量由部署、计算和隔离决定。新增 Memory 的一种形成行为通常只修改认知系统，新增一个通信平台通常只增加一个渠道扩展。

## Nous Wave 的系统组成

| 子系统 | 完整责任 | 对外结果 |
|---|---|---|
| 主体与初始化 | Subject、能力组合、种子采用、分支与导入 | 主体、采用结果、能力状态 |
| 材料 | 原件、选区、派生、资源快照、实际接触 | Material、Encounter、可读表示 |
| 记忆与经历 | Memory、Episode、Journal、Schema、概念与来源关系 | 有修订与时间的认知 |
| 自我 | 独立自我事项、领域知识、叙事连续性 | 当前自我及其变化 |
| 社会认识 | 人物理解、关系、群体认识、语言惯例 | 适用当前情境的社会认识 |
| 动机 | 愿望、关切、期望条件与评价 | 可解释的动机与条件状态 |
| 认知上下文 | 临时工作材料、Session、WorkContext、各调用的认知交付 | 面向当前用途的完整 ContextView |
| 召回 | NousQL、寻址、共享检索、时间查询、拓扑与结果续接 | RankedResult、来源、短引用 |
| 成长 | 形成、分段、日记、跨域反思、学习与有界探索 | 已采用认知或保留的待处理工作 |
| 资源与可移植性 | 外部知识连接、主体导出、清除与恢复 | 资源结果、主体包、清除结果 |

基础数据库、任务、模型调用与文件存储作为这些系统共同使用的库级能力。它们不引入另一套产品对象。

## Heptalogos 的系统组成

| 子系统 | 完整责任 | 对外结果 |
|---|---|---|
| 人物与渠道目录 | 平台账号、人物对应、群体、世界角色与端点 | 稳定 EntityRef 与资料来源 |
| 通信 | 完整收件、历史、通知、材料读取与发送语义 | Message、Conversation、Delivery |
| 世界 | 世界定义、角色与对象、时间、日历、发生的生活 | WorldView、Perception、CalendarView |
| 生活与注意 | 身体精力、情绪、活动投入、候选选择与中断 | 当前生活状态与注意机会 |
| 主体行动 | 单一前台、主观选择、决定采用 | Reaction、Decision、当前活动 |
| 活动与追求 | 长任务、Pursuit、进展、等待、继续与结果 | Activity、TaskResult、PursuitView |
| 表达与陈述 | 自然表达、事实细化、承诺、听众版本与陈述关系 | Expression、Claim、Commitment |
| 计算环境 | 工具权限、工作空间、浏览器、桌面与人工接管 | 可操作环境及正式成果 |
| 产品管理 | 创建、配置、运行、成本、状态、安装和恢复 | 同一 API 下的 CLI 与界面 |

OpenClaw 是执行依赖。Heptalogos 使用其官方运行、上下文、渠道和工具扩展接口；项目保存角色的业务用途与授权，OpenClaw 保存原生运行、历史和物理发送过程。项目中不复制它的队列、压缩器和会话管理器。

## 两个数据库与实际事务

每个产品有自己的数据库。联合安装可以使用同一个 PostgreSQL 实例的两个数据库，独立安装可以连接各自的 PostgreSQL。业务模块可以在本产品的一笔事务内合作，跨产品通过公开操作和持久任务交接。

例如，一次主体决定同时改变当前活动、建立工具任务并准备表达，事务中心是 Heptalogos 的 `adoptDecision`。一次人格初始化同时产生 Self、Social 与 Motivation 内容，事务中心是 Nous 的 `adoptSeed`。领域方法在这些操作内部使用同一事务；外部调用方只提交意图并取得结果。

跨产品的接触交接使用一个稳定接触身份。Heptalogos 保存已经发生的实际接纳及待交付任务，Nous 接收后保存 Encounter 和成长任务。相同身份再次交付读取原结果。认知暂时不可达时，收件与本地生活仍可保全；需要最新认知的主观调用等待交接完成或显示当前依赖故障。

## 保留的语义与移除的机械

保留 Subject、实际材料与接触、认知修订、来源、时间、世界生活、主观选择、任务、自然表达、对外承诺和效果。重建它们之间的实际关系。

移除业务调用方自行登记、准备、再次读取、重新绑定、逐段确认、重复转换和收尾的链条。一个操作内部完成这些必要工作。只有真正跨越模型计算、远端调用、用户选择或长时间等待时，才保存可继续的业务状态。

同一内容分别在 Message、Encounter 和 Memory 出现时，各自承担不同语义：平台收到的消息、主体的一次接触、主体形成的认识。相同内容在 Core DTO、Kernel DTO、owner view 和 renderer wrapper 中反复变形时，收敛为一个正式模型和一次外部协议转换。

## 设计中的取舍

选用 PostgreSQL 和一个嵌入式搜索库，保留一次异步索引交接，换取成熟的混合检索和中文分词。精确读取与正在使用的材料直接读取正式状态；普通召回说明索引时间，要求最新结果的调用可以等待指定写入进入索引。

选用 OpenClaw 官方扩展，保持认知接入和主体行动为项目代码。官方接口缺少的调用事实在运行记录中保持相应状态；安装首个真实场景时核实所选版本的完整路径，缺失接口优先向上游提交改进。运行中不修改依赖文件。

注意、记忆可访问性、世界情绪与成长策略使用明确、可调整的工程规则。规则服务于主体表现，参数允许通过真实生活轨迹改进；模型与算法的能力结论留在研究记录。

## 全功能交付

正文各篇覆盖宪纲的正式功能，包括过去缺少的人物资料、多文件种子、主体分支、多个经历轨道、个体化注意、NPC、假设探索、计算环境、统一管理和多系统部署。语音、共享世界与三维呈现保留明确的扩展合同和实现入口，实施次序单独说明。
