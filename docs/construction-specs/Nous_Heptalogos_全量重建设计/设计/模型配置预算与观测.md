# 模型、配置、预算与观测

## 分开模型资源、角色与调用参数

ModelResource 保存 provider、连接引用、模型名、支持模态、上下文窗口、工具/结构输出能力和价格信息。RoleBinding 保存一项产品工作选择的资源及备用顺序。InvocationPolicy 保存本次使用的输出上限、温度、推理参数、超时和允许工具。

配置只保存真实需要的层次：产品默认、安装、主体、角色。世界、渠道和资源模块注册自己的设置描述。一次调用取得一份已解析配置，过程中不多次读取并重新决定模型。

Nous 的形成、解释、向量化、重排和反思使用 AI SDK 的正式 provider 接口。结构输出用 `generateText + Output.object`，schema 来自领域 Zod 定义。Heptalogos 的工具循环与主体原生调用使用 OpenClaw。两个模型入口各自承担真实用途，不互相包一层再重复执行。

## 角色输入与输出

| 角色 | 主要输入 | 输出与可用工具 |
|---|---|---|
| world.planner | 作者可见场景、规则、相关人物与创作范围 | 世界提案；只开放必要只读资料能力 |
| subject.deliberation | 主体可知情境、当前活动、人格/关系/动机和材料 | Decision；完整业务动作目录 |
| subject.execution | 已采用任务、必要来源、所需成果 | TaskResult；明确授权的专业工具 |
| subject.render | 表达意图、当前听众、自然语言背景 | 文本/媒体表达；默认没有工具 |
| narrative.review | 一项重要表达与冲突/新事实/承诺资料 | 有限的语义采用判断 |
| cognition.formation/reflection | 实际经历、既有相关认识 | 有来源的领域提案 |
| material.interpretation | 实际媒体和表示策略 | 描述、结构与对应选区 |
| retrieval.embed/rerank | 检索表示或有限候选 | 向量/排序 |
| system.assistant | 管理请求与管理读取视图 | 调用授权管理 API |
| machine.assistant | 显式机器任务、安装资料及机器权限 | 操作系统/部署操作及结果 |

同一模型可以绑定多个角色。一个角色的备用模型按实际资源能力选择，不因为模型便宜就获得更多权限。renderer 的语言模型选择可独立于强推理模型，使用自身风格参数与当前社会情境。

## 配置来源与统一入口

每个设置描述 name、schema、default、scope、exposure、applyMode 和 owner。Standard 面向普通行为，Advanced 面向策略，Developer 面向技术调试；schema 和帮助来自同一注册点。

产品内设置保存在产品数据库，导出为人类可读文件。启动所需数据库连接、数据目录和密钥引用使用小型 bootstrap 配置。OpenClaw 原生模型/渠道字段通过其正式配置 API 读写，产品只保存角色引用，不再维护一份值相同的 mirror。

联合界面展示同一设置页，按 owner 调用正式操作。修改返回当前有效值、来源和生效方式：立即、下一调用、需要重启。配置一次改多字段时由对应 owner 一次验证提交；跨产品修改显示两侧实际结果，按原操作身份继续失败侧。

秘密使用 SecretRef，落到 OS keyring、受保护文件或现有密钥服务。日志、公开导出和模型上下文只保留必要引用与是否可用状态。

## 费用与调用预算

Budget 按安装、Subject 和角色限制日/月费用、并发、单次输入输出及自主工作。调用前根据当前模型价格与最大输出预留费用；调用后按实际 usage 结算。并发调用共享原子预算记录，不能每个 worker 各自读取一份旧余额。

预算账本由实际执行模型的产品拥有：Nous 记认知模型费用，Hept 记通过其角色启动的原生费用。独立安装各自管理额度；联合安装将总预算明确分为两个产品子额度，子额度合计受总额限制，时间窗口统一使用同一时区。页面汇总真实用量，调用准入只访问本产品的一处账本。

调整两个产品之间的子额度时先减少供出侧的可用额度，再增加接收侧额度；已预留部分保持占用，失败后沿同一配置操作继续。普通模型调用无需跨数据库协调预算。原生一次多步 run 预留其有限步骤和输入输出上限，追加额度仍回到同一产品预算操作。

真实价格未知时标记 unknown。允许未知价格的显式资源仍受到 token/调用次数上限；预算界面将估算与已计费分开。失败尝试与备用模型产生的实际用量全部计入。

默认普通认知流水线并发2，重型媒体并发1，Subject 专业 worker 并发2，同一 Subject 主观前台1；这些是首次安装的资源初值。费用预算在启用自主付费前由操作者设定，不内置随意的货币金额。

直接查询、收件、日历、状态与确定性世界推进不要求模型预算。可选反思、拓扑模型扩张、生成媒体与 NPC 深度互动在预算不足时延后；已经采用的任务显示其具体受阻条件。

## 调用与成果保留

Invocation 记录实际 provider/model、角色、输入来源、参数摘要、原生 run/step 引用、开始结束时间、usage 与结果位置。模型生成的可重用成果保存在业务操作中，网络库的每个内部回调不另建一份生命周期对象。

原始 provider body、完整 reasoning、HTTP header 与密钥默认不保留。明确诊断时使用 SDK 或原生系统提供的原始请求/响应记录，进入受保护短期日志。数据的实际可得范围由 provider API 决定，不能用 prepare 阶段的 prompt 冒充最终原生 wire body。

响应丢失而请求可能完成时，保留原 run 并查询原生状态。没有可核实结果的调用标记 unknown，操作者或实际新机会决定下一步。普通 provider 的短网络错误使用 SDK 的有限重试；模型结果已经保存的业务重试先复用成果。

## 延迟与资源压力

资源压力分为 normal、constrained 和 exhausted，来源为内存、磁盘、队列积压及预算状态。策略优先保留管理、事实接纳、已接受效果记录和清除操作，减少可选后台并发，再暂停新付费工作。

CPU/内存指标通过 Node/OpenTelemetry 与操作系统取得，日志使用 Pino，指标与调用链使用 OpenTelemetry。告警接入既有 webhook/通知能力。高频监控不调用 LLM。

用户看到当前主体活动、正在等的条件、可用模型、费用和具体失败；开发者可以展开 trace 看关键调用。只把跨业务操作和外部调用作为有价值 span，不为每个 getter 生成跟踪事件。

## 提示词组织

提示词按角色和任务保存 Markdown，代码只提供实际数据与少量拼装。固定角色职责、任务目标、当前情境、可用操作、输出要求依次排列。产品资料与内部运行元数据有不同区域，避免把开发说明写进主体自然输出。

模型层保持完整自然语言，不把为了证明执行过某一步的文案插入产品界面。角色指令与日常内容分离，引用材料保留来源性质。提示词修改与代码一起发布，已有付费结果保留其实际使用版本。
