## 已确认的关键接线

pg-boss 的 `fromKysely(tx)` 可把任务创建与业务写入放在同一笔数据库事务；选择该正式 adapter，模块内不单独保存一份队列 outbox。按 Subject 使用 stately 队列和 singletonKey，框架持有队列执行机械。

LanceDB 提供 Node 原生包、全文索引、向量、过滤和混合查询。FtsOptions 的 ICU 选项用于混合语言；英语 stem/stop-word 行为明确关闭。使用它替换当前共享 serving 的存储机械，领域引用和历史选择由项目负责。

OpenClaw 当前正式 context engine 提供 assemble、commitTurn、原生压缩委派和声明式宿主能力。渠道扩展位于 `openclaw/plugin-sdk/channel-outbound`，产品发送使用公开 Gateway `send` / `message.action`；旧 channel-message 的私有补丁不迁入。普通观察 hook 与正式接受回合分别使用。

AI SDK 的 Output.object 提供结构输出解析；领域在其后检查来源、身份、范围和实际修订。调用 SDK 不替代这些项目语义，也无需再实现 SDK 已有的结构化输出协议。

## 已考虑的替代方向

保留全 Rust 认知内核会继续要求两种领域模型和进程协议，其主要机械已由原生依赖承担。本次选择统一 TypeScript 领域实现，性能工作集中在真实热路径与原生库。

Mem0、Graphiti、LangMem 等适合学习形成、图和记忆策略；直接作为整个认知 owner 会改变本项目的 Subject、修订、主观认识与历史语义。本次复用其公开研究和可独立算法，正式存储由项目领域拥有。

Qdrant 可作为未来独立检索部署选项；当前选择嵌入式 LanceDB，减少默认服务和全文/向量双存储维护。Temporal/DBOS 的更大工作流系统在当前普通任务与单 Subject 前台中没有新增职责，选用 pg-boss 完成同库作业。

既有 QQ 开源插件提供了真实文本/媒体路径，完整原文、转发树、角色接触和当前 SDK 接线仍需具体比较。采用成熟协议SDK与原生渠道组件，项目只维护一处语义 mapper。协议缺陷向对应上游贡献，生产运行不热修改 node_modules。

embedded-postgres 已有18.4.0-beta.17发行信息，但 wrapper 的数据库补丁跟进具有独立周期。它用于开发便捷启动；生产和便携包选取 PostgreSQL 正式维护版本，不把 beta wrapper 作为所有安装的前置条件。

## 上游变更的处理

第三方能力的适配只放在对应系统出口：模型、检索、渠道、媒体、备份或运行环境。它负责真实外部边界的少量转换，不保留旧内部结构。

依赖更新通过正常包管理、正式版本和现有功能场景验证。需要补充通用功能时先向上游实现或采用另一个现成 provider。只有不存在合适实现的项目独有语义留在本项目。

正式来源、所查版本与链接集中在[来源与版本](../依据/来源与版本.md)。这些选择不建立每次开发都要重跑的依赖评分、证据矩阵或资格平台。
