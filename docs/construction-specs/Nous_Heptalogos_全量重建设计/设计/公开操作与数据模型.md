# 公开操作与数据模型

## 一份公开契约

每个产品在 contracts 包维护公开对象、命令与结果的 Zod schema，导出对应 TypeScript 类型。HTTP、Client、CLI、Console 与普通 MCP 消费同一契约。原生 OpenClaw 的类型由其 SDK 提供，在执行或渠道适配器处转换一次。

对外契约使用业务引用和可读视图，隐藏事务、表、连接、内部进度与缓存键。管理诊断可请求 owner 的详细视图，但不会向其他模块暴露可变内部对象。

`Ref` 表示 `issuer / kind / id`；`RevisionRef` 额外指向精确 revision。公开时间使用带 domainId 的十进制微秒字符串，现实记录时间使用 ISO UTC。模型可用 Proquint 或当前结果短引用，服务在入口绑定为正式 Ref。

列表统一接收 filter、limit、cursor，返回 items、nextCursor 和可选 coverage。普通默认 limit 30，上限100；导出、索引和批量内部处理使用独立的流式操作，不借管理列表上限遍历全库。cursor 不携带调用者可修改的 SQL 条件。

## 操作结果

普通确定性命令返回业务结果。需要长模型、导入或网络处理的命令返回 operationId 和 accepted 状态，Client 可以等待结果或订阅进度。读 operation 返回 running、waiting、completed 或 failed 及当前业务问题，内部 queue 状态不逐项投影出来。

重试幂等由原 operationId 实现。对象正文修改使用 expectedRevision；追加真实事件使用独立 eventId；普通查询无需创建回执。API 边界的错误为 invalidInput、notFound、forbidden、conflict、dependencyUnavailable、budgetExhausted 或 operationUnknown，附具体字段/目标和允许的下一操作。

SSE 提供当前操作进度和业务对象变更通知。客户端断线后重新读取正式视图；只有需要可靠跨产品交接的业务通知进入 pg-boss 持久任务。界面刷新事件不建永久消息平台。

## 私有持久结构

Nous 数据按实际查询与生命周期组织：

- `subjects / capabilities / seed_packages / seed_documents / seed_adoptions`；
- `materials / regions / representations / encounters / source_links`；
- `cognition_objects / cognition_revisions / cognition_basis / cognition_relations / cognition_aboutness`；
- `episode_members / journal_items / concept_assets`；
- `sessions / work_contexts / use_events / growth_results / condition_evaluations`；
- `resources / operations / settings / index_changes`。

共同认知表保存机械字段与领域 payload，episode成员、来源和概念连接放在可索引关系中。各领域通过自己 repository 的 typed读取管理 payload，Persistence 不解释 Self 或 Social 的业务含义。

Heptalogos 数据按实际业务组织：

- `persons / external_accounts / profile_snapshots / identity_links / groups`；
- `conversations / messages / platform_events / attachments / contact_positions`；
- `worlds / clock_mappings / actors / objects / calendar_rules / calendar_exceptions / world_events`；
- `life_states / reactions / decisions / activities / tasks / task_results / pursuits`；
- `expressions / claims / commitments / deliveries / delivery_outcomes`；
- `device_environments / operations / settings / budget_usage`。

这些名称描述目标数据职责，具体物理分表可按查询选择；没有独立变化与查询需求的辅助状态不单独建表。原生 run、发送队列和 transcript 留在 OpenClaw，搜索内部文件留在 LanceDB。

## 模块间的只读视图

一个子系统提供 readView、describe、resolveReferences 与自己需要的完整操作。应用事务组合调用其包内事务方法；一般调用只传稳定业务对象，不把 raw Kysely transaction 放入公开请求。

Context 调用领域 describe；World 调用自己的 Clock/Calendar/Actor内部组件；Reactor 调用 SituationView；Expression 调用 AudienceContext；这些视图按实际消费者定义，没有无用途的全局 SuperContext。

跨产品资料使用公开快照或稳定引用。在一次 model operation 内固定实际读取修订；普通状态面板取得最新视图。跨服务调用不持有本地数据库事务等待模型或 HTTP。

## 标准业务示例

一次“阅读朋友发来的图片并回答”只需要上层三个操作：通信接受消息；主体的 readAndConsider 取得图片并执行思考；采用决定后 expressions.create 生成并发送回答。内部的材料导入、上下文、接触、费用和回执由所属完整操作完成。

一次“修改世界中的下一周课表”调用 calendar.change，传规则、未来生效点与修改内容。世界系统保存例外、更新自然节点并返回新日历；客户端无需另调时钟、scheduler、attendance 或状态积分。

一次“把主体迁移到另一台电脑”调用 export，再由目标 import 选择继续同一身份。程序负责实际引用与材料映射，操作者只处理身份、隐私和新机器的真实授权。
