# 仓库、模块与依赖方向

## 两个代码仓库

Nous-Wave 发布认知服务、官方客户端、OpenClaw 认知扩展及可嵌入的认知管理页面。Heptalogos 发布生活与行为服务、管理客户端、OpenClaw 主体扩展及完整控制界面。长期设计文件可继续在 Architecture-Vault 整理；构建与运行只需要两个代码仓库各自的发布产物。

Nous-Wave：

```text
apps/service/                 HTTP、任务宿主、启动组合
apps/cli/                     官方认知命令
apps/console/                 独立认知管理入口
packages/nous/src/
  subject/ seed/ portability/
  material/ experience/ memory/ concept/
  self/ social/ motivation/
  recall/ context/ growth/ resource/
  application/                跨认知领域的完整业务操作
  platform/                   Kysely、pg-boss、模型SDK、blob、LanceDB适配
packages/contracts/           公开schema、值类型与操作描述
packages/client/              生成客户端与少量便捷操作
packages/openclaw/            正式ContextEngine与只读认知工具
packages/console-panels/       认知、来源、种子与修订页面
research/                     算法来源、固定语料与观察
```

Heptalogos：

```text
apps/service/                 HTTP、任务宿主、启动组合
apps/cli/                     完整产品命令
apps/console/                 主体、日历、对话、任务与管理界面
packages/heptalogos/src/
  directory/ communication/
  world/ life/ attention/ agency/
  activity/ pursuit/ expression/ device/
  management/ installation/
  application/                决定、表达、初始化与联合备份等组合操作
  platform/                   Kysely、pg-boss、原生执行与外部设施
packages/contracts/           Hept公开schema与操作描述
packages/client/              管理客户端
packages/openclaw/            主体运行绑定、渠道接入与业务工具
```

这里的领域目录是模块边界。模块内部按真实职责拆分：`model` 表达语义对象，`commands` 表达变更，`queries` 表达读取，`repository` 保存 SQL，`presentation` 输出自然文本。没有相应复杂度时可以直接合并文件。某个文件同时决定身份、权限、材料、模型、发送和恢复时，应移动责任，而非仅把文件拆成几个相互调用的片段。

## 公开面与私有面

每个领域仅公开其 `index.ts` 中的操作和只读结果。数据库行、锁、事务、缓存、队列行、native transcript 路径和供应商对象留在模块内部。包 exports 和现成依赖检查工具限制深层导入。

`application` 可以使用领域的事务内操作，这些操作只供本包组合使用。例如 `world.commands.applyAction(tx, intent)` 与 `activity.commands.applyDecision(tx, decision)` 在一次 Hept 操作中协作。HTTP、CLI、插件和其他仓库使用外部业务接口，接触不到 `tx`。

查询跨模块组合时优先取得完整只读 View，再按页面需要组合。频繁、大量的联查交给明确的查询服务，在本产品只读事务内使用各领域提供的批量查询。查询服务只读取，不凭数据行解释或修改其他领域的规则。

## 依赖方向

服务入口依赖 application 与领域公开接口；application 依赖领域；领域依赖共同值类型及本领域 repository；platform 实现数据库、任务与外部设施。领域的纯语义计算保持与 HTTP、OpenClaw、CLI 和 UI 独立。

跨仓库依赖为 `Heptalogos → @nous-wave/client / @nous-wave/contracts / @nous-wave/console-panels`。Nous 的认知服务和插件均可在没有 Heptalogos 的环境中安装。Hept 插件通过 Nous 扩展公开的绑定操作或 Nous Client 取得认知；不导入 Nous 服务源码。

供应商 SDK 只由对应 platform 或插件模块导入。更换向量服务不会改变 Memory 模型；更换 QQ 协议端不会改变 Reaction；更换表达模型不会改变 Commitment。

## 契约与生成

TypeScript 6 的严格类型和 Zod 4 是公开业务 schema 的来源。HTTP 使用 Fastify 5、`fastify-type-provider-zod` 与官方 Swagger 插件生成 OpenAPI；客户端由 `@hey-api/openapi-ts` 生成。CLI 的参数帮助来自同一操作描述，复杂命令再提供手写的人类友好入口。

每个操作描述声明名称、输入、返回、权限和是否会执行模型或外部效果。它服务于真实接口发现、CLI 帮助、UI 控件和 MCP 工具选择。业务函数直接实现规则，不再经过自制多层 dispatcher。

Zod 在外部输入、模型输出和持久数据读取边界使用。包内已取得的类型化对象直接传递。协议字段命名统一 camelCase，内部变量沿 TypeScript 习惯；数据库列映射由 Kysely 插件集中处理。消息原文、原生字段和源文档保持原样。

OpenClaw 的 TypeBox/SDK 类型留在插件边界，转换到本项目模型一次。外部 API 的 schema 以该供应商为准；项目不会手工复制整份 OpenClaw 配置 schema。

## 发布单位

认知领域和 Hept 领域各自作为一个服务器库构建，内部模块不逐个发 npm 包。只有真正被独立消费的 contracts、client、OpenClaw 扩展和 UI 面板发布独立产物。服务包带固定依赖锁与 Node 运行时，按平台构建原生依赖。

开发期间可以用 pnpm workspace 在本仓链接。跨仓使用已构建的 Nous npm tarball 或正式版本包。一次契约变化先发布 Nous 客户端产物，再更新 Hept 使用方；同一施工主题内删除旧接口及旧消费者。没有平行旧接口运行期。

## 扩展与生命周期

服务级第一方模块用 Fastify/Avvio 的注册、依赖和关闭机制组合。OpenClaw 内的插件用 OpenClaw 的注册与生命周期。配置目录登记模块提供的实际能力、操作和设置，避免另建一套微内核服务注册框架。

扩展点只出现在真实可替换处：材料解析器、资源连接器、召回策略、模型提供方、通信渠道、世界事件来源、设备提供方、管理页面。每种扩展有自己简短的合同，不共用万能插件对象。安装来自包管理器，启停、删除和授权通过管理操作进入相应宿主。

受信任的服务器扩展可作为 npm 模块装入对应服务；具有任意文件或网络能力的第三方工具通过 OpenClaw 沙箱/MCP 运行。独立进程保持自己的失败与停止边界。核心业务数据仍经正式操作访问。

## 工程目录

测试紧邻所属业务场景目录，但不进入生产导出。构建输出归 `dist/`，缓存归 `.cache/`，研究输出归 `research/results/` 并默认不提交。文档保留当前设计、真实操作与必要研究；已替换的开发计划由 Git 保存。

代码组织的完成条件是修改一项语义能够找到一个负责模块，并通过有限、明确的消费者贯通。目录整齐与文件长度只用于识别问题，不能替代这个判断。
