# 记忆、经历、日记与认知图式

## 一套修订存储，独立领域含义

Memory、Episode、Journal、CognitiveSchema、Self 和社会认识共享稳定对象与不可变修订的存储机械。各领域拥有自己的内容 schema、身份规则和操作；共用修订表不改变对象含义。

共同记录包括 objectId、Subject、family、currentRevision、可见状态；修订保存 revisionId、前一版本、完整领域内容、形成方式、认识立场、形成与记录时间。来源、依赖、aboutness 和概念连接使用关系表，常用过滤字段具有普通索引。

存储层提供批量读取、追加修订、目标版本比较和公共分页。领域读取给出完整对象，不返回让调用方重新拼装的散表。默认依赖数据库事务隔离与唯一约束，不建立另一个数据库一致性协议。

## Memory

Memory 保存一个具有身份连续性的认知事项。内容包含可读正文、可选标题、内容角色、形成方式、认识立场、涉及对象、有效时间和依据。内容角色包括具体经历、一般认识与操作经验；形成方式包括直接整理、整合与推断，两个维度分别表示。

`memory.form` 可以使用当前实际接触、已有认知或主体自己的记录意图。它先读取相关旧认识，生成新增、修订、保留或关联的提案；领域提交所选变化。已经存在的事项被更准确地理解时修订它；从“曾在甲处工作”发展到“现在在乙处工作”时保留适用时间和变化关系。

对象身份由事项内容与涉及对象决定。实体消歧、当初指错人、适用范围被纠正都通过明确的 correction 操作表达；旧实现中“aboutness 集合不相交便一律拒绝修订”的规则删除。真正不同事项新建对象，并可以关联原认识。

发生矛盾时按涉及对象、属性、情境和有效时间组织候选。现实变化、不同情境与互斥断言使用不同关系。缺少足够材料时保存多个认识及分歧。模型的采用结果可以出错，后续材料仍能修订它。

## 实际经历流

一次 `encounters.record` 在同一事务写 Encounter 和 ExperienceItem，并创建成长工作。ExperienceItem 引用实际接触，保存所属活动、会话、参与者、时间域与接触时间。它只承担可组织的经历顺序，不复制正文。

系统按实际写入顺序推进处理位置，按接触的时间域组织经历。晚到的接触仍按原接触时间进入受影响区间，已写入的系统时间保留。不同时间域的材料在有明确映射或共同任务关系时组织，日期数字本身不建立可比较性。

## 多轨道 Episode

Episode 是对经历的组织。支持三种内置轨道：interaction 组织交往，activity 组织持续活动，daily 组织一天或一个生活阶段。一个接触可处在多个轨道中；同一轨道同一层级的主要成员顺序保持清楚，子 Episode 可被上层 Episode 引用。

自动分段先用明确事件边界：参与者/会话变化、活动暂停与结束、时间域变化、长间隔、外部打断和显著情境切换。只有存在有价值的歧义时，模型重新组织一个有界邻域。默认查看受影响 Episode 及前后各一段，超出范围由下一次正常成长任务继续。

自动草稿只是同一 Episode 形成操作的内部工作数据。每批接触的成员写入、处理位置与任务完成在同一 Kysely 事务完成。不存在先更新 Runtime draft、再经 RPC 让 Memory ack 的链条。

`episodes.reorganize` 接受选定旧版本与新的成员分配。拆分、合并和层级调整保留组织谱系。原始 Encounter 始终可读；旧 Episode 的被替换状态和新的组织关系足以说明变化，不创建每个成员的修复任务。

## Journal

Journal 保存主体对一段经历的主观组织与叙事，可包含重要事件、感受、未解决的问题、关系变化和自己的解释。它引用具体 Episode 与其他认识，并标明主体解释的部分。

日记在自然结束点或低活跃窗口形成，例如当天生活结束、长活动结束或一组经历需要整理。日期按相应世界日历确定。现实与世界天并列存在时，各自的日记具有明确 timeDomain，不按机器午夜混合。

`journal.compose` 读取指定时段或经历集合、已有日记及当前相关认识，保存模型成果，再采用一份日记修订。来源改变时创建局部修订机会；已经写过的叙事保留版本。自我叙事可以引用日记，日记的正文不取代全部 Self。

## CognitiveSchema

Schema 表达可复用的规律、经验或操作方式。内容包括适用条件、主要关系或步骤、预期结果、例外、失败经验和来源。陈述性 Schema 可组织概念关系；程序性 Schema 可帮助规划和执行。

形成过程比较多个经历或既有认识，提出可复用模式。新经历可以增加支持、反例、边界条件或引起结构修订。整合没有一律“两次才创建”的规定；单次强烈经验可形成暂定 Schema，后续应用再更新。

`schema.split/merge` 为不同适用范围建立独立事项，保留来源和新旧关系。工具执行依据 Schema 时，执行权限仍由 Hept/宿主提供；Schema 内容只提供经验。

## 可访问性与遗忘

召回可访问性由相关性、经过的时间、有意义使用、当前活动和情绪/重要性标记共同影响。使用事件保存 presented、referenced、adopted、acted、outcome 等语义；重复投递同一个 eventId 只应用一次。

初始可访问性使用可读的有界特征：最近使用的对数时间衰减、累计有意义使用的饱和值、当前任务连接与显著性。策略输出排序增益，保持与硬性来源权限和删除状态分开。具体初值在[召回与 NousQL](召回与NousQL.md)给出。

低可访问内容继续存在，可被强线索或明确历史查询唤起。主动抑制阻止普通消费；撤回表示主体不再采用某项判断；彻底清除移除指定数据。管理操作分别暴露这些含义。

## 来源变化的传播

认知依赖记录指向确切修订。正文纠正时，直接依赖的整合认识进入需要复核的集合。来源彻底删除或隐私限制收紧时，当前查询和上下文立即排除相应内容，后台处理其派生材料与历史。

普通修订不递归重写整个关系图。成长任务按真实依赖取局部问题，模型判断哪些结论仍成立。频繁共用的来源查询结果在一次操作中批量读取，不逐个节点往返数据库。

## 实际使用路径

“收到一组消息并在晚间形成认识”的路径是：通信保存消息；主体接受所选内容；Nous 一次接触操作保存经历；成长任务组织 Episode；低活跃窗口形成 Journal，并提出 Memory、Schema 或其他领域的变化。查询和后续表达读取这些领域的当前版本。

这些环节各自具有用途和独立可观察结果。一个已结束的操作不需要等待所有后续认知形成才向用户返回。
