# 系统图谱

这些图表示本次重建目标。图中的事务组、引用、数据返回和执行交接具有分别定义的含义。点击SVG中的节点可打开相应设计文档；离线阅读器支持放大查看。

## 图例

| 图形或关系 | 含义 |
|---|---|
| 圆角矩形 | 提供完整能力的模块 |
| 普通矩形 | 一次业务操作或处理 |
| 折角纸张 | 业务数据、材料或只读结果 |
| 圆柱 | 正式存储或已有框架持久状态 |
| 六边形 | 第三方系统、执行依赖或外部操作者 |
| 菱形 | 图中写明条件的业务分支 |
| 椭圆 | 业务状态 |
| 虚线分组框 | 同一产品或明确的原子提交范围，组名决定含义 |
| 调用箭头（solid） | 源节点请求目标完成标注操作 |
| 数据箭头（solid） | 源节点把标注内容提供给目标 |
| 提交箭头（bold） | 在标注事务中写入正式状态 |
| 交接箭头（dashed） | 事件或持久工作使后续能力获得机会 |
| 引用箭头（dotted） | 源对象引用目标身份或资料；不表示执行 |
| 状态箭头（solid） | 标注条件成立时发生业务状态转换 |

## 图谱导航

| 图谱 | 重点 |
|---|---|
| [两个产品的能力与协作](图谱/system.md) | 模块提供完整能力；箭头表示调用、业务交接或正式数据写入。 |
| [完整业务操作与一次提交](图谱/transaction.md) | 模型计算在事务外；业务写入与后续作业在一笔 Kysely 事务提交。 |
| [当前材料到实际接触](图谱/contact.md) | prepare只组织输入；正式接受回合才推进长期接触。 |
| [经历、反思与跨域采用](图谱/growth.md) | 自动组织和模型反思共享正式来源，互相依赖的认知变更在一个事务组采用。 |
| [召回、历史与搜索投影](图谱/recall.md) | 多个检索来源在一次计划中竞争，最终正文始终由领域按当前许可读取。 |
| [世界、时间与实际生活](图谱/world.md) | 计划、发生与感知分别维护；时钟只决定目前可实现的区间。 |
| [个体化注意与单前台](图谱/attention.md) | 评分组织候选，主观模型保留继续、等待与略过的选择。 |
| [追求、后台任务与成果回流](图谱/tasks.md) | 长期目标、一次任务、原生运行与实际读取有独立生命周期。 |
| [普通表达、重要语义与实际发送](图谱/expression.md) | 普通表达省去模型审查；重要事实和承诺由其owner采用；平台效果统一交给原生队列。 |
| [身份、来源与主观认识](图谱/identity.md) | 本图的虚线引用表示数据关系，没有隐含的模型执行或自动真实性提升。 |
| [披露、当前消费与清除](图谱/privacy.md) | 当前可见性在事务中立即改变，后台完成派生与历史的物理清理。 |
| [多文件种子、主体迁移与分支](图谱/seed.md) | 编辑、预览、采用分别发生；恢复同一身份和创建分支是两个明确目的。 |
| [活动与发送的业务状态](图谱/lifecycle.md) | 椭圆是业务状态；箭头只表示标注条件触发的状态变化。 |
| [运行、管理与备份](图谱/deployment.md) | 操作系统、原生运行和产品各自管理所属状态，界面关闭不停止服务。 |
