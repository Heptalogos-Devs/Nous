# 既有实现中的附加能力与本次处置

## 记录范围

这里记录当前代码和开发分支中已经出现、宪纲未逐项规定的工程机制，以及本次重新设计对它们的处理。源码依据来自此前现状批注的固定提交；本轮重新读取远端分支后，记录的 HEAD 保持一致。完整来源归档见[此前现状批注与图谱](此前现状批注与图谱.zip)。

这些项目先作为实现事实登记，再按当前目标选择。表中的“移除”指新架构不再承担对应旧机械；真实用户数据、原始素材和付费成果按正式导入流程保留。

| 当前已有内容 | 与宪纲的关系 | 新设计的处理 |
|---|---|---|
| Rust Kernel 与 TypeScript Core 的私有服务群 | 历史物理架构选择 | 领域统一 TypeScript；库级原生计算保留；私有 RPC 与重复 DTO 删除 |
| Subject authority sequence、object epoch、expected head 与多层 digest | 解决并发和重试的旧实现细节 | 公开变更只用 operationId 与必要 expectedRevision；索引变更身份留在搜索内部 |
| Material 提前写 Observation，再进行预算和原生 admitted | 实际接触的旧执行顺序，已有错误 | 当前材料只读准备；正式接受回合后写接触 |
| Runtime Episode draft → Memory 提交 → ack 的分段交接 | 旧 owner 分裂形成的机械 | 分段写入和处理位置归同一完整 Episode 操作 |
| 每类领域一套 mutation/helper/transport/结果转换 | 当前模块形状 | 公共修订机械统一；领域保留自己的语义与公开业务操作 |
| Memory aboutness 不相交便拒绝修订 | 旧身份判定策略 | 新增明确的身份/指向纠正操作；普通不同事项仍创建新对象 |
| source root/用途/受众的大量逐调用绑定字段 | 对隐私与真实视角的细化 | 保留语义，收回一次 AccessContext 与领域源读取；调用方不拼装 proof 字段 |
| Core 自己再次改写 Self/Social 的上下文 | 原来的展示结构；Draft开始统一 | describe 由领域唯一维护，Context安排完整语义单元 |
| 所有 provider 最终 body、attempt 与输入快照长期保管 | 宪纲要求用量和可观察性，未要求每次完整wire归档 | 常规保存 provider/model/usage/成果引用；原始body仅为受保护的可选诊断 |
| 固定 OpenClaw 2026.9.1 包、补丁 manifest 与安装 custody | 特定旧原生接线的实现 | 使用当前正式 plugin/context/channel API和包管理；不再修改依赖文件 |
| ContextCompiler 的自有 APPEND/RESET 与原生历史适配 | 原来的传递协议 | ContextView 输出当前语义，原生 Session/epoch/compaction承担历史；保留真实隐私重建 |
| 双队列、DBOS、Host takeover 与多代 fencing | 旧可靠运行设施 | pg-boss业务作业、OpenClaw执行、OS服务各有一处责任；删除重复运行体系 |
| 只有 important/direct/background 的注意竞争 | 当前可用确定性策略 | SituationProfile、个体相关性和中断投入参与统一选择 |
| 普通表达的候选/brief/review/custody多段恢复 | 当前表达实现，Draft已尝试缩短 | 一个Expression及其实际原生交付关联；重要事实/承诺保留专门语义采用 |
| calendar moment 的 semanticAdoptedAt/semanticSentAt 占位 | 开发分支已有聚合读取，相关世界时间未接全 | Decision和Expression的采用/发送记录真实TimePoint，CalendarView只读取组合 |
| 受控 SDK 封装包与大量版本资格检查 | 当前开发/安装方式 | 采用正常构建包与锁文件；一次正常功能检查替代运行时源码资格核对 |
| Ready-only CI、扫描门禁、测试数量与整套资格档案 | 历史工程流程 | 保留正常编译和功能场景，移除无当前责任的门禁、重复mock和生成报告 |
| 原表迁移与旧记录长期兼容 | 历史数据处理方式 | 重要实际资产转换为公开主体包一次导入；新服务不带旧读写路径 |

## 进入新目标的实现价值

真实身份、材料与接触分离、不可变认知修订、用途/视角、世界与现实双时间、未读后台结果、逐部分发送结果、费用、来源与恢复目的都继续保留。它们已经在宪纲中具有产品含义，新的表示按相应设计文档重建。

当前保留的 VCP 数值参考、Proquint 向量、媒体映射、真实故障输入与有价值的完整场景可以迁到新 owner 或研究目录。旧目录、旧测试形式和过长的事务脚手架不随这些内容自动保留。

## 后续遇到的附加能力

实现者发现本表和宪纲都没有说明的真实行为时，先记录其用途、当前消费者及数据后果，再在所属设计决定保留、替换或删除。不要让一个隐藏旧字段或测试断言成为新的全局产品要求。
