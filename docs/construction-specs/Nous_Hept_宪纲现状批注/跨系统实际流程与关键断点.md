# 跨系统实际流程与关键断点

本章将分散在两个仓库中的实现按一件事情从产生到被消费的顺序串起来。源码链接在[实现索引](源码与实现索引.md)，每段流程对应[有向图谱](系统图谱总览.md)及逐箭头记录。所有状态均指 2026 年 10 月 19 日固定源码中的实现；Draft 变化另行标注。

## 一、收到一条 QQ 消息

QQ 原生渠道从 OneBot 收到平台事件。`parser.ts` 将消息分割为有序的 text、at、reply、forward、image、record、video、sticker、card 等部分，未取得的媒体先留下引用和待获取状态。`Messaging.accept` 以平台、接收账号、会话和原生消息 ID 构造稳定接纳身份，在一个事务中保存 `MessageFact`、会话序列、附件/转发节点和 pending。历史补拉与实时收件使用同一入口；历史范围保存为 `limited/gap/unavailable/complete`，不会因为读到空页就清空缺口。

`Attention` 从 Messaging 查询**通知元信息**。直接私聊、@、回复和背景聊天经分类、合并和来源公平选择候选。此时只是有新消息，`Subject` 仍未阅读消息正文。`Reactor` 取得当前前台资格，`subject.deliberation` 先看到 `SituationFrame`，可以选择 `inspect`、`open`、`read`、等待或继续其他工作。若选择 `read`，Host 的 `activity-dispatch` 才按当前 Activity 允许的会话与消息引用准备实际材料，随后将 contacts 提供给下一次原生模型调用。

Nous 集成的 `prepareModelInput` 在一个独立的调用步骤中同步 Session 和 WorkContext、接纳 contacts、准备媒体、计算 Token 预算、准备 Projection、生成实际原生输入并通知 Host `admitted`。这里有已确认的顺序问题：contacts 对应的 Observation/Experience 在预算和最终 `admitted` 完成前已提交；后续输入准备失败，会让长期认知系统看到一次尚未成立的接触。精确位置见[真实模型输入时序图](图谱/09-native-input.md)。

成功准备后，主体模型才在实际内容基础上重新做出选择。若决定表达，由 `DecisionCommit` 指定意图和听众范围；自然表达、采用、发送和回执走独立的后续路径。消息进入、被选作通知、被打开、进入模型输入、主体形成认知和对外发送都对应不同阶段。

## 二、世界时间如何成为生活经历

Nous `CognitiveClock` 拥有主体当前时间域、世界时间与现实运行时刻的映射。Hept `WorldProfile` 保存地点、规则、起点、人物映射和精力参数；`WorldLife` 保存日历定义、已采用安排与已经实现的事件。日历查询可以按 `planned/lived/combined` 与相应视角读取。`world.planner` 获得有界的作者视图，主体的 `subject.deliberation` 获得筛选后的当前见闻。

固定规律由普通程序在当前世界时间之内分段实现；需要选择的生活事件交给规划与主观决定。动作方面，`move`、`participate`、`rest` 先被采用，`completeActions` 只结算时间确实走过的部分。精力积分依据已经实现的生活区间和当前政策计算，未发生的计划不计入实际生活。

一个可供主体感知的世界事件先处于可选 contact 阶段；Host 选择本轮可公开的观察，在真实原生接纳完成后调用 `acknowledgeContact` 将其标成已交付。`WorldRealized` 来源可以随后成为 Nous 的 Observation、Episode、Journal 及 Memory 依据。世界内部尚未交给角色的作者信息留在作者侧，不因发生了世界事件就自动成为角色知识。

Hept 开发分支新增 `calendar-moment.ts`，尝试把事件、主观决定、模型输入和已发送内容合成日历时刻。但该视图的 `semanticAdoptedAt` 和 `semanticSentAt` 目前固定为 `null`，因而事件的世界发生点、决定的世界时间和话语真正发送时的世界语义尚未全部串成完整时间线。该处与真实生活历史的表达需求相关，见[世界时间图](图谱/14-world-time.md)。

## 三、一次认知形成和一次认知查询

Material 保存 Artifact、ObservationOccurrence、SourceRegion 和派生 DAG。带 Session 的实际观察在同一事务创建 `ExperienceItem`，同时可将引用放进 `ResidentSet`。随后 Runtime 根据游标和分段政策将 Interaction feed 写入 Episode 草稿；Memory owner 持有 Episode revision、Journal、Memory、CognitiveSchema、Tag 与关联证据。共享反思与维护可以读取当前来源和既有认知，在事务外调用配置的模型，先保存付费成果，再将建议分发给所属领域的正式 mutation，生成 revision、失效依赖并要求 Serving 更新。

Episode 自动分段的普通草稿推进存在一处具体错误：更新 SQL 使用四个占位符，却绑定五个参数，影响分段完成。这个错误位于 `crates/runtime/src/segmentation.rs` 第 112–113 行，在当前 master 和 Draft 中均存在；自动 Journal 以及后续认知形成会受到由此产生的分段输入缺口影响。详见[认知形成链图](图谱/03-cognition-growth.md)。

查询从 NousQL 自然语言及结构化语法岛进入 Core。Runtime 绑定 Subject、来源权限、CognitiveClock、精确引用、启用 lane 和候选预算；Retrieval 提供 lexical/dense 及按配置启用的拓扑 lane，Runtime 进行统一排序后，将候选分派给 Material/Memory/Self/Social/Motivation 等具体 owner。领域重新检查当前对象、源读取许可、时间与生命周期后生成最终命中。正式 `UseEvent` 另有稳定事件身份，查询命中本身不会直接写入意义使用。

目前检索已有 Tantivy、USearch、QueryPlan、最终领域重验、可重建 Serving 与历史视图。VCP/EPA/Residual/Wave 已作为可选实验 lane 存在，大样本弱线索召回与长期生活语料上的增益仍待单独测量。该机制应在后续研究中与普通 lexical/dense 和简化图扩展比较，不能提前把某个算法的存在当成整个认知能力的质量结果。[查询图](图谱/11-query.md)展示了当前真实分层。

## 四、后台专业任务与当前主体

`subject.deliberation` 选择 `search` 或其他专业执行行为后，`DecisionCommit` 保存任务目标、真实来源引用和工具授权，`roles.startExecution` 向原生 `subject.execution` 派发专业任务。子执行者、浏览器和工具归 OpenClaw 原生循环；Host 管理任务的 adopted scope、角色与原生运行身份。任务的输入、调用、产生的材料和终态保存在各自执行记录中。

专业任务完成后首先产生 `readyResults` 候选。Attention 将“有结果可查看”作为后续机会送进 Reactor。主体实际选择 `read` 时，Host 调用 `releaseResult` 选择本次可交给主体的原结果，并转换为下一模型输入的 contacts；此处沿用前述 Observation/admitted 机制。Hept Draft 正在扩展保留原运行、重试前先恢复候选和继续原任务的操作。

这一链路已经明确区分后台有成果、主体获知成果及主体是否愿意对外使用。尚未完成的实际场景包括浏览器结果交付和原始 GIF 回复。完整的任务回退、受保护资料观看和跨日继续，要基于当前真实交付路径完成，而无需复制专业代理内部的全部历史到认知 Authority。[后台任务图](图谱/13-worker.md)给出已有调用与待继续边界。

## 五、一次对外表达及其后果

主体先形成 `DecisionCommit`，可能同时提供 `expressionIntent`。独立 renderer 读取冻结的 `ExpressionBrief`，根据其实际听众、来源、认识立场和世界细节产生原文。开发分支将普通表达、重要世界事实、严肃承诺和存在重大冲突的表达分成不同路径：普通表达允许先形成发送义务、随后索引 Claim；新世界事实和严肃承诺先完成对应语义准备；重要冲突再经过独立的 `narrative.review`。`retainedCandidate` 保存尚未消耗的原文，后续主体可以采用原稿或放弃。

采用表达后，`Narrative` 与 `Agency` 共同保留实际发送 payload 和来源。原生持久发送队列仅提交已经得到 Host custody 授权的物理 part。QQ 发送适配器在平台提交前重新核对账号、群组/私聊权限、媒体和 presence。平台返回有用消息 ID 时记录 `accepted`，确定失败时记录 `failed/not_sent`，实际已发但结果未知时记录 `uncertain` 并保留原尝试；反馈最终关联到 `Claim` 的实际发送状态。

Claim 应区分“已经采用的说法”和“对方可见的实际表达”。`pendingCommitments`、以后对同一听众的表述，继续读取当前有效的来源与发送记录。当前开发分支仍有整条链路未完成的安装实测与恢复场景。[表达及物理发送图](图谱/05-expression.md)按语义分支绘制，不将所有表达强行放进一个审查路径。

## 六、持续状态怎样分开保存

Nous 的 `Session`、`ResidentSet` 与 `WorkContext` 保存当前认知工作集及其跨会话检查点；原生 OpenClaw 历史保留模型消息、工具调用和自身的固定前缀。`ContextCompiler` 以相同片段前缀决定 `APPEND` 或 `RESET`，并按实际 Subject、Session、consumer 与用途标识上下文轨迹。内容来源由各认知领域持有，模型输入是一次有预算的 Projection。

Hept 侧有另一组持续状态：`LifeActivity` 保存已经采用的工作和下个节点，`SubjectReaction` 保存单次前台、实际运行与动作回执，`Narrative` 保存本次表达，`Pursuit` 保存长期目标与条件评估的引用。两侧通过共同 Subject 和精确来源、模型准备及结果反馈连接。跨仓库运行没有全局事务，因此各侧保留已提交事件与可重放身份。

需要继续完成的是主体状态在整个时间轴上的一致性：世界事件的出现与角色实际知情、付费模型调用的真实提交与恢复、表达与 Claim 的世界时间，以及跨安装保存与恢复的实际闭包。[上下文图](图谱/04-context-history.md)、[生命周期图](图谱/08-mutation-lifecycle.md)和[身份图](图谱/06-identity.md)分别说明其当前运行结构。
