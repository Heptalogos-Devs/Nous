# 系统与流程图谱

## 图例与阅读

本文件是图谱的唯一维护源，使用 Mermaid。矩形表示模块、资料或一个操作，圆角节点表示一个完整工作过程，菱形表示有明确条件的分支，圆柱表示持久存储。流程图的实线箭头表示所标注的调用、提交或内容传递，虚线表示模块依赖、资料引用、观测或配置关联；时序图的实线表示请求，虚线表示返回结果。子图表示实际产品或执行边界。箭头上的文字是关系含义，位置和颜色不编码业务状态。

图中 `prepare/accept` 指正式上下文与实际接触操作；DBOS 指其现成执行机械。图谱与正文中的正式对象相同，图中的分组不新增服务、数据库或协议。

## 收件、选择阅读与认知形成

```mermaid
flowchart TD
  E[平台原始事件] -->|宿主事件转换并保留原文| R(接收完整消息)
  R -->|保存版本与来源身份| DB[(Message / parts)]
  R -->|需立即保全的地址或临时文件| B(取得原始字节)
  B -->|写入实际原件| BS[(BlobStore)]
  R -->|设备允许的通知| N[注意候选]
  N -->|活动与关系排序| D{主体决定查看}
  D -->|等待或忽略| WAIT[保留决定与回看时刻]
  D -->|扫视或阅读范围| READ(取得选定内容)
  BS -->|本次需要解释的区域| READ
  DB -->|选定分段或转发层级| READ
  READ -->|当前材料与区域引用| CP(准备本次模型上下文)
  CP -->|实际模型输入| LLM(完成模型步骤)
  LLM -->|成功结果与实际输入视图| AC(接受真实接触)
  AC -->|主体消费者| EX[(ExperienceItem)]
  EX -->|有意义的新材料与反馈| G(共享成长)
  G -->|采用关联修订组| K[(Memory / Self / Social / Motivation)]
  K -->|后续查询与准备| CP
```

保全原件与实际阅读走不同分支。worker 或 author 接触留在其工作资料，进入主体经历的分支由受信消费者身份决定。见[材料消息](设计/材料消息与来源.md)与[成长](设计/成长与认知维护.md#成长入口)。

## 业务事务与后续工作

```mermaid
sequenceDiagram
  participant Client as 入口或上游工作
  participant WF as DBOS 业务工作流
  participant Owner as 所属业务操作
  participant PG as 产品数据库
  participant Child as 后续工作
  Client->>WF: 稳定请求身份与完整业务输入
  WF->>Owner: 执行本地采用
  Owner->>PG: BEGIN：写正式对象
  Owner->>PG: 同事务写 datasource 检查点
  PG-->>Owner: COMMIT
  Owner-->>WF: 已提交对象引用
  WF->>Child: 启动索引、成长或外部交接
  Child-->>WF: 已接受的工作身份
  WF-->>Client: 业务结果或 OperationRef
  Note over WF,PG: 中断后从现成检查点继续
  Note over Owner,Child: 后续入队发生在事务之后，由父工作流继续
```

这里没有跨产品事务，也没有额外 outbox 队列。变更导航按实际对象事务保存，用于消费者读取当前修订。见[事务与并发](设计/契约与数据事务.md#dbos-的使用范围)。

## 每次模型调用与接触责任

```mermaid
flowchart TD
  NEXT[首轮 / 工具后续 / 模型切换 / 子代理 / 压缩后] -->|实际模型与当前材料| PREP(受信 contexts.prepare)
  PREP -->|权限、相关内容与预算| VALID{准备成功}
  VALID -->|失败| HOLD[保留工作并显示原因]
  VALID -->|成功| CALL(官方持久模型或原生模型调用)
  CALL -->|成功且已保存的输出| ACCEPT(等待 encounters.accept)
  CALL -->|已派发但结果未知| UNKNOWN[查询原请求或明确重新调用]
  ACCEPT -->|subject| SUBJECT[主体经历与使用反馈]
  ACCEPT -->|worker| WORK[工作过程与待查看成果]
  ACCEPT -->|author| AUTHOR[作者资料与世界生成依据]
  ACCEPT -->|接触交接完成| NEXTSTEP[工具执行或采用本次结果]
  NEXTSTEP -->|还需模型理解| NEXT
  HOLD -->|修正输入或恢复依赖| PREP
  WORK -->|主体后来实际读取| PREP
```

AI SDK 路径使用正式 middleware 与 DBOS 检查点；原生路径在 OpenClaw 所属调用边界增加公共扩展合同。中途失败保留此前完成步骤。见[模型接线](设计/上下文模型与原生执行.md#ai-sdk-与-dbos-接线)。

## 世界推进、自发机会与全局注意

```mermaid
flowchart TD
  CLOCK[现实时间与世界映射] -->|到达最近自然节点| ADV(推进已发生生活)
  EXT[消息 / 人物 / 任务结果] -->|新外部变化| ADV
  ADV -->|活动结束、日程、自由窗口| O[机会集合]
  MOT[愿望 / 追求 / 承诺] -->|既定复查或期限| O
  DEV[可用设备与通道] -->|决定可感知范围| VIEW[当前局部情境]
  O -->|少量候选与真实责任| VIEW
  STATE[精力 / 心境 / 中断代价] -->|个体化注意参数| VIEW
  VIEW -->|准备认知并审议| DEC(主观决定)
  DEC -->|阅读、参与或委派| DO[正式动作]
  DEC -->|休息、等待或忽略| KEEP[保存选择]
  DO -->|实际结果| ADV
  DO -->|活动与下一考虑时间| NODE[(最近自然节点)]
  KEEP -->|回看时刻或自由窗口| NODE
  NODE -->|DBOS 独立等待工作| CLOCK
```

没有消息时，自由窗口仍能产生机会；等待节点不占据主体前台。见[自主性](设计/注意自主性与主观执行.md#机会来源)与[世界节点](设计/世界日历与生活实现.md#下一自然节点)。

## 表达、重要采用与实际发送

```mermaid
flowchart TD
  DEC[已采用主体决定] -->|听众与可披露意图| INT[ExpressionIntent]
  PRIVATE[内部理由与私密来源] -.->|只影响内部判断| DEC
  INT -->|角色与关系语言| RENDER(自然表达)
  RENDER -->|正文与可选重要变化| KIND{需要新增重要语义}
  KIND -->|普通表达| SEND(渠道发送)
  KIND -->|生活细节或承诺| ADOPT(相应 owner 采用)
  ADOPT -->|已协调的具体部分| SEND
  SEND -->|每次真实平台调用| RESULT{物理回执}
  RESULT -->|accepted| OK[交往事实与承诺传达]
  RESULT -->|not_sent| FAIL[失败部分及明确重试动作]
  RESULT -->|unknown| UNK[保留未知并查询外部结果]
  OK -->|回应、更正、履约| HISTORY[(交往与责任历史)]
  HISTORY -->|有意义反馈| G[共享成长]
```

private 节点没有通往 renderer 的内容传递箭头。内部理由和对外意图是不同输入。见[意图与表达](设计/追求任务承诺与表达.md#表达意图与自然语言)及[权限](设计/身份时间与权限.md#来源用途与受众)。

## 知识形成与历史截面

```mermaid
flowchart LR
  E[周一发生的资料] -->|主体周一阅读| CONTACT[observed：周一]
  CONTACT -->|当时仅有粗略理解| R1[(修订一 formed：周一)]
  CONTACT -->|周三再次思考| THINK[周三形成新解释]
  THINK -->|来源仍指周一材料| R2[(修订二 formed：周三)]
  R1 -->|周二 knowledgeAt| Q2[返回周二已有认识]
  R2 -->|周三之后 knowledgeAt| Q3[可返回新解释]
  DB[现实 recorded 时间] -->|recordedAsOf 另外过滤| Q2
  DB -->|recordedAsOf 另外过滤| Q3
  POLICY[当前访问策略] -->|限制本次可见内容| Q2
  POLICY -->|限制本次可见内容| Q3
```

valid 说明认识适用的时间，不把后来形成的结论提前写进知情截面。见[两种历史视图](设计/身份时间与权限.md#两种历史视图)。

## 配置、运行与清除

```mermaid
flowchart TD
  SCHEMA[模块 Zod 定义与元信息] -->|生成可读设置与表单| UI[CLI / Console]
  UI -->|稀疏覆盖与明确范围| SAVE(配置事务)
  SAVE -->|提交修订后通知| OWNER[所属运行模块]
  OWNER -->|立即 / 下次调用 / 重启| LIVE[显示实际生效值]
  OWNER -->|新的实际调用| CTX[当前权限与上下文]
  PURGE[正式清除请求] -->|立即限制读取与传播| CTX
  PURGE -->|定位有来源的资料与执行| REMOVE(所属模块清除)
  REMOVE -->|正式删除入口| STORE[(原件 / 索引 / 原生历史 / 检查点)]
  REMOVE -->|forget / prune 或存储删除| BACKUP[(备份范围)]
  REMOVE -->|保留最新删除范围| MAN[恢复前应用的删除清单]
  RESTORE[旧快照恢复] -->|先应用当前删除清单| MAN
  RESTORE -->|暂停未确定外部工作| EFFECT[逐项核对实际效果]
```

配置与清除分别由实际 owner 完成；界面读取已保存值及真实运行状态。见[配置生效](设计/配置模型资源与预算.md#保存生效与历史)及[清除](设计/部署更新导出与清除.md#限制遗忘与物理清除)。
