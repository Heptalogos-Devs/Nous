# 施工顺序

## 起点与工作方式

两个仓库从空数据和新的目录组织开始。保留 Git 历史供查询，当前工作树按新结构替换。项目宪纲原文保留；AGENTS、Spec、README、命令和示例统一到本包。旧数据库、配置、接口与部署脚本没有迁移目标。

先读取架构、契约和本节，再按当前功能阅读相关领域。第三方源码可拉到开发机器供直接采用或改编。每个施工单元完成一条可以运行的正常链，相关旧结构同时删除。当前 Objective、已定 Decisions 和正在进行的功能在工作记录中保持清楚，不新增审批或证明流程。

## 本地收件、召回与回复

建立两个可嵌入应用入口和最小 HTTP/CLI；使用 Node 24、TS 7、PostgreSQL、Kysely、DBOS 和官方 AI SDK 集成。只建立本单元实际消费的模块。

Nous 实现 Subject、Material、Encounter、Memory 的直接创建与读取、LanceDB 中文全文和基础向量查询；Hept 实现同一 SubjectId、本地会话、完整消息 parts、简单 Situation、主观选择和自然表达。一个主体可在 Hept 创建，向 Nous 绑定后使用同一身份。

从 CLI 或本地 Web 提交一条消息，Nous 查询既有认识，主体产生回复，本地会话保存实际消息 ID，成功模型步骤产生实际接触。一个小型成长操作从这次经历形成可再次查询的认识。

从这里就使用正式 schema、来源时间、权限身份、配置读取、traceId、费用记录和 operationId。首条链只需要少量设置，不要求先完成全部设置页面、QQ、原生工具和平台发行包。

运行同一示例，在第二次交往中召回前次认识。观察实际代码调用和用户结果，修正正式输入输出后继续。

## 完整认知对象与自然查询

补全共享对象/修订/来源关系，加入 Episode、Journal、Schema、Concept、Self、Social、Motivation 与语言惯例。实现多文件种子预览和跨领域采用，空种子主体也可工作。

完成 NousQL、五种时间、历史截点、实体与概念过滤、排序、多跳与残差探索、来源展开和索引重建。用同一批真实材料覆盖中文长句、同名人物、独立来源、修订与后来理解。

实现 WorkContext 和共享成长，把新经历、纠正、关系变化、学习与愿望评价接到已有实际调用。先贯通采用与查询，再加入后台整理和可选假设探索。Nous 的独立 memory-only 与完整认知均通过 CLI/API 使用。

## 持续生活与无外部消息的自主性

实现世界包、时钟、日历、实际生活事件、地点与基础人物。接入 Temporal 和 rrule-temporal，给示例主体完整课表、休息和自由窗口。

实现 Activity 通道需求、设备、中断与恢复、精力和心境；Reactor 统一所有机会并通过 DBOS 主体分区串行。加入自由时间、追求、关切和承诺的自主机会与持久 nextNode。

运行“正在上课收到消息”“散步听歌”“没有消息仍安排学习”“睡眠后继续生活”四种情境，可以共用一个示例世界和一条连续生活轨迹。确定性时间推进与模型选择在实际调用中分开。

## 专业执行与认知接入

安装选定 OpenClaw 基线，先通过现成接口完成一个专业 Task：浏览或读取资料，保存 run、进度和可读成果，主体随后选择查看。任务运行期间，主体继续自己的生活。

随后在 OpenClaw 源码责任位置实现逐模型调用 prepare/accept 扩展。采用本包已确定的输入、调用时机和失败行为，保持原生压缩与历史。Nous 插件与 Hept worker 共用它。缺少字段时直接修改该正式合同和消费者，删除重复拦截与二次输入重写。

接入练习覆盖首轮、工具后续、模型切换、子代理、压缩和一次中途准备失败。以实际模型输入、接触和已有结果的继续为观察对象。维护助手随后复用原生执行器，但使用独立身份和管理工具。

## 真实通信与言行连续性

部署 AstrBot 及 NapCat，完成插件的入站停止默认聊天、完整消息接收、临时媒体先保全和平台目录更新。复用上游发送实现，返回每个实际平台调用结果。

在同一 QQ 场景中使用文本、图片、语音、文件、嵌套转发、引用、编辑/撤回与部分发送失败。资料解析按需运行。Hept 全局注意决定查看与参加，平台宿主不再运行另一套主体回复。

加入重要生活细节、承诺传达、履行、改约、失约、解释和有意保留私事。普通表达继续短路径，相关语义在需要的位置采用。所有消息与任务成果保持原目标，后台工作完成后由主体选择使用。

## 完整产品控制与用户界面

完善所有设置的作用范围、稀疏继承、生效、历史与 SecretRef。模型资源、预算、工具环境、渠道和原生配置采用正式入口。完成 CLI 命令组、操作查询、变更流和诊断。

实现 Nous Console 与 Hept Console，联合界面复用认知组件。以创建主体、编辑种子、配置角色、管理日历、交往、查看任务、解释未回复、看费用、暂停与继续为主线。高级结构和技术字段按需展开。

可观测性从前面已存在的操作与 trace 扩展到完整工具/渠道，不建立新的执行账本。费用、来源、隐私和实际发送结果直接连接正式记录。

## 部署、迁移与长期使用

完成本地 embedded-postgres、连接现成 PostgreSQL 与 Compose 形态；系统服务采用 shawl/systemd/launchd。普通服务启停、软件更新与主体启停有明确界面和命令。

实现未来主体导出、导入、分支和安装备份恢复，使用共同截点、逻辑身份与成熟备份工具。恢复旧快照时暂停未确定外部效果；物理清除覆盖索引、原件、原生历史、检查点与可处理备份。测试数据由本轮正式产品产生，旧项目数据无导入任务。

在 Windows 与 Ubuntu 使用同一安装、运行、重启和导出流程；macOS 运行同样入口并确认服务与密钥接线。外部工具依赖按实际能力安装，普通 memory-only 产品保持轻量。

## 三条完整使用轨迹

最终用宪纲第四十五章的三条轨迹串起功能：普通下午的群聊与媒体、长期学习、具有连续性的自述。轨迹中包含正常安装与管理，主体有独立生活，能查看资料、委派、自然表达、形成认识、改口和恢复工作。

这些轨迹同时承担文档示例、人工使用和集成回归。每条保留一个主场景，变体用同一数据表组织。对时间截面、权限传播、预算合并、NousQL 和关键算法保留小型参数化规则测试。上游库机制、生成 Client、薄转发和纯显示不重复建立测试支架。

发现实际缺陷时把重现条件加入所属现有场景，修正源头，再运行受影响范围。测试数量、覆盖率数字和证明文档不作为交付目标。类型检查、格式检查和真实构建是日常开发工具。

## 接线工作与明确选择

以下工作需要在开发机完成，但其目标及处置已经确定：

| 工作 | 实现位置与预期结果 | 出现问题时的处理 |
|---|---|---|
| DBOS + AI SDK | 官方 vercel-ai、prepareStep 与结果接受；成功调用复用，未知调用显式处理 | 调整提供方边界的稳定调用身份与结果等待，不自写持久 Agent 循环 |
| OpenClaw 逐调用接入 | 原生插件合同与真实模型派发/保存位置；所有支持的深度调用经过 prepare/accept | 在原生 owner 补齐合同及当前 harness，删除重复旧路径 |
| AstrBot 物理回执 | 实际客户端发送位置保留原返回值；完整分段对应平台消息 | 改编所属发送函数，不旁路重发或读私有数据库 |
| LanceDB 中文索引 | 显式 ICU；长中文、名称与混合文字可查 | 修正索引配置与构建，整体重建派生索引 |
| 本地数据库与原生包 | embedded-postgres、LanceDB、keyring 的正式平台包 | 使用上游发行与安装接口修正平台接线，不重写其进程与二进制获取机制 |

这些工作排在消费它们的纵切面，执行完即沿该单元继续。新的实现细节写回负责文件，保持同一套设计当前有效。

## 删除范围与完成形态

清除旧 Rust 领域内核与私有 RPC、重复协议 DTO、自建队列/步骤/租约/运行恢复框架、闲置基础包、原生安装后搜改脚本、重复上下文流水线、每句话的语义手续、历史包归档、机械逐句映射和离线阅读器。

采用的旧纯算法和有价值的领域行为按新 owner 重新组织，当前消费者一起迁入正式结构。第三方源代码改编以必要差异维护。删除清单随旧代码退出结束，没有常驻登记制度。

完成时两产品各自安装和运行，联合形成同一主体，核心能力均有正式入口、实际正常路径和可读说明。本包第四十九章对应的扩展方向保留在现成边界，当前重建终点覆盖本包已明确的全部功能。
