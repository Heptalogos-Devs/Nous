# Nous Wave 基建实施规划

日期：2026-10-23。状态：M0 与 M1 主链路已完成 Windows 功能验收，下一阶段为 M2 完整记忆产品。当前进度见 [开发任务](首批开发任务.md)。

## 目标与开发方向

先开发独立的 Nous Wave，以 Rust 单二进制完成实例管理、材料接纳、认知形成、查询及恢复，再向完整 A-Memorix 能力、NousQL、VCP 检索和高级认知扩展。Heptalogos 在正式认知合同形成后，基于 MaiBot 重建，消费 Nous。

需求权威是 [项目宪纲](requirements/项目宪纲.md)，重点对应第十四至十八、十九至三十二、四十六节。附件开发讨论提供技术候选；本方案依据实际源码将候选收敛为工程决策。高级认知可以按主体启用；仅使用记忆的应用也拥有完整产品体验。

完整续接范围与源码、owner、API、依赖批次集中于 [能力续接清单](能力续接清单.md)：多模态材料和检索、原件直接理解与描述后的二次结构化、结构化认知、managed context、steward、Native/DTSC 及完整 TagMemo/RiverMemo 体系均为后续正式能力。CLI 易用性、Prompt 管理与逐调用认知交付随实际消费者一起完善。

首个可使用版本贯通：初始化实例 → 启动 → 创建 Namespace 和 Subject → 提交文本并记录接触 → 持久形成记忆 → 查询 → 阅读来源 → 停止与重启 → 继续读取和处理未完成工作。

M0 提供实例管理、配置与凭据、身份与授权、SQLite 提交设施、持久任务、运行日志及 CLI/HTTP/MCP 入口。M1 已在此基础上贯通文本材料、实际接触、模型资源与版本 Prompt、持久形成、Memory 来源及修订、Tantivy 查询、重启恢复和初版快照恢复。

## 运行形态与依赖

采用模块化单体、单个 `nous` 原生程序。`serve` 持有实例运行权，HTTP 与 Streamable HTTP MCP 同进程服务；`mcp stdio` 作为同一程序的客户端子命令连接服务。普通在线 CLI 也调用服务。离线 `init`、诊断与恢复直接使用同一应用能力，取得实例独占锁后打开数据库。一个实例同一时刻只有一个运行宿主。

| 能力 | 方案 | 实施说明 |
| --- | --- | --- |
| 语言与运行 | Rust、Tokio、Clap | CLI 与服务共用应用操作；长 CPU 工作进阻塞池并有并发上限 |
| 权威存储 | SQLite、SQLx | 一个实例一个业务数据库，包含队列表；WAL、本地磁盘、短写事务 |
| 持久任务 | apalis + apalis-sqlite | 已核实公开 `queries::push_tasks` 接收现有连接；首批验证回滚、重启和任务重投 |
| HTTP | Axum、Tower、Reqwest | 安装级代理、超时、TLS 与按资源覆盖；配置产生共享客户端 |
| MCP | 官方 rmcp | 从官方例子复制改编；日志走 stderr，stdio stdout 留给协议 |
| 模型 | genai 0.7.0 | 共享 Reqwest 0.13，显式 provider、endpoint、模型和协议；M1 使用 OpenAI Chat Completions 与 JSON Schema |
| 词项、向量索引 | Tantivy 0.27、tantivy-jieba 0.21；后续 USearch | 当前中文与英文词项索引；嵌入接入后增加独立模型空间的向量索引 |
| 对象访问 | 本地不可变对象 + tempfile | 本批以同文件系统暂存、原子发布和摘要校验保存文本；出现额外后端需求时接入 OpenDAL |
| 配置 | Serde、TOML、JSON Schema | 有效值、来源、版本与待重启字段可查看；凭据通过 SecretRef 引用 |
| 日志与缓存 | tracing；按需接 Moka | 本批接结构化日志和操作关联；实际缓存使用点与 OTLP 导出随运行需要接入 |
| 服务安装 | 平台原生服务管理 | 发布阶段适配 Windows 服务、systemd；macOS 按相同合同扩展 |

本批依赖已写入 Cargo.lock，apalis-sqlite 1.0.0 与 SQLx 0.9 使用统一版本。单二进制发行包括将必需原生库静态链接或嵌入，Windows 与 Ubuntu 发布包分别验证实际运行依赖。

单写者通过短事务和有界接纳控制。SQLx 连接使用 WAL、外键、FULL 同步和有界 busy 超时；业务写入以 `BEGIN IMMEDIATE` 在读取幂等回执前取得写入权，并发重试因此依次看到已提交回执。批量写入采用有上限的分批事务，每批有独立结果。负载证明调度需要后再增加写入调度器。模型、媒体解析、下载和索引构建都在写事务外执行。

## 模块所有权

Cargo workspace 包含 `nous-domain`、`nous-storage`、`nous-app`、`nous-retrieval`、`nous-vcp` 与宿主 `nous`。领域内部按能力分模块，模型资源和形成准备位于 `nous-app::model`，检索引擎边界由 `nous-retrieval` 提供，VCP 计算由 `nous-vcp` 承担。

| 所有者 | 拥有的内容 | 边界 |
| --- | --- | --- |
| domain/identity | Namespace、Subject、能力供给、调用范围 | Namespace 是隔离与管理范围；Subject 是持续认知身份；无人格用户可只供给记忆 |
| domain/material | Material、Observation；随后接 Representation、SourceRegion 和来源谱系 | 材料属于 Namespace，接触属于 Subject；对象字节、材料存在、实际接触、形成结果各有身份 |
| domain/memory | Memory 及修订、生命周期、证据关联 | 新修订保留前序；软删除、冻结、遗忘、永久清除分别表达 |
| domain/time | 五轴时间值、TimeDomain、区间与比较规则 | 保存事件、接触、形成、适用、记录时间；世界时钟推进属于 Heptalogos |
| app | 完整用例、授权、事务编排、幂等、任务结果采纳 | 一个用例只有一个提交路径；按领域提供操作，事务机制共享 |
| storage | SQLx、迁移、事务、操作回执、队列接入 | 提供真实存储能力；业务决定由对应领域与应用操作作出 |
| retrieval | 当前词项索引、中文分词与提交覆盖；后续候选融合、USearch 和扩展算法 | 读取权威快照；返回结果前验证身份、版本、权限、时间与清除状态 |
| nous-vcp | AGS/几何、CSR/传播、Pyramid/Sense/Fusion/双场、RiverMemo/Thinking 及旧 reference/DTSC | 纯 Rust 输入输出和冻结代际校验；由 retrieval 提供合法资产、实际搜索与身份映射 |
| app/model | 资源、职责绑定、参数、网络、请求结果与成本 | 生成结果交给 memory 用例采纳；凭据与原始输入按访问策略保管 |
| transport | HTTP、CLI、MCP、A-Memorix 映射 | 负责协议转换与错误表示；进入相同应用用例 |

依赖方向：transport → app → domain；app 使用 storage 的具体事务与仓储能力。domain 不依赖 HTTP、数据库驱动和模型 SDK。共享事务贯穿参与的领域仓储；接口只放在真实外部边界、可替换算法和正式消费者合同处。

“事务中心化”落实为一套提交设施和明确的完整用例。每项业务规则归本领域；避免让通用事务对象掌握所有领域的内部语义。首批对象之间使用类型化 ID 与显式外键，必要 JSON 只保存版本化的扩展载荷。

本批本地对象实现由 `nous-app::objects` 管理，向材料用例提供发布与读取；其文件路径只来自 InstancePaths。后续增加对象后端时在此能力边界替换实现。进程支持的能力、Subject 已供给的能力和当前模型资源是否就绪分别报告。

## 持久数据与临时内容

开发目录：源码和文档位于工作区；研究克隆 `temp/repos`，下载 `temp/downloads`，安装解包 `temp/install`，缓存 `temp/cache`，编译 `temp/build`，试验 `temp/spikes`，开发实例 `temp/instances`。统一从 `scripts/dev-env.ps1` 设置当前会话环境。保留已安装工具链；新安装优先项目局部位置。

产品由 `--instance <absolute-path>` 指定根目录，默认位置由平台目录库决定并可在 `paths` 中查看。实例具有 `instance.toml`、`data/authority.sqlite`、`objects/`、`indexes/`、`logs/`、`backups/`、`exports/`、`run/`、`temp/`。临时内容按用途进入 `temp/downloads`、`temp/cache`、`temp/staging`、`temp/install`。正式数据库、原始材料、模型产物和备份保存在各自持久目录。

Paths 组件创建并提供全部路径，模块从 Paths 取得位置。相对配置路径相对于实例根目录解析。用真实解析后的路径与 Windows 大小写规则校验子目录归属，处理 junction/symlink。空间查看、配额清理、暂存租约与孤立对象回收属于后续数据治理操作；本批对象发布失败时由 tempfile 清理暂存文件。重定位在停止实例后进行，迁移描述保留版本与校验。

M1 已提供在线一致性快照和离线恢复到新实例：运行宿主以 SQLite VACUUM INTO 取得快照，备份完成后原子发布；恢复校验清单、摘要和对象引用，在新目标取得实例锁，配置最后发布。认知对象身份保留，管理员凭据重新生成，模型密钥由操作者另行供给，Tantivy 从权威数据重建。后续安装更新替换程序与内置资源，数据迁移拥有独立版本；升级先校验兼容性和备份，再迁移。对象 GC 与备份引用协调继续随数据治理能力扩展。

## 一次业务提交的合同

transport 从认证凭据构建 CallContext，包含调用者身份和 Admin、Namespace 或 Subject 范围；请求携带业务对象及 OperationId。幂等唯一键为 `(caller_id, operation, scope, operation_id)`。`scope` 对实例管理为 `instance`，对 Namespace 操作为 NamespaceId，对主体接触操作为 `namespace:<NamespaceId>/subject:<SubjectId>`。各身份在实例内稳定唯一。

请求摘要以 SHA-256 计算版本化 JSON 编码，包含 `nous.operation.v1`、操作类型、目标范围和业务参数；request/trace 等关联信息独立于业务摘要。相同键和摘要返回首次保存的完整 OperationReceipt，包含 result、commit_seq 和 job_ids；相同键不同摘要返回 Conflict。操作记录随权威历史保留。M1 删除操作把 expectedRevision 纳入摘要，并在提交事务内校验；认知修订继续使用同一合同。

写入流程：

1. 在事务外读取和校验输入、权限范围及大小，完成必要下载与模型工作。
2. 本批文本通过 tempfile 写到同文件系统暂存路径，计算摘要、同步并原子发布到不可变对象路径；数据库提交前验证对象可读、长度与摘要正确。大媒体接入时再提供流式输入。
3. 以 `BEGIN IMMEDIATE` 开启短写事务，处理幂等重放，核对目标对象范围与相关版本。
4. 从实例唯一的 `authority_state` 行分配 commit_seq，写入领域状态、来源和 OperationReceipt；以相同连接调用 apalis-sqlite 批量入队，记录后续处理需要的领域版本。一个完整操作只分配一个序号，回滚同时撤销序号分配。
5. 一次 COMMIT 后返回业务结果与任务 ID。提交前失败整体回滚。对象发布早于权威提交，未被引用的已发布对象保留到对象 GC 接入后回收。

事务内使用 `apalis_sqlite::queries::push_tasks(&mut *tx, queue, tasks)` 的实际签名实现并验证。无需额外维护第二套出站消息队列。后台索引和形成工作直接消费同库持久任务。

Worker 采用至少一次执行。模型调用在事务外，保存 provider/model/参数、输入来源与版本、Prompt 版本、输出、usage、实际费用或未知状态；取消和响应不确定也有独立状态。使用 job ID 与领域版本组合防止重复采纳。任务结果过期时重新准备或结束，不覆盖较新的认知。领域结果提交与队列 ACK 之间崩溃后，重投通过幂等结果返回，再 ACK。数据库只能保证本地采纳幂等；外部模型请求的重复计费由 provider 支持、请求记录和恢复策略处理。

## 查询、索引与时间

当前 SQLite 保存材料、观察、形成状态、模型调用、Memory 及修订，Tantivy 保存可重建的词项表示。Jieba search mode 与小写、长词过滤共同处理中文和英文；Namespace 与 Subject 在 TopK 前过滤。索引替换按对象 ID 删除旧文档再添加当前版本，提交 payload 将格式版本、覆盖提交序号和 generation 与索引一起原子发布。重启读取该覆盖，显式 rebuild 使用新的 generation。

后续 Embedding 数值与生成签名进入权威数据，USearch 保存相应服务表示；不同模型空间分别维护 EmbeddingSpace 与覆盖状态。多代构建期间保留可服务的旧代，成功后切换。

M0 与材料接纳提供按身份精确读取。M1 按自然语言文本、Memory 稳定引用、来源和时间范围查询当前记忆。已提交但尚未进入索引的数据，通过有界增量 SQL 读取合并；若超出预算，返回明确覆盖状态和继续条件。调用者可带 `min_commit_seq` 等待所需可见性。按引用读取直接查询权威数据。候选须按当前权威重新物化；旧索引命中已删内容时直接排除。

NousQL 的正式 AST 与纯自然语言入口进入共同 QueryPlan，逐步支持 `$time`、`$asof`、`$history`、`$return`、`@ref`、`@entity`、`@tag`、`$explore`。完整语法在查询阶段结合旧代码和宪纲设计；M1 先确定类型化 QueryRequest。历史截点先约束可用材料和修订，再做召回，避免先用未来信息扩张候选。

时间值包含明确 TimeDomain 与精确整数坐标；真实记录使用 UTC 时间和 commit_seq 排序。未提供的事件、接触时间保持缺省语义。跨时间域比较使用显式映射；超时与租约采用运行时间机制。Heptalogos 提供世界坐标与接触事实，Nous 校验并保留来源。

Material 保存事件时间，Observation 保存接触时间，两者保存实际记录时间。Memory 保存对应事件、接触、形成、适用与记录五轴，形成与记录使用明确的 UTC 坐标；未知适用范围保持缺省。完整历史截点与跨域映射随 NousQL 接入。

## 配置、授权与模型资源

本批配置采用“内置默认 → 实例 TOML”，包含格式版本、监听地址、网络代理与超时、凭据引用；有效值显示来源及待重启范围。离线编辑在下次启动校验。密钥保存于受保护的实例 credentials 目录，普通配置、日志和响应保存 SecretRef 与脱敏信息。作用域令牌由实例管理操作创建，服务启动时加载认证快照；修改令牌后重启服务。

运行配置随后扩展为“内置默认 → 实例 → Namespace → Subject → 本次允许覆盖”，有效值带来源和修订。在线修改由服务用例统一校验、持久提交并发布。平台密钥库可在 SecretRef 边界接入。

首批即包含管理身份、作用域令牌、Namespace/Subject 授权和对象访问范围，默认监听 loopback。材料及派生内容携带来源访问范围，检索、缓存和上下文复用沿同一范围校验。缓存键至少包含范围、主体、权限版本、认知版本与相关模型空间。

材料接纳属于 Namespace 操作。Namespace 或管理员为 Subject 接纳首次接触；Subject 令牌可读取已经接触的材料，并记录同一材料的后续接触。同一材料的每次真实接触拥有独立 Observation；材料身份和内容摘要用于不同目的。来源级隐私和听众用途范围在认知形成与查询接入时进一步细化，并沿派生关系传递。

当前 memory_formation 职责绑定一个显式模型资源。ModelRuntime 先准备版本化请求元数据，Worker 在数据库事务中预留每日调用次数，再进行一次 SDK 请求；失败和不确定响应仍保留这次预留。源对象版本、实际输入、Prompt 原文与摘要、模型参数、usage、返回的模型身份、原始输出及错误分类进入调用记录。JSON Schema 与本地校验共同要求 1 至 3 条 `MemoryDraft {title, content, epistemic_status}`。价格缺失时成本记未知。

以下实例配置用于本机网关验收；凭据由操作者置于 SecretRef 指向的受保护文件中：

```toml
[models.memory_formation]
prompt_version = "nous.memory.formation.v1"
max_input_bytes = 32768
max_output_tokens = 2048
max_calls_per_day = 20

[models.memory_formation.native_parameters]
thinking = { type = "disabled" }

[models.memory_formation.resource]
id = "local-gateway"
provider = "new-api"
protocol = "openai_chat_completions"
endpoint = "http://127.0.0.1:3000/v1/"
model = "doubao-seed-2.1-lite"
credential = { file = "credentials/model-gateway.token" }
```

`native_parameters` 通过 genai 的 extra_body 传入真正的 provider 参数，并与实际 ChatOptions 一起记录；模型、消息、流式、工具、结构化输出和 token 上限由专属字段管理，原生参数入口拒绝覆盖它们。当前 max_output_tokens 使用 genai 的 max_tokens 选项，对 Doubao 限制回答长度；实际 usage 包含思维链计数，详细合同见 [实测记录](源码研究.md#真实网关实测与参数语义)。

未配置职责或凭据不可读时，形成任务等待配置；每日预留达到限制时等待预算。材料与管理操作继续工作。模型层公开 WaitingConfiguration、Retryable、Permanent、Uncertain 分类，并保留原 SDK 错误类型供 Worker 判断。Embedding、Rerank、更多模型资源与可编辑 Prompt 在相应能力接入时扩展此边界。
