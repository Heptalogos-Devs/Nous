# 完整操作、成果与检索重构

重构目标是让 CLI、SDK 和宿主调用同一类型化完整操作；原件、实际输入、成果、草稿、正式修订和检索交付各有明确引用与保存点。现行行为与剩余能力见[当前工作](../CURRENT.md)，跨模块合同见[架构](../ARCHITECTURE.md)及相应专题。

## 责任和依赖

- 应用入口定义请求、结果和事件，InputReader 在一次请求内接纳外部材料；执行上下文贯穿输入、处理、提交与交付。
- 内容 owner 管理原件身份、原始选择、实际表示、命名成果及来源映射；模型和媒体在形成完整成果后采用，写作与标注各自保存领域上下文。
- 写作保存模型成果，组装可修改的完整草稿，再由文稿 owner 在短事务中采用正式修订、来源和反馈关系。
- 正文提交后由维护 owner 等待或在当前 Runtime 中执行标注及刷新；取消和关闭等待真实资源退出，重开只读取已保存成果。
- 认知检索按轻量目录识别变化材料，复用未变投影和向量；Wave 完整构建后一次发布，领域代次仍相同时提升 current。组排名依据、实际交付片段和反馈目标分别表达。

这些能力通过实际写作、维护查询和多模态来源链贯通。同步迁移生产者、消费者、配置、动态登记、测试和现行文档；用户历史修订和编辑文件继续保留。新实例按当前结构初始化。

## 按共同变化的责任实施

内容来源与表示先确定共同解释。内容模块拥有原件、选区、已确认类型、实际表示、命名成果和坐标关系；认知模块拥有正式修订、来源用途与支持关系。生成、媒体、写作和检索消费同一份内容事实，已有表示的读取沿正式关系完成。确定性转换和正文组装可以传递已有来源，独立见证仍由领域的支持关系决定。

任务语义确定需要共同处理的材料与独立范围，模型路线只决定本次表示。任务输出的结构、来源键和解释集中于具体任务，普通生成只组织执行与完成成果的保存。新增任务输出或媒体格式时，修改应集中在相应任务或表示的负责位置。

认知捕获决定本次组资格与正式上下文，Wave 负责计算单元及其真实输入依赖。资格政策、组显示和计算依赖分别表达；未变单元直接复用，跨组共享的来源及图资料保持共同权威。快照固定本次组上下文，不从历史成员列表寻找当前领域事实。Native 的局部行号由 Wave 一次解释为候选、组、排名依据和交付片段，认知查询只补充正式修订语义。

完整操作定义同时用于 CLI、SDK、宿主和轻量离线配置装配。操作的请求、结果和发现信息归负责能力；入口转换用户语法与文件绑定，组合根完成登记。CLI 公共调用与呈现不依赖子命令的导入副作用，领域规则不通过 Runtime 对象图在入口重新组合。

运行期统一请求的配置、期限、取消与实际退出；文件、网络、媒体和 Native 分别限制自身资源容量。宿主接纳与操作控制保持可达，保存事件和错误使用已经提交的成果事实。正文、附加维护和客户端交付各有自己的完成语义。

共享合同由一个负责者修改，关联消费者跟随迁移。注释保留外部约束和不变量，测试保护完整操作、独立失效、事务与精确历史读取；旧结构专属转发、约定及测试支撑随替换删除。

## 验证重点

从 CLI、SDK 和运行中宿主执行相同操作，核对文件绑定、精确来源、导出及错误。检查草稿修改与基准冲突、标注与刷新独立失败、后台容量及取消、原件与模型表示的关系。检索检查长文末尾、标题命中、实际片段回读、反馈保留、单条变化复用以及发布前中断和并发写入。运行中断后确认已保存成果可读，未完成工作可发起新的操作。
