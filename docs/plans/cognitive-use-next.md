# 认知使用之后的领域发展

## 当前落点

当前主线由[可编排检索与认知使用](composable-retrieval.md)组织：共同材料、Wave 程序、精确原文、可选阅读整理、Work 和实际使用反馈。后续领域复用这些完整能力。执行由普通 Runtime 与异步 Task 持有，Work 保存跨会话认知工作；进程重开读取正式成果和工作状态。

## WorkContext 驱动一次真实研究

WorkContext 保存真实开发或研究任务的目标、仍有效决定、当前进展、待解问题、阻塞及精确认知引用，拥有完整修订和自己的生命周期。Journal 正文通过正式引用使用，工具执行属于运行期。

当前问题与选定工作片段进入 Wave；QueryIntent 保存实际参与的片段、阶段、顺序、贡献及当时 Work 修订。工作目标、焦点、有效决定和明确活动依据默认参与召回与定位，其他情境按[路由合同](../design/cognition/context-routing.md)选择阶段。无 Work 的自然语言查询同样是完整操作，当前激活内容通过正式引用和选区使用。

## 原文交付与阅读整理

Wave 的独立 localizer 从已排名材料定位精确范围，程序读取原文和必要上下文。Steward 按用途读取已保存的 EvidenceDelivery，形成单独的 Markdown 阅读稿及其来源关系。默认直接使用原文，整理稿按用户选择进入写作和正式采用；详细责任见[局部定位](../design/wave/localization.md)与[阅读整理](../design/cognition/steward.md)。

持久可读 identifier 继续跨会话。局部 E 键属于各自 EvidenceDelivery，保存后通过其 ResultRef 回读；未存交付可在稍后显式采用。QueryIntent 固定实际使用的工作修订、阶段情境和条件，计算快照是否仍可用于历史重算单独表达。

## 实际使用后的反馈

依次区分召回、原文交付、阅读整理、宿主编入输入、明确采用和结果反馈。宿主报告实际调用事实。查询反馈绑定实际 E 交付；Work 使用记录也可包括沿引用补读后明确采用的选区。

首个反馈使用选择同一问题/同一Work内调整：排除明确不相关候选、补充查询线索或情境重排。保持Journal真值、准确性、赞同程度、VCP quality_score、RiverMemo ranking_score各自语义。暂不建立训练平台和全局自动增信。

工作中的关键决定可以记录所参考的具体Journal片段；新证据改变决定时，由明确反馈或编辑触发认知修订。保持工作结果与认知来源的可追溯关系，而非把“模型看过”当作知识已被证实。

## Episode 与历史知情

Observation 记录某个主体何时、以什么方式实际接触了哪些材料或表示。材料入库、模型描述、后台索引和主 Agent 阅读分别记录真实事实。Episode 组织事件经过，Journal 表达有视角的理解；occurred/observed/formed/valid/recorded 及其时间域来自正式 TimeService。以一次真实研究或经历完成记录、顺序、回看、形成 Journal 和后续更正。

严格历史视图在选择正文、Concept 意义版本、关联与 SupportGroup 之后构建图资产。显式 SnapshotRef 提供精确旧检索视图；任意历史知情需要领域另行选择当时可见内容，不使用今天命中过滤代替。本文保持已定数学责任，不预建时态数据库框架。

## 计算扩展与客户端

增量沿不可变投影单元和组件清单继续，先处理候选目录与词项，再处理 ANN 的删除／替换及全局数学依赖。完整操作为更新一篇、当前查询、旧快照仍可读、清理旧资产；共享组件必须保持候选键和行映射。全局依赖仍按真实变化重算，不在 Python 补偿检索。

HTTP、MCP、gRPC 和本地认证通道适配同一完整操作，当前宿主持有其监听资源和本进程后台任务。后续远程 SDK 与管理客户端继续复用操作 Schema、事件、期限、输入交付与正式引用。

## 更高认知领域

Ego提供稳定自我与情境片段，Social持有实体/有方向关系/社会语言，Motivation持有愿望与关切。Schema是经验模式，Anchor是吸积地标，Dream保存明确探索性质的认识。它们通过正式来源、Journal与Wave能力协作，拥有各自规则，不成为Journal无限字段或同一个通用生命周期。

后续以这些真实使用经验决定新的实现范围。当前不提前生成空服务、空注册槽、接口包装或永久评测制度。
