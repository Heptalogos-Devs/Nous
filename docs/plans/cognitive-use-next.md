# 持久维护之后的认知使用与发展

## 当前落点

本轮先让正式文稿和维护工作能够长期使用、恢复和观察。收敛身份、来源、无损原文与Runtime执行，是下一条认知使用链可以依赖的共同能力。Job是函数执行记录，WorkContext是认知工作状态，二者从命名、数据和生命周期上保持分开。

## WorkContext 驱动一次真实研究

下一轮选择一个真实开发或研究任务，建立可跨会话保存的目标、仍有效决定、当前进展、待解问题、阻塞及精确认知引用。WorkContext拥有自己的版本与生命周期，不复制Journal正文，不存完整工具执行流水。

当前问题与选定工作片段进入Wave；QueryContext冻结实际参与的片段、顺序和权重以及当时WorkContext版本。当前查询不需要WorkContext也仍是完整操作。Active Memory保存当前激活引用和片段，不再形成一个永久Memory正文容器。

## Steward 负责选择原文交付

Steward可选地读取Wave已经排名的候选，返回精确块/范围及必要上下文。程序按RevisionSelection取回原文，去重仍按精确来源，不让LLM重述成为另一份可能失真的记忆。未配置Steward时直接使用当前检索交付。

持久可读identifier继续跨会话；一次查询可为实际返回结果分配局部短引用，由QueryResult自身映射到RevisionSelection。局部映射不变成全局别名服务，也不把本文未实施的短引用语法写成当前NousQL已完成。

## 实际使用后的反馈

依次区分召回、Steward选择、宿主编入输入、明确采用和结果反馈。宿主只报告自己能确认的实际调用事实。评价绑定当时的查询与工作情境，未交付候选没有负反馈。

首个反馈使用选择同一问题/同一Work内调整：排除明确不相关候选、补充查询线索或情境重排。保持Journal真值、准确性、赞同程度、VCP quality_score、RiverMemo ranking_score各自语义。暂不建立训练平台和全局自动增信。

工作中的关键决定可以记录所参考的具体Journal片段；新证据改变决定时，由明确反馈或编辑触发认知修订。保持工作结果与认知来源的可追溯关系，而非把“模型看过”当作知识已被证实。

## Episode 与历史知情

继续区分材料存在、主体实际接触和认识形成。Episode组织事件经过，Journal表达有视角的理解；occurred/observed/formed/valid/recorded及其时间域来自正式TimeService。

严格历史视图在选择正文、Concept意义版本、关联与SupportGroup之后构建图资产，不能只过滤今天的最终命中。本文不改变已定数学责任，也不预建时态数据库框架。

## 更高认知领域

Ego提供稳定自我与情境片段，Social持有实体/有方向关系/社会语言，Motivation持有愿望与关切。Schema是经验模式，Anchor是吸积地标，Dream保存明确探索性质的认识。它们通过正式来源、Journal与Wave能力协作，拥有各自规则，不成为Journal无限字段或同一个通用生命周期。

后续以这些真实使用经验决定新的实现范围。当前不提前生成空服务、空注册槽、接口包装或永久评测制度。
