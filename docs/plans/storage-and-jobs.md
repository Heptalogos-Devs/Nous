# 内容与持久工作实施计划

## 开始条件与范围

运行基础已经具备配置、路径、数据库、事务、执行和观测。本计划需要单独启动，交付真实内容存取及可继续的后台内容操作。

依据：[内容存储](../design/foundation/content-storage.md)、[事务](../design/foundation/transactions.md)、[持久工作](../design/foundation/durable-work.md)。不提前开发 Journal、完整材料语义或知识导入目录。

## 实施依赖

先让 ContentStore 完成真实文本和二进制流的 prepare、publish、read、attach/detach。物理字节与正式对象身份分开，原文可精确取回。

再把 DBOS 接入同一 SQLite 文件。启动时注册命名任务，恢复资源由组合根明确注入；客户端入队不直接依赖不支持的类方法。

最后用真实后台内容接纳操作贯通提交、入队、工作状态、内容结果与读取。业务 write 和 DBOS enqueue 使用同一事务；已有成功结果按业务身份复用，不复制到永久通用回执表。

## 操作结果

一项大文件接纳可以异步执行，返回可读工作状态及同一结果读取入口。取消前已完成和已采用的内容保持明确，未采用临时文件清理。重启后由 DBOS 继续合法工作，调用者能取得真实结果。

内容管理接口先作为进程内正式能力，由后续材料与接口专题接入。任何为开发验证编写的一次性脚本放 temp，验证完成后不作为生产框架保留。

## 完成条件

真实内容写入、精确读取、重复字节复用、取消、事务回滚不入队、重启继续及结果不随临时任务日志清理而消失。Provider 调用不在本计划范围。

需要修改数据库或执行基础时直接更新共同 owner 及文档；不为保持首轮接口外形增加补偿层。
