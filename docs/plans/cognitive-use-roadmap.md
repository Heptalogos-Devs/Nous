# Journal 维护之后的认知使用路线

文稿、完整操作、类型化查询、草稿和提交后维护为后续认知使用提供基础。正文、成果、标注与快照各自由对应 owner 保存；后台工作属于当前 Runtime。当前能力见[当前工作](../CURRENT.md)。

## 然后接入工作中的记忆使用

详细方向见 [认知使用与发展](cognitive-use-next.md)。

最先选择一个真实开发/研究任务：跨会话保留目标、有效决定、进度和待解问题；根据当前问题召回 Journal；Steward 选出原文段落；宿主把这些段落交给模型，反馈实际有用性。

WorkContext 保存任务状态与精确引用，生命周期跨 Session。Active Memory 是当前激活引用和片段的集合，不复制长期正文。Steward 是可选的交付选择：读取 Wave 已排名候选，返回选段键，程序读取原文；没有配置时直接交付检索结果，不再摘要一遍冒险改写。

QueryContext 固定参与计算的工作片段，而非 mutable 工作 ID；实际召回、交付、编入输入、明确采用和使用反馈分别记录。当前查询 owner 已提供这些接缝，后续不通过 CLI JSON 拼接。

## 情境性反馈的研究

首个利用方向是同一问题/同一 Work 中的明确反馈调整，例如排除不相关候选、补充查询线索或在情境内重排。它不改变 Journal 真值，也不直接写入全局 VCP 质量分。

选择能区分方法价值的实际例子：同一句问题在不同任务中是否需要不同记忆；未交付材料没有负反馈；展示顺序对选择有影响；用户纠正问题本身与否定文稿内容分别处理。可对照查询级 Rocchio/近邻重排等成熟方法，再决定需要哪种学习，不先创建训练平台。

## Episode、多轴时间与社会认知

在持续使用后研究事件发生顺序、主体接触顺序与认识修订的关系。Episode 组织经过；Journal 保存有视角的理解；时间域和五轴继续来自既有能力。严格历史视图必须在图资产选择前成立，不能仅过滤最后命中。

Ego 提供稳定人格文档与相关片段；Social 提供实体和有含义的关系；Motivation 保存愿望/关切；Schema、Anchor、Dream 利用已建立内容与图能力发展。它们各自拥有状态，不成为 Journal 的无限字段和万能生命周期。

## 有限实验

本轮已经交付精确维护与结构贡献接入，先用这些完成认识维护和解释性结构的对照。后续增加 WorkContext 后研究情境性效用，再接 Episode 的时间使用。实验使用正式 API/CLI、真实材料和现有诊断，无新永久评测平台。
