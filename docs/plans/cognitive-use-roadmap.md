# Journal 维护之后的认知使用路线

## 本轮形成的基础

Journal Maintenance 已形成可维护文稿、进程内操作、类型化查询情境、分组结果和部分失败诊断。当前进入 [可靠认知操作与持久维护](durable-cognition.md)，修复身份、来源、原文和执行的一致性并接入真实后台维护。实际完成状态仍见 CURRENT。

## 当前接入 DBOS 与持久宿主

首批持久工作为独立的标注与检索刷新。保存可同时登记两项，标注失败不阻断正文检索；标注成功激活后，在采用事务中登记新代次的刷新。

拥有实例锁的长生命周期宿主运行应用能力与 DBOS。DBOS 使用独立调度循环，真实业务通过有限 RuntimeBridge 回到既有 Nous 循环和共享资源；不另启动一个也 open_instance 的 worker。工作参数只含稳定 Namespace、精确 revision、冻结任务/模板与请求的维护效果。

业务写入与明确维护入队使用同一个 SQLAlchemy 事务及 DBOS 系统数据库。当前官方 `enqueue_in_transaction` 接受同一数据库上的 connection；异步连接通过正式桥接调用。DBOSClient 也支持 class_name/instance_name 注册方法，文档中旧“不支持类方法”的说法应删除。

确实采用的 workflow 细分为：读取精确材料、需要时产生语言结果、采用标注、构建目标知识视图、发布。恢复复用已经采用结果；较旧文稿的结果可以保留，但活动标注与 current 快照更新仍受正式前置条件约束。模型尝试和工作重试不能层层刷新同一操作的尝试额度。对成功计算但尚未记录的外部请求不承诺绝对一次执行。

不增加自制任务总表、通用 outbox、无限 lease/receipt 框架。工作状态由 DBOS，认知结果由实际 owner。普通前台调用仍可直接完成，两个入口复用同一业务操作。

本轮固定 DBOS 3.4.0、portable JSON、成功产物描述、业务采用幂等、注册与关闭顺序及 runtime.jobs/nous job；详见 [DBOS 接入](../design/foundation/dbos-integration.md) 和 [持久维护](../design/cognition/durable-maintenance.md)。使用完整保存→维护→关闭重开通路开发。Job 表示持久执行；WorkContext 保留认知工作语义。

## 然后接入工作中的记忆使用

详细方向见 [认知使用与发展](cognitive-use-next.md)。

最先选择一个真实开发/研究任务：跨会话保留目标、有效决定、进度和待解问题；根据当前问题召回 Journal；Steward 选出原文段落；宿主把这些段落交给模型，反馈实际有用性。

WorkContext 保存任务状态与精确引用，生命周期跨 Session。Active Memory 是当前激活引用和片段的集合，不复制长期正文。Steward 是可选的交付选择：读取 Wave 已排名候选，返回选段键，程序读取原文；没有配置时直接交付检索结果，不再摘要一遍冒险改写。

QueryContext 固定参与计算的工作片段，而非 mutable 工作 ID；实际召回、交付、编入输入、明确采用和使用反馈分别记录。当前查询 owner 已提供这些接缝，后续不通过 CLI JSON 拼接。

## 情境性反馈的研究

首个利用方向是同一问题/同一 Work 中的明确反馈调整，例如排除不相关候选、补充查询线索或在情境内重排。它不改变 Journal 真值，也不直接写入全局 VCP 质量分。

选择能区分方法价值的实际例子：同一句问题在不同任务中是否需要不同记忆；未交付材料没有负反馈；展示顺序对选择有影响；用户纠正问题本身与否定文稿内容分别处理。可对照查询级 Rocchio/近邻重排等成熟方法，再决定需要哪种学习，不先创建训练平台。

## Episode、多轴时间与社会认知

在持续使用后研究事件发生顺序、主体接触顺序与认识修订的关系。Episode 组织经过；Journal 保存有视角的理解；时间域和五轴继续来自既有能力。严格历史视图必须在图资产选择前成立，不能仅过滤最后命中。

Ego 提供稳定人格文档与相关片段；Social 提供实体和有含义的关系；Motivation 保存愿望/关切；Schema、Anchor、Dream 利用已建立内容与图能力发展。它们各自拥有状态，不成为 Journal 的无限字段和万能生命周期。

## 有限实验

本轮已经交付精确维护与结构贡献接入，先用这些完成认识维护和解释性结构的对照。后续增加 WorkContext 后研究情境性效用，再接 Episode 的时间使用。实验使用正式 API/CLI、真实材料和现有诊断，无新永久评测平台。

理论背景与资料范围见 [研究决定](../research/journal-maintenance-decisions.md)。VCP 的长期资产/请求资产、质量分/排名键、结构贡献/独立支持各自保持清楚含义。
