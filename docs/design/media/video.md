# 音视频采样、转换与实际覆盖

音视频继续使用 FFmpeg/ffprobe。进程通过参数数组创建，配置路径与当前实例路径规则一致；默认经 PATH 查找。转换参数、库版本和实际输出范围随结果保存。

## 计划与解码

先探测流、时长和可用时间信息，建立请求时段内的批次。采样计划由实际 PTS/帧位置确定，不能假定固定 FPS。保留 requested_time 与 actual_time。

将当前“每个采样帧从头启动 FFmpeg 解码”改为每个视频/有界连续片段的一次采样遍历，复用成熟 FFmpeg filter/select/时间戳输出。必须取得每张输出帧的实际 PTS 与来源顺序；无法从所选 API 取得时采用依赖支持的时间戳方式，不猜帧时刻。

读取/解码输出有界，产物及时进入 CAS，后续 batch 仅持 refs。需要更多帧时继续同一遍历或合理分片，避免随帧序号累计重复解码整个前缀。

## 音轨与时段

音频转换是确定性操作，使用目标协议支持的实际格式和采样参数。带声音的视频默认处理音轨；显式 without_audio 才排除并记录。模型原生音频与单独转写由 MediaAnalysis 选择，准备器不发网络请求。

分片 local time 与原件 origin time 分开保存。无声、零帧、无可辨语音是不同结果，不能用空描述掩盖解析失败。

## 取消与关闭

保留子进程 terminate → wait → 超时 kill → wait 的所有权。关闭、等待和临时文件清理使用同一实际进程句柄。中断返回已经采用的产物引用和未完成时段。Native Wave 不承担媒体解码，避免再造格式处理实现。

## 原生视频输入

明确接收视频 MIME 的模型路线优先原生视频表示，通过同一 SDK 的 video_url 内容扩展发送有界 data URI。完整且无需剥离音轨的文件可直接引用；时间选区或 --without-audio 由 AudioVisual/FFmpeg 生成 MP4，ResultStore 保存确定性转换及原视频的精确时段。选区文件的本地时钟与原件坐标分别保留；coverage 的 start_ms/end_ms 指原件范围，sent_duration_ms 为实际发送容器时长（编码音轨可能带少量填充）。

音轨 included/excluded/absent 记录实际文件内容；模型能否联合理解音画按实际请求验证。sampling=provider 表示视频由上游处理，本地不声称掌握其全部采样帧。只支持图片的路线继续使用现有采样表示，备用路线切换时按同一原件/范围重规划。协议、请求限制与文件上传边界见[模型输入规划](../models/input-planning.md)。
