# 视频与连续画面准备

## 通用路径

本轮必须完成 FFmpeg/ffprobe 的采样画面与音轨路径。Native video 只在实际 SDK 与统一网关协议共同支持时采用；不为开启视频而把本地网关伪装成另一个厂商 Provider。

读取实际容器、流、帧率、时长与音轨。按配置目标间隔抽帧并保留实际帧 PTS/时间基；requested_time 与 actual_time 分开。ffprobe seek/read_intervals 可能落在邻近位置，因此实际位置以返回帧信息为准。

变帧率视频不能用 `帧号 / 假定 FPS` 猜实际时间。旋转元数据、缩放和画面尺寸由准备结果明确保存。

## 声音与覆盖

有音轨时，默认采用可用原生音频或配置的标准转写任务，与画面一起提供给解释阶段。语义模型消费画面、时间标签和实际声音表示。用户显式选择 `--without-audio` 时，结果清楚表示未处理声音。

分批大小由帧数/输入字节/模型上下文控制。所有被请求时段的采样结果按顺序返回。不得只取最前 12 帧然后声称整个视频分析完成。

连续画面是 sampled coverage，不能据此断言两个样本之间没有其他事件。结果携带采样点和音频实际覆盖，不需要让模型推理这份技术清单。

## 输出与使用

帧、音轨和转写均可以复用为独立 Artifact/ProcessingResult。模型生成的片段描述与结构化输出引用实际消费的输入。

用户需要某段视频时用毫秒/秒选区，所有底层命令仍接收参数数组和真实本地文件。进程取消归媒体 owner，在实例数据库关闭前回收子进程。

依据：[FFprobe 结构化输出、帧信息与 seek 说明](https://www.ffmpeg.org/ffprobe.html)。
