# 按材料组召回与交付

## 组身份与召回

正式认知查询的 top_k 表示最多返回多少个不同材料组，组内再选择有限的原文单元。Wave 研发入口也可选择 candidate 粒度。group_key 在捕获时固定；来源根、物理 Artifact 和标题各自保持原有身份。同一修订的整体候选和局部候选属于同组，不同正式材料即使字节相同也不合并。

词项、向量和直接锚通道按各自预算召回，并在 document 粒度下兼顾组数及组内候选数。Tantivy 按组聚合词项结果；USearch 保留有序批次，在已饱和组和已检查行之外继续寻找其他组，直到组目标、范围耗尽或明确扫描上限。候选联合先给入选组分配代表，再分配剩余额度；覆盖信息保留实际扫描、耗尽与截断原因。

CandidateSet 保存快照内候选的精确身份与每路原分、名次。显式校准产生 CalibratedPool，RiverMemo 消费该值，DTSC 可消费同一 CandidateSet；它们不在读出时重新召回。多条排名按程序配置在组身份上融合，同一路的多个片段不会重复投票。数值合同见 [算子](operators.md) 与 [排名](ranking.md)。

## 排名与正文各自保持

`GroupHit` 保存组描述、组rank、排名依据及定位结果。组内定位对入选材料的局部原文单元独立评分，原文范围与组排名依据分别记录；详见 [原文定位](localization.md)。

字符或字节预算限制实际交付的主片段和必要上下文。已排名组即使没有可放入预算的片段仍然返回正式材料引用与rank，`delivery_status` 标示已选择、预算不足、已由其他范围覆盖或无局部候选。共享原文范围按并集计费；反馈和使用记录只引用实际交付的片段。

`coverage` 保存候选预算、已返回组数、扫描耗尽与截断原因；组合查询还保留各实际分支的覆盖。尚未计算的并集数量保留未知，不能把单个分支的数量当成整个表达式的数量。没有匹配是正常结果，预算不足与未召回是不同状态。

`WaveQuery(grouping="document", passages_per_group=2, top_k=10)` 最多排名十个材料组，每组至多交付两个单元；`grouping="candidate"` 返回候选粒度结果。调用方通过正式快照、候选及内容引用继续读取。
