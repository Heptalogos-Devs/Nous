# 组内原文定位

组排名和局部定位是两项计算。Wave 在所有入选材料组的允许范围内比较局部候选；有问题向量时默认按局部余弦定位，`text_only` 程序按词项定位。程序可显式启用两路，并以 `passages.locate` 的 `lexical_weight`、`semantic_weight` 和 `rrf_k` 合并实际文本与向量的名次；原问题各路权重按其总和归一，分配到定位阶段的情境按父材料质量独立贡献。定位不受召回所用程序限制，也不把组排名依据当作唯一可交付段落。

局部单元在资产准备时由共同 TextView 根据真实正文和布局参数形成；其精确 UTF-8 范围、词项输入及 document 用途向量一起进入快照。相同输入和空间使用既有向量行。改变布局时只复用签名仍然匹配的表示；查询程序和预算变化不重建这些资产。

定位阶段先形成带评分的正式选区，并通过共同 TextView 将被切断的句子闭合，添加可确定的标题、表头、列表引导和代码围栏。主片段之外的范围分别作为 `support_context`，均使用原始 UTF-8 坐标；不连续的支持范围独立记录。可选模型评价只读取其实际预算内的候选。`delivery.read` 在范围选择后批量读取选中的原文，形成 `PassageDelivery.fragments` 和支持上下文。匹配字段、局部 RRF、理论参照、词项和语义原值、名次及权重分别记录；可选评价失败时保留本地定位结果和 issue，调用中断继续向上传播。

选择时对实际文本和上下文的来源范围并集计算增量成本，每步按新增收益除以新增成本选择能放入预算的完整单元。收益由局部相关性、显式方面的新覆盖和已选片段的语义近重复共同决定；方面和近重复只使用实际向量或已有评价，不由字符串规则推测。默认总预算为 2048 字符，请求或程序可指定字符、字节或 token 预算。每个片段的 `scored_ranges` 保留评分所依据的完整原文范围；已经由其他片段交付、当前片段理解所需的部分记录为 `shared_context` 精确引用，新增正文仍分别保存在 `fragments` 和 `support_context`。独立回读可以按这些范围重建内容，相同范围不重复收费和展示。预算不够容纳某单元时选择其他完整单元。已排名材料继续保留，其 `delivery_status` 说明片段已选、预算不足、范围重叠或没有局部候选。

token 预算要求实例显式配置 `wave.query.tokenizer_path`，指向本地 Hugging Face `tokenizer.json`；相对路径以实例配置目录为准。计量原文并集经该 tokenizer 编码后的 token 数，不计模型消息和提示。已保存交付记录实际 tokenizer 身份；后续扩展才需要再次读取该 tokenizer。

程序选择模型排序或评价时，已返回排序结果的候选按模型名次优先选择，未返回或未送评的候选继续保留局部顺序。分类量表仅声明允许的值；程序另以 `category_order` 明确指定全部类别的优先顺序时才据此排序。没有指定顺序时只保存分类判断。数值量表由 `numeric_order` 指定较高或较低值优先。模型原分和评价等级按原尺度保存，不与局部 RRF 数值直接比较；评价摘要同时保存全部实际返回项及其候选和来源范围，预算未选中的评价也可以回查。

查询只返回本次固定快照的候选和来源。保存证据、历史计算引用或反馈时由相应正式 owner 管理保留关系，正文和来源按原有内容引用读取。
