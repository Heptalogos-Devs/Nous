# Nous 语义输入与可替换数值扩展

## 扩展位置

VCP 是 Wave 中完整的一组算法。Nous 的输入模型独立表达描述型概念、多来源候选、关联类型和时间；投影时才转换为 VCP 数值。没有自然对应的语义保留在单独输入/通道中，不截断成一个 Tag 字符串。

本轮扩展是可执行的投影与读取能力，不创建长期认知生命周期。

## Concept 与 Anchor

Concept 的 label/aliases 供精确线索，description 参与向量。Schema 的正文可成为普通候选，其支持根从真实来源取得。Nous Anchor 可以由显式概念或关系中心投影为数值节点/重点集合，但不会与 VCP 直接锚评分或 anchor_gain 共用同一个持久身份。

提供 `inspect_neighborhood` 计算某 Concept 的连接概念、独立根数量、入出权重和候选覆盖。这是吸积研究的只读信号；检索次数不写回事实权重，不自动创建/合并/拆分概念。

## 有类型的关联

关联保留 source/target、类型、方向、strength、confidence、polarity 与独立来源根。三类量分开：业务关系程度、对判断的信度、检索传输数值。配置给每种实际采用的关系类型一个 retrieval_gain。

本轮关系端点为 Concept 节点。未来实体或认知对象先由其领域提供合适投影；不直接把所有 Social 边无差别送进 VCP。

正关联按 [关系投影](evidence-projection.md) 保留完整支持组并计算附加质量。联合前提不均分成独立见证；重复派生不增加同组质量。方向与关系类型保留，未知类型明确报告未投影。解释性关系通过显式实验 profile 开启，原始 VCP 路径可独立使用。

VCP 原始共现事实与附加质量在事实层汇合，再共用同一传输校准/行预算。不要在已经归一化的 CSR 上任意加边。没有附加关联时，走原 VCP 数值路径。

负关联/contradiction 保存在独立的关系索引，不对非负传输算子取绝对值。`include_counterevidence` 根据命中候选的 Concept/root 关联，返回相关反证候选与其明确关系、来源。它不自动降低正文真实性或触发认知修订。需要未来竞争性传播时可在该通道演进，不污染原 VCP 假设。

## 原文与派生独立性

原始来源贡献 source 质量，派生总结、Schema 和 Journal 可贡献有依据的解释结构。二者使用明确类型和支持组，候选数量不增加独立见证。正文血缘与认知支持分开，详见 evidence-projection；来源归并由实际声明决定。

## DTSC

保留独立的 DTSC 字段/曲线算法，位于 `native/vcp/src/dtsc`，通过正式 query.mode=dtsc 调用。输入复用当前 Snapshot、查询观测、候选曲线和配置；不恢复旧 baseline 运行栈。

保留其 field trust、curve contact 和低证据回退的实际公式与诊断。无效矩阵在公共边界返回错误，不沿用历史实现默默裁掉坏向量的补偿。结果明确算法名，不能把它假报成最新 RiverMemo。其是否作为默认路径由真实资料效果另作决定，本轮默认仍是已选完整混合检索。

## 时间与范围

候选与上下文使用现行时间域/多轴值。时序出现顺序不是事件有效时间；不把 VCP 文件时间偷换为 Nous 五轴。过滤在共同 Wave 查询 owner 决定，Native 接受实际候选集合；需要限制证据影响时在构建证据视图时处理。

## 验证目标

真实检索应能分别观察：描述较长的 Concept、未知临时 cue、有上下文/无上下文、多根总结、重复派生、显式正关联和反证返回。判断影响来自哪个通道，保留不提升的结果，不预先承诺算法质量。
