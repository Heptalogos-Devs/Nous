# 配置修改、生效与数据绑定

## 四种修改效果

`live`：可以立即改变的轻量行为，首轮只实现已明确的日志级别。

`next_operation`：后续操作使用新快照，已开始的操作继续使用原值。

`restart`：新配置已经保存，现有运行资源继续旧配置，重启后整体采用。

`new_binding`：值定义持久数据的身份或解释，修改要经过相应 owner 的操作，普通 set/reload 不覆盖已有绑定。

修改影响与呈现层级分别标注。`data_bound` 必须在普通 CLI 说明中解释其后果；把字段放在高级菜单不会解除这一规则。

## 修改操作

Configuration 读当前文件与有效版本，在锁内对补丁合并、校验，生成明确的变化结果。普通修改不强制 dry-run 或重复确认。`preview` 供用户主动查看，不是所有写入的固定前置。

实例文件采用 tomlkit 编辑，只修改目标字段。写入同目录临时文件，再使用操作系统文件替换；临时文件由当前操作清理。标准原子替换用于避免半份配置，不新增多层文件事务或故障恢复数据库。

结果包含：保存位置、变更路径、已保存值、有效值、来源、是否被更高来源遮蔽，以及 `saved / applied / saved_pending_restart / rejected`。离线保存使用 saved，表示下次启动读取；只有当前运行时实际发布后才使用 applied。

离线管理取得实例锁后修改。进程内更新可带 expected_version，版本冲突返回最新状态，调用者重新读取后决定。管理员直接编辑文件后调用 reload；外部修改造成语法或绑定错误时保持原有效快照。

## 首轮的快照发布规则

当补丁全为 live / next_operation 时，候选整体校验后保存文件、发布新的不可变快照，再执行少量明确的 live 设置。文件保存失败时不发布。

当补丁包含 restart 字段时，整项修改保存为期望配置，当前快照保持不变，返回等待重启。已有等待重启修改期间，后续修改也保存为期望配置并等待重启，避免任意拼接两代资源设置。重启成功后清除等待状态。

这里不建设通用资源准备/回滚协议。将来某项资源确需热替换时，在其 owner 内补充明确的能力。

来源覆盖可能令刚写入的值暂时无效。例如设置文件为 INFO 而环境强制 DEBUG，返回 saved-but-shadowed 说明，用户能看到真正的来源。

## 先设置、后形成的绑定

Embedding 的模型、维度、预处理、查询/文档输入规则与归一化共同决定向量空间。首次创建空间时提示需要完整核对。空间投入使用后不得通过 set、更换环境变量或手改 TOML 保留旧 ID 又改变描述。完整合同在[向量空间](../models/embeddings.md)。

时间域 ID 定义已有坐标的解释。首轮在基础数据库登记正式域定义；相同 ID 的 kind、tick_seconds、epoch 改变返回 `configuration.binding_conflict`。名称等显示信息可以更新。需要另一种坐标解释时创建新域 ID，原坐标继续引用旧域。

实例 ID、正式数据根与数据库位置按实例合同处理。修改当前路径时既有数据不应被无声遗落，返回重定位要求。首次 init 之前可自由配置。

配置解析只校验形状；涉及绑定的采用在数据库可用后调用对应 owner 的检查。缺少需要的绑定 owner 或存储不可读时，结果明确为无法检查，不能假定未使用。首轮没有 Embedding 写入，空间的运行绑定由后续 Embedding owner 建设；不得提前允许向量资产写入绕过该合同。

## 权限与凭据

本轮 CLI 是本地操作者权限，不扩展出通用 RBAC 框架。配置中的 credential_ref 可以展示，实际凭据按凭据专题解析，不复制到日志、导出 schema 或快照说明中。危险修改不能靠一个全局 `--force` 跳过数据绑定。

## 完成条件

普通更新、新旧快照、被环境遮蔽、重启待生效、手改文件冲突、时间域身份改变各有实际操作结果。数据库无效时仍可做语法检查和编辑非绑定设置，但不能报告绑定检查已通过。
