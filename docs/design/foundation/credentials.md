# 凭据引用与读取

## 责任与范围

凭据能力将名称解析为运行所需秘密，不承担主体身份或通用权限系统。本专题在模型与网络建设时接入；首轮配置只解析引用形状。

默认支持环境变量与受实例管理的秘密文件。现阶段不实现自制加密保险库；以后需要系统 keyring 时采用成熟后端并单独设计无头环境行为。

## 配置形状

```toml
[credentials.gateway]
kind = "env"
name = "NOUS_GATEWAY_TOKEN"

[credentials.local-file]
kind = "file"
path = "secrets/gateway-token"
```

file 路径相对实例配置目录；env 必须指向明确变量，不在所有环境变量中猜测。Provider 保存 credential_ref，不保存实际秘密副本。没有凭据的本地服务可以明确省略引用。

`resolve(ref) -> SecretValue` 在资源需要时读取。缺失返回清楚错误，不默认以空字符串尝试连接。配置说明只报告引用、是否可解析和必要的错误，不返回秘密值。

## 权限与输出

写入秘密文件时使用平台可用的私有访问方式：POSIX 权限与 Windows ACL 分别按平台能力处理，不宣称一个 chmod 值在所有平台具有相同保证。用户可以自行以环境变量提供凭据。

禁止把实际秘密放到 CLI 参数、Prompt、配置导出、模型结果或普通 Trace。调试也不记录 Authorization/Cookie。凭据读取错误保留可理解的来源名，显示完整秘密没有诊断价值。

## 生命周期

运行中的请求持有自己已解析的凭据。后续新调用按资源策略读取或重建客户端；轮换不改写已发生的调用身份。应用关闭释放客户端，不在后台保留独立凭据轮询器。

完成条件：环境和文件两种方式实际调用可用；缺失可诊断；日志、预览和错误不包含测试凭据。无需为此建设独立身份服务器。
