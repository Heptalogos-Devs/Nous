# 操作、阻塞计算与资源关闭

## 当前保留能力

ExecutionManager 负责根操作名额、配置快照、截止时间、运行范围与实际阻塞工作。继续使用标准 asyncio、ThreadPoolExecutor 和 contextvars。

应用请求可在取得业务名额前固定配置快照和截止时间，以受控方式读取调用方输入；随后进入的根操作沿用该快照和期限，并按正常规则排队。请求本身由运行时跟踪，关闭时等待或取消。

同一 ExecutionManager 内嵌套操作继承上下文；A→B→A 中 B 有独立名额，回到 A 复用 A。前台按作用域完成信号结束，spawn 和持久工作按实际 Task 生命周期结束。持久工作的最终检查点完成前，该 Task 仍受宿主管理。

独立后台任务和持久工作从新的请求边界取得配置与期限，不继承发起请求的操作、期限或接纳状态；Trace 等关联上下文继续保留。

已接纳操作在停止接纳后的宽限期内可完成嵌套阶段和清理；新根操作被拒绝。Job 查询、等待与控制参与生命周期但不占业务并发名额。OperationContext 不保存全局服务容器。根操作绑定所调用 Runtime 的实例/启动关联与观测 provider；队列阶段恢复入队时的 Trace 关联。

## 共同阻塞操作

ExecutionManager.blocking(action, *args, on_cancel=None, **kwargs) 管理实际 worker。等待方收到取消后先调用一次同步、轻量的 on_cancel（若有），等待真实 worker 完成，再传播原 CancelledError。收尾异常附在原取消上；重复取消也继续等待。

Native 使用 on_cancel=token.cancel。CAS 的文件操作和发布复用同一等待能力，文件句柄、临时路径和发布锁保持到 worker 退出。能在 worker 内完成打开/关闭的操作优先使用这一方式。正文缓存命中的反序列化、绑定及未命中的序列化也属于阻塞计算；媒体子进程的终止、必要时 kill 和等待退出在重复取消下继续完成。

异步创建文件句柄、临时目录或子进程时，创建完成与调用方接管之间的资源也有明确所有者：`acquire_owned` 在接管前收到取消时等待创建结束并释放所得资源。文件读取进程、媒体进程与 CLI 子进程共用 `stop_process` 完成终止和回收；已接管后的正常关闭由各自使用范围负责。

## 请求与并行层次

顶层应用操作获得一次并发名额，阶段沿用剩余总期限。阶段 timeout 可以更短，不能延长根期限。业务通过 TaskGroup 管理需要共同结束的子任务；不将普通 create_task 的继承上下文当成脱离父范围的许可，独立后台动作使用 spawn。

Native 所有请求共用一个有界 Rayon 池；Python 的 worker 只承载跨语言调用，不为每个调用新建 Rust 池。选择合理池数而不是逐核嵌套线程爆炸。Native token 仅在循环/批次安全点生效，不伪造杀线程。

## 生命周期范围

多个普通 Runtime 可在同进程使用各自的实例资源与日志作用域。持久宿主独占本进程的 DBOS 单例。

关闭时先停止新入口和持久业务接纳，等待已接纳操作；宽限期后取消仍在运行的任务，并等待协程、子进程和托管 worker 实际结束。宿主再通过自己的线程池销毁 DBOS，之后才关闭 Job 客户端、业务资源、观测与实例锁。正常停机保留未完成工作的恢复资格；显式用户取消改变持久工作状态。
