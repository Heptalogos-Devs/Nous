# 操作、阻塞计算与资源关闭

## 当前保留能力

ExecutionManager 负责请求关联、配置快照、截止时间、运行期 Task 与实际阻塞工作，使用 asyncio、ThreadPoolExecutor 和 contextvars。

应用请求在读取调用方输入前固定配置快照和截止时间；宿主请求从接纳起计时，等待连接容量、输入取得、业务调用与保存共享期限。请求由运行时跟踪，关闭时等待或取消。模型连接、文件读取、媒体转换和 Native 计算各自管理容量。

同一 ExecutionManager 内嵌套阶段继承配置和期限；前台请求按作用域结束，后台工作由 Runtime 持有实际 Task 至退出。

独立后台任务从新的请求边界取得配置与期限，保留发起操作的关联信息；它不持有客户端输入流或观察者。

已接纳操作在停止接纳后的宽限期内可完成嵌套阶段和清理；新根操作被拒绝。运行期操作查询、等待与控制不占模型或转换容量，宿主的等待请求也不会占用取消控制所需的连接容量。OperationContext 不保存全局服务容器，根操作绑定所调用 Runtime 的实例和观测作用域。

## 共同阻塞操作

ExecutionManager.blocking(action, *args, on_cancel=None, **kwargs) 管理实际 worker。等待方收到取消后先调用一次同步、轻量的 on_cancel（若有），等待真实 worker 完成，再传播原 CancelledError。收尾异常附在原取消上；重复取消也继续等待。

Native 使用 on_cancel=token.cancel。CAS 的文件操作和发布复用同一等待能力，文件句柄、临时路径和发布锁保持到 worker 退出。能在 worker 内完成打开/关闭的操作优先使用这一方式。正文缓存命中的反序列化、绑定及未命中的序列化也属于阻塞计算；媒体子进程的终止、必要时 kill 和等待退出在重复取消下继续完成。

异步创建文件句柄、临时目录或子进程时，创建完成与调用方接管之间的资源也有明确所有者：`acquire_owned` 在接管前收到取消时等待创建结束并释放所得资源。文件读取进程、媒体进程与 CLI 子进程共用 `stop_process` 完成终止和回收；已接管后的正常关闭由各自使用范围负责。

## 请求与并行层次

阶段沿用剩余总期限，可以缩短而不能延长根期限。同键派生在所属 owner 的锁内重新检查完成缓存，等待锁不持有模型、转换或 Native 容量。业务通过 TaskGroup 管理需要共同结束的子任务；独立后台动作使用 spawn。

Native 所有请求共用一个有界 Rayon 池；Python 的 worker 只承载跨语言调用，不为每个调用新建 Rust 池。选择合理池数而不是逐核嵌套线程爆炸。Native token 仅在循环/批次安全点生效，不伪造杀线程。

## 生命周期范围

多个普通 Runtime 可在同进程使用各自的实例资源与日志作用域。只有显式允许后台工作的作用域接纳后台维护；活动 Task 和少量近期终态由该 Runtime 持有。

关闭时先停止新入口和后台工作接纳，等待已接纳操作；宽限期后取消仍在运行的任务，并等待协程、子进程和托管 worker 实际结束，随后关闭业务资源、观测与实例锁。未完成工作在运行期结束后消失，已提交成果继续可读。
