# 资源生命周期

## 负责范围

生命周期管理负责实例运行资源的建立、停止接纳、取消和关闭。它不判断某条记忆应保留多久，也不承担持久任务的业务状态。

资源通过标准同步或异步上下文管理器提供生命周期。Bootstrap 使用 `AsyncExitStack` 组合。模块内部只有必要的启动、关闭和状态行为，不创建相互回调的全局服务图框架。

## 生命周期状态

运行时使用 `starting / ready / stopping / stopped / failed`。可选能力有自己的 `ready / disabled / unconfigured / unavailable` 结果。`ready` 只表示当前要求启动的资源已可用。

一个进程默认打开一个有写入责任的 Nous 实例。单元级纯配置、时间和数据值可以任意构造。多个独立实例通过独立进程部署，避免全局 SDK 和日志配置相互覆盖。

## 关闭顺序

传输入口先停止接纳新操作，后台执行停止领取新任务。现有操作在 `runtime.shutdown_grace_seconds` 内完成；到期向可取消工作传播取消。进程内 TaskGroup 结束后关闭模型与网络，再关闭内容和数据库。最后刷新 Trace/指标导出和日志，释放实例锁。

没有启动的资源不执行伪造关闭动作。启动失败只清理已成功取得的资源。取消信号不得被普通 `except Exception` 转为成功。

## 阻塞工作

线程内的同步调用与 Native 计算不会因为等待它的 coroutine 被取消而立刻停止。执行模块维护仍在运行的实际任务及其资源引用；取消后不能立即释放它正在使用的数据库连接、文件或 Native 资产。

可协作取消的计算使用库原有机制；媒体子进程由负责者终止并 wait 回收。超出正常关闭期限时明确报告仍在收尾，不宣称已经完成。第一轮不自研强制杀线程能力。

## 更新资源

首轮对数据库路径、连接池、观测导出器及其他需重建的资源设置采用重启生效。后续确有需要时为具体资源实现新建、切换、旧资源释放；不预建一套通用热替换框架。

配置中的 `next_operation` 字段只影响之后的操作；当前操作继续持有自己的快照。立即生效字段限于合同明确支持的轻量设置，例如日志级别。

## 验证

正常开启和关闭、启动中途失败、等待中的操作被取消、仍在工作的线程不被提前销毁，分别覆盖一条有价值的实际路径。无需为每种库资源建立重复的生命周期 Mock。
