# 提交后标注与检索刷新

正文修订首先在正式事务中提交。`AfterWrite` 决定提交后是否标注、刷新以及等待或在当前 Runtime 后台执行；返回的 `RecordOutcome` 分别携带已提交修订、维护结果和问题。

`annotation=default` 按 `cognition.annotation.on_save` 和召回资格决定；`skip` 不运行，`run` 明确请求。`refresh=run` 使用所选检索模式，`defer` 不启动刷新。`execution=wait` 等待维护；`background` 要求持有后台工作的运行环境，并返回 `RunningOperationRef`。无宿主的显式后台请求在写前拒绝；提交后若容量不足或开始关闭，则正文继续可读，维护报告 not_started。

## 标注

标注读取精确正文、候选概念版本和预期活动标注，生成完整提案并保存。采用时在短事务核验正文及活动指针；已过时的提案保留，不能覆盖新的正文或标注。自动标注只激活仍符合召回资格的当前正文，显式标注未召回 Note 合法。

标注失败作为独立阶段报告；同时请求刷新的情况下，刷新仍会运行。成功激活改变检索视图时推进认知代次，后续刷新或当前查询使用新的正式视图。

## 刷新

刷新读取轻量目录，展开变化的正文、来源与标注，复用不变的投影和向量；Native 组件在事务外构建。最后一个短事务发布完整快照，并只在捕获代次仍是当前代次时提升 current。若构建期间有新写入，本次返回捕获代次、较新的当前代次以及 `current=false`；下一次显式刷新或查询处理新状态。

## 生命周期与状态

当前 Runtime 持有普通异步 Task；运行期可以查询、等待或取消。关闭时停止接纳，等待或取消实际工作，并在子进程和阻塞工作退出后释放资源。进程重开后任务引用过期，已经提交的正文、成果、提案、草稿和快照仍可读取。未完成工作按需要发起新的完整操作。

重复采用已采用草稿返回同一正式修订，不自动补做维护。编辑会话的写入键只保护明确的文稿提交幂等。操作及资源关闭见[执行与生命周期](../foundation/execution.md)。
