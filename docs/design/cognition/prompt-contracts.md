# Journal 语言任务的输入与输出

## 写作

journal-draft 输入为 topic/purpose、必要的 viewpoint、带 S1 等短键的完整材料和目标旧正文（修订时）。目标基准仅在程序端保存，不让模型计算 expected_revision。输入材料按 joint 共同阅读。

system 定义写作要求与禁止行为：提炼、压缩已有内容，自然呈现经历、知识、观点、感受与理解，忠实保留主体、条件、经过、次序、否定和不同观点。作者由写作意图给定；作者不定时使用记述者角度，区分已有主体与立场。不同输入未必属于同一事件，不补造共同身份、先后或因果，也不改变计划、愿望、要求、推测与已完成行动的状态。不擅自添加分析、解释、观点或改变原意的扩写修饰，不把介绍任务或逐份汇报输入的旁白写进正文。

来源使用 `[说明文字](source:S1:C1)`；可见 label 是有意义的标题、主体、内容、观点或指代，应当参与句子，完整机器键只用于回溯。不用“来源 S1”之类机器标签或“这段材料”之类空泛指代作显示文字。没有新增内容可成篇时仅返回 `!NO_MATERIAL!`；trim 后精确匹配由 JournalDraftTask 解释。空响应属于模型输出错误；标记之外的实际文字保持为正文，不做模糊匹配。

user 模板只传递非空的主题与写作意图；来源由共同输入能力附加。写作规则集中在 system，不在 user 重复，也不设置固定字数门槛。

来源键示例用于教会表达，不构成词数上限或强制每句引用。正文之后不追加模型的制作过程说明。模板与字段均沿 PromptCatalog/Jinja；具体模板文件在实施时原地修改，保留当前调用配置及用户实例覆盖。

## 标注

输入为一份 exact TextView 的 B1/B2 正文块，以及可选候选：`C1：资源生命周期（完整说明）`。输出继续为少量 concepts、occurrences、paths。ConceptProposal 可以使用 reuse_key 指向 C1，否则提供新 label/description。正式身份只由程序建立；reuse_key 的内容采用给定候选版本的说明，模型重复写出的 label 不覆盖它。

occurrence 只引用真实块；path 只引用已经提出的 occurrence。无路径是正常输出。新问题的临时 cue 不强制产生长期 Concept。标注不判断独立证据数、时间有效性或图权重。

## 可编辑与可诊断

任务资源以普通 Markdown/Jinja 保存，可用 prompt show/edit/preview。运行前冻结模板及合同；后续用户编辑影响下一次操作。模型无效引用返回任务错误和实际结果，显式配置的结构修复按原共同执行策略进行。

不预设额外“审核模型”。用户选择保存或继续编辑，程序检查确定的身份/选区/版本，语义质量在 journal-use 的实际材料上改进。
