# 可独立发布的基础平台

## 当前研发目标

新仓先建设通用基础平台，达到独立安装、独立使用、独立发布和真实工程复用后即暂停。未经后续新的产品授权，不继续实施 Nous Memory、Wave、Ego、Social 或其他认知业务。

平台是否成功，以两个与 Nous 无关的真实消费者能轻松开发、运行、调试、打包和维护为核心判断。测试服务这一实际目标；不以框架、类、测试的数量或总代码长度作为成就。

## 责任与能力

- Installation / Instance / Session：完整软件发行、Portable 布局、实例选择、资源建立关闭、实际任务取消和运行容量。
- Configuration：分层 TOML、人类可读的字段说明、Zod 类型和有效快照、来源及热切换或重启语义；内部计算参数可以使用 JSON。
- Errors / Logging / Trace / Metrics：有上下文的公共错误，启动期最低诊断与正式运行期追踪，关联真实操作、模型尝试和产物。
- Storage / CAS：SQLite 短同步事务、正式记录和不可变字节，实例级路径，精确来源和备份；旧格式转换是独立离线工具。
- Content / Input：文本、图片与可扩展媒体来源及表示、精确范围、结构化材料和可直接阅读的完成成果。
- Models / Prompt：供应商中立的模型连接与能力选择、真实模型输入规划、结构化输出、可编辑模板、无需查看代码即可理解的任务文档。
- Localization / Time / Application：界面文案和错误本地化；现实、单调与业务时间域；共同类型化 SDK，CLI 为第一入口，HTTP/MCP/gRPC 是适配。

跨模块共享真实标准类型和成熟基础库。实现细节由各 owner 承担；不得通过跨模块复制 DTO、空运行状态、额外身份或通用工作流让调用者承担复杂性。

## 技术基线

Bun 1.4.4、TypeScript 7.0.2、Zod 4.6.7；Bun workspace/catalog/isolated linker。Rust 1.100.0，napi-rs 3.x，独立纯计算 crate 和薄绑定 crate。仓库根维护 bun.lock、Cargo.lock，统一 check:repo 与 CLI/Native 真实构建。

产品层依赖基础平台；基础平台不依赖 Nous 领域。平台可作为独立 TS 包或发行物发布，在 Nous 业务尚未实现时仍能被其他项目使用。

## 当前阶段的截止条件

先完成并使用基础平台，再评估其适用性和修改成本。平台建设阶段结束后，停止向 Nous 领域推进。发现未来 Nous 业务要求修改基础时，先判断是原基础责任缺口、通用新需求还是具体业务职责，优先让领域自身承担专有部分。只有确定通用基础确实不完整时才修订其合同。

旧实现位于 legacy/nous-python，PR #60 保留在原开发分支。它们提供历史信息，不成为新平台 API 和模块树的模板。
