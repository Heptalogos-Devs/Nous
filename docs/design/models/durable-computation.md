# 语言任务与成功结果恢复

## 正式结果与任务语义

GenerationOperations 在发送前冻结实际任务的 Prompt 模板、解释合同、模型语义、参数和路线。输入确实需要转写时，冻结对应转写任务；纯文本任务不依赖无关转写配置。冻结内容通过 Artifact 和 ResultStore 保存，凭据仅保留引用。新请求加载冻结任务时核对当前连接绑定与运行限额。

GenerationRequest 包含任务、SelectedInputs、问题、指令、输出 Schema、批次语义和正式执行依赖。稳定 computation_key 标识一次计算；主动重新生成使用新 key。请求身份由语义输入和精确选择决定，显示名称和物理批次不改变身份。调用方提供的完整输出 Schema（包括描述、示例与字段顺序）进入请求身份；执行前捕获请求值，后续修改调用方对象不会改变本次执行。

模型协议响应完成并通过输出校验后，GenerationOperations 先采用 model.language_response，再由静态 TaskDefinition 解释有名输出。响应保存实际输入与 SourceContext、原始协议输出、请求参数、实际路线、用量、冻结任务引用以及执行依赖。解释合同保存输出验证约束、来源引用及程序产物语义；Prompt 编辑说明和字段帮助不改变解释合同。

## 恢复顺序

完整 run 或领域 propose 先查询自己的正式结果；已采用的结果直接返回。没有正式产物时，produce 按 computation_key 查找已采用响应；存在则使用保存的实际输入和安装的 TaskDefinition 在本地解释。只有两者都不存在时才准备媒体、核对当前模型绑定并发送新请求。同一计算的并发请求在生成 owner 的短键锁内复用结果，不阻塞无关计算。公开的 produce_prepared 使用同一键锁并核对准备内容、输入组、覆盖范围和依赖；即使调用方提供相同的语义身份，不同准备请求也不能复用。

同键等待和执行名额排队共同消耗该操作的原始截止时间。等待键锁不额外占用执行名额；若取得名额时键已被其他工作占用，则先释放名额再等待。根请求按键经过槽外公平入口，已持有名额的嵌套调用绕过该入口并可以先取得可用键，避免单名额互等和同时起跑的活锁。等待者超时或取消只结束自己的调用；运行中的计算继续。关闭实例时等待者也被跟踪，并按关闭宽限期取消和回收。

公开 `produce_prepared` 的身份合同独立于给人看的请求预览：它覆盖实际模型消息及媒体字节摘要、完整输出 Schema、Prompt 执行签名、任务解释合同、有效路线与模型绑定、生成限额、准备后的阅读上下文和 coverage，以及调用方指定的输入组、coverage、选择、阶段引用和依赖。它不使用进程内配置版本、日志设置或 Prompt 编辑说明；成功结果保留最初执行时的诊断信息。二进制内容只参与摘要，不写入身份记录。执行前捕获独立请求快照，使随后修改调用方的可变容器不会改变已确认的身份或结果；coverage 中等价的元组和列表按持久化 JSON 形式统一，无效值在调用模型前拒绝。带固定 producer key 且可能准备备选路线、或使用自定义输出验证器的调用方须提供稳定的 `request_identity`，覆盖回调及其输入的语义；该身份与已准备内容共同核验，不能替代后者。无固定 key 的一次性调用和 `run_prepared` 不需要额外身份。

recover_response(response_ref, snapshot) 和按原 key 重入 produce 使用同一解释路径。当前 Provider、凭据或 Prompt 是否仍然配置不影响已保存响应的本地解释；安装的解释合同已经改变时返回 model.task_contract_changed，原响应保持可读。

语言响应和成功转写先按计算键写入内容目录下的原子、校验恢复记录，再发布正式结果字节并进行事务采用。发布或采用失败后，同一计算键重入 produce 可恢复语言响应；resume_response 也接受错误附带的 PendingResponse 或 producer_key；recover_result 按该键恢复并幂等采用正式结果。转写采用遇到数据库繁忙后，同一已接受输入可在重启后读取记录继续采用。正式响应或转写结果提交后清理记录；尚未采用的记录保留以供重试。语言恢复核对已保存的解释合同和 Schema，并保留调用方显式指定的输入组与覆盖范围。远端完成与本地首次保存之间仍有进程中断窗口；如果恢复记录本身无法写入，只有运行时持有的值可用于恢复。模型执行器按配置执行有限次数的请求和修复。

媒体派生以已接受 Artifact、选区和转换参数共同确定身份。同一 Runtime 内同键音频转换、缓存查询与派生结果采用共享互斥；转换失败或取消后释放锁供重试，不把不同 Artifact 仅按相同字节合并。复用转写不合并调用方各自的描述请求。

## 组合采用

ProducedTask 是进程内的解释结果。prepare_adoption 发布输出字节一次并得到 PreparedProduction；adopt_in(tx, prepared) 在调用者的短事务中采用这些已发布输出，并登记输入、输出映射和执行依赖。事务回滚后可复用同一准备值。ResultStore 的 producer_key 防止同一业务键采用不同结果。

标注生成形成正式提案 ResultRef，之后的标注采用直接读取提案。写作在请求前由 DraftStore 保存 WritingRequest，包含精确 base、来源、反馈映射、写作意图、采用选择与 AfterWrite，并作为语言响应的执行依赖。解释、草稿保存或采用失败返回正式写作请求引用；writing.recover 和 journal draft recover 从该引用继续，保留原基准与意图。已采用草稿重试返回原修订。

执行依赖保存恢复所需引用，不参与独立证据根的计算。字节、实际输入和正式结果分别由 ContentStore、ArtifactStore 和 ResultStore 持有。
