# 重试与备用模型

## 责任与默认

ModelExecutor 是生成尝试的唯一负责者。fallback 列表有固定顺序，来自任务配置并整项覆盖。默认无备用模型；max_attempts 默认 2 是整个操作的上限，不代表必须调用两次。

SDK、HTTP transport 和 workflow 不各自叠加隐式重试。配置中允许的网络重试和模型备用共同计数。

## 触发

连接暂时失败、限流、可恢复的 Provider 5xx 可以按剩余期限和 retry_after 处理。认证/权限、模板缺字段、输入格式、模型能力不足及取消直接返回，修正配置后再运行。

同一资源短暂重试与进入下一模型由任务规则选择。结构化格式修复单独配置，默认 0 次；开启后仍受总尝试次数限制。不得把“模型答案不符合主观期待”自动定义为无限重新生成。

输出已流向调用者后失败按部分结果返回。多模态 fallback 要求候选仍满足实际输入能力；视频转帧属于显式媒体策略，不静默改变任务。

## 资源和出处

下一候选使用自己的 preset、协议能力与 Prompt 角色映射，重新形成 PreparedGeneration。每次真实尝试保留模型、开始结束时间、结果/错误和用量。

相同任务预算和来源范围贯穿所有尝试。备用模型配置不授权新的外部工具或其他系统动作。

## Embedding

只允许在配置中明确声明同一空间合同的等价服务端之间重试。向量维度相同仍可能是不同空间，不能作为备用兼容性判断。需要另一空间时走[向量空间](embeddings.md)的明确转换和重建。

## 采用成熟实现

Pydantic AI FallbackModel 已支持异常及响应条件选择，可用于满足上述合同的部分。需要逐候选重新编译、跨候选统一预算或流式边界时，在唯一 ModelExecutor 中组合相应已支持接口，不再新增独立的通用策略引擎。

验证连接失败进入明确备用、认证错误不重试、流开始后不拼接、总预算不翻倍。依据：[FallbackModel](https://ai.pydantic.dev/api/models/fallback/)。
