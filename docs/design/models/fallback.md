# 统一尝试与备用模型

## 责任

ModelExecutor 是一项语言阶段的唯一尝试负责人。SDK 与 HTTP client 自动重试关闭。网关内部渠道重试由网关配置管理，Nous 不复制渠道策略，不把一次提交记成它无法观察的多次上游调用。

fallback 是任务配置中的有序候选，同一快照选择。主模型名、厂商或价格不触发硬编码分支。

## 具体策略

默认每个语义阶段最多两次本地提交。首次使用主模型；遇到可重试的连接/暂时服务/限流失败时，优先使用下一个明确配置的兼容候选；无候选则在剩余期限内重试同一模型。已有 Retry-After 可以使用，但睡眠计入本阶段期限与根操作期限。

认证/输入/schema/template 不匹配等确定错误直接报告，不通过无限更换模型掩盖。输入超出能力时由媒体或输入 owner 重新组织明确表示，再作为新准备结果执行。

输出格式修复默认 0。启用时它与重试/fallback 共用阶段尝试总数；不增加另一个自审模型。能力检查必须覆盖输入模态、输出模式和有效参数。fallback 不得在未说明的情况下丢音轨、删除 PDF 页面或把原媒体替成摘要。

纠错保留原响应及校验反馈，通过 Pydantic AI Direct API 将反馈投影成当前协议支持的 user/tool 消息后发送；各次已返回的真实用量合计到该阶段结果。输入和模板继续使用原准备快照。

## 流与取消

有用户可见 delta 后停止 fallback。取消不重试。网络超时可能已在网关执行，记录实际已知信息；不新增付费回执或 exactly-once 服务。

## 技术采用

Pydantic AI 的 FallbackModel 在能精确表达所需异常、能力和计数时可复用；无法共享本项目阶段计数时用一个小的、集中在执行器中的尝试循环。两种方式择一，不能同时叠加。

Embedding 仅在同一明确空间合同中备用；普通生成的候选链不跨向量空间套用。
