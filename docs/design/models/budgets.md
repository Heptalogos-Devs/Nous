# 调用期限、用量与技术限制

## 本轮授权

用户已授权使用受控本地网关完成真实调用，不以费用或余额作为本轮前置。金额上限为 null，配置非空上限会被拒绝；价格未知可以正常运行。记录实际 token/用量；本轮不建费用预约、预扣、余额检查、每日限额或支付账本。

## 三个不同范围

根操作继承 Execution 的可选总 deadline，覆盖读取、媒体准备、所有模型阶段、结果保存和取消。无明确总期限时不额外强加整条管线必须在一个模型 timeout 内结束。

一个语义阶段使用 task/model_execution 的 timeout、max_attempts 和输入/输出上限。重试、结构修复和备用模型共享这一阶段的期限与尝试数，不因切换资源重新开始计数。

描述和结构化是两个计划内阶段，各自有正常请求额度；多页分批也是按实际输入形成的多个阶段。应用聚合全部实际用量和耗时，不把 `max_attempts=2` 误当作整份文档只能调用模型两次。本轮不新增默认有限的 pipeline 模型调用总数。

## 输入与分批

输入上限覆盖角色消息、模板、Schema、媒体和来源文字。可获得真实 tokenizer/提供方计数时使用成熟能力；否则标为 estimated，不把字符数写成真实 token。媒体按准备后的尺寸、页数、时长和字节估计；提供方实际用量另存。

超限时按完整页/时段/语义块分批，或者返回需要缩小输入的明确错误。所有被请求范围的处理状态可见；不能只读取前 N 页却报告整个文档完成。

输出上限实际传给支持该参数的 SDK。被截断的结构化输出不能按空字段修补成成功；保留实际结束原因。

## 生效

实例上限、任务选择和调用覆盖由现有配置机制解析。模型能力上限继续约束实际参数。费用无限授权不会消除必要的超时、内存、协议大小和有限重试机制；它们服务于运行与取消，不向模型灌入预算控制提示词。
