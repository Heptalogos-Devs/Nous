# 模型预算与资源计量

## 范围

预算决定一项已授权操作可以使用的调用次数、时间、输入输出规模与并发。费用以真实用量和明确价格来源估计；本轮不建设支付、充值或企业账本系统。

## 合同

实例限制给出上限；任务选择其中所需额度；本次调用可以降低。ModelBudget 包含 max_attempts、deadline/timeout、max_input_tokens、max_output_tokens 及可选金额上限。一个业务操作内的主模型、重试、格式修复和 fallback 共同消耗它。

并发上限由执行能力提供，排队计入总期限。重试睡眠也计入期限。新尝试前检查余量，不在超时后重新开一个完整时限。

## 输入与输出

输入预算覆盖完整消息、工具定义、输出 schema 和实际媒体。模型有可用 tokenizer 或计数 API 时采用其支持能力；只能估计时标记 estimated，保留估计方式。字符数不标作实际 token。

输出上限传给支持该参数的 Provider；实际结果用提供方用量。无法支持所要求的严格输出限制时，在准备中说明能力不足。未知输入长度不能用 0 掩盖。

金额限制依赖已配置的价格与计费模型。缺少可靠价格时只能使用次数/token 等限额，金额状态为 unknown。不要把它描述成硬计费保证。

## 多调用任务

两阶段媒体处理由负责任务分配共同预算。例如描述已经成功但后续结构化失败，成功描述可以保存复用；下一次继续不因重用描述而重复计费。是否重新处理由实际用户操作决定。

持久工作恢复后读取已有结果和已用额度，不能重置为一次全新授权。任务期限仍按实际 UTC 持久条件恢复，进程单调值不跨重启保存。

## 实施

使用所选模型库已有 usage 对象和调用限制，补足 Nous 的共同预算归属。预算不会作为模型需要推理的 JSON 控制计划放入 Prompt。验证一次主调用加 fallback 的总计数、超时、输出用量和未知费用即可。
