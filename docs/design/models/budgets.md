# 技术额度、输入量与实际用量

## 范围

本轮保留总期限、并发、请求字节上限、输出额度和有限尝试。金额批准、充值、余额检查、支付账本不进入产品建设。实际用量照常保留，未报告项保持未知。

## 分开表示的限制

字节上限控制一次请求实际物化与传输大小；模型窗口是 token/模态合同；输出额度由明确协议字段传递；总操作 deadline 包含排队、转换、模型、重试和采用。它们分别解释，不以图片压缩字节数冒充真实 token。

有可靠 tokenizer 或协议计数能力时使用依赖；没有时 `InputSize` 返回 estimate、method 和 known/estimated/unknown。仅估计不能伪装严格窗口证明。文本估计可用于配置的提前分批，媒体遵守实际字节/尺寸/时长限制及模型已知窗口规则；未知模态成本不填零、不硬套 bytes/256 作为拒绝依据。

## 分批与有限内存

Prepared batch 保存引用与 coverage；一次只物化配置允许的 in-flight 批次，默认顺序处理。分批大小不会截断输入总范围；每批失败时返回已完成结果和剩余范围。单个不可再分的输入超出已知硬限制时明确失败。

媒体、查询和 Native 参数从正式配置读取。Native 内存、图边扫描和最大状态预算独立于模型输入，不把一项抽象 effort 当成全部资源的虚假保证。

## 记录

返回每阶段实际 attempts、各请求用量与合计，若任一项未知则合计相应部分标 unknown/partial。原始服务 usage 可保留用于解释；不能以本地字符数作为真实计费 token。备用模型使用自己的实际参数和上限。

## 可测限制与估计

实际请求字节、模型明确上下文/输出上限、图片尺寸和媒体时长按各自单位约束。压缩媒体字节无法可靠换算 token，删除 bytes/256 硬拒绝；未知媒体 token 明确 unknown。Embedding 的每项与每请求上限统一由其批次执行能力落实。

每条路线独立准备额度，根 deadline 与阶段尝试共用；见 [请求尝试](request-attempts.md)。金额审批和费用治理不属于本轮开发。
