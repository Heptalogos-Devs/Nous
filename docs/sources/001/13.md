## Journal 与 VCP 的设计进一步收敛了

### Journal 由正文、修订和独立标注组成

Journal 保存可读 Markdown 和自己的认知身份；正文版本不可变，精确引用固定版本。概念标注绑定正文版本，可以独立更新，**重新标注不必制造一次新的主观记忆修订**。

正文块使用共同 TextView，模型选段、Wave、后续 Steward 和 Journal 共用。它保留 Markdown 的列表、引用、代码块与原文位置，不再分别实现分段。

本轮实际实现 TextView，以及两个专一任务：

- `journal-draft`：共同阅读材料，生成普通 Markdown 草稿。
- `annotate-concepts`：读取正文块，提出概念出现位置和局部路径。

它们使用现有模型、Prompt、CAS 和 ProcessingResult，尚不建立 Journal CRUD 或自动长期采用。

### 多条概念路径保留各自边界

项目研读已经明确：候选概念顺序提供路径线索，长期图、本次观测与正文闭合共同参与评价。分支 · 重构项目架构梳理（VCP 研读）

据此，本轮允许一篇文稿保存“事情经过”“原因解释”等不同局部路径，避免扁平拼接产生不存在的跨节关系。

多路径读出选用**同一条实际路径的 \(P+G\)**，基础分与直接锚只计算一次，继续遵守原有奖励上限。不会从两条无关路径分别取最大值，拼成一条虚构的最佳路径。这是 Nous 的明确扩展，单路径仍保持原定义，实验中单独观察其效果。

详见：journal-projection.md[Journal 的检索投影](sandbox:/mnt/data/Nous_Architecture_Repair_Spec_2026-11-04/docs/design/wave/journal-projection.md)。

### 新的理解可以贡献关系，重复整理不能增加独立证据

文稿、候选和独立来源原本已经分成三种身份；这项分工继续保留。

新的设计进一步区分了：

> **A、B 共同支持一项解释**，与 **A、B 分别独立支持同一项解释**。

前者保存为一个共同依据组，后者才是两个支持途径。派生 Journal 可以贡献新的解释性关系；反复摘要、复制或改写保留原依据，不增加独立见证。

同时，将 VCP 的 **0.15 数值衰减底值**与真实独立支持比例分开表达。原计算需要的权重继续保留，诊断与强见证规则不会把它解释成“至少存在 15% 独立证据”。01_MASTER_CURRENT_RESEARCH_SPEC

详见：evidence-projection.md[关系结构与独立支持](sandbox:/mnt/data/Nous_Architecture_Repair_Spec_2026-11-04/docs/design/wave/evidence-projection.md)。

### 时间先决定可用视图，再参与计算

严格历史查询需要先选择当时可用的正文、概念版本和关系依据，再建立几何与传输资产。只过滤最终结果会留下后来材料对计算的影响。

后续时间门控的数学合同也已写明：保持非负传输、行出流上界，并明确矩阵方向与固定点收敛条件；软新鲜度另作排序偏好。

**本轮只使用明确来源子集的快照进行时间视图实验**，不提前实现任意 `$asof`、时间扩展传播或完整历史存储。
