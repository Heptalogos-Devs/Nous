## 一、你的独立检查进一步确定了整改位置

这几项发现应当进入下一轮的优先整改范围。它们影响正常使用链，不能继续作为入口边界问题处理。

我上一轮的审查需要修正两点判断：**媒体改成引用计划后，合同仍不完整；Embedding 出现批次能力后，原有入口也没有完成迁移。** 看见一个机制已经建立，还需要追到它实际传递了什么，以及所有使用者是否经过同一个完整操作。

### 媒体计划必须保存已经确认的类型和表示

代码中，图片准备已经从实际内容取得 `mime`，并用它构造过 `BinaryContent`；随后 `_batch()` 清空了实际媒体，只留下引用。`materialize()` 再根据 Artifact 的 `media_type` 决定读文字还是读二进制，并使用这个值发送媒体。已识别出的真实类型就在这两个阶段之间丢失了。 

因此，修正应落在**媒体计划的数据合同**上：

> 计划中的每个输入部分，应明确原件及选区、已识别的源类型、要提供的表示、目标 MIME，以及取得这个表示所需的确定性转换。

文件名和接纳时声明的 MIME 可以保留为输入信息；解码识别结果负责决定实际媒体处理。物化阶段执行已经选定的表示，不再根据文件名或初始声明重新判断。

对于尚未执行的转换，计划保存原件引用、目标格式和转换参数；完成后再得到实际输出的 CAS 引用。这样无需提前伪造一个尚不存在的 Artifact。

这也同时解决格式能力没有贯穿的问题。现在图片的原件直传分支会检查 `requirements`，转换分支却没有据此选择输出编码，因而可能继续产生 PNG。

**格式选择应由共同媒体准备能力完成。** 模型只接受 JPEG 或 WebP 时，就从明确支持的转换方式中选出目标表示；没有满足当前内容要求的表示时，在准备阶段说明具体缺项。透明背景、动画、多页等信息是否保留，由显式转换策略决定，不留给下游猜测。

### “延迟加载字节”还应推进到“按需执行转换”

你的补充抓住了上一轮调整的剩余缺口：计划只存引用，降低了二进制驻留量，但若先转换完整部视频或全部 PDF 页，首个模型结果仍然要等到最后一项转换结束。

建议把操作改成：

```text
识别原件并确定范围
→ 形成批次计划
→ 取得下一批所需的实际表示
→ 执行当前批模型任务并采用结果
→ 继续后续批次
```

已存在的派生产物直接复用；没有的产物在消费该批时生成。批次之间有必要重叠执行时，使用现有 Execution 的有界并发。

PDF 可以按需处理页；视频则保持合理的顺序解码或分段处理，避免每取一帧就重新从头启动解码。解码器、子进程和临时内容的生命周期由媒体 owner 持有，消费结束或取消时一起收尾。

**这里需要的是一个能逐批交付的媒体操作，不需要新的调度平台。**

还有一项必须与它同时保留：批次是物理处理单位，用户任务仍然有自己的语义。例如“比较两份文档”，需要先让共同输入规划决定哪些材料应进入同一次请求；无法共同容纳时，再明确怎样分解这项比较。不能把“逐批处理”变成所有任务自动拆开回答。

### Embedding 的批量能力必须成为所有入口的共同能力

当前 `run()` 把全部内容交给 `_adopt()`；`ensure()` 才执行分批，并在整个过程中持有 `_ensure_lock`。你的实测和这两条代码路径一致。

我建议进一步明确职责：

| 所有者 | 完整责任 |
|---|---|
| **EmbeddingExecutor** | 根据实际模型请求约束规划和执行批次，返回每批原始输入下标、向量及用量 |
| **EmbeddingOperations** | 取得内容、检查空间、复用已有向量、采用成功批次，并恢复用户输入顺序 |
| **ExecutionManager** | 承担已有的并发、期限和取消管理 |

`run`、`ensure` 和 `probe` 都经过同一批量执行能力。它们可以在是否复用、是否持久采用上有所区别，网关请求的批次规则保持一致。

实例级长锁应删除。已缓存内容先返回；需要合并进行中工作的，只协调相同的“空间语义、用途、编码输入”键，登记和移除时使用很短的临界区。无关输入继续参与现有并发控制。

每个成功批次仍可以立即采用，最终用有序向量行引用组装完整结果。旧 `run()` 的返回合同若妨碍这一行为，就修改返回合同和消费者，不保留一条绕过分批的旧路径。

### Trace 需要表达真实尝试和业务失败

现有共同 operation 主要记录开始、完成、耗时以及异常类型。对于所有业务错误都表现为 `NousError` 的系统，仅记录类型无法说明真正发生了什么。

这部分也应在两个共同位置完成。

**操作边界**负责稳定的 operation/trace 关联、最终业务错误码、失败阶段、已完成结果和总体耗时。错误在离开这个边界时携带关联信息，CLI 直接呈现；无需从异常文字或日志中反查。

**模型执行策略**负责每次真实请求的模型资源、路线、尝试序号、耗时、返回状态、可用请求 ID，以及进入下一次尝试的原因。生成、转写和 Embedding 共用这些记录语义，媒体和 Wave 不各自重新埋一套。

例如终端可以显示：

```text
媒体描述失败：attachment.bin
阶段：模型请求；模型资源：vision-main；已尝试 3 次
原因：上游服务连续返回 503
原件和已完成转换均已保存
诊断引用：……
```

完整 ID 保存在结构化日志和错误结果里，终端只展示需要拿来定位的关联。这样既解决“看不到是哪次操作”的问题，也避免再次用五六个长 ID 填满每一行。

## 二、VCP 应从 Journal 的结构开始发挥作用

上游 DailyNote 的要求比“给文章加标签”更具体：正文围绕明确事件或主题，Tag 随叙事展开；事件和专名、机制、概括之间形成可理解的顺序，每个 Tag 能回到正文。它还明确允许另写感悟日记，从多个事件中选取概念，按新的推演顺序重新组织。

我建议将这个思想落实为 Nous 的 Journal 合同：

**Journal 保持一篇可读、可修订的 Markdown，同时拥有与该版本正文对应的概念出现记录和有序概念路径。**

### 正文、概念归属和概念路径分别表达

以下是建议结构，并非当前已经实现的 Journal：

| 内容 | 用途 |
|---|---|
| **Markdown 正文** | 人与 Agent 实际阅读的记忆 |
| **正文块与精确选区** | 供引用、Steward 选段、来源绑定和修订定位 |
| **Concept 出现记录** | 某个概念在哪些段落中具有实际含义 |
| **有序 Concept 路径** | 这篇或这一节认识怎样展开，供曲线与关系计算 |
| **来源、作者视角与时间** | 解释这项认识从哪里来、在什么情境形成和适用 |

“这篇文章涉及哪些概念”可以是一组集合；“文章怎样从问题走到解释”需要顺序。两者的用途不同，不能只保留其中一个。

例如一篇排障 Journal：

> 发现取消后文件仍被占用。起初怀疑数据库事务没有结束，后来查明后台线程仍在工作。最终把句柄释放安排到实际工作完成之后。

可读出的概念路径是：

```text
取消操作 → 文件占用 → 事务假设 → 阻塞线程 → 资源所有权 → 释放时机
```

其中“事务假设”还需要在正文里保留“曾经怀疑、后来排除”的含义。概念顺序可以帮助关系寻址，具体主张仍由正文、关系类型和来源表达。

### 一个 Journal 可以有多条局部路径

一篇主题明确的 Journal 也可能有“事情经过”“原因分析”“后续认识”几个章节。我建议允许每个有意义的部分拥有自己的路径，再在确有整体展开时保存文章级路径。

这样可以保留：

```text
经历：发现故障 → 排查 → 修改 → 恢复
理解：等待结束 → 实际工作结束 → 资源释放责任
```

不要因为两个段落在文件中相邻，就自动补一条跨主题关系。重复概念也应保留其出现位置，例如 `假设 A → 反例 B → 修订后的 A`，这是有信息的回访。

这与 RiverMemo 的候选曲线直接对应：它会考察相邻概念、跨一个概念的路径、真实图边和概念到正文的闭合。候选是整篇时使用相应整体结构；候选是一个段落时，使用该选区实际涵盖的概念，避免把全篇所有概念强加给每个片段。分支 · 重构项目架构梳理（VCP 研读）

### 模型只承担写作和语义标注

这里不能再次把全部数据库结构塞进 Prompt。

`journalize` 先形成可读正文；概念标注可以作为独立、可重做的任务，读取正文和有关 Concept，给出少量概念及段落引用。程序解析 Markdown、固定正文版本、解析正式概念身份并保存关联。

模型不计算图边权、独立来源数量、数据库版本或时间域转换。作者也可以直接写 Journal，随后补充结构；一篇尚未标注的 Journal 仍然能阅读和进行普通检索。

## 三、需要修订“派生 Journal 不参与构图”的过宽规定

这是研读材料与当前设计中最值得重新判断的地方。

材料提出“原始来源贡献事实图，派生 Journal 保留检索能力与来源关系”，目的是防止反复总结增加独立证据。这项目的正确。分支 · 重构项目架构梳理（VCP 研读）

但上游 DailyNote 同时强调：**感悟日记可以将多个事件重新连接，形成自己的新曲线。** 若我们整体排除派生 Journal 的构图贡献，就会丢掉这项能力。

**我建议将规则修订为：派生 Journal 可以贡献新的概念组织和解释性关联；来源独立性按实际证据归属单独计算。**

例如：

- 原始经历 A 讲任务取消。
- 原始经历 B 讲事务提交。
- Journal C 将二者联系到“实际完成与资源责任”。

C 提供了一项新的联想结构，有资格帮助今后的查询从 A 找到 B。它的来源仍然是 A、B，以及主体在 C 中形成的这次解释。

这里需要保留两个不同量：

**结构贡献**表示有哪些值得用于寻找记忆的联系。

**独立支持**表示这条具体关系得到多少独立材料的支持。

把 C 再总结成 D，不应重复增加关系的独立支持。A、B 共同启发了某项推断时，也应按共同依据表达；不能把它们拆成两份“各自独立证明这条关系”的见证。强 Wormhole 见证仍按真实的独立材料资格计算，普通解释性关联则可以在明确的投影策略下参与联想。

这还带来一个更准确的原则：**原始与派生应落实到具体内容和关系的来源，不能只给整篇文稿贴一个标签。** 一篇 Journal 可以同时引用旧经历、记录新的主观感受，并提出新的解释。这些内容拥有不同的来源意义。

不必为此建设两套互相复制的图服务。正式关系记录保留类型、产生位置、依据和视角；Wave 根据用途生成可重建的计算投影。

## 四、时间应进入查询视图、关系选择和经历组织

上游已经有 TimeDecay，并有按日期范围管理日记的操作。它们提供了有用的时间能力。Nous 需要进一步处理发生、观察、形成、适用和记录之间的差别，以及非现实时间域。 

### 首先分清三种顺序

| 顺序 | 表达内容 |
|---|---|
| **正文中的概念顺序** | 作者怎样讲述或理解这件事 |
| **经历中的时间顺序** | 事件何时发生、何时接触，以及认识何时变化 |
| **查询传播顺序** | 本次计算沿哪些关系走了几跳 |

一篇 Journal 可以先说结论，再回顾几个月前的经历。其概念路径适合叙述关系寻址；Episode 和时间记录负责实际经过；Sense 的 hop 则负责计算传播。这三者都保留，彼此可以关联。

### 时间查询需要明确实际问题

同一句“那时的认识”，可能对应几个不同操作：

| 用户的问题 | 需要使用的条件 |
|---|---|
| “那天发生了什么？” | `occurred` 与事件组织 |
| “当时我已经看到了什么？” | 指定观察者的 `observed`，以及有关认识的形成情况 |
| “系统当时保存的内容是什么？” | `recorded` 历史截面 |
| “那项安排在当时是否有效？” | `valid` |
| “我后来怎样改变了理解？” | Journal 修订、后续回顾和形成时间 |

例如，今天补录一段去年已经看到的经历，“今天回顾去年所见”可以使用它；“系统去年那一刻保存了什么”则使用当时的记录截面。查询意图必须明确到这个程度，才能正确选择内容和关系。

### 历史视图必须先于图计算成立

对于严格的历史认识查询，仅在最终结果中去掉未来文稿仍然不够：后来形成的概念、关联和背景几何已经可能改变传播路径。

建议的顺序是：

> **确定主体、时间域与知识视图 → 选择可参与的正文版本和关系依据 → 构造或复用该视图的计算资产 → 运行 VCP → 按需应用时间偏好。**

这与研读材料中“来源和时间决定哪些资产有资格参与”的方向一致。分支 · 重构项目架构梳理（VCP 研读）

首版可以围绕实际需要的历史视图生成快照，不必先做一套支持任意时间点、无限常驻快照的引擎。

### 时间还可以成为有解释的关系信号

这部分属于下一步研究建议。

同一时间域中的先后、重叠、持续、紧接某次事件等关系，可以帮助寻找一段经历。它们可以形成独立候选通道，也可以作为明确的关联投影，参与受控传播。

为了继续使用 VCP 的非负、有界传输，可以从满足视图条件的传输矩阵出发：

\[
P^{(q)}_{ij}=P^{\mathrm{view}}_{ij}\,g_q(i,j),
\qquad 0\le g_q(i,j)\le1
\]

其中 \(g_q\) 表示当前查询对这条关系的时间适配程度。这个形式保留原有出流上界；被时间条件削弱的能量可以消散，无需自动重新分给剩余边。它是一个可研究的扩展形式，具体函数应由真实使用场景决定。

“最近”需要明确参考时刻和时间域。虚拟世界、模拟进程和真实 UTC 分别处理；时间未知时保留未知。永久性的技术认识，也不应仅因年代久远就默认下降。

更深入的“沿事件时间向前追踪”还需要路径携带时间条件。那应在 Episode 和关系时间合同形成后，再扩展传播状态，避免拿现有 hop 冒充事件时间。

## 五、这些数学能力可以服务多个认知用途

下面是基于研读材料提出的延伸方向，分别保留实际语义所有者。

| 数学能力 | Nous 中值得使用的地方 | 由谁决定长期意义 |
|---|---|---|
| **有序概念曲线、拓扑对齐** | 找到展开方式相似的经历、解释或做法 | Journal、Schema |
| **Residual Pyramid** | 从一个问题中继续寻找尚未覆盖的侧面材料 | Wave 查询规划；材料由相关领域读取 |

### 社会关系可以复用计算，保持自己的语义

Social 仍然保存实体身份、平台或外部标识、具体关系、程度、信度和适用时间。

最直接的接入方式是：Social 根据当前情境给出相关人物、关系条件和记忆引用，Wave 将其作为查询线索或候选池使用。进一步确实需要社会图传播时，可以复用 Native 的稀疏图和有界传播能力，由 Social 提供对应节点与边。

概念语义图和社会关系图可以共享数值算子，各自保留输入含义。对一个人的信任、关系亲近程度、检索传输率分别定义；一条高权重的检索路径不直接回写为“更信任这个人”。

Schema 也可以利用重复出现的概念路径发现经验模式。但多个文稿来自同一次经历时，来源集合会告诉它们实际共有多少次经历。这样，模式提炼能够利用图结构，又不会被自动总结的数量牵着走。

### Anchor 可以利用这些计算形成关联中心

Nous 的长期 Anchor 可以汇聚某段重要生活、某个长期问题或一类反复出现的经历。Concept 邻域、来源多样性、跨时间出现和有关 Journal 都可以成为组织它的材料。

VCP 的 Direct Anchor 奖励则继续作为本次查询的数值机制，保留原有含义。研读材料已经明确区分这两个名称相近的对象。分支 · 重构项目架构梳理（VCP 研读）

## 六、下一轮的工程范围应当收敛，认知设计继续推进

现在可以确定的工程工作已经足够明确：

**媒体方面**，修复类型和目标表示的计划合同，把确定性转换推进到按批消费，并保留完整任务的多输入语义。

**Embedding 方面**，让所有入口使用同一批量执行能力，移除实例级网络长锁，成功批次继续通过现有事务和 ResultStore 采用。

**观测方面**，在共同操作和请求尝试上补齐真实错误与关联信息，完成可读终端输出和可查询的结构化记录。

**Native 方面**，继续上一轮提出的职责迁移和接口补齐：薄绑定、完整 CandidatePool、清楚的通道预算、稀疏图行为与来源合同。新的时间与认知机制先不混进尚未收敛的接缝。

同时，Journal 的下一份设计应当明确正文、修订、块引用、Concept 出现、概念路径，以及来源贡献。这会直接决定 Wave 以后消费的正式输入，值得现在讨论清楚。

后续最有区分力的实际实验有两个：**同一批材料在无序概念、有序概念和多条局部路径下，关系型召回是否出现有意义的差异；同一段经历经过多次整理后，新增联想是否被保留，同时独立支持数量保持正确。** 时间实验则使用“后来才知道的旧事件”和“已经变化的关系”，观察系统能否分别回答今天的回顾与当时的认识。

**最终应形成的结构是：Journal 保存可读且有来源的认识，Concept 路径保存认识的展开，时间与关系确定当前可用的视图，Wave 使用 VCP 的计算能力把这些认识重新带入当下。** 先把基础合同修到这个方向上，再接入认知对象，后续开发才会围绕同一套完整能力增长。

# VCP 算法体系：从 TagMemo 浪潮到 RiverMemo，以及 Nous Wave 的延续与扩展

**VCP 最有价值的思想，是让 AI 在记录记忆时，把自然语言中的概念及其展开关系编码成可计算的结构；检索时再利用向量几何、概念关联、有限传播和候选拓扑，寻找与当前思考具有关系性联系的内容。**

这与普通向量检索有一个重要区别：向量检索主要测量文本在语义空间中的接近程度，而 VCP 希望进一步利用记忆中已经积累的概念关系，判断一段经历是否能够参与当前问题的理解。

RiverMemo 将这种思想发展为更完整的计算体系：**查询产生概念激活，激活沿长期关系图传播，形成请求级河网；候选记忆作为一条有序概念曲线，接受河网、双场、几何和来源证据的共同评估。**

Nous Wave 则要保留这些能力，同时扩展为适用于 Nous 自身认知对象、来源体系、上下文和修订生命周期的检索引擎。

## 三、长期概念图的建立：从共现到有限传输

### 1. 图中的节点与边分别表示什么

设长期 Tag 集合为：

\[
V=\{t_1,t_2,\ldots,t_n\}
\]

每个 Tag 具有语义向量 \(v_i\in\mathbb R^d\)。

记忆中的有序 Tag 序列形成关系证据。多篇记忆共同提供这些关系，最终构成有向加权图：

\[
G=(V,E,P)
\]

其中 \(P_{ij}\) 表示从概念 \(i\) 向概念 \(j\) 的传输率。

有向并不意味着只能沿一个方向访问。V9.1 使用有序双向事实边，前向和反向可以拥有不同阻尼。

假设有两篇记忆：

这里的关系来源是实际写入的记忆结构。向量相似度负责提供语义质量，位置顺序负责提供方向线索。

### 2. 事实权重先累计，再压缩

同一对 Tag 在多篇记忆中出现，会积累原始支持权重 \(W_{ij}\)。

V9.1 不直接把累计值当成最终传输率，而是先进行对数压缩：

\[
e_{ij}=\log(1+\lambda W_{ij})
\]

其目的在于让重复出现继续增加关系权重，同时降低高频关系的边际增长速度。

例如某对概念共同出现一百次，当然应该与只共同出现一次有所区别；但不能因此让它独占几乎所有传播能量。

图构建还考虑位置距离、前后顺序、语义相似度、Intrinsic Residual 和 Wormhole 增益。

### 3. 枢纽校正抑制通用概念

一个常见问题是：“AI”“编程”“工作”等高频概念可能连接大量记忆。

如果直接依关系数量传播，检索很容易经过这些通用概念，把许多弱相关内容一起带进候选集合。

VCP 统计节点的总体入流，并使用有界幂律校正：

\[
h_j=
\operatorname{clip}
\left[
\left(
\frac{s_j^{in}}{\operatorname{median}(s^{in})+\epsilon}
\right)^{-\eta},
h_{\min},h_{\max}
\right]
\]

直观上，入流过高的常见节点受到一定抑制；稀有节点得到有限补偿。

这个校正有上下界：通用概念仍可能重要，稀有概念也没有无限传播特权。

### 4. 固定出流预算让传播有界

最后，将边质量归一化：

\[
P_{ij}
=
m_{\mathrm{out}}
\frac{\widetilde g_{ij}}
{\sum_k\widetilde g_{ik}}
\]

并要求：

\[
\sum_jP_{ij}<1
\]

这形成一个严格次随机传输算子。

它使概念节点的总输出质量受到限制。某条 Wormhole 边可以取得较高份额，但必须与其他边竞争同一预算。

**这就是 VCP 的重要变化：从累计关联强度，转向有限预算中的关系选择。**

以上机制可见 [TagMemo V9.1 第 5 节](https://github.com/lioensky/VCPToolBox/blob/d5c019ebbac1f317c2938d655d2ce916e41b9164/docs/TagMemo_Wave_Algorithm_Deep_Dive.md#5-从事实矩阵到-v91-传播核)。

## 四、AGS：在长期概念空间中测量局部与全局结构

AGS 使用 Anchored Greedy Gram–Schmidt，即锚定贪心正交化。

其关键思想是：一组概念向量不仅有两两相似度，还具有由多个向量共同张成的子空间。

### 1. 局部 Explain 测量概念的独特程度

假设目标概念向量为 \(v_t\)，其邻居经过正交化形成基：

\[
U=[u_1,u_2,\ldots,u_k]
\]

则邻居能够解释的部分为：

\[
\widehat v_t=UU^\top v_t
\]

剩余部分为：

\[
r_t=v_t-UU^\top v_t
\]

对单位向量，局部残差比例为：

\[
\boxed{R_t=\|r_t\|_2}
\]

这里 \(R_t\) 越大，表示目标概念越难被当前局部邻居张成的空间解释。

例如：

“编程语言”可能容易被一组相关技术概念解释。

“某次特殊故障中的资源释放规律”可能包含更多局部邻居尚未覆盖的方向。

VCP 将这种残差经过固定有界映射，得到节点的 Anchor Gain：

\[
a_t=
\operatorname{clip}
(a_0+a_1R_t^\beta,\ a_{\min},a_{\max})
\]

它影响传输关系的数值质量。

需要注意两个数学量的区别：

- \(R_t\) 是残差**范数比例**；
- \(1-R_t^2\) 才对应近似的邻域**解释能量比例**。

二者具有不同数值意义，不能在参数和诊断中互换。

### 2. 全局 Span 提供背景主题空间

AGS 还从全库概念中构造全局主题方向。

它使用中心化的目标向量，以及共现邻居形成的方向，贪心选择能够提供新覆盖的向量，得到近似正交的主题基底。

这产生三个有用的长期资产：

**全局均值 \(\mu\)**：概念向量的背景中心。

**主题基底 \(B\)**：全库中具有代表性的语义方向。

**覆盖率**：当前主题基能够解释多少已知概念空间。

局部 Explain 用于评价一个概念与邻域的关系；全局 Span 为当前查询提供参考坐标系。

它们属于构建后的长期几何资产，许多查询可以共享。

## 五、EPA：分析查询处在怎样的语义区域

EPA 全称 Embedding Projection Analysis。

在早期 VCP 中，它依赖全局统计与 SVD/PCA 类方法构建主轴；当前 RiverMemo 管线使用 AGS 产生的全局语义基底进行校准。

对查询 \(q\)，先中心化：

\[
x=q-\mu
\]

在主题基 \(b_k\) 上测量解释率：

\[
\boxed{
r_Q=
\frac{\sum_{k=1}^{m}\langle x,b_k\rangle^2}
{\|x\|^2}
}
\]

如果该值较大，说明查询更集中在当前全局主题基所覆盖的空间中。

### 投影熵描述方向集中程度

再计算每个主题方向的能量占比：

\[
p_k=
\frac{\langle x,b_k\rangle^2}
{\sum_j\langle x,b_j\rangle^2}
\]

归一化熵：

\[
H_Q=-\frac{\sum_kp_k\log p_k}{\log m}
\]

早期 EPA 将 \(1-H_Q\) 称作 Logic Depth（逻辑深度）。

当前 RiverMemo 进一步引入域内门控 \(g_Q\)，采用：

\[
L_Q=(1-H_Q)g_Q
\]

其中域内门控还考虑查询解释率与背景参照。

从算法上理解，EPA 试图回答：

> 当前查询主要集中在少数已知语义方向，还是同时触及较多不同方向？

这可以帮助调节 Tag 感应和激活。

这里保留一个重要的理论边界：**投影集中度是几何量，逻辑推理深度是语义量。**

尤其当 PCA 存在重复特征值时，合法基底可以旋转，同一查询的轴上能量熵也可能改变。因此，用 EPA 诊断查询形状是成立的工程用途；将它直接解释为主体真正的逻辑能力，需要另外的语义依据。

这也是 Nous 研究中已经发现的问题：EPA 可以保留和研究，但不能仅因指标名称就赋予它超出数学定义的意义。

## 六、Residual Pyramid：逐层寻找被主主题遮蔽的线索

这是 VCP 最容易直观理解，也最值得深入研究的机制之一。

假设用户问：

> “取消任务以后，数据库仍然被占用，这是不是某个生命周期问题？”

普通查询向量可能主要接近“任务取消”“数据库”。

但问题中还有“资源占用”“实际线程结束”等侧面语义。

Residual Pyramid 尝试逐层寻找这些方向。

### 1. 第一层解释当前查询

设初始向量：

\[
r_0=q
\]

用它检索最接近的一组 Tag，并将这组 Tag 的向量正交化，得到 \(U_0\)。

从查询中减去这些方向的投影：

\[
\boxed{
r_1=r_0-U_0U_0^\top r_0
}
\]

此时 \(r_1\) 表示尚未被第一层基底解释的向量部分。

下一层用 \(r_1\) 继续检索概念，重复投影：

\[
r_{\ell+1}
=
r_\ell-U_\ell U_\ell^\top r_\ell
\]

由此形成多层概念候选。

### 2. 每层具有明确的解释能量

定义该层边际解释能量：

\[
\boxed{
e_\ell=
\frac{
[\|r_\ell\|^2-\|r_{\ell+1}\|^2]_+
}{
\|q\|^2
}
}
\]

VCP 当前管线默认最多三层，边际解释能量低于一定阈值的层不会被接受。残差能量足够小也会提前结束。

此外，当前 RiverMemo 要求实际参与的 Tag 在已发布概念图中具有合法身份。图外近邻可能占据 ANN 候选位置，但不会因此被偷偷补进传播图。

### 3. 标签贡献与解释能量是两个量

某个 Tag 在当前残差中的对齐程度，可以近似表示为：

\[
a_{\ell,t}
=
\frac{|\langle r_\ell,b_t\rangle|}{\|r_\ell\|}
\]

它表示一个方向相对于当前残差的贡献，和整层消去了多少查询能量不同。

VCP 据此执行门控，保留较强、具有字面依据或者明确指定的 Tag。低贡献别名有有限借用机制，避免与强 Tag 高度共线的相关概念完全消失。

**Residual Pyramid 的价值，是提供原查询之外的候选语义方向。**

它的局限也很具体：某个几何残差未必对应一项真实、独立的人类语义需求。实际效果取决于向量空间、概念质量、检索池及后续门控。

## 七、Core Tag、Ghost Tag 与查询向量重塑

VCP 不仅从向量中推测概念，还接受调用者提供的概念线索。

| 类型 | 意义 | 数值作用 |
|---|---|---|
| 普通感应 Tag | 从查询或残差中找到的已存概念 | 作为候选种子、融合输入 |
| Core Tag | 调用者明确指出的核心概念 | 获得显式焦点资格和对应增益 |
| Ghost Tag | 尚未正式入库、但拥有向量的临时概念 | 参与当前查询的语义融合 |
| Emergent Tag | 传播过程中实际到达的概念 | 扩大当前查询的关联范围 |

Ghost Tag 的设计很有价值。

例如用户突然提出“资源所有权在不同语言运行时之间的类比”，这可能尚未是正式 Tag。系统仍能将其作为临时线索参与本次查询。

历史 V9 中，Ghost Tag 主要参加向量融合，不写入持久图；当前管线的显式核心、字面与隐式种子具有更完整的图内资格规则。

最终，将获得的概念向量加权平均、单位化，再与原查询融合：

\[
\boxed{
q'=
\operatorname{normalize}
\left[(1-\alpha)q+\alpha c\right]
}
\]

其中 \(c\) 是当前 Tag 上下文向量，\(\alpha\) 控制增强程度。

这条增强向量可以再次进行 Dense 检索。

其作用是让长期概念关系影响候选生成，而后续 RiverMemo 还会进一步利用传播和拓扑证据决定排序。

## 八、Sense：查询时真正发生的“浪潮传播”

前面已经有了长期关系图，也有了本次查询激活的概念种子。

接下来 Sense 负责回答：

> 从这些概念出发，有限的关联活动会经过哪些关系，到达哪些原本没有直接命中的概念？

### 1. 为什么传播状态必须包含前驱

普通图遍历只需要知道当前节点。

VCP 则需要区分：

“从 A 到达 B”和“从 C 到达 B”。

因为二者下一步返回原路的含义不同。

当前原生状态包含：

\[
x=(previous,current,energy,momentum,hop,sourceLayer)
\]

其中：

- `previous` 记录上一个节点；
- `energy` 是该路径当前可传播的活动量；
- `momentum` 限制普通关联连续展开；
- `hop` 限制传播深度；
- `sourceLayer` 记录来自哪一层查询残差信号。

这些状态使算法能够控制回流、方向和不同层级的扩展。

### 2. 实际边流由多个因素共同决定

对于真实存在的边 \(i\rightarrow j\)，一次注入近似为：

\[
\boxed{
f_{ij}^{(h)}
=
e_i^{(h)}
P_{ij}
d_{ij}
\rho_{ij}
}
\]

其中 \(e_i^{(h)}\) 是当前能量，\(P_{ij}\) 是长期图传输率，\(d_{ij}\) 是传播阻尼，\(\rho_{ij}\) 包含回流修正。

当前上游默认的普通边阻尼为 0.25，Wormhole 边为 0.70，即时回流再乘 0.15。

这些系数是具体实现的数值配置。

例如从节点 A 向 B 传播，假设当前能量为 1、边传输率为 0.4，且这是一条普通边、无需回流折减：

\[
f_{AB}=1\times0.4\times0.25=0.1
\]

如果下一步立即由 B 返回 A，活动量还会受到回流折减。

这样既允许记忆之间发生回顾和双向联系，又能抑制 A—B—A 的短周期振荡。

### 3. 有限时域加权形成查询河网

不同传播跳数的结果不会无条件相加。

VCP 使用有限脉冲响应权重：

\[
a_h=
\frac{\gamma^h}
{\sum_{r=0}^{H}\gamma^r}
\]

当前默认 \(\gamma=0.6\)，从而得到累计节点势：

\[
\boxed{
E_i=\sum_{h=0}^{H}a_he_i^{(h)}
}
\]

近距离关系通常取得较大权重，较远关联仍可参与。

传播同时保留实际通过阈值的边流，以及需要时记录的前驱转移。

这些信息共同形成 RiverMemo 所说的**请求级河网**。

可以将其理解为：当前查询在长期概念图上激活出的一片有方向、有强弱、有路径的局部结构。

它会随查询改变。同一份长期记忆图，对“资源释放”和“数据库事务”两种查询，可以产生不同的河网。

### 4. Wormhole 有三层不同机制

VCP 中的 Wormhole 容易因为名称相同而混淆。

| 机制 | 实际工作 |
|---|---|
| 构图阶段的 Wormhole 增益 | 根据长期边的残差张力等信息，在固定传输预算内提高某些关系的权重 |
| 查询时的 Dynamic Wormhole | 使用更深残差与当前传播状态，从**已经存在的正权边**中动态选择值得探索的关系 |
| RiverMemo 的 Wormhole RRF | 对已经观察到、具有严格证据资格的路线，允许有限的排名修正 |

尤其是第二种。

假设查询第一层激活了“任务取消”，后续残差指向“资源所有权”。

当前节点有许多可能的出边。Dynamic Wormhole 可以利用这份残差，优先探索真正存在、且目标与该残差较一致的边。

当前实现的共鸣定义为：

\[
R(j\mid L)=
\max_{\ell>L}
[\cos(r_\ell,v_j)]_+
\]

动态选边分数：

\[
D_{ij}=P_{ij}R(j\mid L)^4
\]

这种设计会突出残差高度一致的边，抑制一般性的弱相似。

**Dynamic Wormhole 重新选择已有的关系，不在查询时创造新的事实关系。**

这项原则对 Nous 以后的社会关系、认知关联和来源体系也很重要。

## 九、双场：将有限传播转化为连续的关系响应

Sense 产生的是实际激活的节点与边流。

但只依靠有限跳数，可能难以描述这片河网周围更宽的关联结构。

RiverMemo 因此对同一个查询源 \(S\)，使用相同的传输算子 \(T\)，求解两个不同尺度的场。

\[
\boxed{
u_\alpha=(1-\alpha)S+\alpha T(u_\alpha)
}
\]

在收敛条件下：

\[
u_\alpha
=
(1-\alpha)(I-\alpha T)^{-1}S
\]

这里的 \(T\) 是图上的传输算子，表达关系传播。

### Local Field 与 Transfer Field

当前默认：

\[
\alpha_L=0.15,\qquad \alpha_T=0.55
\]

| 场 | 关注的关系尺度 |
|---|---|
| Local Field | 更偏向种子附近、局部相邻的语义 |
| Transfer Field | 更允许沿长期关系扩散，反映较远的关联 |

例如查询“协程取消”时：

Local Field 可能主要集中在任务、线程、取消和等待。

Transfer Field 可能进一步到达文件句柄、资源所有权、事务完成和其他跨领域经验。

这两个场使用相同图和同一个查询源。差别由传播尺度产生。

需要区分的是：**AGS 的局部/全局描述长期语义几何，双场的 Local/Transfer 描述一次查询的响应尺度。**

### 为什么还需要场投影

双场最初是定义在概念图节点上的标量：

\[
u(i)\in\mathbb R
\]

而 Dense 检索需要高维向量：

\[
v\in\mathbb R^d
\]

因此系统选出一组具有代表性的、可追溯的概念节点，依据其场质量和向量构造高维投影。

这些投影可以产生局部场查询向量和迁移场查询向量，进入向量索引。

但不能简单把全图每个节点的向量加权平均。

高频概念、数值尾流和大规模低质量节点可能使投影失去辨别力。

当前 VCP 因此引入流域投影预算：保留实际传播核心，从具有真实连接的节点扩展支持集；不同场使用自己的质量条件，限定节点数和扫描工作量。

**场的求解、场支持节点的选择，以及高维查询向量的生成，是三个不同的计算环节。**

这一设计使 VCP 能在有限计算资源下，利用较远的关联影响后续向量召回。

## 十、RiverMemo：候选记忆怎样接受河网评估

这是 VCP 最有特色的读出机制。

### 1. 候选记忆是一条有序概念曲线

设一篇候选文稿包含：

\[
\Gamma_c=(t_1,t_2,\ldots,t_n)
\]

普通 Tag 重排可能只统计这些 Tag 中有多少与查询激活节点相同。

RiverMemo 还考察：

这些概念是否按合理顺序出现？其关系是否对应当前河网？概念是否真正闭合到候选正文？这条曲线是持续穿过关联区域，还是只偶然接触一个高势能节点？

早期 V9.1 的曲线测地评估，利用局部向量核将查询场插值到候选 Tag 上。

例如对候选 Tag \(t\)，从附近场节点 \(z_j\) 计算：

\[
k(t,z_j)=
\left[
\frac{\cos(t,z_j)-\tau_s}
{1-\tau_s}
\right]_+^p
\]

再用场节点能量、局部特异性等信息形成候选上的势能。

这解决了一个问题：两个概念即使没有完全相同的 Tag ID，也可能位于彼此相关的语义区域。

### 2. 当前 Topology V3 使用更严格的路径证据

RiverMemo V3 的路径读出已经不仅是局部势能插值。

候选中相邻 Tag，以及允许跨过一个 Tag 的 Span-2 路径，都可以参与计算。

它检查两端是否在有效场内、是否存在真实正权图边、是否获得本次传播的支持、方向是否一致，以及两端与正文的语义闭合程度。

Span-2 还会受到额外折减。

因此：

> 候选的概念顺序提供路径假设；长期图与当前查询观测提供关系支持；正文闭合决定这些概念是否真的属于该候选。

这是将记忆内容、长期结构和当前激活连接起来的关键。

### 3. 一对一拓扑对齐

RiverMemo 还会将本次查询河网中的节点与候选曲线中的 Tag 进行对应。

优先匹配精确概念身份，再考虑向量相似度。

同时限制双侧容量：一个候选 Tag 不能因为与多个查询节点相近，就被重复计算成多个独立精确匹配。

对于一个语义匹配，质量同时考虑相似度与候选正文的闭合：

\[
a(r,t)=\sqrt{\nu(s)h_t}\,w(s)
\]

其中 \(s\) 是语义相似度，\(h_t\) 是 Tag 与候选正文的闭合程度，\(\nu\) 和 \(w\) 提供阈值与弱匹配折减。

节点匹配之后，再比较实际查询河网边和候选曲线中的对应关系。

这涉及方向、相对距离、节点对齐质量、传播跳数、来源关系及候选顺序。

### 4. 查询形态决定拓扑证据的解释方式

当前 RiverMemo 从河网中提取形态特征：

传播深度、方向性、集中程度、分叉、汇合、持续性以及浅层比例等。

由此形成不同模式的权重，例如：

**Atomic**：更接近一个局部明确概念。

**Path**：更强调连续展开关系。

**Narrative**：更强调具有叙事组织的关系结构。

这些权重来自实际河网形态，并由 Softmax 归一化及完整度修正。

候选图分综合不同模式，而不由用户问题中的某个关键词直接决定“这是叙事型问题”。

从理论上看，它试图进一步判断：

> 当前查询更需要一个直接概念、一条关系路径，还是一段连贯经历？

这一判断仍是算法内部的形态解释，后续可以与 Nous 正式的 Episode、Journal 等认知结构结合。

## 十一、Ω：查询河网的可观测程度

Ω 是 RiverMemo 的统一拓扑泛函之一。

它只读取当前查询河网，不读取候选正文。

其中涉及三个主要量：

**边活动**：实际产生了多少有意义的边流，相对于种子数量处在什么规模。

**新节点活动**：传播到达了多少初始种子之外的节点。

**流量分布**：实际边流是否形成一定的分布结构。

再结合观测是否完整，产生有界数值：

\[
\Omega\in[0,1]
\]

当前源码使用三类量的几何组合，并具有防数值退化的底值和完整度因子。

Ω 高，意味着本次查询形成了较丰富、可观察的河网活动。

Ω 低，则表明关系传播较弱、较少或者不完整。

**它衡量的是当前拓扑计算的可观测性；关系是否真实、候选是否正确，需要各自的证据。**

Ω 的作用是控制候选图证据能获得多少排序权重。

## 十二、RiverMemo 的最终评分体系

当前 Topology V3 的基本评分公式是：

\[
\boxed{
S_0(c)=
\operatorname{clip}_{[0,1]}
[B(c)+P(c)+G(c)+A(c)]
}
\]

这四项的职责非常清楚。

| 分数 | 含义 | 重要特征 |
|---|---|---|
| \(B\) | 原始查询基础分与有限场共振 | 保留正文与问题的直接语义联系 |
| \(P\) | 双场支持的候选路径奖励 | 反映关系路径质量 |
| \(G\) | 候选自身的拓扑匹配奖励 | 受到 Ω 门控 |
| \(A\) | 直接锚奖励 | 保护明确的概念接触 |

当前默认路径与图共享拓扑奖励上限：

\[
P(c)+G(c)\leq0.08
\]

直接锚另有独立上限，默认 0.10。

场共振已经计入 \(B\)，因此不会再单独重复相加。

这项设计有重要意义：**VCP 的关系证据主要增强已经具有基础语义联系的候选，而不是无限放大某条路径，彻底取代原本的检索相关性。**

### 直接锚保护无需复杂传播的明确记忆

某条候选可能直接包含本次查询的核心概念，却没有形成很丰富的河网。

例如用户询问一条精确技术结论，直接相关的记忆应该能够被检索出来。

Direct Anchor 就是为这种接触提供独立贡献。

它考虑种子身份、精确或语义命中、正文闭合、节点稀有度及来源权重。

多个接触采用有界聚合，最终通过平滑阈值函数获得锚奖励。

这里的 Direct Anchor 与 Nous 设计的**长期 Anchor 认知地标**是两个不同对象。前者是本次查询的数值奖励，后者是具有持久身份与生命周期的认知结构。

### 条件 Wormhole RRF 只处理特定的远距离关联

当前 RiverMemo 还有最后一条特殊排序通道。

某些稀疏知识场景中，查询实际经过了一条有长期事实关系支持的远距离路线，候选也有相应关系落地，但四项基线可能没有充分体现它。

VCP 允许这类路线进一步修正排序，不过要求严格的全局文件见证和候选落地资格。

当前见证机制甚至要求两份不同文件同时包含路线两端，并共享另外的概念，且与其他显式查询焦点存在联系。

通过后，根据原始观测电流和 Ω 计算路线权重：

\[
w_e=\frac{f_e}{f_{\mathrm{ref}}}\Omega^\gamma
\]

再在合格候选上形成条件 RRF：

\[
\boxed{
S_{\mathrm{rank}}(c)
=
\frac{1}{60+r_0(c)}
+
\max_e\frac{w_e}{60+r_e(c)}
}
\]

其中 \(r_0\) 是四项基线排名，\(r_e\) 是某条路线对应的候选排名。

多个路线贡献取最大值，避免相关支路反复投票。

没有合格路线贡献时，直接保留原始基线评分与排序。

### 最终排名与候选质量分已经分离

这是上游近期很重要的一项修正。

`quality_score` 保留候选自身的四项基线质量：

\[
S_0=B+P+G+A
\]

`ranking_score` 保存实际用于排序的键，包括必要时的条件 RRF。

因此，返回结果按排名排列时，质量分可能并不单调下降。

这两种量在 Nous 中应分别保留：**质量用于解释候选本身的证据程度，排序键用于解释它为什么排在当前位置。**

参见上游 [RiverMemo 排序分数合同](https://github.com/lioensky/VCPToolBox/blob/d5c019ebbac1f317c2938d655d2ce916e41b9164/docs/RIVERMEMO_RRF_SCORE_CONTRACT.md)。

## 十三、Thinking：依据实际传播路径组织连续探索

VCP 的 Thinking 并不是让语言模型自由生成一段推理链。

它是对同一次 Sense 观测进行的**路径支撑型候选组织**。

调用者提供多个阶段，每阶段给出候选集合。算法根据已经发生的传播转移，判断哪些候选能够与已选候选形成连续关系。

当前实现对前驱转移具有明确检查：

\[
hop_{\mathrm{next}}=hop_{\mathrm{previous}}+1
\]

并且要求前一条转移的目标是后一条的来源，且前驱状态正确对应。

候选还需要提供实际概念及正文闭合支持。

算法会考虑相关性、传播流量、来源独立性、是否重复使用了同一条路线，以及候选能否接续之前阶段。

最后可以输出类似：

    <box flex="1">

      <text size="xs" color="secondary">起点：直接相关经验</text>
    </box>
  </row>
  <row padding={{left:2}} gap={2} align="center">
    <icon name="arrow-down" color="secondary"/>
    <text size="xs" color="secondary">真实传播路径支持的 continuation</text>
  </row>
  <row align="center" gap={2}>
    <icon name="file-text" color="secondary"/>
    <box flex="1">

这只是说明 Thinking 的使用方式，具体能否形成这样的路线取决于实际图和观测。

它可能标记 root、continuation、analogy 或 supplement 等关系，但只有真实传播支持的链才具备相应路线资格。

**Thinking 更接近“用已有关系计算组织一条值得继续阅读的研究路线”。**

它与 Nous 未来的 Dream 有互补性：Thinking 可以为 Dream 提供跨主题资料及关联路线，Dream 则可以利用语言模型自由联想、形成新解释和创作，不需要受限于一条已经存在的图路径。

上游实现：[memo_thinking.rs](https://github.com/lioensky/VCPToolBox/blob/d5c019ebbac1f317c2938d655d2ce916e41b9164/rust-vexus-lite/src/memo_thinking.rs)。

# 十四、Nous 的改编：保留 VCP 数学，重新定义认知输入

上面描述的是原 VCP 的算法体系。

Nous 的目标更广：它需要在拥有来源、时间、修订、多种认知对象和运行上下文的情况下，继续使用这一套检索能力。

**因此，我们延续 VCP 的计算思想与数值闭包，扩展它所理解的输入和能够解释的结果。**

这里可以区分两个已经产生的设计层次。

**旧 Nous Native 改编**已经完成过一部分工作：把原先依赖 VCP 数据库、Node.js 和 N-API 的数值实现改为 Rust 纯计算，并支持不可变输入、快照和多根来源。

**最新 Wave Native Spec**在这个基础上，进一步规定 Concept、上下文、正式来源、类型化关联、时间范围、候选融合和原生查询接口的完整接入方式。

## 1. Tag 拓宽为 Nous 的 Concept

VCP 的 Tag 主要由名称、向量及在日记中的出现位置构成。

Nous 此前已经将 Tag 的含义扩展到“有描述的概念”，因此我们决定以 **Concept（概念）** 作为正式对象名称。

一个 Concept 可以拥有：

```text
概念名称：资源所有权

描述：
一项资源由谁持有、负责使用，
以及在实际工作完成后由谁释放。

别名：
Resource Ownership
资源归属
资源生命周期责任
```

这里会产生两种不同用途。

**名称和别名**适合字面匹配、精确定位及结果展示。

**完整描述**适合 Embedding，让向量表示更加具体的概念含义。

在 Native 中，Concept 仍可以投影为 VCP 所使用的 Tag 节点；其长期对象身份、描述修订和来源由 Nous 拥有。

这就保留了 VCP 的数学输入，同时增强了概念表示能力。

一个值得注意的研究问题是：描述文本向量与简短名称向量可能形成不同的几何分布。沿用 VCP 算法时，必须让查询线索、Concept 和候选向量使用明确相容的编码约定；不能在没有说明的情况下将两类空间混合。

## 2. 区分文稿、候选与独立来源

原 VCP 的 `file_id` 同时承担文件组织、Tag 顺序和部分来源判断。

Nous 拆出三个不同身份：

| Nous 语义 | 具体负责什么 |
|---|---|
| **Curve Document** | 候选概念曲线属于哪份文稿 |
| **Candidate** | 当前返回的究竟是整篇还是其中一个选区 |
| **Evidence Root** | 这些内容最终来自哪些独立原始来源 |

例如存在：

但它并没有增加第三个独立的原始事实来源。

这直接影响图构建、Wormhole 见证和候选支持度。

最新 Spec 继续沿用，并明确：

**原始来源贡献事实图，派生 Journal 保留检索能力与来源关系；派生的次数不会直接增加独立证据数量。**

这也让未来的 Schema、Dream Journal 和自动总结可以安全地参与检索，而不会因为系统反复整理自己的输出，就不断增加原始图中的“支持”。

## 3. 输入 Context、Core Concept 与临时 Cue

VCP 原本已有 ContextBridge、Core Tag 和 Ghost Tag。

Nous 将它们接入统一查询合同。

<box gap={2}>
  <box border radius="md" padding={3} gap={1}>
    **当前问题**

    “数据库事务完成后，为什么资源还在被使用？”
  </box>
  <box border radius="md" padding={3} gap={1}>
    **WorkContext**

    当前正在整理 Python 应用中异步取消与资源释放的架构。
  </box>
  <box border radius="md" padding={3} gap={1}>
    **核心 Concept**

    资源所有权、任务生命周期
  </box>
  <box border radius="md" padding={3} gap={1}>
    **临时 Cue**

    “协程取消与真实线程结束之间的时间差”
  </box>
</box>

其中 Context 可以有角色、顺序、权重和实际内容。

我们在 Spec 中选定的起步聚合方式，是对近期片段向量采用按角色与序位衰减的加权平均，再与原始查询进行有界融合。

概念上：

\[
c=
\operatorname{normalize}
\left(
\sum_i w_i v_i
\right)
\]

\[
q_{\mathrm{eff}}=
\operatorname{normalize}
\left[
(1-\lambda)q_{\mathrm{raw}}+\lambda c
\right]
\]

这里 \(w_i\) 来自实际上下文权重及序位，\(\lambda\) 是配置的上下文混合系数。

**这是 Nous 新增的上下文输入策略，不是 VCP RiverMemo 原生固定的唯一公式。**

进入 VCP 后，\(q_{\mathrm{eff}}\) 成为本次计算查询向量；算法内部继续进行 EPA、Residual 和双场计算。

原始查询也保留在查询记录中，便于区分“用户原本问什么”和“上下文把检索方向引向哪里”。

### 临时 Cue 与持久 Concept 各有用途

查询中临时提出的概念，可以像 VCP Ghost Tag 一样带着向量参加计算。

它不必先成为正式认知对象。

只有系统以后确实需要长期维护该概念时，才通过 Concept 的领域操作建立正式身份。

这能够支持 Agent 在当前问题中自由探索，同时不制造大量一次性的长期概念数据。

## 4. Association 扩展为有类型、有来源的关系

VCP 事实图的主要基础来自有序 Tag 共现。

Nous 还会拥有其他来源的关联，例如明确的经验联系、Schema 支持关系，以及以后 Social 所维护的关系认知。

因此我们增加了正式的关系输入：

```text
起点：Concept A
终点：Concept B
关系类型：related / supports / sequence ...
方向：有向或无向
关系程度：strength
判断信度：confidence
来源：evidence roots
```

Native 需要的是能够参与检索计算的数值投影。

这些关系的长期意义、来源和修订仍属于相应认知领域。

当前设计将正关联按照类型权重、关系程度和信度转换为有限的附加质量，再与 VCP 的共现事实一起经过传输校准和行预算。

这样，Nous 可以扩展 VCP 所能使用的关系来源。

对于反证、矛盾等负关系，设计采用独立的反证检索与呈现路径。原因是 VCP 的核心传输图假设：

\[
P_{ij}\geq0
\]

直接把负权塞进原来的衰减传输和双场计算，会改变整套数学假设。

例如用户查询某项经验时，Nous 可以同时返回支持它的候选，以及明确与其矛盾、具有实际来源的另一份候选。

这也为之后的认知矫正和社会关系变化提供了合理入口。

## 十五、我们扩展的是完整 Wave，而不只是 VCP

这里需要区分产品能力和算法实现。

VCP 提供完整、复杂的 TagMemo 和 RiverMemo 数值体系。

Nous 的 **Wave** 则拥有更广的检索职责。

| Wave 能力 | 主要实现 | 与 VCP 的关系 |
|---|---|---|
| Lexical | Tantivy、中文分词 | 提供精确文字和 BM25 候选 |
| Dense | USearch、现有 Embedding | 提供原始语义候选 |
| Concept Retrieval | Concept 向量与结构 | 为 VCP 提供已存及临时概念 |
| TagMemo | Rust VCP 数值模块 | 完整感应、残差、传播与增强 |
| RiverMemo | Rust VCP 数值模块 | 完整拓扑与双场读出 |
| DTSC | 旧 Nous 独立数值基线 | 用于保留另一套曲线/场读出方法 |
| Hybrid | Wave 查询规划和融合 | 组织完整候选及结果 |
| Source/Time | Python 内容与时间 owner | 提供来源范围、历史条件与结果解释 |

这里不能把 RiverMemo 当作一个普通的“图打分插件”。

它已经包含多个候选通道、查询增强、双场和内部排序融合。

如果 Wave 外层再把同一组内部通道逐个融合一次，就可能让相同信息重复投票。

我们在新 Spec 中因此决定：**完整 RiverMemo 作为一条具有内部完整数学定义的检索路径；外层只融合真正独立的其他路径。**

### DTSC 保留为独立研究模式

旧 Nous 的 DTSC 具有自己的查询场可信度、候选曲线接触、几何奖励和低证据回退规则。

它与当前 RiverMemo 有相似研究目标，但算法定义和读出对象不同。

所以它应保留可独立调用的模式和诊断，方便研究不同场/曲线方法的实际作用；不能把 DTSC 的评分常量或回退规则随意混入 RiverMemo 的 Ω 与四项评分。

这能保留高性能计算，同时避免 Rust 与 Python 两侧各自维护一套 Concept、Journal、Source 和数据库权威。

### 冻结 Snapshot 具有长期价值

一个 Native Snapshot 包含固定版本的概念向量、关系资产、候选映射、Embedding 空间和算法配置。

它可以被重复查询，也能在重启后重新加载。

新的认知或概念修订由对应领域完成，再按需要发布新 Snapshot。

正在执行的查询继续持有自己明确的计算版本。

这样，索引重建不会要求修改原始记忆，也不会让模型生成请求直接参与索引的内部生命周期。

## 十七、几个最重要的理论问题

VCP 的完整实现已经具备相当丰富的数学结构，但在长期 Nous 的设计中，仍有几个需要明确区分的理论命题。

| 数学或实现机制 | 它实际测量/完成的事情 | 进一步的认知研究问题 |
|---|---|---|
| Embedding 余弦 | 向量方向接近程度 | 这种接近是否对应当前用途的语义相关 |
| AGS 残差 | 概念不能被给定邻域解释的向量比例 | 高残差是否代表有价值的独特认识 |
| EPA 投影熵 | 查询在指定主题基中的能量集中度 | 能否预测复杂、跨主题或弱线索查询 |
| 有序 Tag 图 | 写入文本中的共现与序位关系 | 是否稳定保留了可复用的概念展开 |
| Sense 与 Wormhole | 查询沿已有图关系产生的活动和路线 | 是否找到有意义的远距离候选 |
| Ω | 本次传播河网的可观测性 | 是否能帮助确定结构奖励的可靠程度 |
| RiverMemo 拓扑读出 | 候选曲线与查询图、场及正文的匹配 | 是否改善关系型检索及结果排序 |
| Thinking | 将候选组织成具有前驱支持的路线 | 能否为后续语言理解提供更好的阅读顺序 |

其中我认为最值得深入探索的，是**有序概念编码与可计算关系之间的联系**。

上游的一份 [RiverMemo 思想研究](https://github.com/lioensky/VCPToolBox/blob/d5c019ebbac1f317c2938d655d2ce916e41b9164/docs/RiverMemo_%E6%80%9D%E6%83%B3%E7%AC%94%E8%AE%B0_%E9%80%BB%E8%BE%91%E8%BF%90%E5%8A%A8%E4%B8%8E%E5%8F%AF%E8%A7%82%E6%B5%8B%E6%8A%95%E5%BD%B1_2026-10-04.md)提出了一个更强的假设：

某些自然语言中的关系展开，可能在语义表示中留下可近似计算的方向结构；模型写出的有序概念序列，可能保存了其中足以用于以后寻址的一部分信息。

若这个假设成立，我们就能更清楚地解释 VCP 的独特价值：

它利用写入时已经完成的一部分语言理解工作，形成以后可以重复利用的关系资产。查询时，许多候选发现与关联计算便可以由相对高效的 Native 数值运算完成。

这里的关键研究对象是**关系寻址**，即找到一份可能参与当前问题理解的记忆；确认它具体支持哪项事实或结论，则属于后续阅读和认知解释。

## 十八、Nous 对这一理论的进一步延续

VCP 的有序 Tag、图传播和 RiverMemo 已经将“关系型记忆寻址”推进到了具体的数值实现。

Nous 的扩展方向主要体现在三个方面。

**第一，认知结构更加丰富。**

Journal 保存主题明确的完整叙述，Episode 组织实际经历，Schema 保存跨经历经验，Concept 提供可维护的语义节点，Anchor 形成长期关联中心。

未来这些对象可以共同向 Wave 提供内容、概念曲线与真实关系，但各自的生命周期仍由相应领域拥有。

**第二，认识具有来源与时间。**

同一份 Journal 可能由多份原始资料形成；同一个概念关系可能有多个来源，也可能存在反证；某段认识具有实际形成时间、适用时间和修订历史。

Wave 使用这些条件选择当前有权参与检索的资产。高数值相关性不能覆盖正式的来源、时间和可访问性规则。

**第三，检索与当前认知状态结合。**

用户自然语言、WorkContext、人格相关片段、活跃记忆、核心概念和临时联想线索，可以共同构造查询。

这些信息影响当前检索方向，不自动改变长期记忆。以后 Steward 可以从 Wave 已返回的候选中选择原文段落，Dream 可以利用 Thinking 和弱线索探索形成新的叙事与认识。

这使 Wave 不局限于一次显式搜索，而能够成为持续认知运行时使用长期过去的一项核心能力。

接下来的 Wave Native 开发，最值得坚持的就是这条分工：保留 VCP 完整算法，不缩减其输入语义；让 Nous 的正式 Concept、来源、上下文和时间进入正确的计算位置；保持 Rust 专注高性能计算，Python 专注真实认知与用户操作。

这样形成的 Wave 才能真正服务于 Nous 最初设定的长期目标：**让过去的经历、认识和关系，在新的情境中以有意义的方式重新被唤起。**
