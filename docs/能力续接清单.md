当前 VCP 图由合法原件标签及有序共现导出，完整 `source_refs` 随多来源候选传递。Concept/Association 权威关系图、managed context/steward、完整 NousQL 及高级领域继续续接。媒体执行、描述检索及原生多模态查询已接入共同的来源与向量权威。模型、领域和算法的原文件摘要与许可保存在组件来源清单中。

新算法 owner 为独立 `nous-vcp` 计算 crate，输入来自 retrieval 的冻结资产，输出交回同一查询物化流程。完整计算族、配置、旧 reference 和判别语料已复制改编；当前纯内核及实际验收见 [crate 说明](../crates/nous-vcp/README.md)，精确原文件映射、哈希与许可见 [来源记录](../crates/nous-vcp/UPSTREAM.md)。`geometry/`、`artifact/`、`sensing/`、`pipeline/` 与 `river/` 已按计算阶段分层，retrieval 已接真实向量、索引、资产发布和查询权威。

| 操作                                              | 输入 → 输出                                                                                                                                                                                                |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `geometry::build_geometry`                        | `{dimension, model_sig, tags, memberships, config, recorded_at_ms}` → `{intrinsic, anchor_gain, mean, basis, coverage, signature, epa_cache_json}`；space/producer/watermark 由资产 owner 绑定             |
| `artifact::build_artifact`、`MemoAssets::try_new` | 合法来源快照 + 几何结果 + Tag/候选向量与有序 membership → 校验并冻结 `{generation, signature, CSR, provenance, vectors, files, candidates}`；真实索引与发布归 retrieval                                    |
| `pipeline::run_pipeline`                          | `{query_vector, core_tags, ghost_tags, config}` + 同代资产与 TagSearch → `{observation, enhanced/local/transfer vectors, fields, domains, metadata}`                                                       |
| `river::readout`                                  | 同代 PipelineOutput + 冻结多路候选及 allowed_file_ids → `{ranked numeric IDs, scores, roles, anchors, diagnostics}`；当前 VCP Serving 映射来源并使用 RiverMemo 读出；Native/DTSC 独立正式 profile 继续接入 |
| `thinking::plan`                                  | 同代完整、未截断 observation + 有界 diary/阶段候选 → `{stage selections, predecessor routes}`；source refs 由原 owner 映射                                                                                 |

QueryView 在同一 ReadView 中固定 Subject、准确修订、历史截点和来源闭包，再统一执行请求过滤；文本模型空间由当前资源配置确定。Tantivy 按 scope 内容指纹同步并在 Top-K 前限制合法 ID，USearch 和 VCP 从该视图构造候选与资产，返回正文前再次读取对应权威视图。`ServingCandidate` 保存完整且非空的 `source_refs`，各 lane 数字 ID 与外部认知引用分别映射；代际由实际输入内容生成。几何和图证据按原件根去重，RiverMemo/Thinking 排除候选自身的全部来源根。

N-API、VCP 的数据库注册表、全局 publication gate 和宿主路径在 Nous 组合边界替换；数学内核、成熟向量索引、CSR 和线性代数直接复用。计算层已使用纯输入/输出和冻结资产，业务数据统一经 SQLx 读取；VCP 的原 rusqlite 连接由此边界替换。现有 Tasks/apalis 承担通用作业，ModelCalls 承担付费尝试、预算与恢复；认知和向量 owner 在同一 Operation 中采纳，资产保存可重建结果。
