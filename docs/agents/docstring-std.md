# Python 文档规范

修改 Python 代码时，使用类型注解表达数据结构，使用 Google 风格 docstring 说明调用契约。文档应让开发者和 Agent 找到合适的服务，并在不通读实现的情况下正确调用；涉及实现细节或行为存疑时，仍须查看源码和测试。

项目的架构入口与服务索引负责导航。这里的 docstring 使用中文是为了便于编写，实际通常使用英文，具体根据项目要求进行。

## 文档放置位置

- **现有架构入口和服务索引**：说明去哪里找功能，指向真实模块与公共符号。只有入口、职责或位置变化时才更新，不复制完整接口文档。
- **模块 docstring**：在职责不明显的公共模块或服务入口中，简述提供什么能力、主要入口是什么，以及必要的使用边界。不要重复全局架构或罗列全部函数。
- **类和接口 docstring**：说明服务职责、整体使用方式、资源归属，以及适用于全部方法的约束。
- **方法和函数 docstring**：说明本次调用的输入语义、结果、失败和调用限制。影响正确调用的关键条件应留在这里，不能只放在远处的设计文档中。
- **实现旁的注释**：解释不明显的原因、兼容性约束和算法取舍。不要逐句翻译代码。

共享约束放在最接近它的公共抽象上，方法只补充差异。引用其他文档时使用已核实的路径或符号；不要虚构目录，也不要把容易失效的行号作为唯一定位方式。

## 需求判断标准

公共接口按实际使用边界判断：对外导出的 API、供其他模块复用的基础服务、扩展点，以及 Agent 会直接调用的工具入口。没有下划线前缀不等于必须公开，带下划线也不能掩盖已经存在的跨模块依赖。

- 公共类、接口和非平凡的公共方法必须有足以指导调用的文档。简单接口可以只有一句话；有风险的接口需要写清相关约束。
- 内部函数优先使用准确的命名和类型。实现容易理解且没有隐藏约束时，不必补 docstring。
- 内部实现涉及锁、事务、缓存失效、异常转换或兼容性折中时，写下原因和必须保持的条件。
- `Protocol` 和抽象基类描述所有实现都必须遵守的契约。具体实现补充后端限制或额外能力，不能悄悄削弱公共契约。
- 继承方法没有语义变化时，不复制整段文档。覆盖行为、限制或错误语义发生变化时，明确说明，并检查是否仍满足父接口契约。
- 构造参数统一写在类 docstring 或 `__init__` docstring 中，沿用项目现有习惯，不两处重复。公开属性有非显然语义时使用 `Attributes`，不列内部字段。

不要为了文档覆盖率给每个 getter、私有辅助函数或空的 `__init__.py` 添加同义改写。判断标准是：缺少这段文字，调用者是否容易选错接口、传错参数或误判结果。

## 类型注解与 docstring 分工

公共接口的参数和返回值应有准确的类型注解，采用项目支持的 Python 版本和类型检查约定。无法确定类型时先查清边界，不用 `Any` 掩盖问题，也不为了补文档改变实际接受的输入范围。

类型描述结构，docstring 解释签名未表达的语义，例如：

- 字符串是资源 ID、原始文本还是编码后的内容；路径相对于哪里，时间是否带时区。
- 数值的单位、取值范围，以及 `0`、负数、空值的含义。
- `None` 表示未找到、未配置、自动选择，还是其他状态。
- 返回对象是副本、快照、只读视图还是共享可变对象；调用者能否修改。
- 列表是否有序、结果是否完整、是否去重；迭代器是否惰性读取或持有资源。

签名已经给出类型和默认值时，不在 `Args` 中重复类型，不机械复述默认值；默认值有特殊行为时说明该行为。`async def` 的返回注解描述 `await` 后的结果，不能仅凭 `async` 认定函数不会阻塞或可以安全并发。

## 基础服务的调用契约

按接口实际行为检查以下内容。只有影响调用的项目才写，不要求每个方法都填满一套模板。

**职责和适用范围**

首句说清做什么。有容易混淆的相邻接口时，指出选择条件。服务接收哪些领域对象、依赖哪些外部能力，只写调用者需要知道的部分，不展开完整依赖图。

**生命周期和资源归属**

需要初始化、启动或上下文管理时，写明调用顺序。说明连接、文件、会话等资源由谁创建、谁关闭；传入的依赖是借用还是转移所有权。若关闭后不可用、关闭可重复调用，或后台任务需要等待结束，写清相应行为。

**输入和结果**

说明前置条件、关键边界值及返回语义。不要把类型检查等同于运行时校验。遇到非法输入时是拒绝、规范化还是交给下游处理，应与实现一致。

**错误和恢复**

在 `Raises` 中列出调用者需要处理的异常及触发条件。重点是稳定暴露的错误，不逐层抄录所有依赖可能抛出的异常。必要时说明异常是否转换、是否保留原因，以及未找到是返回空值还是抛错。

涉及超时、取消、网络失败或批量操作时，说明调用者如何判断结果：失败是否可能已经产生部分效果，是否能安全重试，是否需要查询状态。不要将“没有收到成功响应”写成“没有发生写入”。

**副作用和一致性**

存在写库、发消息、文件操作、网络请求、缓存更新、事件通知或后台任务时，说明影响调用决策的副作用。涉及事务、提交时点、部分成功、覆盖写入或重复调用时，说明边界。没有实现和验证依据，不承诺原子性、幂等性、顺序性或自动回滚。

**并发和运行环境**

共享实例是否支持多线程、多个协程或跨事件循环使用，应分别判断。存在外部加锁要求、同一资源的竞争条件、阻塞 I/O 或回调执行环境约束时，明确说明。“异步”“有锁”“使用连接池”都不能代替具体保证。

**示例**

多步生命周期、容易误用的参数组合、特殊错误恢复或资源管理需要示例。普通的一行调用不必展示。示例应短且能说明关键用法；用真实公共入口，不绕过封装调用内部成员。

不清楚的行为先查看实现、调用方和测试。仍无法确认时，在本次工作说明中标记具体疑点，不能把推测写成正式契约，也不能顺手改代码来迎合新写的说明。

## Google 风格写法

使用三双引号。首行是一句准确摘要，后续正文与首行空一行。段落语言沿用项目约定，段名统一使用 `Args`、`Returns`、`Yields`、`Raises`、`Attributes`、`Examples` 等 Google 风格名称。

- `Args`：使用该段时，按签名列出除 `self` 和 `cls` 外的参数，解释各自语义；简单参数简短说明，不制造无意义长句。参数无需额外解释的简单接口可以省略该段。
- `Returns`：说明实际返回结果及特殊值的含义。没有有意义的返回值时可以省略，不写空洞的 `None: 无返回值`。
- `Yields`：生成器说明每次产出的值，并按需说明惰性执行、耗尽和提前终止的行为。
- `Raises`：写异常类型及可判定的触发条件，不写“失败时抛出异常”。
- `Attributes`：仅说明公开属性中调用者需要知道的语义和限制。
- `Examples`：仅在能消除歧义时使用。完整示例应可运行；省略实现的片段须明确标为片段。

生命周期、副作用、并发等说明放在摘要后的正文，或按项目现有工具支持的方式组织。不要擅自增加一批解析器不识别的段名。正文仍是契约的一部分，不能因为自动文档工具忽略它就省略关键限制。

### 一般函数

下面的示例展示空值和边界行为，不重复已经由类型表达的信息。

```python
def split_batches(items: list[str], size: int) -> list[list[str]]:
    """按原顺序将条目分批。

    Args:
        items: 待分批条目；空列表产生空结果。
        size: 每批最多包含的条目数，必须大于零。

    Returns:
        新建的批次列表；最后一批可能不足 size 项。

    Raises:
        ValueError: size 小于或等于零。
    """
    if size <= 0:
        raise ValueError("size must be positive")
    return [items[i : i + size] for i in range(0, len(items), size)]
```

### 服务接口

以下是接口声明示例，生命周期、并发和错误语义都是此示例的约定。

```python
from typing import Protocol


class BlobStore(Protocol):
    """按键读写二进制内容。

    实例交给调用方时已经可用。创建者负责调用 aclose()，借用者不关闭它。
    同一实例支持同一事件循环中的并发读写，不支持跨线程或跨事件循环使用。
    同一键的并发写入不保证先后顺序。关闭前须由创建者等待在途调用结束。
    """

    async def get(self, key: str) -> bytes | None:
        """读取指定键当前可见的完整内容。

        本次调用访问后端，不使用本地缓存，不自动重试。

        Args:
            key: 非空的区分大小写的键，按原样查找。

        Returns:
            已存储的内容；不存在时返回 None。空内容返回 b""。

        Raises:
            ValueError: key 为空字符串。
            RuntimeError: 实例已关闭。
            TimeoutError: 后端读取超时。
        """
        ...

    async def put(self, key: str, content: bytes) -> None:
        """写入完整内容，并覆盖同一键已有的内容。

        返回时后端已确认写入。本方法不自动重试；超时或调用被取消时，
        写入可能已经生效。调用者需核实结果，不能简单认定失败。

        Args:
            key: 非空的区分大小写的键，按原样存储。
            content: 待存储内容，允许为空。

        Raises:
            ValueError: key 为空字符串。
            RuntimeError: 实例已关闭。
            TimeoutError: 等待后端确认超时，写入结果未知。
        """
        ...

    async def aclose(self) -> None:
        """释放实例持有的连接；成功关闭后重复调用无效果。

        调用时不得有在途读写。成功返回后，实例不再接受新的读写请求。
        """
        ...
```

这里把资源归属和并发限制放在类上，把未找到、空内容、写入确认及超时语义放在相应方法上。实际服务只有部分特征时，只保留相关说明。

### 无效文档

下面是反例片段：

```python
def get_data(key: str) -> bytes | None:
    """获取数据。

    Args:
        key (str): 键。

    Returns:
        bytes | None: 数据或 None。
    """
    ...
```

这段文档重复签名，却没有说明键的含义、`None` 的含义或错误行为。单写“线程安全”“支持重试”“高性能”也没有帮助，除非明确适用范围，并有实现依据。不要用这种文字换取覆盖率。

## 修改与检查

文档随行为在同一变更中更新。变更参数语义、默认行为、异常、资源归属、并发保证或副作用时，检查相应 docstring、受影响的调用示例和测试。公共入口或位置变化，再更新已有索引。

补文档前先核实行为；改行为时补上能证明该变化的测试。只改说明且不改变行为时，不为形式增加测试。

完成前检查：

- 调用者能否找到接口，并明确输入、结果和必须遵守的条件？
- 会导致资源泄漏、重复写入、错误重试或并发误用的限制是否写清？
- 是否存在实现不支持的保证，或尚未查证就写成事实的行为？
- 参数名、类型、异常、示例及索引是否仍与当前代码一致？
- 能否删除重复签名、重复架构或逐句解释实现的内容，同时保留调用所需信息？
