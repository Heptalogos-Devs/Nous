# TypeScript 接口文档标准

公共 SDK、扩展接缝与生命周期操作应使调用者不阅读内部实现就能使用。类型系统负责表达字段与可选性，文档负责表达业务含义、单位、重要前置条件、副作用和资源所有权。

- 模块文档写清完整能力及主要入口，避免逐个重复函数名称。
- 方法文档只解释类型无法表达的调用约束、真实错误、取消、结果完成点和配置生效行为。
- 对象方法利用其已绑定的安装、实例、作用域与配置上下文，避免重复传参和冗长命名。
- 解释必要的复杂算法与非显然取舍；简单的内部 helper 无需例行 JSDoc。
- 示例使用真实公开接口，避免依赖私有存储形状、臆造的异常路径和专用测试出口。
- 新增参数或数据字段时，必须能够说明实际消费者；应优先消除多余职责和隐藏依赖。
- 任务输入、配置与持久数据的 Schema 由 Zod 定义，文档从真实定义生成，不手写第二份字段表当作执行权威。

旧项目的 Google 风格 Python docstring 规范随历史实现归档。
