# 当前工作

## 已有能力

本地实例、配置、启停、SQLite、CAS、多轴时间、执行和观测保持共同入口。表由组合根显式收集；开发中变更过内部表的实例需要在明确选择的新目录初始化，不自动改写已有实例。实例可按可读 profile 登记和选择。

配置快照在创建时完成校验，`values` 提供深度不可变的类型化视图；普通操作复用同一快照。在线与离线配置修改进入共同执行边界。根操作绑定其 Runtime 的观测与实例关联，预先创建的异步 worker 同样保持外部 Trace 上下文。

模型和媒体共用输入规划、冻结任务与请求尝试策略。普通任务联合处理多份材料，独立逐批执行显式选择。每次只准备实际选中的路线，备用路线在真正切换时才按同组原件和选区准备表示及所需转写；媒体分析各阶段也通过共同生成操作选择路线。媒体按真实类型协商表示，转换在消费当前批次时执行，保存实际 MIME、范围和来源。Prompt 预览、probe、生成与媒体各阶段消费同一套能力，纯预览不发语言请求。

SelectedInputs 保留原件、离散选区、slot、role 和已确认事实；实际交付的 SourceContext 随输入正式保存。无扩展名视频先探测类型，各阶段从同一选择规划；原生音频主路线不提前检查未使用的备用转写绑定。已保存描述可重开后继续结构化。

Embedding 的 run、ensure、probe 和临时查询使用同一个批次执行器。已采用向量依空间、用途和精确输入选择规范行；网络不占用复用长锁，少量行读取通过 CAS 本地借用及 NPY mmap。临时查询默认不接纳新的正文或向量结果。

内容关系按输入组、part、origin 和输出规范化保存；显式来源槽和不连续选区贯穿实际采用的模型路线。共同阅读视图返回文字或媒体原件及已有表示。TextView 保留定义行、CRLF、空白和尾部，提供精确原文范围及按需结构。缓存读取、解析、绑定与序列化进入受管理线程；批量准备合并请求实际覆盖的范围，读取上限约束返回选区。

输出坐标映射由生产者与结果一起采用，后续读取沿正式映射迭代回溯。实际输入、坐标映射和恢复所需执行依赖分别保存；任务快照不增加独立证据根。

根操作保持稳定关联，子阶段和实际请求尝试可通过 JSONL 追踪。已保存但后续维护失败的 partial 贯穿结果、根终态、`runtime logs` 和 `runtime check`；后者也读取近期正文准备阶段摘要。默认不持久保存完整 Span 树。

日志出口按实例持有，根操作在当前 Task 绑定事件归属；预先存在的 worker 与跨实例嵌套保持正确关联，交错关闭不改变宿主日志配置。Note/Journal 编辑在启动编辑器前持有实际恢复文件，锁占用、冲突和未确认保存的出口保稿；`edit --resume` 使用原 expected 和维护请求，同一次已提交写入可重放。

Wave 使用 Rust retrieval 的 Engine、冻结快照、观测、完整 CandidatePool、召回与读出；PyO3 负责数组、detach 和对象边界。VCP 数值基准为 `d5c019e`，具名 DTSC 保留。稀疏图、长出现序列、多路径和明确支持组均有实际消费；查询可使用临时编码或已采用的显式 VectorRef。

文稿投影、来源、候选向量和概念关系在数据库中按签名共享；未采用快照与其引用同事务持久化，重开验证组件并可重放准备。耗时准备与事务接纳／当前提升分开；查询借用和正式引用保护资产，CLI 提供显式清理。标题进入独立词项字段与语义投影，交付选择查询相关的精确原文范围。

默认 Namespace 可直接保存 Note 和 Journal。`open_instance` 持有一个 Runtime，`runtime.cognition(namespace)` 提供绑定该域的程序内操作。正文、精确来源与不可变版本支持读取、局部精确编辑、全文替换、差异、历史、归档和恢复；并发修改按基准版本检查。Note 默认不参与长期召回，可显式设为 remember。手写记录、修订和 lexical 查询无需模型。

Namespace 句柄持有稳定身份，改名或名称复用不会改变其归属。正文修改在共同 owner 分别核验 target 和 expected，跨对象前置条件拒绝执行。RevisionSelection 携带正式修订与精确选区，来源冻结、草稿、查询和 current_basis 使用同一解析能力；活动标注按实际当前召回视图的变化推进 generation。

`journalize` 只形成新篇；局部自然语言修改建议、明确全文重写和跨篇反思各有独立任务。成功草稿固定输入、基准、来源和意见，可读差异后采用；重复采用返回原版本。正式 Concept 保留稳定身份及独立意义版本，正文标注固定块和 Concept 版本，提案采用后才进入当前认识。保存后可按配置接续标注，失败时保留已保存正文。

当前查询在一致读事务中捕获正式文稿、来源和已采用标注，按需通过 Wave 发布可重建快照；未变更时直接使用当前代次。检索按文稿分组召回和交付，返回完整片段、精确版本、来源及类型化查询情境。反馈保存精确目标或实际交付的查询结果，并可独立处理或与正文修订同事务关联；显式 `current_basis` 的过期依赖显示待复核，历史引用保持可读。

AfterWrite 由维护 owner 形成类型化计划，前台直接执行领域能力，后台标注与刷新在正文 WriteTx 中通过 DBOS 3.4.0 官方接口独立入队；标注采用与承诺的刷新入队共同提交。无需修改正文即可发起新的后台标注请求。普通 `open_instance` 提供可嵌入的 Runtime；显式 `run_host`、`runtime run` 和 `job run` 拥有同循环持久宿主。已有外部 DBOS 时普通 SDK 可用，新的 Nous 宿主拒绝占有；单业务名额下控制等待不阻塞执行，宿主停止后的未完成工作可重开续跑。

语言任务冻结实际模板、模型路线、参数、媒体策略及解释合同。已有正式提案先读取，已有成功响应在本地解释；当前 Provider 或帮助说明变更不阻断恢复。正式写作请求固定原基准、来源和采用意图，writing.recover 与 journal draft recover 可跨重开继续。PreparedOutputs 复用已发布字节；ResultStore、Annotation 和 Wave 吸收提交后的重放。当前快照描述不读取完整候选映射，查询反馈一次批量取得实际交付候选。

## 有效决定

保持供应商中立，真实模型访问统一网关。Python 拥有正式状态和业务采用，Rust 拥有可重建计算与索引。媒体、向量和 Wave 继续复用配置、Execution、事务、时间、内容与观测 owner。

血缘根集合不等于独立支持。关系通过 SupportGroup 区分共同前提与独立见证，解释性贡献通过显式 profile 启用，检索和标注不自动改变长期认识。
