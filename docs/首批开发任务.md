# 首批 Coding Agent 开发任务

## Objective

在统一基础服务和事务权威上，按 [能力续接清单](能力续接清单.md) 完成 M2 的结构化认知、媒体、managed context/steward 与完整 A-Memorix 产品，并续接 M3 的完整查询和 VCP 算法体系。所有入口继续使用同一认知权威与事务设施。

## Decisions

Rust 模块化单体、SQLite + SQLx、apalis-sqlite、Axum 与 rmcp 构成 M0；M1 接入 genai 0.7.0、Tantivy 0.27 和 tantivy-jieba 0.21，M3 文本检索接入 USearch 2.26.2。对象存储本批使用 tempfile 原子发布本地不可变文件，OpenDAL 按实际后端需求接入。进程、配置、凭据、任务、模型和索引均有单一所有者；HTTP、CLI、MCP 调用相同应用操作。材料存在、主体接触、形成记忆分别保存。全部新下载、缓存、安装暂存和编译产物进入 `temp`。

业务写入使用 `BEGIN IMMEDIATE`。幂等键为 `(caller_id, operation, scope, operation_id)`，完整回执与领域结果、任务同事务提交；commit_seq 由实例级 authority_state 分配。Namespace 管理材料与首次接触授权，Subject 读取已接触材料并可记录后续接触。详细合同集中在 [一次业务提交](基建实施规划.md#一次业务提交的合同) 和 [授权](基建实施规划.md#配置授权与模型资源)。

## 运行与材料接纳操作

实例初始化、启停、配置、令牌、材料接纳、接触和来源读取的使用步骤见 [README](../README.md)。保持 CLI 与 `/v1`、MCP 的业务语义一致，以程序实际 `--help` 为参数依据。

在线 CLI 支持明确服务地址和受保护的认证来源；离线管理使用 `--instance`。HTTP `/v1` 按相同业务对象组织操作。提交返回完整 OperationReceipt；异步操作携带 job_ids，并可按 ID 查看状态。稳定错误类别包含 InvalidArgument、Unauthorized、Forbidden、NotFound、Conflict、CapabilityUnavailable、ResourceExhausted、DependencyUnavailable、Internal，MCP/A-Memorix 层按其合同映射。

材料写入保存原文和来源；Namespace 或管理员接纳 Subject 对既有材料的首次接触。`Observation.kind=contact` 表明实际接触，`kind=import` 保存知识导入的来源事实。Subject 可导入自己提供的资料，并读取自身已获准的材料；对既有 Material 的首次接触继续由 Namespace 或管理员授权。NamespaceId、SubjectId、MaterialId 和 ObservationId 保持各自身份。

## M1 的公开操作

当前实现通过以下操作贯通形成与查询，实际参数见程序帮助及 [README](../README.md)：

```text
nous memory form --subject <id> --observation <id>
nous job get <id>
nous query --subject <id> "查询内容"
nous source read <ref>
```

第一版 QueryRequest 包含 Subject、自然语言文本、可选 Memory 精确引用、来源、时间轴与时间域区间、数量和 min_commit_seq。结果包含 Memory 当前修订、可读内容、引用、来源、时间、认识状态及索引覆盖。更多返回对象、历史截点和完整 NousQL 语法继续在 M2/M3 推进。

模型凭据由操作者通过正式配置入口提供，[模型配置例子](基建实施规划.md#配置授权与模型资源) 只保存 SecretRef。形成任务在缺少配置时等待配置，每日预留达到上限时等待预算；材料保存、读取、状态和管理继续可用。本批真实网关验收使用小规模文本，检查实际输入输出、模型记录、形成来源及重启后的查询。
