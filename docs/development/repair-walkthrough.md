# 修复后的实际使用通路

从现有 `nous --instance <实例>` 产品命令使用下面的能力。示例里的任务、模型和空间使用本机实际配置；网关管理与样本生成继续留在开发环境。无需 CI、统一测试门禁或新的测试框架。

## 输入、表示和联合任务

将同一份 PNG 分别命名为 photo.png、attachment.bin、image.txt。三次显示的名字可以不同，识别 MIME、实际输入 part 与模型看到的像素应相同；不是靠 CLI 扩展名分支修正。

配置只接受 JPEG 或 WebP 的真实模型，处理 PNG、PDF 页与视频帧。PreparedAttempt 展示实际发送格式与转换来源。透明图转 JPEG 时使用已明确背景或报告缺项；所有路线都没有格式能力时在请求前报准确错误。

准备 A.md“原定周五发布”、B.md“安排改到周一”，通过同一次 `tools model run --task <联合比较任务> --input A.md --input B.md` 提问变更。一次实际请求包含两份材料；正文和来源键可查。纯 preview 与 show-request 的输入语义一致。

对长 PDF 或视频执行明确逐批的描述。首批转换、模型与结果采用可以在后续批次仍未转换时发生；记录真实阶段时间。取消后已有结果可读，未消费范围明确，解码器和子进程关闭。小样本无法说明长媒体行为，应使用用户已有的实际长样本。

## 所有向量入口

在同一 max_batch_size=2 配置下，向 run/ensure/probe 提交 5 项，观察模型尝试实际为 2+2+1（单项自身合法）。返回行序与原输入一致，重复输入可复用但保留原下标。

同时执行一个多批建库和一个无关交互查询。在实例 Execution 尚有名额时，后者能进入自己的请求，不等待前者全部结束；同一调用内相同输入复用一次编码，跨调用已采用结果立即可用；两个并发未命中可以各自请求，但返回同一规范已采用行。取消其中一个根操作不影响另一个操作。

第二批失败时第一批引用可读，重做 ensure 使用已有行。读取少量向量行通过 CAS 借用实际 NPY，不读取所有向量到额外 bytes。

## 可读诊断

使用用户已控制的环境产生一次暂态失败后恢复，以及一次最终失败。终端报告具体模型资源、实际尝试、原因和已保存产物；错误中的操作关联可以通过 `runtime logs --operation <引用>` 找到完整过程摘要。

export=none 时状态明确 Span 未持久导出，日志依然能定位尝试。OTLP 配置可用时查看同一次 operation 的阶段和 attempt；正文/Key 不随普通事件输出。成功查询的 INFO 输出主要是对象、模式、数量、耗时，不被 ID 占满。

## 来源与检索核心

用两份原件及多级派生调用来源读取，关系访问局限其祖先；加入无关历史不让查询退化为全库复制。PDF 文本取得由媒体公开操作完成，Wave 不自己采用转换结果。

在同一 snapshot 与 observation 上提供固定 CandidatePool，修改 readout 配置，确认没有再次 ANN/BM25；普通 search 使用同一个 recall/readout。将某一路 k 设0，该路不执行；直接锚来源可以来自实际 seed，不仅限用户 core。

单个孤立 Concept、无边图、有显式 core/ghost 的输入仍返回可定义的检索及缺失分量说明；101 项 sequence 不被整体抛弃。Thinking 记录禁用、记录截断、合法无路线、输入错误和取消各自表达。

构建完成发布后只 open 一次。关闭重开后，实际候选、空间、来源和算法配置一致；不重新调用模型。通过 Wave read 精确读回得分对应的内容。

## 本轮记录方式

使用结果用于修复具体负责者，保留用户需要的样本和实例；临时生成脚本放 temp。正常操作完成即回到当前任务，不增加逐字段回归、全仓重复验证、固定性能门槛或审查证明文件。

涉及独立数值合同（质量/排序分离、来源组排除）可保留少量有用的现有回归；它们不代替上面的产品通路。项目所有者负责独立验证。
