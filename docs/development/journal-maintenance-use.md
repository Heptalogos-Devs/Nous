# Journal 维护的实际使用流程

## 使用方式

通过正式 API 和 CLI 完成同一组任务。使用用户已有 Windows 实例和真实材料时，先按当前 schema/配置明确选定实例；需要重建的开发数据只在明确授权范围处理。没有远端 CI 依赖，也不把通路拆成大量 Helper/字段测试。

本包规划者未运行代码或复现用户测量。下列情境是施工后的实际使用要求，用户独立检查继续按其工作方式完成。

## 程序内记录与精确修订

在一个 `open_instance` 生命周期中创建两条 Note、形成一篇 Journal，读取 exact revision 和 TextView。使用公共 edits 修改一条日期，再插入一段新资料。读取 diff，确认原来未选中的段落、代码、换行和引用仍在；读取旧 `@N` 仍是原稿。

同一程序再创建第二个 Namespace 句柄并操作，两个句柄互不改变默认域。程序没有调用 shell、CLI、临时 JSON 或私有表。

编辑基准被另一操作改变时，提交收到冲突，编辑内容/提案仍可读取。再次执行同一已采用提案返回原采用结果，不新增版本。

## 语言任务与意见

用已配置网关执行：新材料 journalize、限定块的修改建议、明确全文 rewrite、两篇旧 Journal 的 reflect。前者生成新篇；局部建议只变指定范围；重写允许明确的全文取舍；反思创建新身份并保留旧引用。

向 journalize 传入已知 Journal 或其已知正文 Artifact 时，得到清楚的意图选择错误，不暗中再摘要。模板预览显示真实 source keys、基准和材料角色，系统指令仍不含本次真实资料。

先提交一条负反馈并留言，确认没有自动模型请求和排名变化；按目标列出意见；显式用这条意见生成修改建议；只在采用后建立反馈→新修订关联。另一次意见明确不采用，能够阅读处理说明。

## 多媒体来源

使用此前已经跑通的文字、PNG/JPEG、音频、视频、PDF。Journal/draft/query/read sources 通过同一阅读能力展开：文字是原文，媒体是准确页/时段、原件以及已有描述或转写。没有表示时仍可正常返回媒体引用；普通读取不重新发语言请求。

## 检索维护与覆盖

保存精确修订，下一次 current 查询固定新代次并构建；旧 snapshot 仍读到旧 revision。构建期间再提交新内容时，本次使用已经捕获的视图，下一次 current 看到新内容，不无限追赶。

复用用户报告的数据形态：

| 情境 | 本轮需要观察的结果 |
|---|---|
| 501 篇短文稿、正文约 144 KB，修改一篇后 lexical 查询 | content_prepare 不再逐候选重复读/解析；输出真实阶段耗时、唯一正文数及 cache 命中，Native 仍使用原引擎 |
| 相同数据不再修改的热查询 | 不重新 capture 全量正文、不重新准备索引 |
| 一篇约 246 KB 分节长文＋四篇相关短记录，top-k=10 | 有足够通道和组预算时返回五个实际匹配文稿组，长文多个片段不吃光名额 |
| 同一正文两个 Artifact 来源身份 | 纯解析可复用，来源身份与独立关系仍各自正确 |
| 原件→Journal→反思，重复生成相同联系 | 候选可找回；解释性结构在启用 profile 下参与；独立来源数不随总结次数增加 |

用户提供的 23.64 秒、0.116 秒与 0.15 秒是该机器上的基线。交付报告写实际前后观测，不预写“已经降低到某毫秒”，不为了数字删掉来源或图计算。

## 部分失败与诊断

启用保存后标注但不配置对应模型，保存一条文稿。响应应为 partial、保留正式 revision、带 `model.task_unconfigured`。错过这个响应后，`runtime logs --operation` 仍显示同一个 partial 及标注阶段；`runtime check` 的近期问题能找到它。

恢复模型配置后显式完成标注，另一次操作可以成功；前一次日志保留当时真实结果，不被改成成功。网络一次失败后重试成功，最终根应为 success，失败 attempt 仍可展开。

一次 `note annotate`/`journal annotate` 从提案到采用只有一个根关联。显式 --draft-only 正常只生成提案。取消或主操作异常保持原语义及已完成内容，不仅验证一个返回字段。

## 语言与 Prompt 编辑

`--language en` 创建无标题笔记，普通输出使用英文默认标题与状态；JSON title=null，正文不变。再使用中文界面读取同一内容，只有界面标签改变。

登记/选定一个 profile 后连续执行产品命令，不再每次输入长路径与 UUID。代码宿主使用显式路径时不被后来 profile 选择改变。

对 journal-edit、媒体描述、结构化提取分别执行 prompt describe/edit/preview，能看见不同模态、变量、Schema、角色、实际资源来源。只改 documentation 不改变执行签名；改模板影响后续根操作，正在执行的资源不变。包内升级不覆盖实例手改模板。

## 结束条件

交付真实操作、准确引用和可解释结果。发现缺陷沿实际 owner 修正并重跑受影响原操作；不要把这份使用说明改造成永久探针库、固定全量压测或测试门禁。
