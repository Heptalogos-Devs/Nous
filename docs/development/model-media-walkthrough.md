# 模型与媒体的实际使用通路

## 验证方式

使用真实产品入口和资料，从输入到结果读取确认能力。开发者用正式操作排查实际问题；用户负责独立验证。不启动、不查询、不依赖 GitHub CI。咨询/审查阶段不另跑本地测试。

固定生产行为的回归可以保留在现有 pytest；普通字段、私有 helper 和第三方库内部能力不单独测试。不建设测试场景 DSL、全量资格矩阵或永久实验工作台。

## 连接并查看模板

在 `temp/nous-model-media` 或用户明确指定的新开发目录执行正式 init，按本地网关指南配置真实资源。使用 config explain 查看有效值，运行 model discover 取得模型名。Prompt list/show/preview 在此时已经可用；preview 中能读到 Markdown 任务、有角色消息、实际输入和媒体位置。

单独读取配置与模板不调用模型。下一步的明确 run/probe 使用用户已经授权的网关，无费用确认停顿。

## 文字与结果读取

接纳一份真实 Markdown 或开发讨论，使用 summarize 生成主题清晰的文本，使用 extract-information 形成小结构结果。读取返回的 res 地址，展开原始 art 地址与请求快照；关闭重开后仍取得相同内容。

将该组候选给 select-passages，确认交付段落逐字来自输入。这里观察任务是否易懂、是否遗漏条件，修改负责模板与任务粒度，不把语义不佳误归因成数据库故障。

## 媒体链

使用真实图片分别执行三种策略。两阶段结果应包含原图、描述及最终结构化结果的关系；显式复用已有描述时不重复描述请求。

对 PDF 指定页区间，查看页图/文本和出处；对音频查看真实转写或原生理解；对短视频查看抽帧点、音轨/转写与解释。超出单次限制的资料按批次返回，尾部范围明确处理或报告未完成。

语义检查由实际内容决定：结果有无看错、Prompt 是否过载、是否发送了正确媒体。这些判断不以测试数量或 JSON 解析通过代替。

## 技术行为沿同一通路观察

在真实文字流中取消，响应关闭且不出现成功 completed 结果；已提交的前序内容仍可读。准备两项兼容配置，可在出现真实可重试故障时观察 fallback；不得修改全局网关渠道制造故障，必要的局部实验留 temp。

对两阶段处理的第二步制造一个局部可控失败，第一步结果可读；修正后显式复用描述继续。实验通过公开任务/Prompt/连接配置开展，不增加生产专用 fail_next 字段。

用真实 embedding probe 建立空间，再 run 保存并重开读取。修改同一已用空间维度/部署，公共 config 操作拒绝；新空间按正常流程使用。

## 数据库争用回归并入产品操作

原 `test_database_contention.py` 不再作为独立底层测试保留。需要长期覆盖的情境放进内容/结果通路：在已打开运行时使用独立 SQLite 连接持有短写锁，同时发起真实 content ingest 或结果采用；释放锁后，该操作完成并可按地址读取。

断言围绕操作等待/成功与正式内容，不重复列举每个连接 PRAGMA，不研究断电。该段可与内容重开读取、失败不返回成功结果的场景在一个有意义的通路测试中维护。只保留保护实际操作的代码，清理旧文件和专属支撑。

## 交付说明

报告真实采用的输入种类、模型/连接与可读结果、已发现并修正的问题，以及具体未完成能力。临时命令输出和样本留 temp；需要人阅读的少量结果可作为当前任务交付，但不要求永久证据归档。
