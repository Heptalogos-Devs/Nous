# 一条持续认知使用通路

本文件用于开发者定位当前功能与项目所有者独立验证。所有操作经正式 CLI 或同一进程内 API。按实际改动选择情境，不要求每次局部修改重新运行所有内容，不建立 CI、专用平台或逐字段检查。

## 从经历到可找回的理解

记录两个 Note：其一讲取消等待后线程仍在读文件，其二讲将资源释放放到实际工作结束后问题消失。将一条 Note 设为 remember，另一条保持默认。读取两者，确认保存与是否长期召回的区别能被理解。

用 journalize 将它们共同整理成“取消与资源责任”草稿。读草稿、展开 S1/S2、编辑一处文字，再采用。模型写作、材料整理和正式采用分别显示实际结果；用户不需要手写数据库 ID 或 Wave 清单。

调用 annotation，看到复用和新建的概念、对应正文块、路径。查询“任务结束后文件为什么还没释放”，获得正式 Journal 的片段、精确 revision 和来源；按返回引用读全篇及原 Note。

## 纠正与历史

保存一次明确 correction。再查询当前内容，新正文出现；之前的命中仍能读回原 revision，并提示已有新版本。正文更新但尚无新标注时，不能沿用旧块关系；仍可普通读取和 lexical/dense 查询。

另写一篇 reflection 引用旧版，usage=reference。再编辑旧 Journal，这篇反思仍解释其历史引用。另做一篇带显式 current_basis 的派生结论，纠正其依据后当前查询显示它待复核，`--include-review` 可读取原文；更新依据后恢复。

## 模型任务质量

给材料保留否定、两个人的不同观点、旧计划与取消后的计划。观察正文是否保留各自归属，路径是否误把对照强连成因果。出现问题先定位来源组织、写作 Prompt 或标注任务，不默认增加自审模型和通用护栏。

再整理同一批材料两次。新的解释可有新路径，来源支持仍归原依据；反复摘要不产生更多独立见证。测试直接读取原件仍能回答正文遗漏的细节。

## 正常失败与冲突

| 操作情境 | 应见到的用户结果 |
|---|---|
| 两个编辑器从 @1 修改 | 一个得到 @2；另一个保留编辑稿，返回当前引用，不覆盖 |
| 模型为 @2 写完稿前人工提交 @3 | 草稿可读；采用报告目标冲突，不重新调用模型 |
| 一个草稿重复 adopt | 返回同一个采用 revision，不多建 Journal |
| 保存成功但 Embedding 断开 | 正文立即可读；current semantic 查询说明更新失败；显式 lexical 可用 |
| 构建 G 时又保存 G+1 | 本次读 G 的一致视图，下一次 current 读 G+1；不无限追赶 |
| 标注执行期间正文改了 | 提案固定旧正文；current 采用冲突，旧位置不移到新文稿 |
| 名称相同、含义不同的两个 Concept | 身份独立，可读说明可区分；不自动合并 |
| 概念描述改了但旧文稿未重标 | 旧文稿使用原意义版本，新绑定可以用新版本 |
| 正文里有代码文本 `[S1](source:S1)` | 代码内容不被当成引用；真实 link 使用绑定 |
| source key 不存在 | 草稿保留并指出位置，正式采用不成功 |
| 归档又恢复 | 当前候选/自身图贡献退出再进入，旧引用始终可读 |
| 虚拟时间经历被今天导入 | observed/formed/valid 按明确域保存，recorded 为本次真实采用，不混淆 |
| 无模型配置 | 手工 Note/Journal、修改、历史与 lexical 查找都可用 |
| 另一 Namespace 的认知引用混入 | 明确指出域不一致，调用方需显式选择合法材料采用 |

## 观测与操作易用性

制造一次真实上游请求失败后恢复，查看终端和 runtime logs --operation：必须能看到真实模型、同路线重试或切换、原因、耗时和最终结果。保存失败与检索失败显示不同位置。普通成功输出主要是标题、正文、短引用和必要状态，不是 UID/SHA 列表。

参数错误的 --json 结果、非零退出、stderr 进度和 stdout 正文保持既有合同。高级状态能解释 content generation 与 covered generation，普通用户只需知道已保存/待更新/已更新。

## 由使用结果决定后续工作

如果正文内容和来源正确而检索未找到，检查候选、向量、概念身份/路径及 Wave 通道；如果召回正确而模型误解，修订任务输入或 Prompt。真实规模下重建慢，围绕变化投影、向量复用和 Native 计算定位实际成本。
