## Notes

### 2026-11-04 · 1

用我个人网站的真实文章进行 Wave 算法实验，发现 Wave 算法在处理多语言文本时存在隐性问题。
具体情况是：词法检索可能会使用中文中常见虚词检索，如“的、了、在、是、我、你、他”等，导致结果不准确。

> 这里更需求深入研究，而非立刻上手更改。

### 2026-11-06 · 1

Coding Agent 编写的提示词有效但是语言难以理解，明显出现 GPT 的刻板限定与边界防御模式。
虽然，这对于使用此提示词的小模型来说可能是更明确的边界限定，能够一定程度上提升回复质量。
但是，这种语言模式过于生硬，难以理解，逻辑上更加复杂且心智负担更重。小模型、低推理模型，更容易不遵循而出错。

即便现在检索效果还不错，这仍是问题：对于 Journal 生成，明显适用更高遵循性的模型，如 lite；而对于短文本生成、媒体解析，更建议 mini。

### 2026-11-06 · 2

当前用于编写提示词的上下文提示内容过于笼统，不能帮助开发者。

```toml
[documentation]
title = "形成新 Journal"
purpose = "从材料形成一篇新的 Journal。"
consumers = ["writing.generation"]
input_notes = "本次主体、视角、主题、要求与真实来源放在 user。"
output_notes = "返回 Markdown；无可写材料时精确返回 !NO_MATERIAL!。"
```

对于这个，input_notes、output_notes 就是废话，不能帮助开发者理解模型将会收到的上下文提示内容和模型输出后代码系统所需的信息。

模型在被调用时，会有以下输入：

- system prompt（必须，稳定的任务规则、要求与示例）
- user prompt（必须，本次问题、材料等；Jinja 模板变量替换；JSON Schema）
- attachments（可选，如图片、音频、视频等）

（以及模型具体参数）

输出文本（必然非空）：

- 自由文本 OR JSON

TOML 文件应当说明这份提示词的环境：

这份提示词的目标是让系统得到什么数据，格式如何，期望如何？自由文本还是 JSON？如需 JSON，对应 Schema 如何，JSON 示例如何？
模型会得到什么数据？文本，格式是什么，有什么编号吗，还是有其他什么特殊内容？媒体，什么文件，图片、音频、视频？
Jinja 会渲染什么？数据究竟是什么样的？

### 2026-11-06 · 3

Coding Agent 对 LLMs 非期望输出的错误归因。
在处理材料时，Agent 掌握了原视频约 99 秒、只选取前 10 秒的背景，却没有把这些信息明确告诉模型。

当时保存的实际请求：模型收到的主题是“观察两只猫在视频片段与照片中的互动”，附件是约 10 秒的原生视频和一张照片。来源标题里有 S1:V0-10000，但请求没有解释这个键的单位，也没有说明原视频的总时长。

因此，“动态互动的完整过程”自然指它看到的那段片段。
若直接把它归为模型错误，是 Agent 把自己知道的背景用进了评价。

注意：这是一整类问题：（1）错误归因，浅层思维，分不清所知与未知；（2）没提供足够信息给调用的模型。尤其是（1），这是大语言模型普遍缺失的能力，经常无法区分自己所知与外部对象所知，这种问题在故事、小说写作或者角色扮演中尤为明显。
