# 认知运行与维护

Nous 的认识、经历组织与来源限制由 knowledge、materials、retrieval 和 cognition 各自保存。主体形成的认识沿固定修订和实际接触读取；需要持久恢复的后台工作使用 DBOS。当前架构与完整能力合同见[工程设计](https://github.com/Heptalogos-Devs/Architecture-Vault/tree/feat/specs-infrastructure-research)，基础设施进度见[当前施工](construction.md)。

## Current Work

当前阶段先完成公共底座和真实消费者接线。现有认知实现保留以下能力，完整领域重建在基础设施完成后继续：

- 将认识、修订与来源读取改成按批取得，公开列表和历史使用真正的键集游标。
- 在正式修订事务中维护概念成员，合并和拆分遍历全部实际引用，保留旧修订及关系历史。
- 将认识形成时间与主体实际接触时间共同用于历史截点，并保持当前来源限制即时生效。
- 只重判成长冲突组，允许编辑或结束无效组，已采用的独立组保持成果，后续新经历继续进入新批次。
- 以预览行锁采用种子，使用可信宿主提供的主体形成时刻。
- 接入自然结束、纠正、批次数量和后台窗口的成长机会，完成日终日记和便宜整理；执行继续由 DBOS 保存。

待后续完成的认知能力包括：指称和别名消解、图联想的历史与排序、重排与向量资源的完整费用接线、来源独立性维护、精确上下文裁剪、WorkContext 历史与临时集合清退、媒体派生、资源变更观察、后台假设探索及完整的领域学习与语言作用域查询。媒体与产品管理的施工由对应 owner 继续。

本地连续场景位于 `tests/cognition-database.test.ts`，集中规则位于 `tests/cognition-rules.test.ts`；它们随当前能力扩展，使用正式 API、PostgreSQL、模型 SDK 和来源记录。
