# Python diagnostics hook

The PostToolUse hook runs read-only Ruff syntax checks and BasedPyright type
checks for changed `.py` and `.pyi` files in this Git worktree. It considers index
and worktree changes and untracked files that Git does not ignore. It does not
format files, apply fixes, change the index, or scan outside the Git repository.
Per-session fingerprints under `temp/cache/codex-python-diagnostics/` suppress
unchanged reports; changing `pyproject.toml` invalidates those fingerprints.

## Generated stub rules

Configure generated-stub filtering in the existing `pyproject.toml`:

```toml
[tool.codex-python-diagnostics]
generated-stubs = [
  { paths = ["typings/pypdfium2/**/*.pyi"], marker = "This type stub file was generated by pyright." },
]
```

A file is skipped only when it is a `.pyi`, its repository-relative POSIX path
matches a rule, and its leading comments or module docstring contain that rule's generator marker
within the first 1024 bytes. Mentions in later code or examples do not mark a
handwritten stub as generated. Recursive
`**` matches both zero directory levels and nested directories. Add paths or
rules for other generators as needed; an empty rule list disables this filter.

Handwritten stubs without a matching marker remain checked, including files in
`typings/pypdfium2/`. Python `.py` files remain checked even if they contain the
same marker. Git-ignored untracked files and files outside this worktree are not
selected. Diagnostics from imported files outside the selected Git scope are
not included in the hook response.

BasedPyright resolves maintained dependency stubs from `typings/manual/`, as set
by its `stubPath`. Generated reference snapshots elsewhere under `typings/` are
preserved without taking over dependency imports. Handwritten `.pyi` files in
any Git-visible location still receive explicit hook checks when changed.
